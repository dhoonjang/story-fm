# 에이전트 센터와 협상

협상은 스토리·경기와 나란한 경험이다. 대회·성적과 같은 탭 줄에서 에이전트 센터를 열고,
협상 건을 선택하면 메인 채팅 자리에서 해당 협상의 대화가 열린다.
하나의 협상 건에는 하나의 협상 GM과 독립된 이력·요약이 있다. 구단·선수·에이전트를
같은 GM이 연기한다. 수신 범위는 기록하지만 모델 사이의 비밀 격리는 보장하지 않는다.

## 에이전트 센터

에이전트 센터는 이적·재계약의 허브다. 상단에는 선수 검색을 두고, 진행 중인 협상,
계약 만료 예정 선수, 우리 팀 이적 명단과 종료된 기록을 한 화면에서 확인한다.
검색은 현재 저장 세계의 다른 구단 선수와 무소속 선수를 대상으로 이름·구단·포지션으로
좁히며 서버에서 페이지 단위로 조회한다. 전체 선수단을 매 턴 브라우저로 보내지 않는다.
검색 결과에는 이름·구단·나이·포지션과 현재 열린 문의 여부를 보여주고 선수 카드로 이어진다.
타 구단의 숨겨진 능력치나 비공개 협상 이력은 검색 결과에 노출하지 않는다.
‘이적 문의’는 우리 구단을 영입 구단으로 하는 건을 열고, 무소속은 자유계약으로 구분한다.
이미 진행 중인 건이 있으면 그 대화로 이어가며 동일 선수에 대한 중복 문의를 만들지 않는다.
문의는 게임 날짜를 진행하거나 조건을 발송하지 않고 협상 화면에서 첫 감독 입력을 기다린다.
메인 GM으로 시작한 건과 같은 코어·권한·요청 중복 방지·최신 소속 검증을 사용한다.

우리 팀 이적 명단은 명시적으로 시장에 내놓은 선수만 보여준다. 이름·포지션·나이·희망 이적료·
등재일을 표시하고 관련 매각 협상으로 이어진다. 명단 등재·해제와 희망 이적료 변경은
메인 대화의 검증된 명령으로 수행한다. 등재 자체는 이적 합의가 아니며, 매각·계약 만료로
우리 구단을 떠난 선수는 더 이상 우리 명단에 표시하지 않는다. 이적 명단의 실제 상태와 호가는
메인 GM과 세계 시장 검토가 함께 읽어 다른 구단의 접근 판단에 반영한다.
계약 만료 예정 선수는 바로 재계약 대화를 열거나 기존 건을 이어갈 수 있다.
경기 중이거나 감독이 구단을 맡고 있지 않으면 조회만 가능하고 문의·등재 조작은 잠긴다.

## 협상 목록과 개별 협상 화면

영입·매각·자유계약·재계약은 선수와 관련 구단을 지정한 협상 건이다. 상대 구단,
선수 측을 실제 대화 상대로 구분한다. 내부 처리 기록은 대화 상대가 아니며 같은 협상의
공통 기록으로 표시한다. 대화 전문은 메인 채팅에 복제하지 않는다.
목록은 선수·협상 종류·상대 구단·진행 상태·새 소식과 다음 행동을 표시한다.
진행 중인 협상을 먼저 보여주고, 그 아래에 1년 안에 계약이 만료되는 우리 선수 목록을
만료일 순으로 표시한다. 선수 이름으로 카드를 열고 나이·만료일·남은 기간·주급을 확인한다.
같은 선수의 진행 중인 재계약이 있으면 해당 협상으로 이어갈 수 있다. 종료된 협상은
접힌 기록으로 구분한다. 계약 만료 목록은 공통 재정 조회의 데이터를 그대로 사용하며 재정 화면에 중복 표시하지 않는다.
건을 선택하면 목록 패널을 닫고 메인 채팅 자리를 협상 대화로 전환한다.
대화 상단의 ‘메인 대화로’ 버튼과 채팅 탭은 기존 스토리 대화로 돌아가고, 에이전트 센터 탭은 허브를 다시 연다.
선택한 협상과 열린 장부는 별개라 다른 정보를 보면서도 같은 협상을 이어갈 수 있다.
협상 대화는 메인 대화의 ChatTurnView와 Composer를 그대로 사용한다. 감독 메시지는
유저 말풍선으로, 상대 메시지는 같은 화자·지문·시점 파서와 선수 이름 링크로 표시한다.
협상 메시지를 화면용 ChatTurn으로 연결하는 책임은 application에 있으며 원문은 그대로 보존한다.
협상 GM은 공통 대화 문법인 `@이름:`·`@:`·`*지문*`을 사용하고, 협상 대화만으로
게임 시계를 이동시키지는 않는다. 입력은 전송 전용이며 시간 진행 조작은 두지 않는다. 상대별 대화는
펼친 타임라인으로 읽는다. 상단에는 실제 상대가 둘 이상일 때만 대화 상대 선택을 두며, 별도 조건·절차 화면을 두지 않는다.
재계약은 선수 측 대화로 바로 이어진다. 저장된 내부 메시지는 권한으로 걸러진 기록만
현재 대화와 함께 순서대로 표시하고, 입력의 수신 범위로 내부 업무를 선택하지 않는다.
조건은 협상 대화에서 자연어로 제안하고 조정한다. 별도 제안서 작성 폼이나 전송 옆 작성 버튼은 두지 않는다.
협상 GM은 대화에서 논의한 조건을 구조화된 초안으로 정리하고, 상대가 제시하거나 동의할 수 있는
조건은 해당 당사자 명의의 제안으로 기록한다. 감독의 질문·초안·자연어 동의만으로 유저 구단의
수락이나 서명을 만들지 않는다. 상대의 조건 제시는 협상 판단이며 유저 구단의 동의와 분리한다.
대화 안의 읽기 전용 조건 카드에는 현재 논의 중인 이적료·주급·계약 기간·보너스·분할금·약속을
정리한다. 초안은 합의가 아니며 확인 버튼을 두지 않는다. 상대가 유효한 제안으로 조건을 확정하면
‘조건 확인 후 합의’로 정확한 조건을 확인한다. 수정할 내용은 대화로 이어간다.
이전 조건은 접어 두고, 만료·철회·교체된 제안에는 확인 버튼을 표시하지 않는다.
계약 기간은 연수로 보여주며 시작·종료일과 제안 유효 기한은 장부에서 관리한다. 재계약의 기본
시작일은 현재 날짜, 이적의 시작일은 구단 간 합류일과 맞춘다. 연 단위 조건은 시작일의 해당
연수 마지막 날까지이며, 금액·기간·약속이 모호하면 대화로 확인한다.
메디컬·서명·등록은 해당 단계가 되었을 때 조건 요약과 함께 대화 아래 진행 카드로 표시한다.
재계약에 불필요한 메디컬 안내나 아직 할 수 없는 서명 버튼은 표시하지 않는다. 메디컬 결과와
위험은 별도로 확인하며, 최종 서명 전에는 합의한 모든 조건을 다시 볼 수 있다.
상태는 제목 아래 상대 정보와 함께 표시하고, 제안 전에는 ‘협상 중’으로 표시한다.
협상 철회는 제목 오른쪽의 더보기 메뉴에서 실행한다. 협상 목록은 전역 에이전트 센터 탭으로 열며
개별 화면에는 목록 복귀 버튼을 중복 배치하지 않는다.
스토리 대화의 기록·입력 초안·스크롤은 협상을 오갈 때 보존한다.
협상은 메인 GM에게 자연어로 요청하거나 에이전트 센터에서 문의하거나 다른 구단의 접근으로 시작된다.
메인 GM은 협상을 열거나 현황을 조회할 수 있으며 제안 발송·수락·서명을 대신하지 않는다.
메인 대화에서 진행 중인 건의 제안 발송을 요청해도 기존 협상을 열어 이어가며, 실제 발송
기록 없이 발송 완료나 상대 답변 대기를 서술하지 않는다.
감독이 시작한 협상은 상대 답변·제안서·후속 답변 예약 없이 열리고 감독의 첫 입력을 기다린다.
같은 협상 GM 설정으로 읽기 전용 구조화 호출을 수행해 감독 시점의 첫 제안 문구만 생성한다.
이 문구는 `start_negotiation` 성공 기록의 구조화 payload에 보관하고, 입력창 placeholder와
자동완성에 사용한다. 전송 전에는 협상 메시지나 발송한 제안이 아니며 수락·서명도 만들지 않는다.
첫 감독 메시지가 전송되면 초기 문구를 더 이상 표시하지 않는다. 생성 실패는 협상
생성을 취소하지 않으며 일반 입력 안내로 돌아간다. 기존 건을 다시 열 때 재생성하거나
상대의 말을 추가하지 않는다. 다른 구단이 시작한 접근과 AI끼리의 협상은 기존 시장 흐름을 따른다.
메인 GM의 `start_negotiation`이 성공하면 현재 턴의 응답 표시가 끝난 뒤 해당 협상으로
자동 전환한다. 이미 진행 중인 건을 반환해도 같은 건으로 이동한다. 성공 기록에
구조화된 협상 id를 남기며, 화면은 현재 턴의 기록과 보이는 협상 목록을 검증해 이동한다.
한 턴에서 여러 건을 열면 마지막 유효한 건을 연다. 실패한 요청이나 과거 기록의
재조회는 자동 이동을 만들지 않는다. 대화의 도구 칩 이름은 ‘협상 시작’이다.
에이전트 센터의 선수 검색에서 선택한 선수에게 바로 이적 문의를 시작할 수 있다.
이 화면은 이메일 수단을 가정하지 않으며, 읽기와 조건 논의는 게임 시간을 진행하지 않는다.
메인 GM의 협상 시작 도구는 선수·구단의 이름 또는 실제 id를 받아 기존 공통 조회
규칙으로 해석한다. 영입 구단을 생략하면 현재 맡은 구단이다. 명시한 구단을 찾지 못하거나
이름이 여러 당사자와 맞으면 후보와 조회 방법을 돌려주고 협상을 만들지 않는다.
코어에는 확정된 id만 전달하며 맡은 구단과 관련 없는 협상은 열 수 없다.
영입 구단은 현재 세계에 존재하고 재정 원장을 가진 구단이어야 한다. 무소속은 영입 당사자가 아니다.
같은 협상 건을 다시 여는 요청은 기존 건을 반환하며 추가 모델 호출을 만들지 않는다.
진행 중인 경기의 명단·체크포인트를 유지하기 위해 경기 중에는 협상 조작을 잠근다.

초안은 대화에 따라 갱신하고 발송한 제안은 불변이다. 수정은 새 제안으로 남으며 같은 범위의
이전 제안과 동의는 더 이상 집행 근거가 아니다. 구단 간 이적료와 선수 계약 조건은
각각 동의를 받는다. 금액은 £ 정수, 주급은 주 단위이며 분할 지급은 날짜·금액으로 적는다.
역할 등 자유 약속은 당사자의 기억이며 출전을 강제하지 않는다. 미지원 금전 조항을
자유 약속으로 우회하여 체결하지 않는다.

## 합의와 실행

모델은 상대의 이해관계·실제 대안·새 사실로 수락과 거절을 판단한다. 반복 설득 점수는
없다. 코어는 당사자·제안·동의·현재 계약·자금·날짜·중복 실행을 검증한다. 유저의
수락과 서명은 직접 조작으로 기록한다. 모델은 유저의 서명을 대신할 수 없다.

이적은 양측 조건 합의 → 메디컬 → 서명 → 합류·등록으로 이어진다. 재계약에는
구단 간 합의와 신규 영입 메디컬을 요구하지 않는다. 검사는 실제 부상 기록에서
현재 상태와 회복 전망을 읽는다. 결과 때문에 없던 부상을 만들거나 재검사로 추첨하지
않는다. 추가 검사는 시간이 필요하며 서명 전 위험 감수·재협의·철회를 선택한다.
서명 후 계약 의무는 검사·등록 실패나 감독 교체만으로 사라지지 않는다.

계약·소속 변경·선수단 정리·현금과 미래 지급 의무는 함께 기록된다. 날짜별 분할금은
한 번만 정산한다. 등록 자격과 계약은 구분하며, 미등록 선수는 경기에 나서지 못한다.
여름·겨울 등록 기간과 자유계약 예외는 게임의 시즌 규칙이며 현실의 모든 협회 예외를
모사하지 않는다. 리그별 규정 확장은 같은 검증 경계를 사용한다.

## 기억

원문은 보존하고 모델 이력만 협상별로 압축한다. 요약은 거절 이유·양보·미해결 쟁점을
담으며 정확한 조건과 동의는 구조화된 제안서에 남는다. 요약 실패 시 원문을 버리지 않는다.
메인 GM은 현재 조건·동의·절차와 공개 범위 안의 최근 짧은 대화, 거절 사유를 읽어 일상 장면을 잇는다.
협상 전문을 메인 이력에 복제하지 않으며, 자연어 발췌는 집행 근거가 아니다. 매각 구단에는 선수 측 비공개 조건을 노출하지 않는다.
현재 계약·소속·건강·재정은 매 호출 최신 상태에서 읽는다. 협상 GM은 update_character로
기존 비동기 편집 경로에 직접 요청한다. 메인 GM은 편집 중개자가 아니다.

## 세계 시장

날짜 진행은 계약 만료·부상·감독 교체·선수단과 재정 변화에 대한 검토를 예약한다.
세계 판단은 구단의 보강·매각·재계약 계획과 감독 고용을 구조화하여 제출한다. 선수단
필요와 예산은 코어의 사실이고 인물의 선택은 모델의 판단이다. AI끼리도 같은 협상·동의·
메디컬·계약 코어를 사용한다. 유저 구단의 서명은 대신하지 않는다. 시장 검토와 답변은
게임 날짜에 묶이며 UI 열기·읽기로 재추첨하지 않는다. 실패한 모델 호출은 재시도할 수
있고 완료한 검토는 다시 실행하지 않는다. 세계 판단으로 부상을 생성하지 않는다.

검토는 하루에 오래 기다린 구단 10개와 중요한 사실이 달라진 구단 최대 2개를 순환한다.
같은 사실을 가진 구단은 7일 안에 다시 검토하지 않는다. 부상·선수단·계약·감독 변화는
우선 검토의 근거다. 세계 구단의 완료된 영입은 등록 제한을 확인해 등록하고,
기존 전술 배치와 선수별 적응도 기억을 유지하며 AI 라인업을 다시 구성한다.
유저의 선수 등록과 라인업 선택은 직접 조작으로 남는다.

구단별 세계 판단은 실제 명단에서 수준·포지션과 계약 상황이 맞는 후보를 추려 읽는다.
AI 영입 구단은 진행·합류·등록 대기 협상을 최대 두 건 유지하고, AI끼리의 답변은 하루 최대
12건을 오래 기다린 순서로 처리한다. 나머지는 다음 날로 예약하며 유저가 참여한 협상은
이 처리 한도와 따로 응답한다. 날짜 진행은 이런 내부 업무를 처리한 뒤 요청한 목적지로
이어지고, 경기일·유저의 판단이 필요한 사건에서는 멈춘다.

negotiation은 협상·제안·메디컬 절차·시장 판단을, common은 계약·건강·재정·인물 사실을
