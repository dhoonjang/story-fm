# 0001. MVP는 실명 실데이터로, 라이선스는 출시 전 청산

- 상태: 채택
- 날짜: 2026-06-20

## 맥락

선수/팀 데이터 소싱을 조사한 결과(→ [data-sourcing.md](../design/data-sourcing.md)),
두 가지 구조적 제약이 드러났다.

1. **능력치는 합법적으로 사올 수 없다.** 무료·유료 라이브 API 중 FM·FIFA식
   능력치(스피드·슈팅·패스)를 제공하는 곳이 하나도 없다. 능력치를 가진 소스
   (SoFIFA/EA, Football Manager DB)는 전부 게임사 IP라 상업적 탑재가 불가하다.
2. **실명 데이터는 4개 권리 레이어**(선수 NIL · 클럽 상표 · 리그 상표 · 데이터)를
   건드리며, 정식 라이선스는 인디/프로토타입 단계에서 비현실적인 비용
   (FIFPRO·리그 단위 수천만~수억 원대)이다.

현재 단계는 MVP/프로토타입이며, 검증할 것은 *"AI 감독 + LLM 내러티브"라는 핵심
루프가 재미있는가*이지 *라이선스 게임으로 출시 가능한가*가 아니다.

## 결정

1. **MVP는 실명 실데이터로 진행한다.** 능력치는 Kaggle EA FC 데이터셋 등에서
   가져와 프로토타입의 시드 데이터로 즉시 사용한다.
2. **능력치는 "생성"을 기본 전략으로 둔다.** 실측 경기 스탯 → 능력치 변환 AI
   모델을 자체 학습하고, EA/FM 능력치는 _교사 데이터로 참고만_ 한다. 출시
   빌드에는 자체 산정값만 탑재한다.
3. **라이선스는 MVP에서 보류하되, 청산해야 할 "부채"로 명시 기록한다.**
   ([data-sourcing.md §7](../design/data-sourcing.md)의 부채 원장)
4. **법적으로 깨끗한 코어**(리그/팀/일정/선수 메타)는 처음부터 CC0 소스
   (OpenFootball, Wikidata)로 구축해, 나중에 실명·🔴소스만 걷어내면 출시 가능한
   구조로 둔다.

## 근거 / 대안

- **왜 실명 MVP인가** — 프로토타입의 목적은 핵심 재미 검증이다. 가명/합성부터
  시작하면 데이터 통합·밸런싱 작업이 두 배가 되고, 정작 검증할 루프가 늦어진다.
  실명은 즉시 풍부한 데이터를 주고, "부채"로 격리하면 출시 경로도 막지 않는다.
- **왜 능력치 생성인가** — 능력치를 합법적으로 살 수 없다는 제약과,
  [AGENTS.md](../../AGENTS.md)의 "내러티브 우선 · 자체 시뮬레이션 코어" 비전이
  같은 방향을 가리킨다. 제약이 곧 차별점이 된다.
- **검토했지만 버린 대안**
  - _처음부터 정식 라이선스_ — 비용·협상력 모두 프로토타입 단계에 비현실적.
  - _처음부터 완전 합성 세계관_ — 데이터 통합 부담이 커 핵심 루프 검증을 지연.
    출시 단계에서 재검토할 수 있는 선택지로 남겨둔다.
  - _🔴소스(EA/FM/Transfermarkt)를 출시까지 그대로 사용_ — IP 침해·약관 위반으로
    상업 출시 자체가 불가. 명백히 배제.

## 영향

- **코드/데이터**: CC0 코어와 🔴 부채 소스를 데이터 적재 단계에서 분리 가능하게
  설계한다(소스별 플래그). `packages/domain`에 통합 키(`internal_player_id`)와
  매핑 테이블을 둔다.
- **기획**: 능력치 변환 모델 설계가 후속 기획 항목이 된다(별도 design doc 후보).
- **출시 전 게이트**: data-sourcing.md §7 부채 원장의 5개 항목을 모두 청산하기
  전에는 상업 출시하지 않는다. 출시 직전 관할권별 변호사 검토를 받는다.
- **후속**: 정식 출시 단계에서 "가명 전환 vs 완전 합성 vs 정식 라이선스"를
  다시 결정하는 새 ADR이 필요하다.
