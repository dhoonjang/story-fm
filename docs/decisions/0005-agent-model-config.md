# 0005. 에이전트별 제공자·모델을 YAML로 직접 설정

- 상태: 채택
- 날짜: 2026-08-11

## 맥락

기존 설정은 `gm`·`match`·`chore` 티어와 제공자별 모델 표를 코드에 함께 뒀다.
세 결산 에이전트가 `chore` 하나를 공유했고, 키 유무와 제공자 선호 환경변수에 따라
실제로 호출되는 모델이 설정자의 의도와 다르게 폴백할 수 있었다. 특정 에이전트의
모델만 바꾸려 해도 코드와 테스트를 수정해야 했다.

## 결정

1. `config/llm.yml`을 에이전트별 LLM 설정의 유일한 원본으로 둔다.
2. `gm`, `match-caster`, `match-rater`, `training-rater`, `mood-rater`가 각각
   `provider`, `model`, `max_tokens`와 제공자 전용 옵션을 가진다.
3. 팩토리는 설정된 제공자의 어댑터를 정확히 선택하며 키 유무로 다른 제공자에
   폴백하지 않는다.
4. 설정은 프로세스 시작 시 Zod로 검증하고, 누락되거나 잘못된 설정은 호출 전에
   실패시킨다.
5. 사용량과 토큰 예산 장부도 같은 에이전트 이름으로 나눠 기록한다. GM과
   매치 캐스터는 예산을 넘어도 계속 실행하고, 코어 앵커가 있는 세 결산
   에이전트만 건너뛸 수 있다.
6. 제공자 선택 환경변수는 두지 않는다. 실호출 키와 `LLM_MODE`, 토큰 예산만
   환경변수로 남긴다.

## 근거 / 대안

- TypeScript 상수는 타입 안전하지만 모델 변경마다 코드 diff가 필요하고 배포 설정과
  실행 설정의 경계가 흐려진다.
- 에이전트별 환경변수는 조합이 늘수록 이름과 배포 설정이 폭증한다.
- YAML은 한 파일에서 전체 배치를 검토할 수 있고, 각 에이전트의 제공자와 모델을
  한 변경으로 명시한다. Zod 검증을 붙여 문자열 설정의 약점을 시작 시점에 막는다.
- 키가 없을 때 다른 제공자로 폴백하는 방식은 가용성은 높지만 품질·비용·저장 이력의
  제공자가 조용히 바뀐다. 명시적 실패를 택한다.

## 영향

- 모델 교체는 `config/llm.yml`만 수정한다.
- 결산 세 종류의 사용량과 실패를 서로 구분할 수 있다.
- 설정 변경으로 provider/model이 달라지면 기존 원형 대화 이력은 섞지 않고 새로
  시작한다. 경기 장부와 전력 패킷은 유지된다.
