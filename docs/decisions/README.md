# 설계 결정 기록 (ADR)

중요한 설계·기술 **결정과 그 근거**를 시간순으로 남긴다. 기획서(`../design/`)가
"무엇을"이라면, ADR은 "왜 그렇게 정했나"를 기록한다.

## 작성 규칙

- 파일명: `NNNN-제목.md` (예: `0001-deterministic-core.md`). 번호는 4자리 증가.
- 한 결정 = 한 파일. 결정은 되도록 **번복하지 않고**, 바뀌면 새 ADR로 대체하며
  기존 ADR의 상태를 `Superseded by NNNN`으로 표시한다.

## 템플릿

```markdown
# NNNN. 제목

- 상태: 제안 | 채택 | 폐기 | NNNN으로 대체됨
- 날짜: YYYY-MM-DD

## 맥락

무엇을 결정해야 했고, 어떤 제약/배경이 있었나.

## 결정

무엇으로 정했나.

## 근거 / 대안

왜 이걸 골랐나. 검토했지만 버린 대안과 그 이유.

## 영향

이 결정이 코드·기획·비용에 주는 영향. 후속 작업.
```
