# 로어북과 대화 요약

서사는 로어북과 대화 요약에 보존한다. 관계·기억·의도·갈등과 인물의 평가는 자유
정보와 대화로 이어진다. 선수의 희망과 의사도 자유 기록으로 관리한다.
경기·몸 상태·계약·재정·고용의 실제 사실은 해당 원장이 소유하며 로어북의 문장으로
변경하지 않는다. 저장 형태와 모델 입력의 버전은 각각 `SAVE_VERSION`과 `config/game-version.yml`이 소유한다.

## 항목

팀·선수·인물 카탈로그는 이름, 키워드 목록, 한 줄 설명, 자유 형식 정보를 기본값으로
관리한다. 필드는 `name`, `keywords`, `description`, `information`이다. 새 게임은 이를 복사하고 이후 편집은 세이브에만 반영한다. 이름과 내부 ID는
고정이며 키워드·설명·정보는 바뀔 수 있다. 관계·의도·갈등도 정보 안의 자유 기록이다.
인물 생성용 본문은 최초 등록에만 쓰며 진행 중 페르소나·고용 후보에는 본문을 복사하지 않는다.
새로 등장한 인물도 같은 로어북에 생성할 수 있다. 이 등록은 선수·계약 생성이 아니다.

**한 줄 설명은 바뀌지 않는 기본 정보다.** 이 항목이 누구·무엇인지를 처음 읽는 사람에게
알리는 사실만 담고, 성격·동기·각오·관계는 자유 정보로 보낸다. 소속·포지션·나이·리그처럼
시간이 지나면 바뀌는 사실은 저장하지 않는다 — 원장이 그 값을 갖고 주입이 붙인다.

| 갈래 | 한 줄 설명                              | 예                                   |
| ---- | --------------------------------------- | ------------------------------------ |
| 선수 | 국적 · 출생연도 · 주발 · 키 (있는 것만) | `프랑스 · 2001년생 · 오른발 · 190cm` |
| 인물 | 직책 종류. 기자는 매체까지              | `수석코치` · `기자 · 시티 이브닝`    |
| 팀   | 나라의 구단                             | `잉글랜드 축구 구단`                 |

## 주입

메인·매치 GM 모두 현재 유저 입력과 직전 모델 발화에서 이름과 키워드를 검색해 현재 유저 메시지 마지막에
항목을 추가한다. 항목마다 그 순간의 원장 사실 한 줄(`now`)이 함께 실린다 — 선수는
소속(무소속·은퇴)·주 포지션·나이, 인물은 지금 고용된 구단과 직함, 팀은 리그·체급·홈구장·
역대 우승. 이 줄은 주입한 순간에 만들어 턴 기록에 함께 남으므로 이력을 다시 그려도 같다.
같은 버전이 현재 이력 안에 있으면 중복 주입하지 않는다. 항목이
갱신되거나 주입한 턴이 요약되어 이력 밖으로 나가면 다음 키워드 일치 때 다시 주입한다.
항목 본문과 요약의 후보 목록은 검색 대상이 아니며 연쇄 주입하지 않는다.
주입한 본문과 버전을 턴에 저장해 이후 이력 조립에서도 같은 메시지를 재현한다.
로어북 본문을 포함한 메시지 길이로 압축 시점을 결정한다.

협상 GM은 해당 선수·구단·대화 상대의 최신 로어북을 협상 참조 맥락으로 읽는다.
협상 이력과 정확한 계약 조건은 별도의 협상 장부에서 읽는다.

## 편집

메인·협상·매치 GM이 `update_character` 스킬로 대상과 추가 정보를 전달한다.
대상은 항목 ID 또는 이름이며 동명이인은 ID로 지정한다. 새 인물은 `newCharacter`에
이름·키워드·설명·정보를 함께 전달한다. 요청은 원래 턴과
함께 저장하고 lorebook-editor가 비동기로 처리한다. 같은 항목의 요청은 순서대로
처리하고 완료 시 최신 세이브의 항목만 갱신한다. 편집 접수는 화면에 호출 칩을 만들지 않고 로그에 남긴다. 원래 턴이 실패하면 요청도 저장하지
않는다. 실패 시 기존 항목을 유지하며 다음 실행 기회에 재시도한다.
성공한 편집은 이전 항목의 본문·버전, 요청한 추가 정보와 작업 ID를 갱신 이력에 남긴다.
현재 항목은 빠르게 읽는 설명이며, 갱신 이력은 재작성 과정에서 빠진 정보를 복원할 근거다.
편집 에이전트는 기존 항목과 추가 정보로 키워드·한 줄 설명·정보를 합쳐 다시 쓰며,
이름은 바꾸지 않는다. 완료된 갱신은 다음 모델 호출부터 사용할 수 있다.
모델 설정은 `config/llm.yml`의 `lorebook-editor`가 소유한다.
모델 호출은 게임 잠금 밖에서 실행하고 완료 시 잠금 안에서 최신 세이브를 다시 읽는다.
요청과 대상 버전을 확인해 오래된 응답이 그 사이의 편집을 덮어쓰지 않게 한다.
게임 GET은 저장된 미완료 작업을 다시 실행하므로 서버 재시작 뒤에도 요청을 잇는다.
편집 호출과 완료 기록은 `traceBoard`로 board shelf에 남는다.

협상 GM은 관계·약속·갈등을 직접 편집 요청한다. 메인 GM을 경유하지 않는다. 협상 원문과
정확한 제안·동의는 협상 건에 남으며 로어북은 다른 경험에도 이어지는 기억을 담는다.

## 요약

평시 이력이 예산을 넘으면 이전 요약과 접힐 원문을 합쳐 지난 일과 열린 이야기를
요약한다. 원문은 요약이 검증·저장된 지점까지만 모델 이력에서 제외한다. 압축 실패 시
요약되지 않은 원문을 조용히 버리지 않는다. 전체 화면 채팅은 보존한다.
요약 에이전트는 로어북을 편집하지 않는다. 카탈로그와 세이브의 인물 후보에서
**최대 240명의 이름·한 줄 설명만 입력**한다. 이전 요약의 이름, 최근 주입한 항목,
현재 선수단과 페르소나를 우선 포함하고, 나머지는 요약 회차로 결정적으로 순환하는
새 항목으로 채운다. 전체 카탈로그의 상세 정보나 수천 명의 색인을 매번 보내지 않는다.

모델은 주어진 풀에서 활용할 만한 이름·한 줄 설명을 고른다. 선택 목록은 같은 풀에서
보충해 30명을 채우고, 풀이 더 작으면 전원을 남긴다. 이 후보는 요약과 함께 보존한다. 이 목록은
상세 로어북 주입을 트리거하지 않는다. GM이 이름을 발화하거나 유저가 키워드를
입력하면 다음 유저 메시지에서 상세 정보가 주입된다. 목록은 등장 의무가 아니다.
경기의 결과·대화도 종료 후 메인 GM이 로어북 갱신과 서사 전개에 사용할 수
있도록 전달한다.

## 원장과 검증

편집 결과는 키워드·설명·정보의 Zod 스키마를 통과해야 한다. 항목의 ID·이름·종류는
편집 결과로 변경하지 않으며 정상 완료하면 버전을 올린다. 키워드는 최대 40개,
한 줄 설명은 최대 240자, 정보와 요청의 추가 정보는 최대 12,000자다.

인물의 의사와 평가는 GM이 대화의 맥락으로 판단한다. 고용·은퇴·계약·재정 결정은
해당 명령의 검증을 거쳐 원장에 반영한다. 법적 당사자, 날짜, 금액, 소속과 중복 집행
여부는 코어가 확인한다. 로어북의 인물 등록과 실제 선수·스태프 고용은 별개다.

현재 경기·훈련·계약·재정 사실은 스냅샷과 조회로 전달한다. 사건 로그는 실행 이력을
기록하며, 이야기의 장기 기억은 로어북과 대화 요약이 소유한다.

## 코드 위치

- 항목·편집·요청·주입 스키마와 렌더링: `packages/domain/src/common/lorebook.ts`
- 검색·편집 접수·완료·후보 풀: `packages/engine/src/common/people/lorebook.ts`
- 편집 에이전트: `packages/agents/src/story/lorebook-editor.ts`
- 비동기 작업 실행·저장·재개: `apps/web/application/lib/lorebook-jobs.ts`
- 이력 압축: `packages/agents/src/story/history-compactor.ts`

## 경기와 세계의 사실

선수의 능력·몸 상태·폼·적응, 실제 훈련 배정과 경기 결과는 경기·훈련 원장을 따른다.
일정, 부상, 징계, 선수 등록, 계약 만료와 지급은 실제 행동의 가능 여부를
결정한다. GM은 이 사실을 읽어 인물의 반응과 장면을 구성한다.
