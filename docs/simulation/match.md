# 경기 시뮬레이션

**코어가 선수별 슈팅과 각 슈팅의 xG·결정력·결과를 굴려 확정하고, LLM은 그것을
중계·연출·대화로 옮긴다.** 감독의 지시는 전력 패킷을 통해서만 결과에 닿는다.

요구사항:

1. **영향성** — 능력치·전술·상태·감독 능력이 결과에 통계적으로 반영된다.
2. **일관성** — 경기 장부(스코어·시계·인원·스탯)에 모순이 없다.
3. **설명 가능성** — 주요 사건은 패킷 항목(원인 태그)으로 설명된다.
4. **양방향** — 유저의 결정이 좋은 쪽으로도 나쁜 쪽으로도 결과를 움직인다.
5. **결정성** — (시드, 경기, 구간)이 같으면 같은 사건. 개입은 패킷을 바꿔
   **그다음 구간부터** 반영된다.
6. **눈금** — 한 경기의 총량(슈팅·카드·부상)은 패킷의 기대치이며, 구간이 몇 번으로
   끊기는지와 무관하다 (§1.4).

## 1. 전력 분석 패킷 (코어, 결정적)

킥오프·교체·전술 변경·구간 진행마다 재계산되는 경기의 판세. 힌트가 아니라
**결과를 만드는 수치**다.

```ts
StrengthPacket {
  lineup / bench,        // 개인 단위 전력 + 깎인 이유 분해 (§1.1)
  zones,                 // { attack, midfield, defense } × 양팀
  matchups,              // 존별 우열 + 양팀 존 수치
  tactical,              // 지시 적용률(uptake) + 이득·대가 태그
  keyPoints,             // 전술 미스매치 (sim/key-points.ts, 14축)
  guide: {
    shotProfiles,        // 선수×경로의 기대 슈팅·평균 xG — 두 시뮬의 공통 원본
    expectedShots, chanceXg, expectedGoals, // 위 프로필을 팀 단위로 합친 판독값
    possession,          // 중원 우위가 만든 점유 — 두 시뮬과 패스 배분의 원본 (§1.5)
    intensity,           // 0.80~1.22 — 피로·파울·부상률을 함께 움직인다
  },
}
```

#### 패킷이 싣는 것은 태그다 — 문장은 뷰가 만든다

`keyPoints` · `tactical.notes` · `matchups` · 공략 표적은 전부 **사실 태그**
(`PacketTag`)이고, 그것을 읽는 화면·중계·CLI가 같은 렌더러 하나로 문장을 만든다
(→ [overview.md](../overview.md) §1 철칙 4).

```ts
PacketTag {
  source,      // counter | gap | mismatch | zone-plan | directive | exploit | tactical
  code,        // 축·상성·지시의 코드 — 판정과 집계의 열쇠 ("space_behind", "backline-pace")
  favours,     // 이로운 편 (home | away | null) — 약점을 **가진** 쪽이 아니다
  holder?,     // 그 사실을 **가진** 쪽 — 미스매치 문장의 주어. 없으면 이로운 편의 반대다
  sharp,       // 수치를 드러내도 되는가 — 감독의 눈(분석)이 정한다 (§1.6)
  playerIds,   // 이름이 서는 선수들 — 팀 단위 사실이면 빈 배열
  values,      // 라벨 붙은 수치 { pace: 88, defencePace: 61 }
  flags,       // 문장 안에 숨어 있던 조건부 축 ("sweeper", "trap-unfamiliar")
  text?,       // 구조로 못 옮기는 자유 문장 — 지역 플랜의 모델 원문, 옛 세이브의 줄
}
```

⚠️ **`sharp`가 안개다.** 정밀한 문장과 흐린 문장은 같은 사실의 두 해상도이고, 어느
쪽을 낼지는 렌더러가 `sharp`로 가른다 — 태그에서 이 칸을 빼면 감독이 못 본 수치가
노트로 새어 들어온다 (§1.6).
⚠️ **`favours`는 이로운 쪽, `holder`는 가진 쪽이다.** 두 뜻을 한 칸에 담으면 골의
원인과 화면의 색이 정반대가 된다. **뒤집는 규칙은 축마다 다르다** — 느린 센터백·불안한
골문처럼 가진 쪽이 잃는 축은 이로운 편이 반대지만, 창조자·마무리·골키퍼 배급·세트피스
키커는 **가진 쪽이 곧 이로운 쪽**이다. 한쪽으로만 접으면 우리 에이스가 상대에게
이로운 사실로 실린다 (`key-points.ts`의 `AXIS_FAVOURS_HOLDER`).

### 1.1 전력은 개인에서 시작한다

```
effective(선수) = roleFit(16축 × 자리 가중치)
                × stateModifier(폼 + 체력·경기 중 피로)
                × profFactor(포지션 적응도)           0.10~1.00
                × famFactor(전술 적응도 × 자리 민감도) 0.79~1.00

zones = XI 가중 평균(ZONE_CONTRIBUTION) × 존 기준선(ZONE_BASELINE)
      × (1 + 전술 델타·상성, tanh로 ±18% 포화) × tacticalFit(감독)
      × 구멍 감점(라인별) × 수적 열세 감점(빠진 인원 × 12%, 최대 3명)
```

`roleFit`은 각 배치의 실제 `roleId`를 사용한다. 존 기여도는 포메이션 프리셋이나
포메이션 이름이 아니라 각 선수의 전술판 `point`를 사용해 공격·중원·수비 사이를
연속적으로 배분한다. 양 팀 모두 같은 경로를 쓴다.

**XI 가중 평균은 평점의 지수를 한 번 지난다** (`abilityCurve` — `ABILITY_LOG_SLOPE`
0.017 · `ABILITY_PIVOT` 72). 축구 득점의 표준 통계 모델(Maher 1982 · Dixon–Coles 1997)은
`log λ`가 공격·수비 **평점의 차**에 선형이다 — 전력은 평점의 지수이고, 같은 5점 차는
60 대 65에서도 80 대 85에서도 같은 승률 차다(Elo와 같은 꼴). 존의 가중 평균을 그대로
비율로 맞세우면(거듭제곱을 포함해) 같은 점 차가 위에서는 작게 아래에서는 크게 세어져
우승 후보가 중위권에 발목을 잡히고 강등권만 짓눌린다 — 우승 승점이 70점대에 주저앉고
(실제 1부 84~93) 시즌 xG 비도 1.4:1에 멎는다(실제 2.5:1). 그래서 세 존의 가중 평균 x를
`exp(0.017 × (x − 72))`에 올린다: 두 팀의 전력 비는 `exp(0.017 × 평점 차)`이고 축의 위치와
무관하다. 전술·상성·공략·개인 지시는 이 곡선 **뒤에** 곱해지므로 지시 한 칸이 존을
움직이는 폭은 그대로다 — 벌어지는 것은 능력의 격차뿐이고, 존 안의 폼·체력·적응도·
관중이 옮긴 몫은 같은 지수를 탄다. 축은 절대값(화면의 존 숫자)에만 닿는다.

**세 존은 한 눈금 위에 선다 — 매치업 비율의 기준선은 1이다** (`ZONE_BASELINE`
공격 0.957 · 중원 1 · 수비 1.045). 같은 전력이 맞설 때 `우리 공격 / 상대 수비`가
1이어야 "우리 진영이 밀린다"가 신호가 되기 때문이다. `ZONE_CONTRIBUTION`의 가중치
자체는 기울어 있지 않다(전술과 공략을 모두 끄고 재면 세 존이 1.00에 선다). 기울기는
존 위에 얹히는 두 층에서 오고, 그 둘은 **구조적으로 공격 쪽으로만 실린다**:

- **공략**(§1.6) — 키포인트가 드러내는 약점은 대개 상대 수비 쪽이라 14축 중 9축의
  이득이 공격 존으로 들어온다. 이득을 "상대 수비를 깎는다"로 옮겨도 `공격/상대 수비`
  비율은 똑같이 오르므로 재분배로는 닫히지 않는다.
- **전술 6축**(§1.2) — 프리셋을 3에 맞추고 갈래를 대칭으로 만든 뒤에도 리그 평균이
  공격 ×1.037로 남는다.

그래서 보정은 가중치가 아니라 **존이 완성된 자리**에 걸고, 공격과 수비에 절반씩
나눠 건다(한쪽에만 걸면 화면의 격자가 그쪽 줄로만 눌린다). ⚠️ 리그 실측에 묶인
값이다 — 전술 프리셋·공략 크기·역할 가중치를 만졌으면 편성 400경기의
`우리 공격 / 상대 수비` 평균을 다시 재고 그 비율의 제곱근만큼 두 값을 반대로
움직인다.

- `profFactor = 0.10 + 0.90 × log(1 + clamp(적응도, 0, 99) / 5) / log(1 + 99 / 5)`.
  정규화한 `log1p`라 낮은 구간은 크게 벌리고 높은 구간은 평평하게 만든다:
  0 → 0.100 · 1 → 0.154 · 25 → 0.631 · 40 → 0.752 · 70 → 0.903 · 85 → 0.957 ·
  95 → 0.988 · 99 → 1.000. 목록에 없는 자리의 폴백은 25라 보통의 생소한 배치는
  0.631부터다.
- `famFactor = 1 − (1 − clamp(적응도, 0, 100) / 100) × 0.15 × 자리 민감도`.
  전술 적응도 0일 때 자리별 하한은 중원 0.79부터 스트라이커 0.91까지다.
- 포지션 적응도 0의 감점 폭(90%p)이 전술 적응도(기본 15%p)보다 크다 — 전술은 몇
  주면 익히지만 자리는 커리어가 만든다.
- 전술 적응의 무게는 자리마다 다르다(`TACTICAL_SENSITIVITY`): 중원 1.4 · 수비 1.2 ·
  AM 1.0 · 윙/CF 0.7 · ST 0.6 · GK 0.8.
- 명단의 단일 `적응` 게이지(`adaptationOf`)는 두 적응도의 **저장값을 그대로**
  섞은 표시용 파생값이다 — **선형이고 로그 곡선을 씌우지 않는다.** 섞는 비율은
  게임이 실제로 방문하는 폭(`ADAPTATION_GAUGE_BAND` — 자리 0.37 · 전술 0.15 ×
  자리 민감도)이 정한다. 경기 계산은 그 값을 쓰지 않고 위 두 팩터를 각각 곱한다
  (→ [player.md](../data/player.md) §8).
- 지시 적용률(`uptake` 0.45\~1.0)만은 팀 평균을 쓴다 — 전술 지시는 열한 명이 함께
  소화한다. `0.45 + 0.35×(감독 전술/99) + 0.20×(팀 전술 적응도)`.

### 1.2 전술 6축 — 이득과 대가를 함께 낸다

| 축              | 이득                                  | 대가                                    |
| --------------- | ------------------------------------- | --------------------------------------- |
| 멘탈리티 ↑      | 공격                                  | 수비                                    |
| 압박 ↑          | 중원 (체력이 받쳐줄 때 더) + **수비** | 뒷공간(더 크다) + 강도↑(피로·카드·부상) |
| 수비 라인 ↑     | 중원(압축) + 공격(상대를 밀어낸다)    | 수비 — 상대 최전방이 빠를수록 비싸다    |
| 템포 ↑          | 공격                                  | 실책 (침착성 낮으면 더) + 강도↑         |
| 폭 ↑            | 공격 (측면 자원이 좋을 때 더)         | 중원 밀집 약화                          |
| 롱볼 ↑ / 짧게 ↑ | 공격(제공권 필요) / 중원(연결 필요)   | 중원 점유 / 공격 전진                   |

**여섯 축의 낱말표는 하나다** (`packages/domain/src/tactics.ts` — `TACTIC_AXES`).
눈금마다 낱말 하나(`매우 수비적` · `수비적` · `균형` · `공격적` · `매우 공격적`)를
갖고, 전술판·상대 전술 카드·GM 도구 설명이 모두 그 표를 읽는다(`tacticWord`).
표가 둘이면 같은 `4`가 판에서는 `공격적`, 중계 옆에서는 `보통`으로 서고 감독은 어느
쪽이 지금 값인지 알 수 없다.

**적용률은 이득에 전부, 대가에는 절반만 반영한다.** 지시가 스며들지 않으면 의도한
이득은 줄고, 실제로 수행하지 않은 만큼 대가도 일부 줄지만 어설프게 따라간 몫은 남는다.

**대가가 소화율을 타는 층은 둘뿐이다.** 소화율이 닿는 자리는 네 곳인데 대가의
규칙이 둘로 갈린다:

| 층               | 이득    | 대가                |
| ---------------- | ------- | ------------------- |
| 전술 6축 (§1.2)  | ×소화율 | ×(0.5 + 0.5×소화율) |
| 공략 (§1.6)      | ×소화율 | ×(0.5 + 0.5×소화율) |
| 개인 지시 (§1.7) | ×소화율 | 온전                |
| 전술 상성 (§1.3) | ×소화율 | 온전                |

**위 둘이 대가를 절반만 무는 것은 지시하지 않는 것이 최적해가 되지 않게 하려는
것이다.** 6축은 공격↔수비처럼 크기가 같은 대칭 축을 갖고 공략은 언제나 이득과 대가가
한 쌍이라, 대가만 소화율을 비켜 가면 소화율이 1 미만인 한 산술적으로 늘 순손실이 된다.

**아래 둘이 대가를 온전히 무는 것은 그 대가가 이미 치러졌기 때문이다.** 전술 상성은
세워 둔 전술이 상대와 맞물린 결과라 소화하지 못한다고 뒷공간이 덜 열리지 않고, 개인
지시는 그 선수가 본업을 비운 몫이라 지시를 못 따라가도 비운 자리는 그대로다.

**세 존이 모두 이득과 대가를 함께 받는다.** 어느 한 존이 대가만 무는 자리가 되면
판세가 늘 같은 말을 하고, 리그 평균이 그 방향으로 통째로 기운다. 수비로
이득이 들어오는 축은 **압박**이다: 상대 빌드업을 상대 진영에서 끊으면 우리 문 앞
장면 자체가 준다(⚠️ 뒷공간 대가보다 작게 둔다 — 크면 압박이 공짜 축이 된다).

**축은 3을 기준으로 대칭이어야 한다.** 라인을 내리면 우리 공격 시작점도 함께
멀어지고, 짧은 패스는 점유를 얻는 대신 문 앞까지 가는 수가 늘어난다. 한쪽 갈래만
이득을 주면 리그 평균이 3이어도 그 존만 부푼다.

**프리셋의 리그 평균이 3에 서야 한다** (`engine/core/state.ts` `initialTactics`).
3이 중립이고 델타는 3에서의 편차라, 프리셋이 쏠리면 리그 전체가 같은 방향의 이득과
대가를 달고 선다. 각 스타일은 올린 축만큼 내린 축을 갖는다 — 점유는 라인·폭을
올리는 대신 템포와 패스 길이를 내리고, 역습·롱볼은 라인과 압박을 내린다. 지금
리그 평균은 여섯 축 모두 3.09\~3.16이다.

### 1.3 전술 상성 (`sim/tactical-counters.ts`, 14종)

두 전술이 서로를 만나는 지점. 설계 규칙 셋:

1. **조건이 맞을 때만 발동** — 코어가 사실만 대조한다(판정 LLM 없음). 대가는 이미
   치렀으므로 근거 없는 지시는 손해가 된다.
2. **발동하면 태그로 드러난다** — 상성 코드가 키포인트 태그로 올라가고 중계가
   그것을 문장으로 옮겨 인용한다.
3. **한 축이 존 하나를 움직이는 폭은 이득 2.5\~8% · 대가 5\~15%다** — 세게 잡으면
   "정답 전술" 게임이 된다. 가장 큰 것이 **뒷공간**의 −15%이고(라인 5 · 22 이상
   느린 최종 수비 · 손발이 안 맞는 오프사이드 트랩이 겹칠 때 — `space_behind`),
   **중원 과부하**와 **백라인 숫자**만 상한이 따로 없다 — 인원 차 한 명당 각각
   3.5% · 2.5%라 포메이션이 폭을 정한다. 이득에는 소화율이 곱해지고 대가는 온전히
   치른다. 한 존이 실제로 움직이는 폭은 이 축들과 전술 6축·개인 지시·공략을 합쳐
   `TACTIC_SWING`(0.18)에서 tanh로 포화한다.

뒷공간 · 압박 함정 · 압박 우회 · 빌드업 붕괴 · 중원 과부하 · 측면 자유 · 크로스
폭격 · 무딘 점유 · 블록 흔들기 · 역습 · 늘어진 전술(멘탈리티>라인) · 속도의 대가 ·
백라인 숫자 · 측면 일대일. 같은 스쿼드로 전술만 바꿔 xg가 40%까지 갈린다
(전력 열세여도 역습이 맞으면 앞선다).

### 1.4 슈팅 생성과 결정력 — 두 확률 레이어

팀 기대 득점을 먼저 정하지 않는다. 전술판의 선수 `i`가 왼쪽·중앙·오른쪽 공격
경로 `r`에서 갖는 슈팅 강도 `λᵢᵣ`를 직접 계산하고, 팀 수치는 마지막에 합한다.

```
ln λᵢᵣ = ln PLAYER_SHOT_BASE
        + ln(그 경로를 맡는 비중)                ← 좌표 + 지역 플랜의 배분 이동 (§1.7)
        + SHOT_DEPTH_LOG_WEIGHT       × (전술판 전진 깊이 − 0.5)
        + ROLE_SHOT_LOG_WEIGHT        × ln(역할의 결정력 요구)
        + POSSESSION_SHOT_LOG_WEIGHT  × (logit 점유 − logit 0.5)      (§1.5)
        + ROUTE_SHOT_LOG_WEIGHT       × 포화시킨 경로 우위             (§1.7)
        + CREATION_SKILL_LOG_WEIGHT   × ln(기회 생성 전력 / 65)
        + FINISHING_ACCESS_LOG_WEIGHT × (결정력 − 75) / 34
        + ln(경기장 노출 — 홈 1.06 · 원정 0.96 · 중립 1)
        − LEAD_SHOT_LOG_RATE × 앞선 골 차 + TRAIL_SHOT_LOG_RATE × 뒤진 골 차   (경기 상황 노출)

선수 기대 슈팅 = Σᵣ λᵢᵣ
팀 기대 슈팅   = ΣᵢΣᵣ λᵢᵣ
```

**홈 어드밴티지는 경기장 노출 한 줄이 전부다** — 홈 `HOME_SHOT_EXPOSURE`(1.06) ·
원정 `AWAY_SHOT_EXPOSURE`(0.96)가 슈팅량에 곱으로 실린다. 존 전력에도 슈팅 질에도
홈 계수는 없다. 결승처럼 중립 경기장이면 `PacketOptions.neutral`이 양쪽을 1로
만든다 — 경기(`MatchRecord.neutral`)가 갖고 있는 사실이 그대로 패킷으로 들어온다(§7).
⚠️ 두 값의 비(1.10)는 실제 1부의 홈:원정 득점 비(1.22\~1.28)보다 낮다 — 관중과
분위기가 게임 시스템으로 서는 자리는 아직 없다(§9).

**경기 상황 노출은 스코어가 정한다** (`gameStateExposure` — `PacketOptions.lead`는
홈 득점 − 원정 득점). 슈팅 발생률의 로그에 골 차가 선형으로 실린다 — 푸아송 회귀가
경기 상황을 다루는 꼴 그대로라 골마다 같은 배가 곱해진다: 앞선 팀은
`e^(−LEAD_SHOT_LOG_RATE(0.10) × 골 차)`(한 골 0.90 · 두 골 0.82 · 세 골 0.74), 뒤진 팀은
`e^(TRAIL_SHOT_LOG_RATE(0.05) × 골 차)`(1.05 · 1.11 · 1.16). 실측(xG의 경기 상황 분해)이
한 골 앞서면 0.85~~0.9, 두 골이면 0.7~~0.75, 뒤지면 1.1~~1.2인 계단을 이 지수가 그대로
지난다. 전력차만으로 굴리면 3-0 뒤에도 앞선 팀이 같은 밀도로 문 앞에 서서 5-0·6-0이
실제(팀 4골+ 5~~6%)보다 잦다. 두 시뮬이 같은 문을 지난다 — 구간 시뮬은 구간마다 패킷을
다시 세우고(`match-flow.ts`가 장부의 스코어를 넘긴다), 간이 시뮬은 골 정지점마다 다시
세운다(§7).

경로 우위는 현재 3×3 격자의 후방·중원·공격 칸을 잇는다. 각 칸의 전력에는 실제
좌표, 역할, 점유, 전술 6축, 전술 상성, 개인 지시, 공략, 지역 플랜과 지시 적용률이
이미 들어 있다. 이 값을 다시 별도 전술 계수로 곱하지 않는다 — 같은 지시를 두 번
세지 않기 위해 **기회 전력 격자 하나**가 슈팅 생성의 수치 원본이다.

**이득 쪽 경로 우위는 포화한다** (tanh). 같은 우위가 슈팅량에는 `exp`로, 슈팅
질에는 `logit`으로 들어가 두 번 곱해지므로, 포화시키지 않으면 전력차가 벌어질수록
**총 득점이 지수로 부푼다** — 실제 축구는 전력차가 커도 경기당 총 득점이 3.4\~3.8을
넘지 않는다.

두 축이 만드는 것이 달라 **폭도 다르다**: 슈팅 **양**의 비대칭이 승패와 승점
분포를 만들므로 넓게 두어 거의 선형이고(`ROUTE_SHOT_SATURATION` 0.75), 슈팅
**질**만 좁게 포화시켜 총량을 잡는다(`ROUTE_XG_SATURATION` 0.45). 밀리는 쪽은
포화시키지 않고 오히려 더 깎는다(`ROUTE_SHOT_DEFICIT` 1.3) — 전력차는 "강팀이 두
배로 친다"가 아니라 "약팀이 절반만 친다"로 나타난다.

선수의 실제 `finishing`은 기회 전력에서 빼고 명시적인 작은 접근 효과로 한 번만
넣는다. 결정력이 좋은 선수에게 동료가 마지막 공을 조금 더 맡기고, 그 선수가
슈팅 동작까지 완성하는 차이다. 주효과는 아래 골 전환이며 접근 효과는 그보다 작다.

슛 하나의 질 `q`는 경로 평균 `μᵢᵣ`를 갖는 베타분포에서 뽑는다. 결정력과 슛의
결과는 `q`에 들어가지 않는다.

```
logit(μᵢᵣ) = logit(BASE_SHOT_XG)
           + ROUTE_XG_LOGIT_WEIGHT        × 포화시킨 최종 공격 지역 우위
           + SHOT_DEPTH_XG_LOGIT_WEIGHT   × (전술판 전진 깊이 − 0.5)
           + CHANCE_SKILL_XG_LOGIT_WEIGHT × (기회 능력 − 65) / 34
           기회 능력 = 침투 0.4 + 드리블 0.25 + 스피드 0.2 + 공중볼 0.15

qᵢⱼ ~ Beta(μᵢᵣ κ, (1−μᵢᵣ) κ)                κ = SHOT_XG_CONCENTRATION

logit(pᵢⱼ) = logit(qᵢⱼ)
             + FINISHING_LOGIT_WEIGHT × (finishingᵢ − FINISHING_PIVOT) / FINISHING_SCALE

goalᵢⱼ ~ Bernoulli(pᵢⱼ)
```

`q`는 기회의 xG, `p`는 그 선수가 찼다는 사실까지 반영한 골 확률이다. 따라서
`Σq`는 기회 xG, `Σp`는 결정력 반영 기대 득점, `Σgoal`은 실제 득점이다.
중립점 75는 게임 데이터의 슈팅 가중 리그 평균이다. 그래서 리그 전체에서는 `Σp`가
`Σq` 근처에 머물고, 좋은·나쁜 결정력은 그 기준에서 양방향으로 갈린다.

⚠️ 슈팅 수·xG·득점에는 게임 결과를 잘라내는 상·하한을 두지 않는다. 선수별
포아송 과정과 슈팅별 베타·베르누이 분포가 대부분의 경기를 현실적인 구간에 모으되
아주 적거나 많은 슈팅과 득점도 꼬리 확률로 남긴다. 이벤트 배치 상한은 한 번에
처리할 양만 끊고 다음 구간에서 계속하므로 경기 결과를 자르지 않는다.

#### 총량은 패킷의 것이다 — 구간이 몇 번으로 끊기든

발생률은 위 기대 슈팅을 `/90`으로 나눈 값이다. 그러므로 **한 경기의 실측 슈팅은
패킷의 기대 슈팅이어야 하고, 감독이 몇 번 멈춰 섰는지와 무관해야 한다.** 이것이
계약이다 — 여기가 어긋나면 밸런스 손잡이(`PLAYER_SHOT_BASE` 등)가 서 있는 눈금이
감독의 개입 횟수를 타고, 같은 상수를 재는 자리가 구간 시뮬과 간이 시뮬 둘로 갈린다.

계약을 지키는 것은 **연속 시계**다. 사건의 분은 정수라(`Math.floor`) 장부에 실릴 때
소수가 잘리지만, 사건을 굴리는 시계는 소수 자리까지 다음 구간으로 넘어간다
(`SegmentPlan.clock` → `SegmentInput.clock`, 세이브는 `pendingMatch.segmentClock`). 그래서
장부의 분과 굴리는 시계는 **다른 값**이고, 한 하프에 굴리는 시간은 언제나 규정
분수 그대로다.

- 구간이 끝나 대기를 굴리다 만 자리는 **그 대기를 버리고 끝에서 다시 굴린다.**
  지수분포는 무기억이라 같은 분포다. ⚠️ 다만 **버리는 조건에 하프의 끝을 섞으면
  안 된다** — "구간의 창은 넘었지만 하프는 안 넘었을 때만 버린다"로 두면 하프까지
  넘긴 대기만 살아남아 "이 하프에 사건이 없다"가 두 경로로 세어지고, 굴린 시간은
  90분 그대로인데 사건이 3% 준다.
- 사건 사이의 간격에 **최소값을 깔지 않는다.** 0.5분 바닥은 짧은 간격을 전부 그
  값으로 밀어 올려 평균 간격을 1.5% 늘리고 경기당 슈팅을 그만큼 깎았다.

재는 자리는 `pnpm balance segment-shots` — 정지점까지 가는 진행과 5분마다 끊는
진행을 각각 800경기 굴려 패킷 대비 배율이 ±1.5% 안에 서는지 본다.

### 1.5 점유 — 중원 우위가 닿는 길

중원 존이 **점유**로 번역되고, 점유가 세 곳에 실린다.

```
점유(우리) = 우리 중원 / (우리 중원 + 상대 중원)        범위 [0.35, 0.65]
```

| 어디에    | 어떻게                                                                                                                            |
| --------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 슈팅량    | 선수별 슈팅 로그오즈에 `POSSESSION_SHOT_LOG_WEIGHT × (logit 점유 − logit 0.5)`가 더해진다(§1.4) — 점유 0.65면 ×1.22, 0.35면 ×0.82 |
| 체력      | 공 **없는** 팀이 더 뛴다 — `chaseFactor`가 소모에 곱해진다(양 끝 ±12%)                                                            |
| 패스 배분 | 구간 길이 × 점유 × 템포로 팀 총량을 정한다 (§4)                                                                                   |

- 세기(`POSSESSION_SHOT_LOG_WEIGHT` 0.32)를 작게 둔 이유는 미드필더의 질이 이미 두
  축에 들어 있어서다 — XI 평균(질)과 존 가중 평균(판). 여기서 더하는 것은 **점유라는
  별개의 사실**이 만드는 몫이다.
- **체력 경로가 이 설계의 핵심이다.** 중원에서 밀린 팀은 90분 내내 공을 쫓느라
  더 지치고, 그 피로가 구멍 문턱(78)에 먼저 닿아 후반에 라인이 열린다 —
  중원 우위가 즉시 골이 되는 게 아니라 **경기 후반에 값을 한다.**
- ⚠️ 점유는 **패킷이 갖는다**(`guide.possession`). 기대 득점·체력·패스가 같은
  값을 봐야 갈리지 않는다. 간이 시뮬도 같은 함수(`possessionShare`)를 쓴다.

### 1.6 공략 (`sim/exploits.ts`)

키포인트를 표적으로 만든다 — 감독이 "요케레스 뒤로 계속 보내"라고 하면 중계 모델이
후보 목록에서 id를 골라 `exploit_point`를 부르고, 코어가 실재를 대조한 뒤 존 조정을
얹는다. 없는 지점은 반려. **동시에 두 곳까지**.

**표적 목록은 감독의 눈과 같은 해상도다.** 표적이 싣는 것도 태그라, 감독이 읽는
문장은 태그의 `sharp`가 정한다. 패킷에 실려 화면과 모델이 읽는 목록은
그가 실제로 본 키포인트뿐이고, 라벨도 그가 읽은 그 문장이다 — 개수는 **분석**이,
문장의 정밀도는 **전술**이 정한다(`readKeyPoints`, `key-points.ts`). 전부 실어
보내면 분석 30인 감독의 모델도 정밀 표적 열댓 개를 읽고 겨냥하니, 안개가 화면에서만
끼고 결과에는 끼지 않는다.

**못 본 지점도 그라운드에는 있다.** 코어가 실재를 대조하는 목록과 **AI 벤치가 고르는
목록**은 감독의 눈과 무관하다 — 상대가 우리 약점을 노리는 것이 그 약점이 드러나는
유일한 경로이므로, 우리 감독이 어둡다고 상대까지 눈이 멀면 그 경로가 닫힌다. 다만
그쪽 표적의 라벨은 **흐린 문장**이다: 걸린 공략의 노트를 감독 화면과 중계가 그대로
인용하므로, 정밀 문장을 실어 두면 그가 못 본 수치가 노트로 새어 들어온다.

**안개를 지키는 것은 고르는 문이다.** `exploit_point`는 패킷의 목록에 없는 id를
반려하므로 감독은 못 본 지점을 겨냥할 수 없다. 반대로 **한 번 걸린 공략은 그 지점이
사라졌을 때만 끊긴다** — 교체로 키포인트가 다시 정렬돼 목록 밖으로 밀려났다는 이유로
끊기면, 감독이 내린 적 없는 취소가 된다.

**AI 벤치는 가장 크게 벌어진 곳부터 자기 등급만큼 고른다** — `AUTO_EXPLOIT_TWO`(78)
이상이면 두 곳, `AUTO_EXPLOIT_ONE`(58) 이상이면 한 곳, 그 아래는 판을 읽지 못한다.
그 등급은 **분석 축**이다(career.md §2). 감독에게는 분석과 전술이 따로 있지만 AI
감독은 등급이 하나뿐이라(`Team.aiManagerTacticsRating`) 그 하나가 두 축을 겸한다.

이득과 대가는 **전술 6축과 완전히 같은 규칙**이다 — 이득에는 소화율을 전부, 대가에는
절반만. 대가만 소화율을 비켜 가면 걸기만 하면 순이득이 되므로 두 쪽이 같은 문을
지나고, 공략 하나가 존을 움직이는 폭은 7% 안쪽에서 멎는다 — 전술 상성(§1.3)과 같은
자리다.

**이득은 벌어진 폭을 탄다.** 키포인트는 그 짝이 얼마나 어긋났는지를 `weight`로 이미
알고 있다 — pace 25 차이의 뒷공간과 문턱을 겨우 넘은 뒷공간이 같은 수를 내면 감독이
무엇을 읽었는지가 결과에 남지 않는다. 이득은

```
EXPLOIT_GAIN_FLOOR + EXPLOIT_GAIN_SPAN × tanh(weight / EXPLOIT_WEIGHT_SCALE)
```

이라, 문턱을 겨우 넘은 지점이 2.6%(`EXPLOIT_GAIN_FLOOR`)이고 크게 벌어진 지점이
7.1%에서 포화한다(+`EXPLOIT_GAIN_SPAN`). 눈금(`EXPLOIT_WEIGHT_SCALE` 18)은 AI 감독이
고르는 1순위 표적의 weight가 서는 자리라, 리그에 거의 상수로 얹히는 층은 제자리를
지키고 **그 위아래로만 갈린다.**

**상대의 강점을 지우는 공략은 우리 존이 아니라 상대 존을 깎는다.** 창조자·마무리·
활동량 세 축(`AXIS_EFFECT`의 `gain: "erase"`)이 그 갈래다 — 배급을 끊었는데 우리
중원 전력이 오르면 지운 자리가 어디에도 남지 않고, 그 선수를 그대로 둔 판과 결과가
같은 모양으로 갈린다. 감산은 **표적이 선 그 존, 그 레인**에 상대 격자로 실리고(상대
격자는 상대 방향이라 거울이 필요 없다), 대가는 그대로 우리 쪽이다. 소화율 규칙은
나머지 축과 같다.

**공략은 표적이 선 레인으로 실린다** — 어느 칸인지는 §1.7이 정한다. 다만 **골문과
죽은 공에는 레인이 없다**(`AXIS_EFFECT`의 `flat`): 공이 그 선수 곁을 지나가는
공략만 자리를 갖는다. 세트피스 키커가 오른쪽 풀백이라고 코너킥이 오른쪽에서만
오지 않고, 골키퍼는 언제나 가운데에 선다 — 뜻 없는 좌표를 실으면 감독이 읽지 않은
방향으로 공격이 몰린다.

**버려진 공략은 노트로 드러난다.** 사라진 표적(교체로 그 선수가 나갔다), 우리 쪽
지점, 셋째 이후 — 셋 다 조용히 사라지지 않고 그 사실이 `tactical.notes`에 남는다.
노트가 없으면 그것을 인용하는 중계도 화면도 걸리지 않은 공략이 걸린 줄 안다.

**두 곳을 세는 것은 실재를 확인한 뒤다.** 사라진 표적과 우리 쪽 지점은 `MAX_EXPLOITS`
의 자리를 먹지 않는다 — 개인 지시의 `MAX_EFFECTIVE`(§2)와 같은 규칙이다. 자리를
먹으면 감독이 노린 곳 하나가 이유 없이 사라지고, 노트는 "셋째라 안 걸렸다"고 엉뚱한
이유를 댄다.

**안개는 개인 수치에 걸린다.** 이름과 능력치를 부르는 문장 — 키포인트·표적, 그리고
명단과 체력(§8) — 은 감독의 눈을 지나 나온다. 반대로 **팀 단위 집계는 그대로 선다**:
판세의 9칸 격자와 그 줄 합, 매치업 문장이 인용하는 존 전력, 상성 `why`의 팀 평균(빌드업·
제공권·중원 숫자), 전술 6축과 배치 골격이 그렇다. 90분 동안 눈에 보이는 사실이고
판세 화면이 이미 같은 수를 세우므로, 여기까지 흐리면 화면과 문장이 서로 다른 판을
말하게 된다.

⚠️ **공략의 이득은 구조적으로 공격 존에 실린다** — 키포인트가 드러내는 약점이 대개
상대 수비 쪽이라 14축 중 9축이 그렇다. 등급 58 이상 AI 감독이 매 경기 하나씩 걸므로
이 층은 리그 전체에 **거의 상수로** 얹히고, 그만큼이 `ZONE_BASELINE`(§1.1)에 들어가
있다. 공략의 크기를 만지면 그 상수를 다시 재야 한다.

### 1.7 경기장 9지역

세 전선을 좌·중·우로 나눈 3×3 격자는 실제 전술판 좌표와 개인 유효 전력으로
계산한다. 각 줄 세 칸의 평균은 그 줄의 존 전력과 같다 — 격자는 존을 **쪼갠 것**이지
새 수치가 아니다. 이 칸들이 §1.4의 경로 우위(`pathEdge`)로 들어가 선수별 슈팅량과
슈팅 질을 함께 정한다.

**격자가 존을 그대로 물려받으므로 존의 기준선이 곧 격자의 기준선이다.** 존 눈금이
기울면 화면만이 아니라 득점까지 함께 기운다: 공격 줄이 3% 부풀면 양 팀의 경로
우위가 함께 오르고(`ROUTE_PATH_WEIGHTS` 공격 0.55 · 수비 0.15) 그만큼이 리그 득점
눈금에 실린다. 그래서 매치업 비율의 기준선 1은 화면의 문제가 아니라 **수치의
문제**이고, `ZONE_BASELINE`(§1.1)이 그 자리를 지킨다.

자연어 세부 전술은 경기 전용 **지역 플랜**으로 구조화한다: 지역(우리 진영·중원·
상대 진영) × 레인(좌·중·우) × 의도(과부하·압박·보호·전환)와 감독의 표현 한 줄이다.
코어가 좌표와 범위를 검증해 동시에 두 곳까지만 유지한다(`MAX_REGIONAL_PLANS`).

**플랜은 두 곳에 실린다** — 그 칸을 두껍게 하고(`REGIONAL_INTENT_WEIGHT`), 공격
배분을 그 레인으로 끌어온다(`PLAN_ROUTE_FOCUS`).

- 칸만 두껍게 해서는 결과가 움직이지 않는다. 격자는 줄 합이 보존되도록 정규화되므로
  한 칸을 올리면 옆 칸이 내려가고, 선수의 레인 배분이 좌표로만 정해지면 세 레인
  로그 우위의 가중 합이 거의 그대로다 — 오히려 로그의 오목성 때문에 손해가 난다.
  **공을 그쪽으로 더 보내야** "그쪽을 파고들어라"가 성립한다.
- 그래서 배분 이동은 의도가 정한다: 과부하 3 · 전환 2.1 · 압박 1.5 · **보호 0**.
  보호는 우리 공격을 옮기지 않고 그 칸을 두껍게 할 뿐이다. 줄도 갈린다 — 상대
  진영 1 · 중원 0.5 · 우리 진영 0(뒷선 플랜은 우리 슈팅을 옮기지 않는다).
- 소화율(`uptake`)을 타고 선수의 자리 가중치에 곱해지므로 레인을 통째로 바꾸지는
  못한다. 반대편 윙어는 여전히 자기 쪽에서 더 많이 찬다.
- **양방향이다.** 상대가 이미 강한 칸으로 공격을 몰면 기대 득점이 내려간다.
  잘못 읽은 지시는 손해가 되어야 지시가 판단이 된다.

**셋째를 걸면 가장 오래된 플랜이 밀려나며 그 사실이 결과 메시지에 실린다** —
조용히 버리면 감독은 아까 내린 지시가 아직 걸려 있는 줄 알고, GM은 그것을 전제로
다음 장면을 쓴다. 적용된 플랜은 새 키포인트로 패킷에 나타나므로 중계와 화면이 같은
근거를 읽는다. 경기 종료 시 사라지며 팀의 장기 전술에는 남지 않는다.

#### 개인 지시와 공략도 같은 해상도로 실린다

지역 플랜만 칸으로 가고 개인 지시·공략이 존 셋으로만 실리면, 한 경기 안에서 두
지시가 다른 눈금으로 산다 — 오른쪽 풀백을 마크하든 왼쪽 윙어를 마크하든 상대 수비
줄 전체가 같은 비율로 깎이고, 키포인트가 "사카(88) vs 무뇨스(61)"까지 짚어 준
정밀함이 결과에서 사라진다. 그래서 `applyDirectives`·`applyExploits`의 산출은 존
셋이 아니라 **밴드×레인 아홉 칸**(`LaneCells`)이고, 그 칸이 두 갈래로 접힌다.

- **줄 평균이 존 델타다.** 세 칸의 평균이 그 줄의 존 전력에 실린다. 격자의 계약이
  "세 칸의 평균 = 존 전력"이므로 델타도 같은 눈금으로 접혀야 한다 — 칸을 존과 함께
  밀면 그 전력이 두 번 세어진다.
- **줄 안의 편차가 레인 편향이다**(`SidePacket.laneBias`). 평균을 뺀 나머지가
  정규화 전의 칸 값에 얹히고, 정규화가 줄 평균을 존 전력으로 되돌린다. 그래서
  **존 전력은 그대로고 줄 안의 배분만 기운다** — 지역 플랜이 값을 하는 것과 같은
  경로이고, 결과에는 §1.4의 경로 우위(`pathEdge`)를 타고 닿는다.

칸을 고르는 것은 **좌표**다. 겨냥한 상대·지시받은 선수가 선 레인은 그의 전술판
x에서 가장 가까운 레인이고, 밴드는 맡은 자리가 정한다. 겨냥당한 쪽의 편향은 그
팀의 격자에 그 팀의 방향으로 적힌다 — 홈의 왼쪽이 원정의 오른쪽과 만나는 뒤집기는
`zoneGrid`가 이미 한다.

몰아주는 폭은 `LANE_FOCUS`(0.75)다: 겨냥한 칸이 존 델타의 2.5배, 나머지 두 칸이
0.25배씩이라 세 칸의 평균은 여전히 존 델타다. 이웃 칸이 0이 아닌 것은 선수가 점이
아니라 영역을 맡기 때문이고(`REACH`와 같은 이유), 한 칸이 줄 안에서 기울 수 있는
폭은 `LANE_BIAS_CAP`(0.3)에서 잘린다.

**레인을 갖지 못하는 지시는 예전과 정확히 같은 수를 낸다** — 세 칸이 같으면 편차가
0이라 존 델타만 남는다. 표적이 팀 전체인 공략(백라인 조직·중원 활동량)과 특정 자리를
겨냥하지 않는 지시가 그 갈래다.

## 2. 경기의 문과 진행 루프 (`start_match` · 해석 → 코어 → 중계)

**킥오프는 세 걸음이다.**

| 걸음              | 누가                   | 무슨 일                                                                                                                           |
| ----------------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| ① 문이 열린다     | GM이 `start_match`     | 라인업을 세우고(부상·정지는 **1군에서** 자동 대체) 패킷을 계산해 `phase`를 `match`로. 화면은 아직 평시고 입장 확인 창이 선다      |
| ② 감독이 들어선다 | 감독이 **경기장 입장** | `pendingMatch.entered`가 서고 화면이 경기로 넘어간다. 캐스터가 **첫 휘슬만** 연다 — 도구도 패킷도 없는 턴이라 사건이 생길 수 없다 |
| ③ 공이 구른다     | 감독이 진행            | 여기서부터 패킷을 쥔 보통의 진행 턴 — 해석이 진행 의도를 내면 코어가 0분부터 구간을 굴린다                                        |

①에서 중계를 쓰지 않는 것은 ②가 그 자리이기 때문이고, ②에서 사건이 없는 것은
③이 그 자리이기 때문이다. 화면은 `MatchView.beforeKickoff`(= `entered`가 아직
서지 않음)로 ①과 ②를 가른다.

**①이 진행되는 동안 화면은 평시 그대로다.** 코어의 `phase`는 이미 `match`지만
경기 탭·판·경기 머리는 서지 않고, 감독은 창 뒤에서 마지막으로 명단을 훑거나
마음을 바꿀 수 있다. 화면이 경기로 넘어가는 시점은 문이 열릴 때가 아니라
**감독이 문을 지날 때**다.

**②의 이력은 라커룸에서 이어진다.** 경기 이력(`casterHistory`)이 아직 비어 있어
캐스터가 첫 마디를 여는 근거는 경기 전 대화(팀토크·브리핑)다 — 그 한 턴만
평시 이력을 그대로 넘긴다(`relevantTurns`). 판세를 함께 쥐여 주면 아무 일도
일어나지 않았는데 첫 마디부터 우열을 읊으므로 패킷은 ③부터 싣는다.

GM은 감독이 들어가자고 하거나 경기 전 점검(라인업·전술·팀토크)이 끝나 그날
남은 일이 경기뿐일 때 되묻지 않고 부른다. 문을 여는 판단은 GM이 하고, 걸어
들어가는 것은 감독이다.

**①의 명단은 양 팀이 같은 문을 지난다.** 감독의 경기라고 해서 우리에게만, 또는
우리를 상대하는 클럽에만 다른 규칙이 서면 안 된다(§7).

- **1군이 먼저다** — 자동 대체도 벤치 채움도 `squadLevel`이 `first`인 선수를 먼저
  뽑는다. 2군은 승격 후에만 배치된다(→ [team.md](../data/team.md) §5)는 규칙이
  `set_lineup`에만 걸려 있으면, 감독이 손대지 않은 자리를 코어가 대신 채우는 이
  경로가 그 규칙을 우회한다 — 2군이 가용한 1군 자원을 제치고 서는 일은 없다.
  - **그라운드의 열한 자리만은 비울 수 없다.** 부상·정지가 겹쳐 1군으로 선발을
    채우지 못하면 그때만 2군을 부르고, 그 사실을 자동 대체 안내에 "2군 호출"로
    밝힌다. 규칙을 지키느라 경기가 열리지 않는 쪽이 더 나쁘다. **벤치는 그렇지
    않다** — 1군이 모자라면 벤치가 짧아질 뿐, 2군이 앉지 않는다.
- **벤치의 골키퍼 한 자리는 잘리지 않는다** — 배치된 벤치가 이미
  `MATCHDAY_BENCH`(9)를 채웠고 그중 골키퍼가 없으면 기량이 가장 낮은 필드 선수가
  자리를 내준다. 뒤에 붙였다가 상한에서 잘라 내면 "GK 확보"가 배치 인원수에 따라
  있다 없다 한다.
- **상대의 명단은 간이 시뮬이 짠 그대로다** — 선발도 벤치도 `simSquadOf`가 돌려준
  목록을 쓴다. 벤치를 여기서 다시 짜면 그 함수가 걸러 낸 정지 선수·2군·로테이션으로
  쉬게 한 선수가 감독의 경기에서만 벤치에 선다(§7).

```
감독의 말
→ 지시 해석(LLM): MatchIntent JSON 하나 — 교체·전술·지시·플랜·공략·대화·진행 여부
→ 코어: 의도를 스킬로 옮긴다 (실재 확인은 여기서) → 패킷 재계산
→ 코어: simulateSegment(패킷, 장부) — 다음 정지점까지 사건 확정   [진행 의도일 때만]
  · 선수×경로 슈팅 발생률 = λᵢᵣ/90 · 카드·부상 = 강도 비례
  · 슈팅 시각은 지수분포 → xG 표집 → 결정력 반영 → 골 여부 표집
→ 장부 검증(§5) → 기록 → 경기 중 피로 누적 → 패킷 재계산
→ 매치 캐스터(LLM): 확정된 사건 목록과 **새 패킷**을 중계·연출·대화로 옮긴다
→ 정지점 — 감독 개입 가능
```

**두 LLM 어느 쪽도 도구를 쥐지 않는다** — 해석은 JSON을 내고 캐스터는 문장을 쓴다
([../llm/agents.md](../llm/agents.md) §3). 그래서 "지시를 먼저 처리하고 그다음
진행한다"는 순서가 프롬프트의 규칙이 아니라 **호출 순서 그 자체**이고, 중계는 자기
턴에 바뀐 판을 읽는다 — 지시가 발동했다는 노트도 걸리지 않았다는 노트도 그 턴에 잡힌다.

**대화만 건 턴은 구간을 굴리지 않는다.** 해석이 대화로만 읽으면 시계가 멈춘 채 그
장면만 오간다. 조금이라도 흘려 주면 이기고 있을 때 말을 걸어 시간을 끄는 길이 열린다.
**사건 없는 턴에는 진행이 없다** — 골도 슛도 찬스도 없다. 중계가 쓸 수 있는 것은 멈춘
공 앞의 대화와 분위기뿐이고, 화면의 시각도 장부의 분 그대로 선다.

- **정지점**: 골 · 퇴장 · 부상 · 하프타임 · **연장 개시** · **연장 하프타임** ·
  종료 · (조용하면) 25분 상한 · **사건 15건**(`MAX_SEGMENT_EVENTS` — 장부의 배치
  한도 20 아래로 두어 정지 이벤트와 AI 교체가 뒤에 붙을 자리를 남긴다).
- **한 턴에 얼마가 흐르는지는 감독의 말이 정한다** — 진행 의도가 있는 턴만 구간
  하나를 굴리고, 대화·지시만 있는 턴은 시계가 멈춘다. 벤치에서 한마디 한 대가로
  구간이 지나가면 감독이 개입하려던 자리가 사라지고, 반대로 조금씩 흘려 주면
  이기고 있을 때 말을 걸어 시간을 끄는 길이 열린다.
  - 구간을 특정 분에서 끊는 길(`simulateSegment`의 `maxMinutes`)은 밸런스 하네스만
    쓴다. **게임의 턴에는 그 경로가 없다** — 시계는 멈추거나 정지점까지 가거나
    둘 중 하나다.
- **국면은 넷이고, 각 하프는 규정 분수만큼만 굴러간다** — 전반 45 · 후반 90 ·
  **연장 전반 105 · 연장 후반 120**(`PHASE_END`). 한 하프의 끝은 그 국면의 종료
  시각이고 **추가시간을 시계에 얹지 않는다**: 전반이 47′에 끝나면 후반이 47′에서
  시작해 90분 기준선이 92\~96분으로 불어나고, 연장 두 하프는 그만큼 밀려 30분이
  27분으로 줄어든다. 슈팅률도 피로도 `/90` 눈금으로 서 있으므로(§3·§1.4) 시계가
  불어난 만큼 경기당 슛과 소모가 함께 어긋난다. 90분이 끝날 때 승부가 남았으면
  `full_time` 자리에 `extra_time_start`가 들어가 장부가 계속 열려 있고, 감독은 그
  정지점에서 **다른 정지점과 똑같이** 교체·전술을 지시한다. 연장으로 가는지는
  구간 시뮬이 아니라 코어의 `needsExtraTime`이 정해 `toExtraTime`으로 넘긴다 —
  구간 시뮬은 대회도 대진도 모른다.
- **장부의 분과 굴리는 시계는 다른 값이다** — 장부의 시각은 마지막 사건의 분이라
  정수이고, 사건을 굴리는 연속 시계는 소수 자리째 다음 구간으로 넘어간다
  (`SegmentPlan.clock` → `SegmentInput.clock`, 세이브는 `pendingMatch.segmentClock` —
  옛 세이브엔 없고 없으면 장부의 분에서 잇는다). 이어 주지 않으면 정지점마다 최대
  1분이 되감겨 그 시간이 두 번 굴려지고, **감독이 멈춰 선 횟수가 곧 그 경기의
  슈팅 수가 된다**(정지점 일곱이면 +7%, 5분마다 끊으면 +19%). 총량이 왜 패킷의
  것이어야 하는지는 §1.4.
- **연장의 슈팅 발생률은 0.84배/분** — 30분에 90분 기대 슈팅의
  `EXTRA_TIME_SHOT_SHARE`(0.28)만큼 만든다. 카드·부상은 그대로다: 지친
  다리는 덜 뛰지만 덜 거칠지는 않다. 피로는 30분치가 그대로 더 쌓인다.
- 개입(전술·교체)은 패킷 재계산으로 그 구간부터 반영. 재시뮬은 없다.
  ⚠️ 재계산은 **구간을 굴리기 직전에 `advanceSegment`가 한 번** 한다. 스킬마다
  각자 부르면 부르는 스킬과 안 부르는 스킬이 갈려, 전술을 바꾸고 곧바로 진행한
  구간이 절반만 새 전술로 구른다(6축·개인 지시는 인자로 새로 가는데 존 전력·
  소화율은 옛 값).
- **개입이 그 턴에 반영되는 것은 해석이 진행보다 앞서기 때문이다** — 순서가
  뒤집히면 그 구간이 옛 판으로 구른다. 그 순서는 프롬프트의 규칙이 아니라 코어의
  호출 순서 그 자체이고, 캐스터에게는 지시를 걸 도구가 없다.
- 화면의 대기 중 교체·좌표·역할·전술 축은 진행 전에 코어가 먼저 적용한다. 이때
  `계속`은 진행만 허용하며 캐스터가 승인받지 않은 교체나 전술을 추가할 수 없다.
  경기 전술판은 저장된 시즌 선발이 아니라 현재 경기 장부의 온필드·벤치를 표시한다.
- 자연어 포메이션 변경은 현재 선발의 개별 자리·역할 변경으로 번역한다.
  ⚠️ **판을 못 보는 쪽에 좌표를 요구하지 않는다.** `set_player_tactic`은 좌표(x·y)
  대신 `move`를 받는다 — 레인(좌·중·우) × 밴드(우리 진영·중원·상대 진영)이고
  지정하지 않은 축은 지금 자리를 그대로 쓴다. 지역 전술과 **같은 낱말**이고
  **같은 y**(`PITCH_BANDS.center`)라 한 경기 안에서 두 도구가 같은 자리를 다르게
  부르지 않는다. 밴드 y는 포지션 라인의 경계가 아니라 **안쪽**에 있어 세 밴드가
  각각 다른 라인에 닿는다 — 우리 진영은 DEF(LB·LCB·CB·RCB·RB), 중원은
  MID(LM·LCM·CM·RCM·RM), 상대 진영은 CFW(LW·LF·CF·RF·RW). 수미(LWB·LDM·CDM·
  RDM·RWB)와 공미(LAM·CAM·RAM)는 밴드로 닿지 않는 자리라 `position` 코드로
  부른다. 좌표는 화면의 드래그가 쓰는 값으로 남는다.
- **개인 지시는 `kind`가 있어야 판이 움직인다.** 시뮬로 가는 것은
  `directive.kind`뿐이고 자유 서술(`note`)은 화면·스냅샷에만 남는다. `kind` 없이
  들어온 지시는 그 사실을 결과 메시지에 밝힌다 — 성공으로만 답하면 GM이 "먹혔다"로
  서사를 쓰는 거짓 성공이 된다.
- **포메이션이 바뀐 턴에는 구간을 진행하지 않는다** — 감독이 전술판을 보고 다음 턴에
  진행해야 새 배치로 경기가 재개된다. 진행 의도가 함께 왔더라도 **코어가** 그 턴의
  진행을 미룬다(자리를 옮기지 않는 개인 지시·6축 변경은 해당 없다).
- **세기가 세 갈래다** — `directive.intensity`(`light` · `normal` · `heavy`)가
  이득·대가·체력 소모에 함께 걸리고, 이득 상한(`GAIN_CAP`)도 같은 배수를 탄다.
  없으면 `normal`이라 옛 세이브와 세기를 보내지 않는 호출이 그대로 선다. 종류가
  다섯으로 접히는 것은 설계지만 **정도까지 접히면** "붙어서 아예 지워버려"와
  "따라가진 말고 견제만"이 같은 수를 내고, 자연어 인터페이스의 폭이 결과에서
  사라진다. 세게 걸수록 이득만 크는 것이 아니라 대가도 다리도 함께 커진다.
- **판에 닿지 못한 지시는 그 사실이 남는다.** 넷째 지시(`MAX_EFFECTIVE`는 셋),
  그라운드에 없는 선수의 지시, 사라진 표적 — 셋 다 `tactical.notes`에 오르고
  중계·감독 화면이 그대로 인용한다. `set_player_instruction`은 그중 **지시하는
  순간에 알 수 있는 것**(벤치에 앉은 선수, 이미 걸린 셋)을 결과 메시지로 되돌려
  준다. 조용히 버리는 것은 `kind` 없는 지시를 성공으로 답하던 것과 같은 거짓
  성공이다.
  - **셋을 세는 것은 실재를 확인한 뒤다.** 벤치에 앉은 선수의 지시, 교체로 사라진
    표적을 향한 지시는 걸릴 수 없으므로 `MAX_EFFECTIVE`의 자리를 먹지 않는다.
    자리를 먹으면 감독이 내린 셋 중 하나가 이유 없이 사라지고, 노트는 그것을
    "넷째라 안 걸렸다"고 엉뚱한 이유로 설명한다. 공략의 두 자리도 같은 규칙이다
    (§1.6).
- 자연어 전술 변경은 **차이만** 적용한다. 기존 좌표·역할·전술 축은 유지하고,
  포메이션을 만들기 위해 꼭 필요한 선수만 옮긴다. 역할이나 전술 축은 감독이 그
  항목의 변경을 명시했을 때만 바꾼다. 자리를 옮겨도 기존 역할이 새 자리에서 유효하면
  유지하며, 호환되지 않을 때만 새 자리의 기본 역할로 돌아간다.
- **경기 중 스냅샷은 "지금 걸어 둔 것"을 되비춘다** — 6축·포메이션·지역 플랜·개인
  지시와 역할이 매 턴 실린다(`buildLedgerNote`). 경기 중에는 평시 스냅샷이 실리지
  않으므로, 이 줄이 없으면 `set_tactics`("현재 값과 다른 축만")·`set_match_plan`
  (두 곳 제한)·`set_player_tactic`("생략한 항목은 유지")이 모두 지금 값을 모른 채
  불리고, "압박 올려"에 모델이 숫자를 지어낸다.
- **교체 투입은 자리를 잇고 역할은 자기 것을 쓴다** — 빈 자리의 포지션·좌표는 나간
  선수 것을 그대로 잇지만, 역할은 **들어온 선수가 그 자리에서 맡던 것**(역할 기억,
  → [player.md](../data/player.md) §3.2)이 먼저다. 기억이 없을 때만 그 자리에 걸려
  있던 역할을 잇는다. 역할은 `roleFit`으로 전력에 그대로 닿으므로, 나간 사람 것을
  물려주면 감독이 그 선수에게 시킨 적 없는 값이 승부를 움직인다.
  - **어느 자리를 잇는지는 교체 사건이 정한다** — `actors`의 [나간 선수, 들어온
    선수] 짝을 따라가 그 선수가 쥐고 있던 자리를 넘긴다. 빈 자리 중 적응도가 가장
    높은 곳을 고르면 킥오프 자동 대체로 이미 비어 있던 자리를 대신 집어 "왼쪽을 뺐는데
    오른쪽에 섰다"가 되고, 감독이 본 전술판과 패킷이 다른 판이 된다. 짝이 닿지 않는
    자리 — 킥오프 자동 대체로 선 선수 — 만 남은 빈 자리 중 적응도 순으로 앉는다.
- **그 경기의 대응은 그 경기에서 끝난다** — 종료 시 6축·자리·역할·개인 지시와
  적응도가 킥오프 값으로 되돌아가고(`restoreTactics`), 경기 중 거친 전술은 **전술
  기억(`drilled`)에도, 역할 기억(`roleMemory`)에도 적히지 않는다**. 적응도만 되돌리면 잠깐 거친 조합이 "익힌
  전술"로 남아 나중에 공짜로 되찾아진다 (→ [player.md](../data/player.md) §7.3).
- **LLM에게 결과를 바꿀 도구가 없다** — 중계에만 있는 골도, 기록 누락으로 멈추는
  시계도 구조적으로 불가능하다. **장면의 시각도 장부가 붙인다** — 중계가 적은 분은
  화면에 닿지 않는다 (→ [../llm/agents.md](../llm/agents.md) §3 ④).
- **AI 벤치도 경기를 쫓는다** — 정책은 `planBenchSubs`(`sim/match-engine.ts`)
  **한 벌**이고 간이 시뮬(§7)도 같은 함수를 부른다. 갈래는 셋이고 **순서가 곧
  우선순위**다.
  1. **부상** — 무조건 뺀다. 시각도 확률도 피로 문턱도 건너뛰고, 이 갈래가 나온
     정지점에서는 다른 갈래를 부르지 않는다. 같은 계열이 벤치에 없을 때의 마지막
     갈래는 **골키퍼와 필드를 가른다**: 필드 선수의 자리는 필드 선수만 잇고,
     골키퍼가 쓰러졌는데 벤치에 키퍼가 없을 때만 필드 선수가 장갑을 낀다. 기량
     순으로만 고르면 예비 골키퍼가 윙으로 뛴다. (부상 정지점은 구간 시뮬에만 있다 —
     간이 시뮬의 부상은 경기 후 추첨이라 이 갈래가 설 자리가 없다.)
  2. **스코어와 남은 시간** — 뒤지고 있으면 `SUB_CHASE_MINUTE`(두 골 이상 뒤지면
     `SUB_CHASE_MINUTE_TWO`)부터 벤치 최고 공격 자원을 넣고 가장 지친 수비 자원을
     뺀다. 앞서고 있으면 `SUB_HOLD_MINUTE`부터 그 반대다 — 가장 지친 공격 자원을
     빼고 수비 자원을 넣는다. **줄이 무너지지 않는 선까지만**이라, 승부수는 필드에
     수비 셋을 남기고 굳히기는 공격 하나를 남긴다. 경기당 `SUB_CHASE_MAX`장·
     `SUB_HOLD_MAX`장이고, **그 수는 장부의 교체 사건이 쥔 `causes`로 센다** —
     세이브에 새 칸을 두지 않으므로 옛 세이브를 로드해도 셈이 맞는다.
  3. **피로** — 58분 이후(휴식 정지점은 그 전에도) 문턱을 넘은 필드 선수를 지친
     순서로 같은 계열 최고 벤치 자원으로.
     교체의 `causes`는 중계가 그대로 인용한다(→ [../llm/agents.md](../llm/agents.md) §3) —
     "승부수 — 공격 자원 투입"이 곧 감독이 읽는 "상대가 던졌다"는 장면이다.
  - **한 정지점은 교체 창 하나다** — 실제 벤치가 그러듯 한 번 일어설 때 여러 장을
    쓴다(2번과 3번이 같은 창에 설 수 있고, 3번은 문턱을 넘은 선수 수만큼). 한 창의
    상한은 `SUB_WINDOW_MAX`, 경기 전체는 장부의 `subLimitsOf`(5인/3창, 연장 +1)를
    **같은 함수로** 본다. 휴식 정지점의 교체는 창을 소모하지 않으므로 창이 소진돼도
    하프타임에는 움직인다 — 장부(§5)와 같은 규칙이다.
- **부상 정지점에서 빼지 않으면 그 자리는 구멍으로 남는다.** 장부의 `injury`는 그
  선수를 명단에서 빼지 않으므로(§5) 교체하지 않으면 그대로 뛴다. 남은 시간의 전력은
  **구멍 문턱**(§3.2)으로 계산한다 — 패킷이 보는 그 선수의 경기 중 피로를
  `GAP_THRESHOLD`(78) 아래로 두지 않아 개인 전력이 깎이고, 그 라인이 −7%를 치르고,
  키포인트에 "교체하지 않으면 그 자리가 계속 열린다"가 뜬다. 이미 그보다 지쳐 있었다면
  그 값 그대로다 — 부상이 다리를 되살리지는 않는다. 교체하는 순간 사라진다.
  - **깎는 것은 패킷뿐이다.** 경기 후 체력 정산이 읽는 누적 피로
    (`pendingMatch.matchFatigue`)는 건드리지 않는다 — 부상의 대가는 결장 일수가 이미
    치른다(§6). 여기서 함께 깎으면 같은 부상을 몸에서 두 번 뺀다.
  - 그래서 이 정지점의 선택에 값이 매겨진다. 빼면 교체 카드 한 장과 벤치 자원을 쓰고,
    두면 그 라인이 남은 시간 내내 열린다. AI 벤치는 언제나 빼지만
    (`planAiSubstitution`), 교체 창을 다 썼거나 자리를 이을 자원이 없으면 AI의 다친
    선수도 같은 규칙으로 남는다.
- **AI의 경기 중 6축은 킥오프 전술에서 `AI_SHIFT_BOUND`(2)눈금까지만 벌어진다.**
  완성된 전술은 `TacticsSpecSchema`를 다시 지난다. 상한이 킥오프 값에 걸리는 이유는
  **판단이 정지점마다 다시 불리기 때문**이다 — 지금 값에 ±1을 얹는 것만으로는
  골·부상·카드가 잦은 경기에서 같은 판단이 대여섯 번 쌓여 5·5·5나 1·1·1에 붙고,
  상대의 성향이 스코어가 아니라 **정지점 횟수**의 함수가 된다.
- **판의 모양도 한 번은 바뀐다** — 뒤지고 `AI_SHAPE_CHASE_MINUTE`을 넘겼으면 공격형
  프리셋으로, 앞서고 `AI_SHAPE_HOLD_MINUTE`을 넘겼으면 5-4-1로. **경기당 한 번**이다.
  - **고르는 것은 스쿼드를 아는 코어(engine)다.** 구간 시뮬은 의도(`"chase"`·`"hold"`)만
    돌려주고, 후보 프리셋 중 **지금 그라운드에 선 열한 명이 가장 잘 서는 모양**을
    `match-flow`가 고른다(라인업을 앉히는 것과 같은 잣대 — `buildAssignments`).
    시뮬이 프리셋을 직접 고르면 센터백 둘로 3-5-2에 서는 팀이 나온다.
  - **좌표가 먼저고 이름은 파생이다**(`shapeOf`). 프리셋 좌표(`FORMATION_LAYOUTS`)에
    열한 명을 다시 앉히고, 그 좌표에서 읽은 이름이 `aiTactics.formation`이 된다.
    이름만 갈아 끼우면 판은 그대로인데 장부의 모양만 달라져 화면과 갈라진다.
  - **값을 치른다.** 낯선 자리에 선 선수는 포지션 적응도로 깎이고(`profFactor`, §1.1),
    팀은 전술 적응도 `AI_SHAPE_FAMILIARITY_COST`를 잃는다 — 감독이 경기 중 판을
    갈아엎을 때 내는 것과 **같은 눈금에서 파생한다**(`FORMATION_CHANGE_COST` ×
    경기 중 계수). 공짜면 지는 AI는 언제나 바꾸는 것이 옳고, 그건 판단이 아니다.
  - **되돌릴 것이 없다.** 바뀐 자리는 `pendingMatch.aiShape`에만 살고 저장된 팀
    전술도 배치도 건드리지 않는다 — 유저 팀의 `tacticsBefore`/`restoreTactics`에
    해당하는 자리가 AI에는 필요 없는 이유다. 옛 세이브엔 없다(optional).
- **경기 중 옮긴 AI 전술은 판 전체에 닿는다** — 존 전력뿐 아니라 구간 시뮬로 가는
  전술 인자(체력 소모·패스 배분)도 `pendingMatch.aiTactics`를 읽는다. 패킷만 새
  전술로 서면 상대는 "세게 미는 팀의 전력"으로 계산되면서 "원래 전술의 다리"로 뛴다.
- mock과 실모드가 같은 시뮬레이터를 쓴다 — 차이는 서술 주체뿐.

경기 중 대화 규칙: 킥오프 전·하프타임(라커룸)은 선수 전체와, 진행 중 정지점은
수석코치·벤치 선수와만. 그라운드 위 선수에겐 외침(짧은 개인 지시)뿐. 대화 자체는
상태 무영향 — 판정형 스킬로 이어질 때만 상태가 변한다.

**정지점은 감독의 차례다.** 캐스터는 감독을 화자로 세우지 않고 감독의 대사·판단·
지시를 대신 쓰지 않는다. 팀 토크와 개인 면담은 **말과 강도를 감독이 고르는
자리**이므로, `team_talk`·`talk_to_player`는 감독이 그 말을 한 턴에만 불린다 —
캐스터가 지어낸 대사가 사기를 움직이면 감독이 고른 적 없는 효과가 장부에 남는다.
감독이 선수를 부르기만 한 턴에 캐스터가 할 일은 그 선수를 데려오는 연출까지다.

**부름은 판정이 아니다.** 같은 규칙이 캐스터보다 먼저 **해석**에 걸린다 — "일루와봐"
처럼 선수를 부르기만 한 말에는 `talk`을 싣지 않는다. 판정 라벨은 감독이 **그 선수에게
건넨 말**이 있을 때만 나오고, 부른 턴의 몫은 연출까지다. 이름을 부른 것이 격려로 읽히면
감독이 고르지 않은 사기가 장부에 남는다 (→ [agents.md](../llm/agents.md) §3 ②).

**같은 선수의 면담은 하루에 한 번만 셈한다.** 한 경기는 하루 안에서 끝나므로 이 게이트가
곧 경기당 한 번이다 — 정지점마다 같은 선수를 불러 폼을 쌓는 길이 여기서 막힌다
(→ [career.md](./career.md) §2).

### 승부차기 — 코어가 굴리고 캐스터가 한 발씩 옮긴다 (`competition/shootout.ts`)

연장까지 치르고도 합계가 같으면 승부차기다. **어느 경기든 킥 하나가 사건 하나로
장부에 남는다** — 누가 찼고, 누가 막아섰고, 들어갔는지 나갔는지, 그리고 그 킥의
성공 확률까지(`ShootoutKick`, → [../data/game-state.md](../data/game-state.md)).
결과만 두 숫자로 남던 자리라 중계도 화면도 인용할 것이 없었다.

- **성공률은 키커와 골키퍼가 함께 정한다.** 키커의 승부차기 기량은 결정력·침착성·
  킥력(0.5 · 0.3 · 0.2)이고, 골키퍼의 것은 골키핑·침착성(0.7 · 0.3)이다. 둘의 차가
  0이면 `PENALTY_BASE`(0.71)이고 거기서 기량 차 1당 `PENALTY_EDGE`(0.0035)씩
  오르내리되 **대역은 그대로 0.62\~0.80**이다 — 실력이 덜 갈리는 무대라 폭이 좁고,
  그래서 이변이 여기서 태어난다.
- **차는 사람은 그 경기를 끝낸 열한 명이다** — 장부의 온필드(`homeOnPitch` ·
  `awayOnPitch`)가 곧 그 목록이고, 퇴장이 있었으면 그보다 적다. 감독의 경기는 마감이
  승부차기 **뒤**에 오므로 결과가 아직 없어, 키커도 골키퍼도 **진행 중인 장부의
  온필드**에서 선다(`finishingXi` — 결과가 있는 타 팀 경기는 거기서 읽는다). 기본
  순서는 승부차기 기량 내림차순이고 골키퍼가 맨 뒤다. 열한 발을 다 쓰면 처음으로
  돌아간다. **막아서는 골키퍼도 그 열한 명 중의 GK다** — 교체돼 나갔거나 퇴장당한
  골키퍼는 막지 않는다.
- **먼저 차는 쪽은 동전이 정한다** — 홈을 고정하면 조기 확정이 들어온 뒤로 홈에
  체계적 이점이 생긴다. 시드에서 떨어지는 결정적 동전이라 같은 세이브는 같은 결과다.
- **규정대로 조기 확정한다.** 남은 킥으로 뒤집을 수 없으면 거기서 끝난다 — 3–0으로
  끝난 승부는 장부에도 3–0으로 적힌다. 5킥씩 차고도 같으면 서든데스로 넘어가고,
  **거기엔 상한이 없다**: 성공률이 대역 안(0<p<1)에 갇혀 있으므로 언젠가 갈린다.
  이 판정은 `shootoutSettled` 하나가 갖는다 — 코어도 화면도 같은 함수를 읽는다.

**감독의 경기는 정지점을 하나 더 갖는다.** 120분이 끝나고 승부차기가 남았으면 장부는
`finished`지만 경기는 끝나지 않는다 — 진행 턴은 `shootout_start`에서 멈추고 감독은
**키커 순서**를 지시할 수 있다(`set_shootout_order` — 그 경기를 끝낸 열한 명 중에서,
말한 사람이 앞에 서고 나머지는 기본 순서로 뒤를 잇는다). 그 뒤로는 진행 한 번에
**한 발**이고, 캐스터는 코어가 확정한 그 한 발을 문장으로 옮긴다 — 다른 정지점과
같은 분업이라 **결과를 정하는 것은 언제나 코어다**. 승부가 갈리면 그때 `finalizeMatch`가
`MatchResult.penalties`에 합계와 킥 목록을 적는다.

**타 팀 경기는 같은 함수를 조용히 돌린다** — `resolveShootout` 한 번에 킥 목록이
장부에 실린다. 대진 승자를 묻는 자리(`domesticTieWinner` · `euroTieWinner`)는 **읽기만
한다**: 연장과 승부차기를 굴리는 것은 `resolveDomesticTie` · `resolveEuroTie`이고,
그것을 부르는 곳은 대회를 진행시키는 `advanceDomesticCups` · `advanceEuroKnockouts`뿐이다.
화면이 브래킷을 그릴 때마다 승부차기가 새로 굴러가면 안 된다.

## 3. 체력 — 자리와 전술이 함께 정한다 (`sim/stamina.ts`)

실제 포지션별 주행거리를 기준선으로: 중앙 미드 1.25 · 풀백/윙백 1.20 · 윙어/DM
1.15 · AM 1.10 · ST 1.00 · CB 0.85 · GK 0.20. 여기에 전술 배율(0.72\~1.40)이
얹히고, 자리마다 같은 지시의 무게가 다르다(폭→측면, 압박→앞선·중원).

**소모를 움직이는 축은 넷뿐이다** — 압박(한 칸 0.09)이 가장 비싸고 템포(0.055) ·
수비 라인(0.03) · 폭(0.025)이 뒤를 잇는다. 멘탈리티와 패스는 소모에 닿지 않는다.
넷을 다 올려도 1.40이고, 아래는 0.72에서 잘린다.

소모는 남은 체력에 비례해 둔화되는 지수 감쇠 곡선이다. 즉 `log(남은 체력)`이
활동량에 따라 선형으로 줄어들어, 초반에는 빠르게 떨어지지만 바닥에 가까울수록
같은 1분이 가져가는 절대량은 작아진다. 구간을 몇 번으로 나눠 진행해도 같은
시간·전술이면 결과가 같다.

⚠️ **그러려면 구간의 경계가 장부의 분이어야 한다.** 조용히 끝난 구간(`flow`)의
시각은 **마지막 사건의 분**이다 — 그 뒤의 대기까지 이 구간의 시각으로 돌려주면,
장부는 마지막 사건에서 멈추고 다음 구간이 같은 분에서 다시 출발해 그 1\~2분의
피로와 패스를 두 번 센다. 사건이 하나도 없는 구간만은 흐른 시각을 그대로 돌려주고
(그 시각의 흔적 하나를 남기거나 호출부가 `advanceClock`으로 민다) 시계가 그만큼
나아간다.

체력 100·기본 전술·평균적인 날 기준으로 지구력 70이 풀타임을 뛰면 중앙 미드는
30, 풀백 31, 윙어·DM 33, AM 34, 공격수 38, 센터백 44, 골키퍼 82를 남긴다. 하프타임은 그
중간이 아니라 위쪽이다(중앙 미드 55) — 지수 곡선이라 초반이 가파르다. 자리·전술·
점유·개인 지시·경기별 편차는 감쇠 전 활동량을 함께 움직인다.

전술이 이 위에 얹힌다. 지구력 70 중앙 미드가 90분 뒤 남기는 체력: 기본 30 ·
압박 5는 21 · 압박과 템포를 함께 올리면 18 · 둘 다 내리면 46.

⚠️ **한 경기가 스쿼드를 비우되 바닥에 눕히지는 않는다.** 소모가 이보다 크면
경기 종료 시점이 늘 구멍 문턱(§3.2) 아래가 되어, 교체를 미룬 대가가 아니라
90분을 뛴 대가가 된다 — 그러면 구멍은 판단의 결과가 아니라 상수다.

- **그날의 몫 ±12%** (`drainVariance`)가 곱해진다. `시드:경기:선수` 해시라
  결정적이고 **경기 내내 고정**이다(구간마다 굴리면 평균으로 상쇄된다).
  ⚠️ FNV-1a만으론 하위 비트 확산이 약해 편차가 숨은 능력치처럼 굳는다 — murmur3
  마무리 믹스 필수(테스트로 고정).
- **정산도 이 값 그대로** (`pendingMatch.matchFatigue`) — 화면에서 본 소모와
  장부에 남는 소모는 같은 숫자다. 상대 팀도 같은 장부에서 정산된다.

### 3.1 회복

소모와 같은 축(`stamina`)이 회복도 정한다(`dailyRecovery`): 본훈련 11 · 훈련 없는
날/휴식/경기일 13 · 회복 세션 16.

중앙 미드필더가 **가장 무거운 날**(+12%) 풀타임을 뛴 뒤 돌아오는 자리:

| 지구력 | 경기 직후 | 3일 | 5일 | 7일 |
| ------ | --------- | --- | --- | --- |
| 50     | 20        | 60  | 83  | 100 |
| 60     | 23        | 64  | 87  | 100 |
| 70     | 26        | 69  | 92  | 100 |
| 90     | 33        | 78  | 100 | 100 |

**만 7일이면 누구든 온전히 돌아오고, 사흘은 누구도 못 채운다.** 그 사이가 감독이
판단하는 구간이다 — 닷새면 지구력 90은 다 채우고 50은 83에서 나선다. 고강도
전술·낮은 점유율·개인 압박 지시가 더한 소모는 이 표의 범위 밖이다.

⚠️ **실제 일정은 주 1경기가 아니다.** 리그와 대항전이 겹치는 구간의 경기 간격은
3\~5일이 표준이고 7일 이상은 A매치 브레이크 언저리뿐이다. 그래서 이 표의 왼쪽 두
칸이 실제로 감독이 사는 자리이며, **로테이션은 선택이 아니라 스쿼드 운영의 기본**
이다. 회복 기준선을 "주 1경기"에만 맞춰 잡으면 달력이 그 리듬을 주지 않아
스쿼드가 시즌 내내 하강한다.

- ⚠️ 회복이 지구력으로 갈리는 폭(`recoveryFactor` 0.84\~1.17)은 소모가 갈리는 폭
  (`staminaFactor` 1.39\~0.64)보다 훨씬 좁아야 한다 — 한 축이 양쪽에 곱으로 걸리면
  격차가 복리로 벌어진다.
- 하루의 회복은 하루에 한 번 — 그날의 성격 하나를 정해 한 번만 얹는다.

### 3.2 구멍 — 교체를 미루면 그 라인이 열린다

피로 78(= 체력 22)을 넘으면 그 라인 전체가 −7%(최대 −25%)를 치르고, 키포인트에
문장으로 뜬다("교체하지 않으면 그 자리가 계속 열린다"). 부상 확률도 함께 오른다.

**구멍은 90분을 뛴 대가가 아니라 덜 회복된 몸으로 나선 대가다.** 온전한 몸
(체력 100)으로 시작하면 어느 자리도 90분 안에 문턱에 닿지 않는다. 문턱에 닿는
것은 이미 지친 채 나선 선수다:

| 시작 체력 | 지구력 50 중앙 미드 | 지구력 70 중앙 미드 | 지구력 90 |
| --------- | ------------------- | ------------------- | --------- |
| 100       | —                   | —                   | —         |
| 80        | 82분                | —                   | —         |
| 65        | 69분                | 81분                | —         |

그래서 사흘 만에 같은 XI를 다시 세우면 후반에 라인이 열린다. 자리도 갈린다 —
같은 조건에서 풀백은 중앙 미드보다 서너 분 늦고, 공격수와 센터백은 웬만해선
닿지 않는다.

⚠️ 구멍 문장에 소진 수치는 적지 않는다 — 상대 체력은 안개를 지나 막대로만 간다.

### 3.3 수적 열세 — 퇴장은 승부에 닿는다

그라운드에 열한 명이 못 서면 **빠진 한 명마다 그 팀의 세 줄이 12%씩** 얇아진다
(최대 세 명까지). 존 전력은 XI의 가중 평균이라 인원이 줄어도 값이 그대로다 —
평균 이하인 선수가 나가면 오히려 오른다. 이 감점이 없으면 퇴장은 장부에만 남고
승부에는 닿지 않는다.

퇴장 계수를 따로 두지 않는 이유가 여기 있다. 존이 얇아지면 상대의 경로 우위가
그만큼 커지고, 그 우위는 이미 슈팅 양(exp)과 질(logit)로 번역되는 길을 갖고 있다.
열 명이 된 팀은 90분 기준으로 **실점 +15\~30%, 득점 −20\~25%**가 된다.

두 시뮬이 같은 문을 지난다 — 구간 시뮬은 퇴장·교체마다, 간이 시뮬은 그 시각마다
온필드 명단으로 패킷을 다시 만들기 때문이다.

## 4. 사건과 기록

```ts
MatchEvent { minute, type, team, actors[], causes, xg, goalProbability, shotOutcome }
```

- `causes`는 코어가 패킷 항목에서 뽑는다(매치업 → 키포인트 → 전술 노트) — 문장이
  아니라 **패킷 태그 그대로**다. 키포인트는 `favours`가 득점한 편을 가리키는 것만
  고르므로, 그 칸이 뒤집히면 상대의 강점이 우리 골의 근거로 실린다. 이 태그가 감독의 전술 XP 근거가 되므로 검증 없는
  자유 문자열을 두지 않는다.
- **교체의 갈래는 `subCause`가 갖는다** (`injury` · `chase` · `hold` · `fatigue`).
  한 경기에 쓸 수 있는 승부수·굳히기 장수를 세는 것도, 부상 교체를 먼저 세우는 것도
  이 코드다 — 근거 문구를 고쳐도 벤치의 판단은 그대로다.
- `actors` 순서가 뜻을 갖는다 — goal은 [득점자, (도움)], substitution은 [아웃, 인].
- 도움은 골을 무효로 만들지 못한다 — 못 믿을 도움 슬롯은 조용히 떨구고 골은
  살린다(`sanitizeEvent`).

**사건이 될 만한 것만 사건이다.** 골·슛·선방·카드·교체·부상은 `MatchEvent`,
패스·전진 패스·xG 합은 `MatchLedgerState.stats`에 숫자로 쌓인다. 흐름의 양은
굴리지 않고 나눈다: 구간 길이 × 점유 × 템포로 팀 총량 → 자리·`passing`·`vision`
으로 배분. 전진 패스 비율은 전술 × 선수 성향(`daring` = 시야 0.5 · 킥 0.3 ·
침착성 0.2)이라 같은 팀 안에서도 23\~38%로 갈린다.
⚠️ 템포 계수의 기준(3)은 1.0 — 아무 지시도 안 한 팀이 손해 보면 안 된다.

모든 실제 슛에는 기회의 질 `xg`와 결정력 반영값 `goalProbability`가 함께 붙는다.
골도 별도 발생 사건이 아니라 `shotOutcome="goal"`인 슈팅이다. `chance`는 슈팅 전
장면이라 xG를 쌓지 않는다.
⚠️ 한 값은 한 곳에서만 — 뷰의 슛·선방·패스는 `stats`가 원본, 골·도움·카드만
사건에서 센다.

**도움은 결과까지 살아남는다** — `MatchResult.assists`는 `scorers`와 같은
순서·길이·형식(`"home:playerId"`), 단독 득점은 빈 칸. 유저 경기와 타 팀 퀵심이
같은 규약을 쓴다.

## 5. 검증 — 경기 장부의 무결성

| 규칙      | 내용                                                                                                                                                                     |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 시간 순증 | 이벤트 분은 단조 증가, 0\~90 — 연장이면 120까지 (추가시간은 시계에 얹지 않는다)                                                                                          |
| 국면      | 전반→후반→(연장 전반→연장 후반)→종료. 종료는 90′ 또는 120′ 이후에만                                                                                                      |
| 인원      | 퇴장·교체아웃 재등장 금지 · 교체 5인/3회(**연장이면 6인/4회**) · 휴식 정지점의 교체는 창 미소모 · 미등록 선수 금지                                                       |
| 스코어    | goal 이벤트 수 = 스코어                                                                                                                                                  |
| 배치 크기 | 장부가 한 번에 받는 이벤트 20개(`LEDGER_LIMITS.maxEventsPerBatch`) · 구간 시뮬은 15개(`MAX_SEGMENT_EVENTS`)에서 끊는다 — 처리 단위만 끊고 슈팅·득점 분포는 자르지 않는다 |
| 파생 스탯 | 요약 스탯은 이벤트에서 코어가 재계산                                                                                                                                     |
| 퇴장      | 경고 누적 퇴장은 `yellow_card` + `red_card` 두 줄 — 뒷줄 레드만 통과                                                                                                     |
| 부상      | `injury`는 온필드 명단을 바꾸지 않는다 · 같은 선수의 두 번째 `injury`는 없다                                                                                             |

사건을 만드는 쪽이 코어이므로 이 검증은 LLM 방어가 아니라 **시뮬레이터의 계약
검사**다 — 반려는 시뮬레이터의 버그를 뜻한다.

**창을 면제받는 자리는 분이 아니라 정지점이 정한다.** 교체 기회(창)는 같은 분의
연속 교체를 한 번으로 세고, **휴식 정지점**(하프타임 · 연장 개시 · 연장 하프타임)의
교체는 아예 창을 쓰지 않는다 — 실제 규정이 그렇고, 장부도 그 셋을 배치가 끊기는
정지 사건으로 이미 알고 있다. 45′·46′ 같은 분으로 재면 그 시각이 조금만 움직여도
규칙이 사라진다. 면제되는 자리는 정지 사건의 **앞뒤 양쪽**이다:

- **뒤** — 정지점에서 감독이 부르는 교체. 다음 배치의 첫 사건으로 온다.
- **앞** — 구간 시뮬이 정지 사건과 함께 올리는 AI 교체(`insertBeforeStop`). 같은
  배치에서 정지 사건 바로 앞에 선다.

**경기가 재개되면 창이 다시 선다** — 정지 사건 뒤에 교체가 아닌 사건이 기록되거나
시계가 그 분을 지나면 그때부터는 보통의 교체다.

**부상은 명단을 바꾸지 않는다.** `injury` 한 줄은 그 선수가 쓰러졌다는 사실만 적고
온필드 명단은 그대로다 — 그라운드에서 빼는 것은 교체뿐이다. 대신 **같은 선수는 한
경기에서 두 번 쓰러지지 않는다**: 구간 시뮬은 장부에 이미 `injury`가 걸린 선수를 부상
후보에서 제외한다(퇴장자와 같은 자리에서 걸러진다). 제외하지 않으면 경기 후 반영이 그
선수에게 INJURY row를 두 장 열어 하루에 두 번 다친 이력이 남고(§6), 교체를 미룬 감독이
그 대가를 두 번 치른다.

**두 번째 경고는 경고 한 줄과 퇴장 한 줄로 남는다.** 장부는 경고 2장을 자동 퇴장으로
바꾸지만(온필드에서 빼고 `sentOff`에 넣는다) 경기 후 반영은 **사건 타입만** 읽는다 —
`red_card` 줄이 없으면 `cause:"red"` 출장 정지도 평점의 퇴장 감점도 생기지 않는다.
그래서 구간 시뮬은 두 번째 경고 자리에서 두 줄을 함께 넣고, 장부는 **방금 그 경고로
나간 선수의 레드 한 줄만** 받는다 — 같은 선수의 두 번째 레드도, 퇴장 뒤의 다른 사건도
그대로 반려다. 간이 시뮬이 같은 모양이라(§7) 중계는 그 쌍을 경고 누적 퇴장
(`second_yellow`)으로 읽는다.

## 6. 경기 후 반영 (코어, 결정적)

스탯 적재 → 평점·결과의 폼 Δ → 피로 정산 → 부상 확정 → 재정 → 리그 테이블.
사건은 창발, 반영은 공식.

`finalizeMatch`는 그 결과를 **갈래로 나눠** 돌려준다(`MatchDigest`).

| 갈래      | 무엇                                   | 어디로                        |
| --------- | -------------------------------------- | ----------------------------- |
| `ours`    | 우리 경기 — 스코어·카드·부상·전술 복구 | 결산 기록의 요약(대회 말풍선) |
| `finance` | 매치데이 수익·수당·원정 비용           | GM 입력(`pendingNews`)        |
| `others`  | 같은 라운드의 다른 경기·유럽/컵 대진   | GM 입력(`pendingNews`)        |

말풍선은 **우리 경기만** 싣는다 — 나머지는 대회·재정 화면이 이미 갖고 있고,
알림이 그 화면의 내용을 옮겨 적으면 한 줄이 글자 벽이 된다. 대신 모델은 셋을 다
읽는다: 순위가 뒤집힌 걸 모른 채 다음 장면을 쓰면 세계가 멈춘 것처럼 읽힌다.

### 마감은 양 팀에 적는다

장부 하나에 두 팀이 있으므로 정산도 두 팀이다. 우리 것만 적으면 우리를 상대한
클럽만 출전·득점·징계 없이 시즌을 보내고, 득점왕·평점·정지가 **우리 경기만큼**
어긋난다 — 리그가 우리 팀만의 규칙으로 돌면 안 된다(§7). 쓰는 함수도 간이 시뮬과
같은 것이다.

| 무엇                                                  | 우리 | 상대 |
| ----------------------------------------------------- | ---- | ---- |
| 출전·득점·도움·평점 합계 (`SEASON_STAT`)              | ○    | ○    |
| 폼 Δ (`squad/form.ts` `formDeltaFromMatch`)           | ○    | ○    |
| 체력 소모 (`pendingMatch.matchFatigue` 그대로)        | ○    | ○    |
| 부상 확정 · 부상 성향 하강 (`squad/injury.ts`)        | ○    | ○    |
| 카드 → BOOKING·SUSPENSION (`match/discipline.ts`)     | ○    | ○    |
| 출장 정지 소화 (`serveSuspensions`)                   | ○    | ○    |
| 연패·연승의 라커룸 (`squad/slump.ts`)                 | ○    | ○    |
| 포지션 적응도 (아래)                                  | ○    | ○    |
| 경기별 평점 (`MATCH.result.ratings`) · 결산 판정(LLM) | ○    | ✗    |
| 말풍선 한 줄 (카드·정지·부상 일수·무드)               | ○    | ✗    |

아래 두 줄이 우리 팀만인 것은 **감독이 읽는 화면**이기 때문이다. 경기별 평점은
간이 시뮬도 남기지 않고 시즌 합계만 쌓는다(§7) — 상대의 평점도 같은 눈금으로
`ratingSum`에만 들어간다. 남의 팀 카드·정지·부상 일수는 브리핑하지 않는다(하루 열
경기의 카드를 나열하면 소음이다) — 조회 도구가 알려 준다.

### 포지션 적응도 — 그 자리에서 뛴 경기가 올린다

뛴 선수는 **실제로 밟은 자리**의 `proficiency`가 `MATCH_PROFICIENCY_GAIN`(1)만큼
오른다(상한 99, 양 팀 공통). 자리는 저장된 배치가 아니라 그 경기에 선 자리다 —
교체로 들어온 선수는 물려받은 자리로, 로테이션으로 다른 자리에 선 선수는 그 자리로
오른다. 패킷을 세울 때마다 그때 밟은 자리가 `pendingMatch.positionsPlayed`에
남고(자리를 정하는 곳이 거기 하나다) 마감이 그것을 읽는다. 목록에 없던 자리는
폴백값(→ [player.md](../data/player.md) §8)이 시작점이 되어 함께 오른다.

### 평점 (`engine/match/ratings.ts`)

기준선 6.0에서 장부 사실만으로 조정(난수 없음): 승 +0.4/패 −0.3 · 골 GK +2.0 ·
DF +1.4 · MF +1.1 · FW +0.9 · 도움 +0.6 · 무실점 GK +0.8/DF +0.5 · 실점(첫 골
면제) GK −0.3/DF −0.2 · 경고 −0.3 · 퇴장 −1.5. 범위 3.0\~10.0.
시즌 평점은 저장하지 않고 `ratingSum ÷ apps`로 파생(`seasonRating`).

**출전 시간은 그라운드를 떠난 시각까지다** — 교체로 나간 분과 **퇴장당한 분**이
같은 자격으로 끝을 정한다(둘 다 걸리면 이른 쪽). 퇴장을 세지 않으면 20분에 나간
선수도 90분으로 남아, LLM 채점이 "풀타임을 뛰고 퇴장까지 당한 선수"를 읽는다.

**경기 후 LLM 채점** — 코어가 앵커를 박고(`buildRatingBrief` — finalizeMatch와
같은 함수), LLM이 사건 목록·출전 시간을 읽어 앵커 ±`RATING_BAND`(1.2) 안에서
재채점 + 근거 한 줄. 실패하면 앵커가 남는다(경기 결과를 막지 않는다). mock 모드는
건너뛴다.

### 징계 — 카드가 정지가 되는 길 (`engine/match/discipline.ts`)

카드 한 장은 `BOOKING` 한 줄로 남고, 두 시뮬레이터가 **같은 문**(`recordCard`)을
지난다. 리그가 우리 팀만의 규칙으로 돌면 "다음 경기 경고 조심"이 상대에게 성립하지
않는다.

| 무엇         | 규칙                                                                                                |
| ------------ | --------------------------------------------------------------------------------------------------- |
| 경고 누적    | 그 시즌의 **세는 경고**가 `YELLOWS_PER_SUSPENSION`(5)의 배수에 닿을 때마다 — 5·10·15장 — 정지 1경기 |
| 퇴장         | `red_card` 한 줄이면 그 자체로 정지 1경기 (`cause: "red"`)                                          |
| 두 번째 경고 | 정지는 **퇴장 하나뿐**이다 — 한 사건에 한 건                                                        |
| 세는 단위    | 경고는 **시즌** 단위로 세고(`seasonYellowsOf`) 대회를 가리지 않는다                                 |

**두 번째 경고의 두 장은 누적에서 빠진다.** 장부에는 경고 한 줄 + 퇴장 한 줄이 그대로
남지만(경기 기록은 실제로 그랬다), `seasonYellowsOf`는 **한 경기에서 두 장을 받은 경기의
경고를 세지 않는다** — 두 장은 그 자리에서 퇴장 정지 한 건으로 값을 치렀다. 그래서:

- 첫 장이 이미 누적 눈금에 닿아 정지를 걸었다면, 두 번째 장이 그 정지를 **물린다**
  (`sus-<선수>-<경기>` 한 줄이 사라진다). 한 사건은 한 정지다.
- 이미 경고가 있던 선수의 **다이렉트 퇴장**은 다르다 — 그 경기의 경고는 한 장뿐이라
  누적에 그대로 남고, 누적 정지와 퇴장 정지가 함께 걸릴 수 있다.

**소화도 대회를 가리지 않는다.** 정지 중인 선수가 결장한 **대회 경기** 하나마다
`served`가 1 오르고, `served ≥ lengthMatches`면 그 정지가 닫힌다
(`serveSuspensions`) — 리그에서 받은 정지를 컵이나 유럽에서 소화할 수 있다.

- **소화는 새 카드보다 먼저다.** 순서가 뒤집히면 방금 퇴장당한 선수가 바로 그
  경기로 자기 정지를 소화한다. 우리 쪽 대상은 킥오프 시점의 명단
  (`pendingMatch.servingSuspension`)이 원본이고, 상대는 간이 시뮬과 같은 방식으로
  마감 시점에 센다 — 그 시점엔 이 경기의 카드가 아직 쌓이기 전이라 같은 집합이다.
- **친선은 어느 쪽도 아니다** — 친선의 카드는 어느 대회에도 쌓이지 않고, 친선으로
  정지가 소화되지도 않는다. 정지는 대회가 매기는 벌이다.
- **정지 선수는 명단에서 자동으로 빠진다**(`isAvailable`) — 감독의 라인업도
  간이 시뮬의 라인업(`simSquadOf`)도 같은 문을 쓴다(§2·§7). 부상과 같은 자리다.
- 정지가 걸리면 그 사실이 한 줄로 감독에게 간다 — **물린 정지의 줄은 브리핑에서
  빠진다**(두 번째 경고가 앞선 누적 정지를 지운 경우). 브리핑의 줄 수와 실제로 걸린
  정지 수가 어긋나면 감독은 몇 경기를 못 쓰는지 알 수 없다. 남의 팀 정지는 브리핑하지
  않는다 — 조회 도구가 알려 준다.

## 7. 타 팀 간이 시뮬 (`engine/match/quick-sim.ts`)

시즌 2,100여 경기 중 유저 경기만 구간 시뮬을 지나고 나머지는 같은 선수×경로
슈팅 모델을 구간별로 묶어 한 번에 처리한다. **규칙은 같고 해상도만 다르다**:

- 결과·득점자·도움 + **슈팅 수·기회 xG·결정력 반영 기대 득점·골의 분·카드·퇴장·교체**까지 남긴다.
- 카드의 **빈도**(`teamCardRate` — 경기당 기대치를 팀이 나누고 자기 강도를 곱한다)도
  **누가 받는지**(`bookingWeight` — 거칠기 + 태클 미숙, `BOOKED_AGAIN_WEIGHT`)도
  구간 시뮬과 한 벌이고, BOOKING·SUSPENSION은 같은 문(`engine/match/discipline.ts`)을
  지난다 — 리그가 우리 팀만의 규칙으로 돌면 안 된다. **두 번째 경고의 모양도 같다** —
  경고 한 줄 + 퇴장 한 줄(§5)이라 다음 경기 정지가 양쪽에 똑같이 걸린다.
  공유하는 상수와 식은 `packages/sim`이 한 벌만 갖는다 (→ 아래 표).
- 퇴장·교체 시각마다 온필드 좌표로 패킷을 다시 만들므로 남은 슈팅 분포가 바뀐다.
  카드 수신자와 도움도 그 시각의 온필드 선수만 후보가 된다. 교체 한도는 장부의
  `subLimitsOf`(5인/3창) 그대로이고, 피로는 뛴 시간만큼이며 구간 시뮬과 같은
  `conditionDrain`을 사용한다. 포지션·지구력·전술·점유율·경기별 편차가 모두
  동일하게 적용되므로 CM과 GK의 소모 기준도 같다.
- **벤치도 스코어와 남은 시간을 읽는다** — 경기를 시간순으로 굴리며 구간 시뮬의
  정지점과 같은 자리(골·퇴장·하프타임·조용한 25분)에서 같은 정책(`planBenchSubs`,
  → §2)을 부른다. 스코어는 그 분까지 굴린 슛이 만든 값이고, 피로는 그 분까지의
  소모를 같은 `conditionDrain`으로 추정해 같은 문턱(`SUB_FATIGUE`)에 댄다. 교체를
  시간표로 미리 박아 두면 리그 전체의 후반이 감독의 경기와 다른 규칙으로 돈다.
- 도움은 골의 68%에만 붙는다(`ASSIST_RATE` — 이것도 구간 시뮬과 한 벌이다).
- **중립 경기장은 결승의 사실이다** — 경기(`MatchRecord.neutral`)가 갖고 있는 값이
  그대로 간이 시뮬로 들어가 홈 노출(1.06·0.96)을 1로 만든다. 넘기지 않으면 명목상의
  홈이 결승에서 공짜 우위를 얻는다.
- **골 정지점마다 패킷을 다시 세운다** — 스코어가 벌어진 뒤의 슈팅 노출
  (`gameStateExposure`, §1.4)이 구간 시뮬과 같은 문을 지나야 한다. 정지점 없이 90분을
  한 패킷으로 굴리는 갈래(2군 리그 · 연장)는 스코어를 모르므로 노출 1로 돈다.
- **부상은 실제로 뛴 선수 전원에게 걸린다** — 뛰고 안 다쳤을 때의 성향 하강
  (`easeProneness`)은 선발 + 투입된 교체가 대상이다. 유저 경기가 쓰는 것과 같은
  목록이라 로테이션 자원의 부상 성향이 리그 전체에서 한 눈금으로 움직인다.
  **추첨 후보에서는 퇴장자가 빠진다** — 구간 시뮬이 `gone`을 거르는 것과 같은
  규칙이고, 그라운드를 떠난 발이 다치면 같은 경기의 장부가 두 말을 한다. 성향
  하강은 그래도 받는다: 뛴 것은 사실이다. 빈도는 `teamInjuryRate`가 쥔다 — 팀당
  몫 × 강도 × **추첨 후보의** 성향 평균, 구간 시뮬과 같은 함수다.
- **부상의 난수 채널은 `injury:<경기 id>` 한 모양이다** — 두 시뮬이 같은 문을
  쓴다. 시즌·대회·차수로 채널을 엮으면 차수가 겹치는 경기(친선)가 같은 난수열을
  받아 같은 자리에서 같은 부상이 반복된다.
- **사건의 분은 구간 시뮬과 같은 시계 위에 선다** — 정규 경기의 마지막 분은
  `PHASE_END.second_half`(90′)이고 추가시간은 시계에 얹지 않는다(§2와 같은 이유).
  91′부터는 연장의 시각이라, 정규가 그 위로 넘으면 정규 93′ 골 뒤에 연장 91′ 골이
  붙어 `goalMinutes`가 역행한다.
- **슈팅의 분은 구간 안에서 균등하고, 전·후반의 밀도가 갈린다** — 전반이 사건의
  `QUICK_FIRST_HALF_SHARE`(0.46)를 갖는다(체력이 떨어지고 뒤진 팀이 밀어붙인다).
  45분씩 두 하프라 발생률은 전반 ×0.92 · 후반 ×1.08이고 합은 90분 그대로다.
  **로그 곡선에서 뽑는 것은 카드의 분뿐이다** (`quickMinuteOf` —
  `N(u, s) = ln(1 + su) / ln(1 + s)`, `u`는 0\~1 균등 난수). 그 눈금 `s`도 몫에서
  유도한다 — 90분의 절반에 `p`가 실리려면 `s = (1 − 2p) / p²`라 0.46에서 0.378이다.
- **회복은 리그 전체가 받는다**(`tickOtherClubs`) — AI의 경기 당일도 감독 팀처럼
  훈련일이 아니라 휴식 눈금을 적용한다.
- **같은 날 경기는 킥오프 순서를 지킨다** — tick은 우리 킥오프 이전 경기까지만
  굴리고 나머지는 `finalizeMatch`가 잇는다. 감독이 미래 결과를 미리 알면 안 된다.

#### 두 시뮬이 공유하는 눈금 — 숫자가 사는 곳은 한 곳이다

**같은 값을 두 파일에 적지 않는다.** 눈금이 갈리면 그날부터 리그의 절반이 다른
규칙으로 돈다 — 우리 경기만 카드를 받고, 감독의 연장만 조용해진다. 아래는 전부
`packages/sim`이 원본을 갖고 `engine/match/quick-sim.ts`가 import한다.

| 눈금                                                     | 원본                                       | 무엇이 갈렸었나                                        |
| -------------------------------------------------------- | ------------------------------------------ | ------------------------------------------------------ |
| `teamCardRate(intensity)`                                | `sim/match-engine.ts`                      | 나누는 수와 강도 곱이 양쪽에 따로 적혀 있었다          |
| `teamInjuryRate(intensity, prone)`                       | `sim/match-engine.ts`                      | 간이 쪽만 강도를 빼고 굴렸다                           |
| `CARDS_PER_MATCH` · `INJURY_PER_MATCH`                   | `sim/match-engine.ts`                      | 손잡이는 이미 공통 — 위 두 함수가 그 손잡이를 읽는다   |
| `STRAIGHT_RED_CHANCE` · `bookingWeight` · `injuryWeight` | `sim/match-engine.ts`                      | —                                                      |
| `ASSIST_RATE`                                            | `sim/match-engine.ts`                      | —                                                      |
| `EXTRA_TIME_SHOT_SHARE`                                  | `sim/match-engine.ts`                      | —                                                      |
| `EXTRA_TIME_MINUTES` · `EXTRA_TIME_DENSITY`              | `sim/match-engine.ts`                      | 같은 0.84를 두 식으로 냈다 (`PHASE_END` 차 vs 상수 30) |
| `EVEN_POSSESSION`                                        | `sim/stamina.ts`                           | 0.5가 두 벌이었다                                      |
| 교체 정책 `planBenchSubs` · `SUB_*` 문턱 · 창 규칙       | `sim/match-engine.ts`                      | 간이 쪽만 시간표(46·60·68·76·82)로 스코어를 안 읽었다  |
| `conditionDrain` · `chaseFactor`                         | `sim/stamina.ts`                           | —                                                      |
| 선수×경로 슈팅 프로필 · xG · 결정력                      | `sim/strength-packet.ts` · `shot-model.ts` | —                                                      |

**강도(`matchIntensity`, 0.80\~1.22)는 카드와 부상에 양쪽 모두 곱한다.** 압박·템포를
올린 팀이 자기 카드와 자기 부상을 더 받는 것은 6축의 대가(§1.2)이고, 간이 시뮬이
고정값을 쓰면 압박 5로 서는 AI 팀은 **우리와 붙는 한 경기에서만** 그 대가를 치른다
— 리그 전체가 강도 1로 사는 세계다. 프리셋의 리그 평균이 3.09\~3.16이라(§1.2) 리그
평균 강도는 1.01 언저리고, 이 변경으로 리그 카드 총량은 1\~2% 오르고 **분포가
갈린다** — 고압박 팀이 더 받고 로우블록 팀이 덜 받는다.

남은 차이는 **표집 방식**뿐이다. 구간 시뮬은 이 발생률로 90분을 지수분포로 굴려
사건을 뽑고, 간이 시뮬은 카드를 푸아송 한 번, 부상을 베르누이 한 번으로 뽑는다.
팀당 부상 기대치가 0.05\~0.07이라 λ와 1 − e^(−λ)의 차이는 3% 안쪽이고, 대신 간이
쪽은 한 팀이 한 경기에 두 명을 잃지 않는다. **재는 자리는
`pnpm balance injury-rate`** — 같은 두 팀을 양쪽 시뮬로 굴려 카드·부상률을 나란히
찍고, 비가 밴드를 벗어나면 빨개진다.

#### AI 로테이션 — 명단·벤치·교체가 한 줄로 이어진다

**로테이션은 선택이 아니라 스쿼드 운영의 기본이고**(§3.1), AI가 컵·유럽을 병행하는
대가는 오직 이 경로로만 치러진다. 라인업을 짜는 곳은 `engine/core/tick.ts`의
`simSquadOf` 하나다.

- **누구를 빼는가** — 피로 `ROTATION_FATIGUE`(20) 이상인 선발을 같은 포지션군에서
  기량이 `ROTATION_OVR_DROP`(7) 안쪽이면서 `ROTATION_FRESHER`(15) 이상 더 신선한
  자원으로 바꾼다. 그런 자원이 없어도 체력이 `EXHAUSTED_CONDITION`(35) 이하면
  **기량과 무관하게** 같은 포지션군에서 가장 신선한 사람으로 바꾼다 — 대체 불가한
  스타가 체력 0까지 가는 것을 막는 갈래다.
- **뺀 선수는 그 경기의 벤치에도 없다.** 벤치는 선발에서 빠진 사람 중 OVR 순
  `MATCHDAY_BENCH`(9)명이지만 **로테이션으로 쉬게 한 선수는 그 목록에서 빠진다.**
  안 그러면 방금 지쳐서 뺀 에이스가 벤치 맨 위에 서고, 투입 후보를 포지션군과
  OVR로만 고르는 벤치 정책(`planBenchSubs`)이 그를 이른 정지점에 그대로 되돌린다 —
  로테이션이 선발
  명단에서만 일어나고 출전 시간에서는 일어나지 않는다. 거르는 자리는 **명단을
  짜는 이곳 한 곳**이다. 투입 시점에서 한 번 더 거르면 같은 규칙이 두 곳에
  흩어져 다음 사람이 어디를 볼지 모른다.
  - **감독의 경기도 이 명단을 그대로 받는다**(§2) — 상대 벤치를 `startMatch`가
    다시 짜면 "한 곳"이 두 곳이 되고, 정지 선수와 2군이 우리와 붙는 경기에서만
    벤치에 선다.
- **자리는 사람과 함께 움직인다.** 전술판의 자리(좌표·역할)는 그대로 두되
  **숙련도·적응도는 들어온 선수의 것으로 다시 선다.** 물려받으면 강도 패킷이
  그라운드에 없는 사람의 숫자로 서서, 약해진 라인업이라는 로테이션의 대가가
  장부에 안 잡히거나 엉뚱하게 잡힌다. 경기 중 교체로 들어온 선수도 같다
  (`slotsAt`) — 자리는 물려받고 그 자리에서의 숙련도·적응도는 자기 것이다.

#### 연장과 승부차기 — 90분과 같은 원본에서 선다

타 팀 경기의 연장 30분은 `resolveExtraTime`(`competition/extra-time.ts`)이 한 번에
굴린다. 그 30분의 입력은 **90분을 굴린 것과 같은 원본**이다: 전술판의 자리·좌표·
역할, 팀 전술, 개인 전술 적응도, 감독의 전술 눈금. 팀 id와 선수 목록만 넘기고
나머지를 기본값(자연 포지션 · `DEFAULT_TACTICS` · 적응도 60 · 감독 65)으로 두면
90분과 연장이 서로 다른 팀의 경기가 되어 **연장에서만 약팀이 살아나거나 죽는다.**

- **연장을 뛰는 사람은 종료 시점에 그라운드에 서 있던 사람이다.** 명단
  (`homeLineup`)은 **뛴 사람 전부**라 교체로 나간 선수와 퇴장당한 선수가 섞여
  있고, 앞 열한 명을 자르면 그들이 연장을 뛴다. 그래서 결과는 종료 시점 온필드를
  따로 남긴다(`homeOnPitch`·`awayOnPitch` — 옛 세이브엔 없어 명단 앞 열한 명으로
  폴백한다). 퇴장이 있었으면 연장도 그만큼 적은 인원으로 뛴다.
- **승부차기를 차는 사람도 같은 열한 명이다** — 소속 선수 전체의 상위 11이 아니다.
  성공률은 킥마다 **그 키커와 그 골키퍼**가 정하고 위아래 양쪽이 잘린다
  (`PENALTY_FLOOR` · `PENALTY_CEILING`) — 식은 §2의 승부차기 절이 쥐고, 대역과 그
  사상은 [../data/competition.md](../data/competition.md) §6이 쥔다.

- **연장의 밀도도 한 곳에서 온다** — 30분에 90분의 `EXTRA_TIME_SHOT_SHARE`(0.28)를
  내려면 분당 0.84배이고, 그 나눗셈은 `sim/match-engine.ts`가 국면표(`PHASE_END`)에서
  한 번만 한다(`EXTRA_TIME_MINUTES` · `EXTRA_TIME_DENSITY`). 간이 시뮬은 그 값을
  그대로 받는다 — 두 식이 같은 0.84를 각자 내면 분모를 고친 날 감독의 연장과
  세계의 연장이 조용히 갈린다.
- **연장에도 카드와 부상이 있다** — 분당 발생률은 90분 그대로다(구간 시뮬과 같은
  규칙: 지친 다리는 덜 뛰지만 덜 거칠지는 않다). BOOKING·SUSPENSION은 같은
  문(`discipline.ts`)을 지나고, **90분의 경고와 이어진다** — 90분에 경고를 받은
  선수의 연장 경고는 경고 한 줄 + 퇴장 한 줄이다. 연장 퇴장자는 남은 연장을 열
  명이 뛰고 **승부차기 명단(`homeOnPitch`)에서도 빠진다**. 부상은 연장을 뛴 전원이
  후보이고 심각도·기간은 90분과 같은 공식(`openInjuryFor`)이 정한다. 연장의 피로도
  퇴장 시점까지만 쌓인다. **교체만 없다** — 간이 연장의 명단은 90분 종료 온필드
  그대로다(§9).

⚠️ 두 모델은 `buildStrengthPacket`의 선수별 슈팅 프로필과 `shot-model.ts`의 xG·
결정력 함수를 공유한다. 어느 쪽만의 골 배율을 두지 않는다.

### 밸런스 기준선

**목표 구간도 실측도 `world-season` 하네스의 서술자가 쥔다** — 같은 숫자를 문서와
단언에 두 번 적지 않는다 (→ [balance-harness](balance-harness.md) ·
`pnpm balance --list`). 리그 평균 슈팅·기회 xG·결정력 반영 기대 득점·득점, 우승
승점, 분포·승점 곡선·카드의 눈금이 모두 거기서 나온다. 시드 간 폭이 목표 폭만큼
크므로 **한 시즌 한 시드는 표본이지 판정이 아니다.**

⚠️ **종합의 눈금이 움직이면 여기가 따라 움직인다.** 존 전력이 `roleFit`의 가중
평균이라(→ [player](../data/player.md) §4) 팀 간 **비율**이 그 눈금을 탄다 — 우열
라벨의 문턱(`edgeOf`)이 그 폭에 맞춰 서 있으므로, 가중치나 축 파생을 만졌으면
그것을 다시 잰다.

**하네스**: `pnpm balance world-season` (시드당 수십 초 — PR 게이트가 아니라 주간
스케줄로 돈다 → [balance-harness](balance-harness.md) §5). 감독 팀은 "지시하지 않는
감독"이라 훈련·이적·전술 없이 로테이션만 한다 — 그 조건의 순위 분산도 그대로
기록하며, 특정 시드의 감독 팀 성적을 목표값으로 맞추지는 않는다. 하네스가 감독 팀을
로테이션시키는 문턱은 `simSquadOf`가 쓰는 상수 그것이다 — 눈금이 갈리면 로테이션을
재는 자리가 재려는 대상과 다른 것을 잰다.

같은 하네스가 리그의 카드를 **굴린 시뮬레이터로 갈라** 함께 찍는다 — 감독의 38경기
(구간 시뮬)와 나머지 342경기(간이 시뮬). 감독 팀의 강도가 리그 평균보다 낮으면 그
갈래도 낮게 서는 것이 정상이다(지금 감독 팀은 0.96, 리그 1.04). **판정은 여기서
하지 않는다** — 38경기에 실리는 카드는 130장이라 잡음이 9%고, 눈금이 갈린 정도
(10\~20%)가 거기 묻힌다. 표본을 키워 판정하는 자리는 `injury-rate`다.

`overall-scale` 하네스는 시즌을 돌리지 않고 세계 하나만 세워, 종합을 읽는
것들의 분포를 한 장에 찍는다 — 자리별 평균 · 축 범위 밖 인원 · 시장가 · 희망 주급 ·
실제 주급 · 잠재력 간격. 가중치나 축 파생을 만졌으면 여기부터 대조한다.

같은 시즌을 나눠 쓰는 `ai-rotation` 하네스가 **AI 스쿼드의 체력 분포와 로테이션
발동 빈도**를 함께 찍는다.
로테이션 문턱 셋(`ROTATION_FATIGUE`·`ROTATION_OVR_DROP`·`ROTATION_FRESHER`)은
동시에 걸려야 하므로 깊이가 얕은 팀에서는 통째로 불발하고 `EXHAUSTED_CONDITION`
갈래만 남는다. 그 값들은 재봐야 움직일 수 있는 값이고, 이 하네스가 재는 자리다.

**리그 전체가 같은 축 위에서 움직인다.** 폼·전술 적응도·부상 성향이 감독 팀에만
쌓이면 나머지 95%가 상태 없는 세계가 되고, AI의 로테이션도 값을 하지 못한다.

① **간이 시뮬도 선수×지역 패킷을 쓴다** — 실제 배치·역할·상태·적응도·전술·상성을
모두 다시 계산하므로 남의 팀이 지치거나 폼이 바닥이면 결과가 달라진다.
② **폼이 리그 전체에서 오르내린다** — 간이 시뮬의 경기 평점이 그대로 폼에 실린다.
③ **AI 팀도 전술을 익힌다** (`FAMILIARITY_DRIFT_CAP` 80). 감독 팀은 결산 판정으로
95·100까지 가므로 그 위에 자리가 남는다.
④ **연패·연승이 라커룸에 남는다** (`squad/slump.ts`) — 3연패부터 팀 폼이 깎이고
4연패면 한 명이 등을 돌린다. 3연승은 그 거울(이득이 손해보다 작다).
⚠️ 움직이는 축은 **폼이지 체력이 아니다** — 체력에 걸면 연패한 팀이 회복까지 못 해
악순환에 빠지고 "일주일이면 온전히 돌아온다"는 회복 불변식도 깨진다.
⑤ **부상 성향이 벤치에서도 움직인다** — 간이 시뮬의 부상 추첨도 성향 하강도 뛴 선수
전원이 대상이라 오름과 내림이 함께 걸린다. 한쪽만 넓히면 상승 경로 없는 선수가
하한까지 단조 감소한다.

그래서 밸런스를 **단일 xG 배율로 누르지 않는다.** 슈팅량·기회 질·결정력은 각각의
레이어에서 따로 보정한다.

⚠️ 남은 편향: **포지션 적응도는 감독의 경기에서만 오른다** — 마감이 양 팀에 적으므로
(§6) 우리와 붙은 클럽은 받지만 간이 시뮬에는 그 경로가 없다. 리그의 95%가 자리
적응도에서 멈춰 있고, 우리를 상대한 팀만 시즌당 그 경기 수만큼 오른다.
⚠️ 남은 편향: 감독 팀의 능력치·전술 적응도는 결산 판정(LLM)에만 걸려 있어 mock
모드에서는 자라지 않는다. 그래서 하네스가 `drillUserTactics`로 "훈련하는 감독"을
대신 모델링한다 — 그것 없이 재면 감독 팀만 기준선에 멎은 세계를 재게 된다.

## 8. 경기 화면

경기 중 탭 셋(`apps/web/components/match-view.tsx` · 데이터 `views/views.ts`):
**판세**(기대 득점 + 경기장 모양으로 펼친 **9칸 격자**와 그 위의 배치 + 키포인트 +
**공략 중**과 **전술 노트** — "어디가 밀리나 · 거기 누가 서 있나 · 왜 · 내 지시가
먹혔나"를 한 화면에) · **팀**(전술판 + 명단, 우리/상대) · **대회**(순위표 + 다음
경기까지 며칠). 전술 6축은 전술판에만 (읽는 김에 고칠 수 있는 곳). 상대 쪽은 조작
없음 + 수치 흐림(체력은 구간, 전력은 ±오차 — 명단 화면과 같은 채널
`observationOf`). 전술 6축과 배치 골격은 흐리지 않는다(90분 동안 보이는 사실).
등번호·나이·시즌 평점도 마찬가지로 공개 사실이라 우리 명단과 **같은 열·같은 표기**로
선다. 킥오프 전·종료 후엔 탭이 없다.

**우열의 색은 코어가 정한다 — 화면은 문턱을 갖지 않는다.** 아홉 칸도 줄 머리(존
매치업)도 `edgeOf`(`sim/strength-packet.ts`)가 매긴 `edge`·`size`를 그대로 받아
칠한다. 화면이 같은 문턱을 다시 적어 두면 한쪽만 손봤을 때 같은 판이 두 색으로
보이고, 그때 감독이 믿는 것은 화면이지 판정이 아니다. 값도 우열도 **우리 편
기준**(`ours`/`theirs`)으로 접혀 오고, 좌우 자리만 홈 기준이다 — 스코어보드·득점과
방향이 어긋나지 않게(§1.7).

**공략 중과 전술 노트가 지시의 증거다.** 공략(§1.6)과 지역 플랜(§1.7)은 경기 중에만
부를 수 있고 장부에 흔적을 남기지 않아 레일 말풍선이 없다(overview §5). 그래서
걸린 공략은 표적 라벨 그대로 판세에 **공략 중**으로 서고, 걸리지 않았거나 버려진
공략·개인 지시의 결과는 **노트**(`tactical.notes`)로 선다 — 노트가 화면에 서지
않으면 감독은 걸리지 않은 공략을 걸린 줄 안다. 상대의 노트는 흐린 문장이라(§1.6)
팀 탭의 상대 전술 옆에 선다.

**경기 중 대회 탭의 "다음 경기"는 팀의 것이다.** 90분 안에 감독이 일정에서 묻는 것은
이 경기가 끝난 뒤 언제 누구인가지, 지금 보고 있는 대회의 다음 라운드가 아니다. 메인
UI의 같은 탭은 반대로 **고른 대회의** 다음 우리 경기를 세운다(overview §5) — 그 화면에
온 이유가 그 대회이기 때문이다. 어느 쪽이든 **지금 치르는 경기는 다음 경기가 아니다**:
결과는 종료 시점에 쓰이므로 결과 없는 첫 경기를 그냥 고르면 "오늘 · 지금 상대"가 선다.
남은 경기가 없는 대회(탈락·일정 종료·추첨 전)에는 카드가 서지 않는다 — 머리줄이 이미
그 자리를 말한다.

**경기 중 체력은 두 탭이 한 값이다.** 판세 탭과 팀 탭 모두 감독이 **읽은
값**(`readCondition` · §9.2)을 같은 경기 채널로 받아 구간 막대로 그린다. 팀 탭만
참값을 쓰면 감독이 두 탭을 견주는 것만으로 안개가 걷힌다. 그 경기의 출전 명단(선발·
벤치) 밖에 있는 선수는 아침에 잰 값 그대로라 구간 폭이 0이다.

경기의 앞뒤는 화면을 덮는 카드 한 쌍이 지킨다 — 입장 확인(대회·라운드·대진·
홈/원정과 **경기장 입장** 버튼)과 종료 화면(스코어·득점·평점 상위). 입장 확인은
닫는 손잡이가 없다: 되돌아간 자리에서 다시 열 방법이 없기 때문이다.

판세의 선수 마커는 패킷이 계산한 실제 전술판 좌표를 쓰며, 마우스나 키보드 포커스로
등번호·이름·자리·전력을 확인한다. 최전방 마커는 상대 골키퍼와 겹치지 않고 수비선
앞뒤에 놓인다.

**교체 표기의 한도는 뷰가 싣는다.** 우리·상대 머리글의 `교체 n/m · 기회 n/m`에서
m은 장부의 `subLimitsOf(ledger.phase)`를 뷰가 `subs.limit`으로 실어 온 값이다(연장
6인/4회 — §5). 화면이 5/3을 다시 적어 두면 연장에서 다섯 장을 다 쓴 감독에게 5/5가
서서 여섯 번째 카드가 없는 것처럼 읽힌다. 우리 머리글의 표기는 경기 중에만 선다 —
평시 스쿼드에 교체 카운터는 뜻이 없다.

경기 중 전술판에서 교체를 고르면 작업 사본에는 즉시 교체 결과가 보이고, 지시는
다음 경기 진행 턴에 함께 전달된다. 이 표시는 확정 장부가 아니며, 진행 턴의 교체
검증이 끝난 뒤 서버 상태로 다시 맞춘다.

승부차기로 넘어가면 경기 머리의 스코어 옆에 승부차기 합계가 서고, 킥 하나하나가
찬 순서대로 남는다 — 누가 찼고 들어갔는지 막혔는지가 보여야 감독이 다음 키커를
정할 수 있다 (§2의 마지막 절).

경기가 진행되는 동안 채팅에는 현재 `matchId`의 중계와 감독 지시만 보인다. 평시
채팅은 경기 컨텍스트에 들어가지 않으며 화면에서도 숨긴다. 경기가 끝나면 평시
채팅으로 돌아가고, 경기 기록은 결과 한 줄 아래에 접힌다. 경기 판과 중계 채팅은
화면 폭과 관계없이 평시 메인 화면과 같은 좌우 분할을 유지한다.

## 9. 미해결

- **홈 이점이 계수 한 줄이다** — 슈팅 노출(1.06·0.96, §1.4)뿐이라 두 값의 비가 실제
  1부(1.22\~1.28)보다 낮고, 리그 실측의 홈:원정 득점이 그만큼 평평하다. 관중·응원·
  라커룸의 사기가 게임 시스템으로 서면 그 자리에서 홈 이점이 나오고 이 계수는 물러난다 —
  코어에 별도의 홈 수식을 더 세우지 않는 이유다.
- **간이 시뮬의 연장에는 교체가 없다** — 카드·부상·퇴장은 90분과 한 벌이 되었지만
  (§7) 명단은 90분 종료 온필드 그대로 30분을 뛴다. 구간 시뮬의 연장은 교체 한 장이
  더 열린다(`subLimitsOf`) — 벤치 명단과 피로·출전 정산까지 얹어야 하는 일이라
  여기서 함께 고치지 않았다.
- **분포 하네스는 PR 게이트가 아니다** — 시드당 몇 분이라 주 1회 스케줄로 돌고,
  손으로는 `pnpm balance`다. 밴드를 벗어나면 그 워크플로가 이슈를 연다
  ([balance-harness](balance-harness.md) §5). 이 문서의 밴드가 어느 하네스의 어느
  지표인지도 그 문서가 목록으로 쥐고 있다.
