# 구단 재정 (Club Finance)

> 실제 구단의 매출·비용 구조를 옮긴 재정 모델 — 실시간 원장 + 월간 보고서.

---

## 1. 문제 — 현재 재정이 얇은 이유

v6 프로토타입의 재정은 원장 한 종류(`{date, kind, label, amount}`)에 다음이
전부다.

| 지금                                               | 위치            |
| -------------------------------------------------- | --------------- |
| 중계권·스폰서십·구단 운영비 (tier별 월 정액 3항목) | `tick.ts`       |
| 선수단 주급 (활성 계약 합, 매주 월요일)            | `tick.ts`       |
| 홈 입장 수입 (tier별 경기당 정액)                  | `match-flow.ts` |
| 대항전 상금                                        | `euro-prize.ts` |

여기서 오는 결함:

1. **성적과 재정이 무관하다** — 우승해도 강등권이어도 수입이 같다. 실제 구단
   수입의 최대 변동 요인(순위별 중계 수당·관중·스폰서 조항)이 전부 없다.
2. **리그 구분이 없다** — 라리가·리그1 팀이 EPL 중계권 배분을 받는다.
3. **집계 키가 문자열**이다 — 월별 집계를 `label`로 접으므로 항목명이 바뀌면
   과거 월이 조용히 쪼개진다.
4. **과거가 사라진다** — 원장 600건 상한에서 앞을 잘라내므로 세이브가 길어지면
   지난 시즌 재정이 없어진다.
5. **상수가 흩어져 있다** — 티어 상수가 세 파일에 하드코딩돼 밸런싱이 어렵다.
6. **96팀 전부에 상세 원장을 쌓는다** — AI 팀 재정은 이적 예산·매각 압박에만
   쓰이는데 엔트리 비용은 팀 수에 비례한다.

## 2. 실제 구단 구조 (설계 기준)

EPL 클럽 회계(2023–25 어림)를 참고한다. 게임에 옮길 가치가 있는 것은 **금액**이
아니라 **무엇이 금액을 움직이는가**다.

### 매출 3대 축

| 축           | 실제 비중 | 움직이는 요인                                                                       |
| ------------ | --------- | ----------------------------------------------------------------------------------- |
| **중계권**   | 40~50%    | ① 균등 배분 ② **순위별 성적 수당**(1위와 20위 차 £45M+) ③ **생중계 편성 횟수 수당** |
| **상업**     | 30~45%    | 브랜드 규모(≠ 성적) + 셔츠·키트 계약의 **UCL 진출·우승 보너스 조항**                |
| **매치데이** | 10~20%    | 수용인원 × 점유율 × 티켓 단가 + 호스피탈리티                                        |

참고 수치: 2023-24 EPL 배분은 우승팀 약 £176M, 최하위 약 £110M. 매치데이는
아스날 약 £130M부터 중소 클럽 £15~30M까지 벌어진다.

### 비용 4대 축

| 축              | 실제 비중                     | 비고                                                      |
| --------------- | ----------------------------- | --------------------------------------------------------- |
| **급여**        | 매출의 60~75% (EPL 평균 ~70%) | 선수 급여 + 비선수(코칭·사무) 급여 12~18% + **승리 수당** |
| **이적료 상각** | 큰 클럽 £100~200M/년          | 이적료 ÷ 계약기간을 매년 비용화. PSR 판정의 핵심          |
| **운영비**      | 15~25%                        | 경기 운영, 시설·아카데미, 원정·의료                       |
| **부대비용**    | —                             | 에이전트 수수료(이적료 ~10%), 이자·세금                   |

### 규정

**PSR**(수익성·지속성 규정) — 3시즌 누적 손실 £105M 한도. 실제로 위반 시 승점
삭감 사례가 있다. 게임에선 "보드가 이적 예산을 왜 그만큼 주는가"의 근거가 된다.

## 3. 설계의 축

| #   | 질문        | 결정                                                                                    |
| --- | ----------- | --------------------------------------------------------------------------------------- |
| A   | 이적료 회계 | **현금 + 상각 2축** — 현금은 즉시, 손익은 계약기간 월 상각. 보고서가 두 줄을 보여준다   |
| B   | 밸런스 기준 | **현실 정합** — 매출 대비 인건비·상각·순익의 **비율**을 실제 구단에 맞춘다 (§10)        |
| C   | 관중 데이터 | **96팀 구장 수용인원 실측 근사**를 카탈로그에 넣는다 (라이선스 부채는 data-sourcing §7) |
| D   | PSR 제재    | **보드 경고 + 이적 예산 동결**까지. 승점 삭감은 넣지 않는다                             |

## 4. 데이터 모델

### 4.1 원장 엔트리 — 실시간 재정 이벤트의 원본

```ts
LedgerEntry = {
  // "led-<날짜>-<category>-<그날 순번>" — 결정적. 원장은 유저 팀만 쌓으므로 teamId가 없다
  id: string,
  date: DateString,
  time?: string,                  // 같은 날 순서 안정 (경기 후 항목)
  kind: "income" | "expense",
  category: FinanceCategory,      // 집계 축 — 안정 키 (§4.2)
  label: string,                  // 사람이 읽는 상세 (서사 재료)
  amount: number,                 // 항상 양수. 방향은 kind가 정한다
  ref?: { type: "match" | "player" | "transfer" | "competition", id: string },
  accounting: "cash" | "noncash", // 상각만 noncash — 현금흐름/손익을 가른다
}
```

- **집계는 언제나 `category`로.** `label`은 표시·서사 전용이며 집계 키가 아니다.
- `ref`는 드릴다운("이 £4.2M은 어느 경기인가")과 서사 연결용.
- **멱등 키는 label이 아니다.** `euro-prize.ts`의 "같은 상금 두 번 금지" 검사는
  `category + ref + 무엇 + season`으로 만든 안정 키를 쓴다 — 항목명을 고쳐도
  같은 상금이 다시 나가지 않는다. `무엇`은 리그 페이즈 · 단계(`MatchStage`) ·
  우승을 가르는 축이라, 한 대회 한 시즌 안에서 키가 겹치지 않는다.

### 4.1.1 서사 재정 이벤트 — 허용 카테고리와 한도

GM 스킬 `apply_finance_event`가 서사에서 벌어진 매출·비용을 원장에 넣는다. 원장에
들어가는 순간 월간 보고서·급여 비중·PSR로 그대로 전파되므로, **무엇을 얼마까지**
움직일 수 있는지가 규정으로 닫혀 있다.

**허용 카테고리** — 세상의 반응으로 흔들리는 축만 연다.

```
수입: commercial · merchandising · matchday
지출: facility · travel_medical · bonus · matchday_opex
```

중계권·주급·이적료·상각·상금은 계약과 규정에서 계산되므로 닫혀 있다 — 서사가
손대면 장부가 두 개의 진실을 갖는다.

**한도는 세 겹이다.** 셋 다 코드가 막고, 거부 메시지에 **허용 상한을 실어** 보낸다
— 모델이 금액의 눈금을 배우는 곳은 프롬프트의 설명이 아니라 거절당한 값이다.

1. **최소 £10k** — 식사·회식·택시처럼 그보다 작은 일상 비용은 게임 재정에서
   무시한다(기록하지도, 금액을 올려 잡지도 않는다).
2. **카테고리별 건당 상한** — 그 축이 이 구단에서 실제로 움직이는 폭. 새 금액을
   만들지 않고 **같은 축의 기존 상수에서 파생**한다.
3. **하루 누적 상한 = 주급 총액 × 2** (`NARRATIVE_FINANCE_WAGE_LIMIT`) — 같은
   장면을 여러 번 나눠 불러 하루를 통째로 흔드는 것을 막는다. 건당 상한과 역할이
   다르므로 둘 다 있다.

| 카테고리           | 건당 상한            | 파생                   | 아스날 / 레체   |
| ------------------ | -------------------- | ---------------------- | --------------- |
| `bonus`            | 주급 총액 × 0.25     | 승리 수당(0.1)의 2.5배 | £914k / £138k   |
| `travel_medical`   | 최중상 치료비 × 2    | £400k — 구단 규모 무관 | £800k / £800k   |
| `facility`         | 월 시설비 × 0.5      | tier별 월 정액         | £1.75M / £0.80M |
| `matchday`·`_opex` | 전형적 홈 수입 × 0.3 | 매치데이 공식의 기본값 | £0.93M / £0.10M |
| `commercial`       | 월 정액 × 0.5        | 브랜드 규모별 스폰서십 | £4.53M / £0.32M |
| `merchandising`    | 월 정액 × 0.5        | 브랜드 규모별 굿즈     | £1.52M / £105k  |

- 표에 없는 카테고리는 **포상 한도로 떨어진다** — 두 체급 모두에서 가장 좁은 자라
  새 카테고리가 한도 없이 통과하는 일이 없다.
- 원정·의료만 구단 규모를 타지 않는다 — 코어의 치료비·원정비도 정액이다(§6).
- 도구 스키마의 바깥 울타리는 **£10M** — 어떤 카테고리도 그 위를 시도할 수 없다.

**이적 예산 조정**(`adjust_transfer_budget`)은 원장이 아니라 자본이므로 자가 다르다
— 하루 누적 **주급 총액 × 10**(`BUDGET_ADJUST_WAGE_LIMIT`). 예산은 매출보다 큰
단위로 움직이지만, 이 도구로 **이적료를 흉내 내는 길**은 막혀 있어야 한다(매각
대금은 `accept_deal`이 원장을 거쳐 넣는다).

### 4.2 카테고리

```
수입: broadcast_equal      중계권 균등 배분
      broadcast_merit      중계권 성적 수당 (전 시즌 순위)
      broadcast_facility   생중계 편성 수당 (경기별)
      matchday             입장·호스피탈리티 수입 (경기별)
      commercial           스폰서십 (셔츠·키트·파트너)
      merchandising        머천다이징
      prize                대회 상금 (리그 순위 + 대항전)
      transfer_in          이적료 수입

지출: player_wages         선수 주급
      staff_wages          코칭·사무 스태프 급여
      bonus                성적 보너스 (승리 수당·우승 보너스)
      matchday_opex        경기 운영비
      facility             시설·아카데미 운영
      travel_medical       원정·의료
      agent_fee            에이전트 수수료
      transfer_out         이적료 지출
      amortisation         이적료 분할 비용 (noncash)
```

`transfer_out`과 `amortisation`은 같은 영입의 두 얼굴이라 **이름만으로 갈려야 한다** —
`이적료 지출`은 한 번에 나간 현금이고, `이적료 분할 비용`은 그 값을 계약 기간에 나눠
매달 장부에 적는 몫이다. `상각`은 회계 용어라 감독이 화면에서 읽을 말이 아니다.

원장 라벨은 `<항목명> — <대상>`으로 쓰고 **항목명에 카테고리 이름을 넣지 않는다** —
피드가 카테고리를 따로 찍으므로 같은 말이 한 행에 두 번 선다. 항목이 카테고리와
같으면(선수별 상각·선수별 주급) 라벨은 대상만 남긴다.

**정기 비용은 대상별로 적는다** — `player_wages`는 매주, `amortisation`은 매월 1일에
선수 한 명당 한 줄이다. 합계만 적으면 "누구에게 얼마"가 원장에서 사라지고, 감독이
드릴다운할 곳이 없다. 화면이 길어지는 문제는 피드가 접어서 푼다(§8.1).
**AI 팀은 예외로 합계 한 줄**이다 — AI 팀은 애초에 원장을 남기지 않으므로(§4.5)
명세를 만들면 잔고를 스물몇 번 나눠 더하는 값만 치른다.

카테고리를 도입하기 전 세이브의 엔트리는 `other`로 읽는다. **`other`는 수입·지출
양쪽에 각각 선다** — 방향은 `kind`가 정하므로 한쪽으로 몰면 반대편 엔트리가 그 합에서
빠지거나 상계돼 §4.4의 불변식(보고서 합 = 원장 합)이 조용히 깨진다.

### 4.3 월간 재정 보고서 (신규 테이블)

```ts
FinanceReport = {
  id: string, teamId: string,
  month: "2026-08", season: number,
  openingBalance: number, closingBalance: number,
  income:  Array<{ category, amount, top: Array<{label, amount}> }>,  // top 3
  expense: Array<{ category, amount, top: Array<{label, amount}> }>,
  incomeTotal: number, expenseTotal: number,
  cashNet: number,      // accounting:"cash"만 — 통장의 변화
  pnlNet: number,       // 이적료 지출 제외 + 상각 포함 — 장부의 변화
  wageRatio: number,    // (player_wages + staff_wages) / 매출
  seasonToDate: { income, expense, cashNet, pnlNet },
  psr: { rolling3Season: number, headroom: number } | null,
  notes: string[],      // 코어가 결정적으로 붙이는 **사실 줄** — 조언은 없다 (§7.1)
  highlights: Array<{   // 그달의 큰 비정기 항목 — 날짜와 금액을 남긴다 (§8.2)
    date, kind, category, label, amount
  }>,
}
```

`state.financeReports` — **유저 팀만** 생성한다.

### 4.4 보존 정책

| 데이터      | 보존                                         |
| ----------- | -------------------------------------------- |
| 상세 원장   | **최근 3개월 롤링** — 실시간 피드·드릴다운용 |
| 월간 보고서 | **영구** — 집계·추이·PSR용                   |

보고서가 `openingBalance`를 갖기 때문에 원장을 잘라도 잔고 재구성이 가능하다.
불변식(테스트로 고정): `가장 오래된 보고서의 openingBalance + 이후 모든 흐름 = balance`.

카테고리 합계만 남기면 **"그 £37.5M이 언제 들어왔나"**에 답할 수 없다 — 두 건이
합쳐진 한 숫자만 남는다. 그래서 마감할 때 **그달의 큰 비정기 항목만 날짜째로
`highlights`에 옮겨 적는다**(§8.2). 절단 전에 옮기므로 원장이 잘려도 남고, 문턱을
넘는 일회성 항목만이라 달마다 한두 줄이다.

### 4.5 AI 팀은 잔고만

AI 팀은 **엔트리를 남기지 않고 잔고만 갱신**한다. `market.ts`의 매각 압박
(`balance < 주급×20`)과 이적 예산은 잔고만 보므로 충분하고, 168팀 × 월 10여 건의
엔트리는 세이브만 부풀린다. `recordFinance`가 이 분기의 유일한 지점이다.

그래서 상금 중복 지급은 원장 조회가 아니라 **`FINANCE.prizesPaid` 키가 막는다.**
원장은 3개월만 남고 AI 팀은 아예 없으므로 "원장이 곧 사실"이 성립하지 않는다.

AI 팀도 간이 시뮬 경기마다 홈 수입·생중계 수당·원정 비용을 받는다
(`applyAiMatchFinance` — 순위표·폼을 쓰지 않는 가벼운 공식). 이게 없으면 AI 팀은
매치데이 수입 없이 주급만 내는 구조적 적자에 빠진다.

### 4.6 카탈로그 추가

```ts
// packages/engine/src/data/club-profile.ts — 96팀 (신규 파일)
ClubProfile = {
  stadium: string,
  capacity: number, // 실측 근사 (결정 C)
  commercialTier: 1 | 2 | 3 | 4, // 브랜드 규모 — 전력 tier와 별개
};
LeagueCatalogEntry += {
  broadcastPool: number, // EPL 1.00 기준 배율
  avgTicketPrice: number, // 리그 평균 티켓 단가
};
```

구장·브랜드는 `TeamCatalogEntry`에 얹지 않고 **별도 파일**에 둔다 — 정체성
(이름·리그·전력 등급)과 살림(구장·브랜드)은 바뀌는 이유가 다르고, 재정 밸런싱은
표 하나만 만지는 편이 낫다. 등재되지 않은 팀은 tier 폴백을 쓴다.

`commercialTier`를 `tier`와 분리하는 이유: 뉴캐슬·에버튼·발렌시아는 성적보다
브랜드가 크고, 본머스·브렌트포드는 반대다. 실제 상업 수입 격차의 원인이다.

리그 중계권 풀 배율(초기값): EPL 1.00 · 라리가 0.45 · 분데스리가 0.35 ·
세리에 A 0.32 · 리그 1 0.16.

## 5. 수입 공식

모두 **결정적**이다 — 난수는 시드 해시만 쓴다 (같은 세이브·같은 날 = 같은 금액).

### 5.1 중계권

| 항목        | 시점      | 공식 (EPL 기준값)                                                            |
| ----------- | --------- | ---------------------------------------------------------------------------- |
| 균등 배분   | 매월 1일  | 시즌 £110M ÷ **12개월** = 월 £9.2M                                           |
| 성적 수당   | 매월 1일  | `£2.4M × (리그팀수+1 − 전 시즌 순위)` ÷ 12개월 → 1위 월 £4.0M, 20위 월 £0.2M |
| 생중계 수당 | 경기 직후 | 국내 리그 TV 슬롯 경기당 £1.1M                                               |

- **12개월 분납**이다. 실제 배분은 시즌 중 분기 지급이지만, 경기 없는 달(6·7월)에
  방송 수입을 0으로 두면 그 달의 급여 비중이 300%로 튀어 지표가 무의미해진다 —
  실제 구단도 현금은 연중 들어온다. 총액을 유지하고 고르게 나눈다.

- **세 항목 모두 리그별 `broadcastPool` 배율을 곱한다** — 균등 배분도 포함이다
  (`EQUAL_SHARE_LEAGUE_SCALED`). 실제로 각국 중계권 규모는 리그마다 크게 다르다
  (리그1은 EPL의 0.16). 균등분만 배율을 끄면 약체 리그 구단이 EPL 수준 주급을 내면서
  6분의 1 수입을 받아 파산한다 — 수입과 지출이 같은 축을 타야 성립하고, **주급 곡선도
  리그를 안다**(`wages.ts` · §6.2).
- **TV 슬롯 판정은 캘린더에서 파생한다** — 주말 라운드를 금·토·일·월 실제 중계
  슬롯으로 흩는 편성이 이미 있으므로(AGENTS 현재 상태), **토요일 15:00만 비중계**로
  본다(실제 블랙아웃 규약). 시즌 38경기 중 약 32경기가 편성된다.
- **대항전은 생중계 수당 없음** — 유럽 방송 수입은 이미 UEFA 배분(참가비·승무
  수당)에 들어 있어 이중 계상이 된다.
- **첫 시즌은 전 시즌 순위가 없다** → 구단 `tier`로 대체한다
  (`euroEntrants`의 첫 시즌 처리와 같은 패턴). AI 팀은 지난 시즌 순위표를 저장하지
  않으므로(시즌 전환에서 파생 후 버린다) 항상 tier 어림을 쓴다 — AI 재정은 잔고만
  읽히므로 충분하다.
- 합계 어림 (12개월 만근 · 세 항목의 합 × `broadcastPool`):

  | 리그       | pool | 팀 수 | 우승팀 | 최하위 |
  | ---------- | ---- | ----- | ------ | ------ |
  | EPL        | 1.00 | 20    | £193M  | £148M  |
  | 라리가     | 0.45 | 20    | £87M   | £66M   |
  | 분데스리가 | 0.35 | 18    | £65M   | £51M   |
  | 세리에 A   | 0.32 | 20    | £62M   | £47M   |
  | 리그 1     | 0.16 | 18    | £30M   | £23M   |

  EPL 값은 실제 배분(£176M / £110M)과 근접하다. 아래 리그는 **수입만 배율을 타고
  지출·초기치는 타지 않아** 지금 구조적으로 가라앉는다 — 배율 자체가 아니라 그
  비대칭이 문제이며, §6.2의 리그 배율이 양쪽을 함께 잡는다.

**리그전을 굴리지 않는 리그**(컵 전용 2부)는 홈 경기가 없어 매치데이 수입이 없다 —
주급·스태프·시설·이자는 매달 내면서. 그 몫을 같은 공식으로 월할해 채운다
(`unplayedLeagueMatchdayMonthly`). 새 상수를 만들지 않고 수용인원 × 기본 점유율 ×
티켓가 × 호스피탈리티에서 파생한다 — 임의 금액을 넣으면 밸런스의 근거가 사라진다.

**무소속(`freeagents`)은 구단이 아니다** — `isClubTeam`으로 걸러 재정을 굴리지
않는다 — 굴리면 선수 명부 하나가 매달 시설비와 이자를 내며 적자를 쌓는다.

### 5.1.1 리그 순위 상금 — 시즌 리뷰에서

`(리그 팀수 + 1 − 순위) × £700k × broadcastPool`. 1부 다섯 리그 합계 연 £321M
(EPL £147M · 라리가 £66M · 세리에 A £47M · 분데스리가 £42M · 리그 1 £19M).

- **리그는 언제나 세이브 기준**(`leagueOfTeamIn`)이다. 승강은 `state.leagueOf`로만
  표현되므로 카탈로그 리그로 순위표를 부르면 강등팀도 승격팀도 자기가 없는 표를 받아
  순위가 0이 되고 **상금이 통째로 사라진다.**
- **리그전을 하지 않는 2부는 받지 않는다.** 0경기 0승점 순위표는 정렬이 안정적이라
  카탈로그 등재 순서가 그대로 순위가 되고, 매 시즌 같은 팀이 같은 돈(다섯 리그 합
  연 £17.0M)을 받아 2부의 재정 서열이 영구히 굳는다. 그 리그의 수입은 매치데이
  대체분이 메운다.

### 5.2 매치데이 (홈경기 직후)

```
attendance = round(capacity × occupancy)
occupancy  = clamp(base + Σ보정, 0.45, 1.00)
수입       = attendance × 단가 × (1 + 호스피탈리티율)
```

| 요인          | 값                                                |
| ------------- | ------------------------------------------------- |
| base          | tier1 0.97 · tier2 0.90 · tier3 0.85 · tier4 0.80 |
| 순위          | `(11 − 현재순위) / 10 × 0.04`                     |
| 최근 5경기 폼 | `(승률 − 0.40) × 0.05` → −0.02 ~ +0.03            |
| 상대 매력도   | 상대 tier1 +0.04 · tier2 +0.02 · tier4 −0.02      |
| 대회          | 컵 경기(국내 컵·대항전) +0.02                     |
| 킥오프 슬롯   | 월~목요일 −0.03                                   |
| 시드 해시     | ±0.02 (결정적 미세 변동)                          |

단가 = `리그 avgTicketPrice × tier 보정(1.3 / 1.1 / 0.95 / 0.8)`, 유럽전 ×1.15.
호스피탈리티율 = tier1 0.35 · 2 0.28 · 3 0.20 · 4 0.15.

**리그 평균 단가는 EPL 대비 비율로 잡는다** — 실제로도 다섯 리그의 티켓 가격 차는
중계권 차보다 크다(EPL만 유독 비싸고 분데스리가는 입석·시즌권 보조로 가장 싸다).

| 리그       | 단가 | EPL 대비 | 실효 객단가 (tier1 / tier4) |
| ---------- | ---- | -------- | --------------------------- |
| EPL        | £30  | 1.00     | £52.7 / £27.6               |
| 라리가     | £17  | 0.57     | £29.8 / £15.6               |
| 세리에 A   | £15  | 0.50     | £26.3 / £13.8               |
| 분데스리가 | £13  | 0.43     | £22.8 / £12.0               |
| 리그 1     | £12  | 0.40     | £21.1 / £11.0               |

**절대값은 실제의 0.67배다** — 매출의 다른 축과 같은 눈금이다(§10.1). 축마다 배율이
다르면 **구단을 가르는 축이 브랜드가 아니라 구장 크기**가 된다. 세 축이 같은 배율에
서야 아스날의 수입 구성이 실제와 겹친다(§10.2).

**중립 경기(결승)는 홈 수입이 없고 양 팀 다 원정 비용을 낸다.** 게이트는 개최지의
몫이라 우리 장부에 오르지 않고, 두 팀 모두 남의 구장으로 이동한다. 편성표의 홈·원정
표기는 중립 경기에선 자리 이름일 뿐이라, 그것으로 원정비를 가르면 같은 결승에서 한
팀만 £120k(유럽 £400k)를 낸다.

**프리시즌 친선은 리그의 60%다** — 관중과 단가 **양쪽**에 0.6을 곱하므로 게이트
수입은 리그 홈경기의 약 36%다(실제 프리시즌도 관중이 덜 들고 표가 싸다). 관중
보정은 리그와 같은 공식을 쓰되 순위 보정이 사실상 0이고(프리시즌엔 순위표가
비어 있다) 대회 보정도 없다. **최근 5경기 폼 보정도 대회 경기만 센다** — 친선의
승패가 표를 팔면 프리시즌 성적이 살림에 남는다(season.md §2). 배율은 하한(0.45)을
적용한 **뒤에** 곱한다 — 친선을 만석 판정에 넣지 않기 위해서다. 운영비(opex)와
원정 비용은 리그와 같은 비율로 그대로 나가므로 프리시즌 홈경기는 작은 흑자, 원정은
순지출이다.

**중계권 수당은 없다**(`isTelevised`가 거짓) — 대회 상금도 승리 수당도 없다.
친선은 장부에 홈 매치데이로만 남는다.

**친선 원정에는 비용을 매기지 않는다** — 주최 측이 부담하는 자리다. 실제 프리시즌은
초청이라 판을 벌인 쪽이 게이트를 갖고 방문 클럽에는 출전료가 간다. 우리 모델엔
출전료가 없으므로 방문 쪽에만 정규 원정비(경기당 £120k)를 물리면 **한쪽만 있는
장부**가 된다. 그 차액이 특히 아픈 곳이 **리그전을 굴리지 않는 2부**다(§5.1) —
메울 리그 수입이 없어 프리시즌마다 구조적으로 깎이고, 실측에서 그 리그의 중간
잔고가 흑자에서 적자로 뒤집힌다. 새 상수를 만들어 깎는 대신 매기지 않는다.

**상대 구단의 몫도 같은 자리에서 넣는다.** 간이 시뮬은 두 팀을 다 챙기는데
(`applyAiMatchFinance`) 유저 경기는 유저 쪽만 기록해, 유저가 원정 가는 시즌 열아홉
경기의 **홈 팀이 입장 수입을 받지 못한다**(대신 운영비·원정비도 내지 않는다).
`applyMatchFinance`가 그 함수를 함께 부르고, 그 함수는 유저 팀을 건너뛰므로 겹치지
않는다.

### 5.3 상업·머천다이징 (매월 1일)

```
commercial   = base(commercialTier) × (1 + 조항)
조항         = UCL 진출 +0.15 · UEL 진출 +0.06 · UECL 진출 +0.03 · 지난 시즌 트로피 +0.20
merchandising = base(commercialTier) × (1 + 최근 승률 보정 ±0.10 — 6경기, 친선 제외)
```

| 브랜드 | 연 상업+굿즈 | 실제 어림 | 누가                      |
| ------ | ------------ | --------- | ------------------------- |
| 1      | £145M        | £220M     | 맨유·레알·바이에른·아스날 |
| 2      | £55M         | £82M      | 뉴캐슬·에버턴·발렌시아    |
| 3      | £24M         | £36M      | 중소 1부                  |
| 4      | £10M         | £15M      | 승격팀·2부                |

**등급 폭이 15배다** — 실제 격차(맨유 £300M 대 승격팀 £20M)가 그만큼이다. 값은
**실측 × 0.67** — 중계권이 이미 그 눈금에 있고(§5.1) 매치데이도 같은 배율에 선다(§5.2).

상업:굿즈는 대략 3:1로 가른다 (실제 회계의 스폰서십 대 리테일 비).

조항은 **지난 시즌 성적에서 파생**한다 — 저장하지 않는다. 실제 스폰서 계약의
성과 보너스 조항을 옮긴 것이고, "유럽 진출이 다음 시즌 살림을 바꾼다"는 루프가
여기서 생긴다. 진출 조항은 대회마다 쌓이고, **트로피는 종류를 가르지 않는다** —
리그·국내 컵·대항전 어느 것이든 지난 시즌 우승이 하나라도 있으면 +0.20이고 두 개여도
같은 값이다. 트로피 기록은 유저 팀만 쌓으므로(`state.trophies` — 시즌 리뷰)
AI 구단의 조항은 진출분뿐이다.

## 6. 지출 공식

| 항목             | 시점             | 공식                                                                               |
| ---------------- | ---------------- | ---------------------------------------------------------------------------------- |
| 선수 주급        | 매주 월요일      | 활성 계약 합 (현재 동작 유지)                                                      |
| 스태프 급여      | 매월 1일         | 월 주급 총액 × tier별 22 / 24 / 26 / 28%                                           |
| 승리 수당        | 경기 직후        | 주급 총액 × 10% (승리 시에만)                                                      |
| 우승·진출 보너스 | 시즌 리뷰        | 주급 총액 × 배수 — 리그 1위 ×4 · 2–4위 ×2 · 5–6위 ×1 · 그 아래 없음                |
| 경기 운영비      | 홈경기 직후      | 매치데이 수입 × 12%                                                                |
| 시설·아카데미    | 매월 1일         | tier별 £3.5M / 2.8 / 2.2 / 1.6M **× 경제 수준**(§6.2)                              |
| 원정·의료        | 원정경기·부상 시 | 국내 원정 £120k · 유럽 원정 £400k · 부상 minor £30k / moderate £120k / major £400k |
| 에이전트 수수료  | 영입 확정 시     | 이적료 × 10% — **AI 구단의 영입도 같다**                                           |
| 이자·세금        | 매월 1일         | tier별 £1.5M / 1.1 / 0.7 / 0.4M **× 경제 수준**(§6.2)                              |
| 이적료           | 협상 타결 시     | 현금 즉시 (`transfer_out`, cash)                                                   |
| **상각**         | 매월 1일         | `이적료 ÷ 계약 개월수` (`amortisation`, **noncash**)                               |

현재의 "구단 운영비" 단일 항목은 시설·원정의료·이자세금으로 쪼갠 것이다.

**에이전트 수수료는 사는 쪽이 누구든 붙는다.** 이적료는 168개 구단 사이를 오갈 뿐이라
세계의 총액을 바꾸지 않지만 수수료는 밖으로 나간다 — 유저에게만 물리면 AI 구단은 같은
영입을 10% 싸게 하고, 규모가 있는 배수구가 인건비 하나뿐인 세계에서(§6.3) 그 차이는
시즌마다 쌓인다.

**우승·진출 보너스의 순위 문턱은 고정된 계단이다** — 리그 팀 수에서 파생하지 않고,
대항전 티켓 수(`cup-catalog`의 `slots` — EPL은 UCL 5 · UEL 4 · UECL 2)와도 별개다.
선수단에 무엇을 약속했는가의 자이지 진출 자체의 판정이 아니다. 유저 팀에만 붙는다.

### 6.1 상각 (결정 A)

```
£60M · 4년 계약 영입
  현금흐름  2026-08  −£60.0M   (즉시, transfer_out)
  손익      매월      −£1.25M × 48개월 (amortisation)
```

**취득원가와 원래 상각 기간이 자산의 정체**다. 둘은 계약 이력에서 파생하고
(`acquisitionOf`) 재계약이 그것을 바꾸지 않는다 — 재계약은 새 계약 행을 쌓고 이전 행을
`"ended"`로 남기므로 **첫 계약이 세이브에 그대로 있다.** 새 테이블도 새 필드도 없다.

- **불변식: 한 취득에서 털어 내는 상각의 총합은 취득원가를 넘지 않는다.** 아래 세 가지가
  전부 이 하나를 지키기 위한 규칙이다.
- **취득원가**는 두 갈래로 정해진다.
  - 게임 중 영입 — `TRANSFER.fee`
  - **시작 스쿼드** — `주급 × (52/12) × 0.7 × 원래 계약 개월수`. 시작 스쿼드는 이적
    기록이 없어 그대로 두면 상각이 £0이 되고 현금과 손익이 같아진다 — 결정 A도
    PSR(§9.2)도 죽은 코드가 된다. 자가 시장가가 아니라 주급인 이유: 취득원가는 움직여선
    안 되는데 시장가는 폼·나이로 매달 흔들린다. 계수 0.7은 실제 구단의 상각 비중
    (비용의 3할 안팎)과 §10.1 밴드를 동시에 만족한다.
  - 무상 이적·유스는 장부가 없다 — 낸 돈이 없다.
  - **"시작 스쿼드인가"는 고정된 게임 시작일(시즌 1의 7월 1일)로 가른다.** 남아 있는
    계약의 최소 `since`로 읽으면 원계약이 만료될수록 그 날짜가 **뒤로 표류해**, 그해
    유스 콜업이 시작 스쿼드로 판정돼 레거시 상각을 받는다. 시즌 번호만으로 정해지는
    값이므로 세이브에 새 필드를 두지 않는다.
- **그 뒤는 한 길이다.** 원래 계약 동안은 `취득원가 ÷ 원래 개월수`를 매달 털고,
  **재계약하면 그 시점의 잔존가를 새 기간에 다시 편다** — 총액은 그대로이고 연 상각은
  낮아진다 — 실제 회계도 재계약으로 잔존가를 지우지 않는다.
  - ⚠️ 남은 원래 기간보다 **짧게** 재계약하면 월 상각이 오른다 — 같은 잔존가를 더 적은
    개월에 펴니 그렇고, 총액은 그대로다.
  - ⚠️ **잔존가는 계약 사슬을 따라 접는다** — 첫 계약의 직선이 아니라 계약마다 기울기가
    갈리는 꺾은선이다(`bookValueOf`). 첫 계약의 직선으로만 읽으면 재계약이 두 번 겹치는
    순간 불변식이 양쪽으로 깨진다: 짧게 재계약한 뒤 또 재계약하면 이미 더 빨리 턴 값을
    원래 눈금으로 되돌려 **총 상각이 취득원가를 넘고**, 만기를 넘겨 재계약하면 원래
    눈금이 이미 0이라 **남은 잔존가가 통째로 사라진다.**
- **계약 이력은 시즌 전환에서 정리되지만 장부가 읽는 사슬은 남는다.** 계약은 시즌마다
  2천 줄씩 쌓여 세이브와 모든 순회를 무겁게 하므로 `transitionSeason`이 끝난 계약을
  지운다. 그런데 취득원가도 잔존가도 그 이력에서 파생하므로, 통째로 지우면 재계약 행이
  첫 계약 자리에 올라앉아 **취득원가가 재계약 시점으로 옮겨 다시 펴지고**(이중 계상)
  시작 스쿼드는 아예 £0이 된다. 그래서 **그 팀에 아직 활성 계약이 있는 선수의 끝난
  계약만** 남긴다 — 떠난 선수·은퇴 선수의 이력은 아무도 읽지 않으므로 그대로 지운다.
  남는 줄은 스쿼드 크기 × 재계약 횟수로 묶인다.
- **매각하면 잔존가를 털어 낸다** (`bookValueOf`). 매각 대금은 `transfer_in`으로 전액이
  이익에 잡히는데 실제 처분 이익은 `매각액 − 잔존가`다. 지우지 않으면 선수를 팔 때마다
  장부가 좋아진다. 매각 자리(협상·AI 시장)가 재정을 직접 적으므로 **월초에 이적 원장을
  훑어** 넣는다 — `payOnce`로 한 번만, noncash라 현금 불변. 훑는 창은 **최근 두 달**
  (`WRITEOFF_WINDOW_MONTHS`)이다: 월초 정산이 한 달에 한 번 도니 한 달이면 충분하고
  한 달치 여유를 더 둔 값이며, 잔존가가 0인 건은 키를 남기지 않아 창이 없으면 시즌마다
  수백 건씩 쌓인 이적 원장을 매달 다시 계산한다.
- **원래 기간이 다 지나면 잔존가가 0이다.** 시작 계약의 만기가 1~~4년에 흩어져 있어
  시작 스쿼드의 상각은 3~~4시즌에 걸쳐 마르고, 그 자리는 게임 중의 실제 영입이 채운다 —
  사지 않는 구단의 장부가 좋아지는 것은 실제 회계와 같다.
- 이적 예산(`transferBudget`)은 현금과 별개인 **보드 허가 한도**로 남는다 (§8).

### 6.2 리그 경제 수준 — 지출과 초기치도 리그를 안다

수입은 리그를 아는데(§5.1의 `broadcastPool`) 지출·초기치가 tier만 보면 비대칭이
생긴다. 세리에B 구단이 EPL tier와 같은 시설비를 내면서 리그 배율이 걸린 수입만
받아 가라앉고, PSG가 아스날과 똑같은 £120M으로 시작해 6분의 1 중계 수입으로 같은
살림을 산다. **네 자리가 같은 축을 쓴다** (`clubEconomyLevel` — `world/wages.ts`):

| 무엇                       | 공식                                         |
| -------------------------- | -------------------------------------------- |
| 시설·아카데미 · 이자·세금  | tier 정액 × 경제 수준                        |
| 초기 잔고 · 초기 이적 예산 | tier 정액(`TIER_FINANCE`) × 경제 수준        |
| 시즌 예산 base             | tier 정액(`SEASON_BUDGET_TOPUP`) × 경제 수준 |
| 선수 주급                  | 구단 임금 예산이 이미 같은 축을 쓴다         |

**축은 `broadcastPool`이 아니다.** 중계권 격차(EPL 대비 리그 1은 0.16)를 비용에
그대로 곱하면 인건비가 실제보다 훨씬 아래로 내려간다. 임금 모델이 이미 갖고 있던
**리그 임금 수준**(EPL 1 · 라리가 0.62 · 세리에 A 0.58 · 분데스리가 0.58 ·
리그 1 0.42)이 그 완만한 곡선이고, 실제로도 비용 격차는 수입 격차보다 작다 —
중계 수입이 적은 리그도 구단이 다른 수입으로 살림을 대기 때문이다.

- 여기에 **브랜드 보정**이 얹힌다 — 세계적 브랜드는 자국 리그 사정을 덜 탄다
  (레알·바이에른·PSG). 임금이 쓰는 보정을 그대로 쓴다.
- **2부는 그 나라 1부에서 파생한다** — 상수 하나로 묶으면 챔피언십과 리그 2가 같은
  살림을 산다. 실측 연 인건비: 챔피언십 £18.3M · 세리에B £14.3M · 리그 2 £12.7M.
- EPL은 배율 1이므로 **§10.2의 측정이 그대로 유지된다** — 이 작업은 EPL을 기준으로
  두고 나머지 리그를 그 눈금에 맞춘 것이다.
- ⚠️ **살림 두 줄은 세이브를 읽는다** — 시설·이자 고정비와 시즌 예산 base는
  `clubEconomyLevelIn(state, teamId)`으로 **지금** 리그·체급을 본다. 카탈로그
  소속으로 읽으면 강등한 구단이 2부 수입을 받으면서 1부 고정비를 내고 1부 예산을
  배정받는다. 초기 잔고·이적 예산은 세이브가 서기 전에 도는 값이라 카탈로그판
  (`clubEconomyLevel`)이 맞다 ([../data/game-state.md](../data/game-state.md) §1).

### 6.3 임금 천장 — 고정비를 뺀 뒤 쓸 수 있는 돈

```
쓸 수 있는 돈 = (연 매출 어림 − 연 고정비) × 0.85 ÷ (1 + 스태프 급여율)
clubWageBudget(주) = 그 값 ÷ 52
```

**천장은 매출에서 나온다.** 카탈로그 값만 곱하면(`상수 × 성적 등급 × 브랜드 × 경제
수준`) **예산이 시즌 내내 상수**로 앉고, 자동 재계약이 매 시즌 인건비를 그 상수로
되돌려 **번 돈이 나갈 축이 없어진다**(§10.3의 2번). 닫힌 세계에서 이적료는 168개 구단
사이를 오갈 뿐이고 상각은 noncash라 잔고를 건드리지 않는다. 규모가 있는 배수구는
인건비뿐이다.

매출 하나로 접으면 **네 축이 저절로 따라온다** — 리그(중계 풀·티켓 단가)·브랜드
(상업 정액)·구장 크기가 이미 매출에 들어 있다.

- **분모에서 고정비를 먼저 뺀다.** 매출에 비중 하나(0.60)를 곱하면 여력 ×1.1이 얹혀
  주급이 매출의 0.66까지 허용되고, 거기에 스태프(주급의 22~~28%)·고정비(매출의 2~~3할)·
  경기 운영비를 더하면 **매출을 넘는다.** 현금 하한은 매수 시점만 보고 부채 동결선도
  매수만 막으므로, 천장을 넘긴 주급은 매주 잔고를 판다 — 막는 자리가 천장뿐이다.
  고정비가 매출의 0.28인 리그(리그 1)와 0.18인 리그(EPL)가 같은 비중을 쓰지 않게 되는
  것이 요점이다.
- **스태프 급여까지 벗긴다** — 주급 £1을 늘리면 실제로 £1.24가 나간다(§6의 스태프 급여는
  주급에 비례한다). 천장은 선수 주급의 몫만 말해야 한다.
- **0.85의 근거는 아스날·맨시티가 이미 앉아 있는 값**이다(0.875·0.890). 두 구단의 실측
  시드를 신뢰하므로 그것을 전 구단의 자로 쓴다 — 단위 9에서 0.60을 고른 것과 같은 방법이다.
- 자는 `catalogRevenueEstimate` — **성적이 아니라 구단 규모**를 잰다. 상금·대항전을 넣지
  않으므로 좋은 컵 여정 하나로 천장이 튀지 않는다. 세이브 없이도 읽히므로 새 게임의
  초기 주급(`initialWages`)이 같은 자를 쓴다.
- **중계 몫엔 브랜드 보정이 붙는다** — 리그 풀을 전 구단에 고르게 곱하면 레알이
  브렌트포드와 같은 규모가 되고(실측 매출은 네 배 차다) 레알의 천장이 브렌트포드보다
  낮아진다. 고정비·초기치가 쓰는 그 보정(`clubEconomyLevel`)을 그대로 얹는다.
- **실측 시드는 천장 아래에서 출발한다** — EPL은 t=0에 매출의 0.43이고 재계약으로
  4시즌에 걸쳐 0.48까지 오른다. 시드가 천장이 아니라 **출발점**이라는 뜻이다.
- **천장도 세이브 소속을 읽는다**(`leagueOfTeamIn`) — §6.2의 살림 두 줄과 같은 자리에
  선다. 강등한 구단은 그 자리에서 2부 매출로 천장이 내려가고 승격한 구단은 1부 매출로
  올라간다. 카탈로그 소속으로 읽으면 고정비만 승강을 알아, 강등 구단이 2부 수입에
  1부 급여 천장을 그대로 갖고 승격 구단은 1부 수입에 2부 천장으로 묶인다. 세이브가
  서기 전(`initialWages`)만 카탈로그판이다.

### 7.1 시즌의 마지막 달은 전환이 닫는다

월초 훅만으로는 **시즌의 마지막 달이 시즌 안에서 마감되지 않는다.** 시즌은 6월 초에
끝나고 전환이 곧바로 7월 1일로 건너뛰므로 다음 월초 훅은 8월 1일이고, 그때 6월
보고서가 나온다. 그런데 6월은 리그 상금과 시즌 보너스(§5.1.1·§6)가 앉는 달이고,
이적 예산과 PSR 판정(§9.1·§9.2)은 **전환 안에서** 지난 시즌의 손익을 읽는다 — 마지막
달이 빠진 성과로 다음 시즌의 예산과 동결이 정해진다.

그래서 `endSeason`이 **시즌 리뷰와 전환 사이에서** 마지막 달까지 마감한다
(`closeSeasonBooks`). 순서는 이것 하나뿐이다:

```
시즌 리뷰 (상금·보너스가 6월 원장에 앉는다)
  → 남은 주급 지급 → 6월 마감 (보고서 발행)
  → 시즌 전환 (예산 보충·PSR 판정이 6월을 포함한 손익을 읽는다)
```

- **마감은 `state.season`·`state.calendar`가 아직 끝난 시즌일 때** 돌아야 한다.
  보고서의 시즌 번호는 그 둘로 역산하기 때문이다(`seasonOfMonth`).
- 8월 1일의 월초 훅은 6월 보고서가 이미 있는 것을 보고 건너뛴다 (멱등).
- **마감이 남은 주급을 함께 문다.** 주급은 월요일에만 나가는데(§6) 전환이 6월의
  남은 월요일을 건너뛴다. 정액 수입·고정비는 1일에 한 달치가 다 앉으므로, 그대로
  두면 마지막 달만 수입은 만근이고 주급은 한 주치다 — 그 후한 값이 다음 시즌
  예산과 PSR에 그대로 닿는다. 그래서 마감 **전에** `closeSeasonBooks`가
  **다음 시즌 시작(7월 1일) 전날까지 남은 월요일 수**만큼 주급을 문다
  (`payWeeklyWages(state, weeks)`). 선수는 6월 30일까지 계약돼 있으므로 회계로도
  나가야 하는 돈이다. 원장에는 시즌 종료일 하루에 `(N주)`로 한 줄 선다 — 지나가지
  않은 날짜에 돈을 앉힐 수는 없다.

## 8. 실시간 노출

원장은 이미 실시간이므로 보이게만 한다.

1. **재정 활동 피드** — 오피스 재정 뷰 상단, 최근 **30줄** (날짜 · 카테고리 ·
   상세 · ±금액). → §8.1
2. **달력 일지 연동** — 큰 비정기 항목은 일자별 events에 `money`로 함께 (§8.2)
3. **tick 다이제스트** — 홈경기 수입·이적료·상금은 발생 즉시 한 줄

### 8.1 피드는 접는다 — 30줄은 사건 30개다

**접는 것은 뷰의 일이다.** 원장은 선수별로 정확히 남고(PSR·처분 이익이 그 값을 읽는다),
화면에 내려보내는 피드에서만 묶는다.

정기 비용은 한 사건인데 원장에는 여러 줄로 앉는다 — 주급은 매주, 상각은 매월 1일에
**선수 한 명당 한 줄**이라 계약이 마흔다섯이면 그 하루가 피드를 통째로 덮는다. 접지
않으면 30칸이 사건 30개가 아니라 **한 날 한 카테고리**가 된다.

**묶는 단위** — `날짜 · 수입/지출 · 카테고리 · 현금/장부 · 항목명`이 모두 같은 원장
엔트리. 항목명은 라벨의 `—` 앞부분이고, 없으면 카테고리 자체다. 그래서 같은
`amortisation`이라도 선수별 상각(항목명 없음)과 **`매각 잔존가`(항목명 있음)는 따로
선다** — 매달 도는 비용과 그 달의 매각은 감독이 갈라 읽어야 하는 사건이다.

**대상이 있는 줄만 묶인다.** 항목명이 붙었거나 `ref`가 무언가를 가리키는 줄이다.
`이자·세금`과 `시설·아카데미 운영`은 카테고리가 같아도 서로 다른 사건이라 각자 선다 —
묶으면 라벨이 사라지고 두 항목이 한 금액이 된다. 항목명이 카테고리 이름을 되풀이하는
줄은 — 옛 표시명(`이적료 상각`)이라도 — 항목명이 없는 것으로 읽는다. 라벨 규약 이전
세이브의 원장이 3개월 롤링으로 빠질 때까지 한 행에 같은 말이 두 번 서지 않게 하는
장치이고, **세이브를 고치지는 않는다.**

**한 줄이 싣는 것** — 합계와 대상별 명세(이름 · 금액, **큰 금액부터**). 한 건짜리
묶음은 접지 않고 원래 라벨 그대로 선다.

**항목명 자리는 비워 두지 않는다.** 카테고리로만 묶인 줄은 항목명이 없지만, 건수만
남기면 그 자리가 아무것도 알려주지 않는다 — 가장 큰 명세의 이름과 나머지 수로 읽는다
(`브루누 페르난데스 외 44명`). **세는 단위는 뷰가 낱말로 낸다** — 묶인 엔트리의
`ref.type`이 하나로 모이면 그것이 정한다(`player` → 명, 아니면 건). 무엇이 묶였는지는
코어만 알고, 문장(`외 N명`)은 목록과 그 낱말로 화면이 잇는다 (overview §5). 펼침은
갈매기 표식이 알린다 — 달력 `기록` 블록과 전술판이 이미 쓰는 규칙이라 새 상호작용이
아니다.

**30줄은 접은 뒤에 센다.** 원장을 30건 자른 다음 접으면 접기 전과 같은 화면이 된다.

**금액 눈금** — 접힌 줄의 합계와 명세 한 줄은 자릿수가 세 자리씩 다르다(합계 £1.2M,
명세는 월 £40k짜리). 그래서 **금액이 눈금을 고른다** — 백만 이상은 `£1.2M`, 그 아래는
`£40k`. 눈금을 백만으로 고정하면 명세가 전부 `£0.0M`이 되어 서른 줄이 아무 말도 하지
않는다. 이 자만 쓰는 것은 피드가 아니라 게임 전체다 (overview §5).

### 8.2 달력 일지에 서는 돈

달력은 **되돌아보는 화면**이다 — 부상도 성장도 카드도 날짜로 남는데 돈만 남지
않으면, 시즌을 넘긴 뒤 그해 가장 큰 거래의 날짜가 세이브 어디에도 없다.

**서는 것은 두 가지 조건을 다 넘긴 항목뿐이다.**

**① 비정기 항목만** — 카테고리로 가른다. 라벨은 보는 글자지 집계 축이 아니다(§4.1).

|             | 카테고리                               |
| ----------- | -------------------------------------- |
| 선다        | `prize` · `source: "narrative"`인 항목 |
| 서지 않는다 | 나머지 전부                            |

매달·매경기 같은 자리에 서는 항목(중계권·스폰서십·머천다이징·주급·스태프·시설·
매치데이·운영비·상각·수당·원정의료)은 문턱을 넘어도 서지 않는다. 아스날의 월
중계권은 £9M이라 언제나 문턱 위인데, 그 줄이 매달 서면 일지가 글자 벽이 되고 그날
실제로 벌어진 일(부상·경고·이적)을 덮는다.

**이적료 축(`transfer_in`·`transfer_out`·`agent_fee`)도 서지 않는다** — 그 자리엔
이미 이적 일지가 그날 그 이름으로 서 있다. 대신 **그 줄에 금액을 적는다**
(`마누엘 우가르테 이적 · £37.5M`). 돈 줄을 따로 세우면 한 거래가 세 줄이 되고,
에이전트 수수료는 이적료의 10%라 새로 말하는 것도 없다.

**② 문턱을 넘을 것** — `min(£1M, 잔고의 1%)`, 하한 £100k.

둘 중 낮은 쪽이라 규모가 작은 구단은 자기 눈금으로 본다(잔고 £20M이면 £200k부터).
하한이 있는 이유는 빚진 구단이다 — 잔고가 0 이하면 1%도 0 이하가 되어 모든 항목이
통과한다. 문턱을 재는 잔고는 **마감된 달은 그달 기말 잔고, 진행 중인 달은 오늘
잔고**다.

**절단 뒤에도 남는다.** 일지는 저장하지 않고 기록 테이블에서 파생하는데(→
[game-state](../data/game-state.md) §5) 원장은 3개월 뒤 잘린다. 그래서 파생 원본이
둘이다:

| 달           | 어디서 파생하나                                       |
| ------------ | ----------------------------------------------------- |
| 진행 중인 달 | 원장 (`finance.ledger`)                               |
| 마감된 달    | 보고서의 `highlights` — 절단 전에 옮겨 적은 것 (§4.3) |

마감은 절단보다 먼저 돌므로(§7) 옮겨 적을 원장이 언제나 있다. 두 원본이 겹치지
않는 이유는 마감이 **지난달까지만** 하기 때문이다 — 진행 중인 달은 보고서가 없다.

## 9. 재정이 게임에 물리는 지점

### 9.1 이적 예산 = 성과의 함수

`balance`는 현금, `transferBudget`은 **보드가 허가한 순 이적 지출 한도**다
(둘 다 이적료에 반응하는 현재 동작은 의도된 것 — 문서화한다).

시즌 전환의 예산은 **세 조각**이다 (`topUpTransferBudget`):

```
예산 = min(안 쓴 예산, base)    // 이월은 한 시즌치까지
     + base(tier) × 경제 수준    // 등급별 기준액 (§6.2)
     + clamp(전 시즌 운영 손익 × 0.5, −base×0.5, +base)
PSR 여유가 없으면 통째로 동결한다 (§9.2)
```

- **이월은 한 시즌치까지.** `+=`로 얹기만 하면 안 쓴 예산이 그대로 남고 그 위에
  base와 성과가 얹혀 아스날이 £90M → 180 → 270 → 360 → 450으로 갔다(정확히
  +£90M/시즌). 판매로 자금을 만든다는 이적의 긴장(transfer.md §3)이 사라지는
  자리다. 예산은 현금이 아니라 보드 허가 한도이므로 **잘린 이월분은 어디로도 가지
  않는다** — 잔고는 그대로다.
- **성과의 자는 `pnlNet`이 아니라 운영 손익**(장부 손익 − 매각 대금)이다. 매각
  대금은 협상이 타결될 때 이미 예산에 들어간다. 손익으로 또 세면 한 번 판 선수로
  예산을 두 번 받는다 — 매각 즉시 +이적료, 다음 시즌 +최대 base다. 보드가
  보상하려는 것은 장사가 아니라 살림이다.
- 등급별 기준액은 건드리지 않고 위아래를 자르기만 한다 — 이적 루프가 죽지 않게.
- **전 시즌 운영 손익은 그 시즌의 마지막 달까지 포함한다** — 상금과 보너스가 앉는
  달이라 빠지면 성과 조각의 부호까지 뒤집힌다. 마감 순서는 §7.1이 원본이다.

### 9.2 PSR (결정 D)

- 3시즌 누적 `pnlNet` < −£105M → **보드 경고**(서사 이벤트) + **여름 이적 예산
  동결** → 매각 없이는 영입 불가
- 승점 삭감은 넣지 않는다
- 보유 시즌이 3개 미만이면 있는 만큼만 합산
- 미구현 `request_board` 스킬의 판정 근거가 된다

### 9.3 급여 비중

경고선은 게임 기준으로 65%(주의) / 75%(위험)이고 보고서 `notes`에 실린다.
오피스 카드의 헤드라인은 **시즌 누계**(`seasonWageRatio`)를 쓴다 — 한 달만 보면
프리시즌(매치데이 수입 0)에 100%를 넘어 지표가 무의미해진다.
보드 신뢰·재계약 협상의 입력으로 쓰는 것은 후속 작업이다.

### 9.4 부채 — 음수 잔고의 값

잔고가 음수로 내려가면 그만큼 **빌린 것**이다. 별도 테이블도 상환 일정도 두지
않는다 — 통장의 부호가 곧 부채이고, 흑자가 나면 저절로 갚아진다.

```
이자      매월 1일   부채 × 8% ÷ 12   (`facility` · 라벨 "부채 이자")
동결선    부채 > 주급 총액 × 20
```

- **이자는 그 달을 시작한 잔고**에 붙는다 — 이번 달 수입이 들어오기 전에 먼저 뗀다.
  새 카테고리를 만들지 않고 이자·세금과 같은 자리에 라벨로만 갈린다. 이자는 비용이라
  손익에 잡히고 PSR로 그대로 전파된다.
- **원금은 자본 이동이라 손익에 없다.** 구단주 출자가 PSR을 풀지 못하는 것과 같은
  이유다(§4.1.1) — 빌려서 산 선수의 값은 상각이, 빌린 값은 이자가 문다.
- 연 8%는 실제 구단의 차입 금리대(6~8%)의 상단이다. 여기서 빌리는 구단은 이미
  곤란한 구단이고, **무이자면 음수 잔고가 공짜**여서 재정이 게임에 물리지 않는다.
  금액이 아니라 비율이라 구단 규모를 저절로 탄다.
- **동결선은 새 자가 아니다** — `market.ts`가 매각 압박에 쓰는 주급 20주치를 반대
  방향으로 쓴다. 사다리가 이렇게 선다:

  | 잔고가 주급 20주치 **아래로** | 상대가 우리 선수를 싸게 부른다 (매각 압박) |
  | 빚이 주급 20주치를 **넘으면** | 보드가 이적 예산을 동결한다 |

  §10.3 불변식 4번(부채 > 연 매출)보다 훨씬 이른 선이다(아스날 기준 매출의 0.22배)
  — 불변식에 닿기 전에 제동이 걸려야 한다.

- **판정은 매달 다시 본다.** 시즌 끝에만 보면 감독이 시즌 내내 빚을 키우며 영입해도
  아무 일이 없다. 갚으면 그 자리에서 풀린다.
- **AI 팀도 같은 규칙**을 받는다. 잔고만 갱신하므로(§4.5) 부채도 부호로 읽고,
  `ai-market`이 이미 `budgetFrozen`을 보므로 빚더미 구단은 영입을 멈춘다.
- 감독이 읽는 자리: 월간 보고서 `notes`(부채·연 이자·동결 여부)와 `get_finance`의
  둘째 줄. 화면은 이 사실을 받아 그리기만 한다.

### 9.5 2부의 인건비 비중 — 우리 세계는 0.60이다

실제 2부(챔피언십 등)의 인건비/매출은 0.8~1.0이고 **그 구단들은 적자를 낸다** — 구단주
출자와 파라슈트가 그 차이를 메운다. 우리 2부에는 그 장치가 없으므로(AI 구단에 구단주
출자를 만들지 않는다) **재정적으로 건전한 0.60이 맞는 값이다.**

그리고 이 값은 튜닝의 대상이 아니라 **식이 정하는 상수**다:

```
인건비/매출 = 0.85 × (1 − 고정비/매출) ÷ (1 + 스태프 급여율)
2부(고정비/매출 0.10 · 스태프 0.28) = 0.60
```

천장이 매출에서 파생하므로(§6.3) 매출을 깎아도 분자·분모가 함께 줄어 비율이 그대로다 —
티켓 단가를 내려도 0.59다. 0.8에 닿으려면 비중이 1을 넘어야 하고, 그건 "매출에서
고정비를 뺀 것보다 급여를 더 쓴다"는 뜻이라 §10.3의 1번과 정면으로 부딪친다.

(2024/25 EPL·EFL)을 그대로 옮긴 것이다.

| 상업     | 계약 만료 시점에 **늦게** 온다 — 리즈 −10% · 레스터 −26%                                         | `RELEGATED_COMMERCIAL` [−10%, −25%, −35%]                                                                                                 |
| 총매출   | −33 ~ −41%                                                                                       | 같은 자리                                                                                                                                 |

- **파라슈트는 새 시스템이 아니라 균등 배분의 파생이다** — `떠나온 리그의 배율 ×
연차 비율`. `TeamFinance.parachute`(optional — 세이브 버전 유지)가 출처와 연차를
  갖고, 월 정산이 균등 배분과 같은 항목에 **다른 라벨**로 적는다(감독이 "이 돈이
  언제 끊기나"를 원장에서 읽어야 한다).
- **승격하면 그 자리에서 끝난다** — 1부 배분과 겹쳐 받을 수 없다. 낙하산 기록도 함께
  지워지므로 **재강등 2년 규칙은 우리 세계에 없다** — "아직 받는 중"인 상태가 남지
  않는다. 실제 EPL의 2년 조항은 위 표의 실제 열에만 있다.
- ⚠️ **상업 감소와 파라슈트 종료가 3년차에 겹친다** — 실제로 노리치·왓포드가 맞은
  "이중 절벽"이다. 의도된 것이고, 그래서 강등 3년차가 재정의 최대 고비다.
- ⚠️ **4년차부터는 상업이 브랜드 정액으로 돌아온다.** 감소는 세 해짜리 지연 효과이지
  2부의 상업 수준이 아니다 — 상업 정액은 `commercialTier`(브랜드 등급)에서 나오고 그
  등급은 리그를 모른다(§5.3). 감소를 이어 가려면 상업 정액 자체가 리그를 알아야 하고,
  그건 새 축이라 이 표의 값이 아니다.
- ⚠️ **성적 수당은 리그가 바뀌면 지난 순위를 쓸 수 없다** — 챔피언십 1위와
  프리미어리그 1위는 같은 수당이 아니다(`SeasonRecord.leagueId`로 가른다).
- ⚠️ **이미 쓴 계약은 강등을 모른다** — 코어에 강등 조항이 없다. 실측의 −42~48%는 조항 +
  매각의 합인데 우리 세계엔 조항이 없으므로 **전부 감독이 매각으로 만들 몫**이다.
  다만 **임금 천장은 그 자리에서 내려간다**(§6.3) — 개별 주급은 그대로여도 새 계약과
  재계약이 2부 예산을 나눠 갖고, 급여 여력(`wageRoomOf`)이 음수로 내려간 구단은 더
  얹지 못한다.

## 10. 밸런스 기준 — 현실 정합

**기준은 총량이 아니라 구조다.** 실제 구단이 무엇을 얼마나 벌고 쓰는지의 **비율**에
맞춘다 — 우리 매출 규모가 실제의 몇 할이든, 매출 대비 인건비·상각·순익의 자리가
같아야 재정이 게임 기계(PSR·이적 예산·매각 압박)를 돌린다.

### 10.1 기준 축은 장부 손익이다

현금(`cashNet`)은 이적 활동이 지배해 시즌마다 크게 흔들린다. **판정은 장부
손익(`pnlNet`)이 한다** — PSR이 읽는 축이고, 상각이 들어오면 두 축이 갈라진다.
현금은 같은 하네스가 함께 찍되 판정하지 않는다: 두 축을 한 이름으로 부르면
"순익 밴드 안"이 어느 쪽을 말하는지 알 수 없다.

**구간의 숫자는 `finance-tier1` 하네스의 서술자가 쥔다**
(→ [balance-harness](balance-harness.md) · `pnpm balance --list`). 여기 적는 것은
그 구간이 왜 그 자리인가다.

| 지표                                   | 왜 그 구간인가                                                  |
| -------------------------------------- | --------------------------------------------------------------- |
| tier1 유저 **연 장부 손익**(`pnlNet`)  | PSR 한도가 닿을 수 있는 거리 — 아래 참고                        |
| tier1 유저 연 **현금 순증**(`cashNet`) | 이적 활동이 지배하는 축. 자릿수만 본다 — 판정은 손익이 한다     |
| 경기 달 급여 비중                      | 실제 EPL 평균 ~70%. 프리시즌 달은 매치데이가 없어 대상에서 뺀다 |
| tier1 유저 연 수입                     | 실제 상위 구단 £400–700M — 우리는 그 6–7할                      |

손익 밴드를 PSR에서 파생시킨 이유: 한도가 3시즌 −£105M이므로 **시즌 평균 −£35M이
위반선**이다. 정상 운영은 그 위여야 하므로 하단을 위반선 바로 위에 두고, 상단은
흑자만으로 이적 예산이 무한히 불어나지 않을 만큼에서 잘랐다. 밴드 중앙이 소폭
흑자인 것은 실제 구단과 같다 — 대부분의 시즌은 본전 근처이고, 나쁜 해에 적자가 난다.

⚠️ **두 상단은 12개월 합을 잰다.** 마지막 달이 시즌 안에서 마감되므로(§7.1) 이 합은
11개월이 아니라 12개월이고, 그 12번째 달이 순위·컵 상금을 통째로 진다 — 살림이 후한
것이 아니라 **세는 창이 그만큼**이다. 하단은 PSR에서 파생한 값이라 그 창과 무관하다.

**총량은 지금 자리에 고정하지 않는다.** 고정하면 §9.2(PSR)·§9.1(이적 예산)이
영원히 죽은 코드로 남는다.

### 10.2 지금 값

측정: `pnpm balance finance` — 시드 42·7 · 아스날 · `createTestGame` + `advanceAndPlay`
mock 진행(경질 없이 `keepSeat`) · 시즌 1의 월간 보고서 합. **구간은 `finance-tier1`
하네스의 서술자가 쥔다** — 하네스가 실측 옆에 나란히 찍으므로 여기 옮겨 적지 않는다.
**한 시즌은 12개월(7월~6월)이다** — 마지막 달이 전환 안에서 마감되므로(§7.1) 상금이
앉는 달까지 이 합에 든다.

|                  | 시드 42     | 시드 7     | 판정         |
| ---------------- | ----------- | ---------- | ------------ |
| 시즌 1 보고서 수 | 12          | 12         | ✓            |
| 수입             | £507.6M     | £478.6M    | ✓            |
| 지출             | £474.5M     | £472.1M    | —            |
| **장부 손익**    | **+£33.1M** | **+£6.5M** | ✓            |
| 현금 순증        | +£170.8M    | +£144.5M   | ✓            |
| 상각             | £137.7M     | £138.0M    | 비용의 29% ✓ |

⚠️ **마지막 달 주급이 이 표에 들어와 있다** (§7.1). 6월의 남은 월요일 수만큼이 지출에
한 번에 얹히므로, 그 달의 급여는 다른 달과 같은 눈금이다 — tier1 유저 기준 네 주치가
£15M 남짓이다.

⚠️ **성적 하나가 손익을 통째로 가른다.** 두 시드의 살림은 사실상 같다 — 지출이
£2.4M 차이인데 손익은 £26.6M 갈린다. 그 차이는 거의 그대로 시즌 말 순위·컵 상금이고,
그 상금이 앉는 달이 바로 12번째 달이다. 밴드가 한 시즌의 **성적**에 걸려 있다는
뜻이므로, 두 시드가 다 들어오는 폭이 아니면 가드 구실을 못 한다 — 상단이 12개월
기준인 근거가 여기다(§10.1).

**수입 구성 — 실제 아스날과 겹친다** (§5.2·§5.3이 세 축을 같은 눈금에 세운 결과).
시즌 말 **순위·컵 상금은 뺀 분모**로 잰다 — 실제 구단의 중계 항목에는 성적 수당이
이미 들어 있어, 그것을 따로 세우는 우리 눈금과 그대로 비교되지 않는다:

|           | 우리 (시드 42 / 7) | 실제 아스날 |
| --------- | ------------------ | ----------- |
| 매치데이  | 0.23 / 0.21        | 0.21        |
| 상업+굿즈 | 0.36 / 0.37        | 0.35        |
| 중계      | 0.41 / 0.43        | 0.44        |

상금까지 넣은 총수입 대비로는 상금이 0.15 / 0.09를 차지하고 나머지 셋이 그만큼 내려간다.

⚠️ **시드를 바꾸면 총액이 몇 % 움직인다**(수입 £507.6M vs £478.6M · 손익 +£33.1M vs
+£6.5M). **AI 시장을 스치는 변경 하나에도 같은 폭이 움직인다** — 이적이 달리 성사되면
그 나비효과가 컵 여정과 순위에 닿는다. 밴드를 읽을 때 그만큼을 감안하고, **배수의
소수점은 읽지 않는다.**

### 10.3 다년 불변식 — 5시즌까지 지킨다

한 시즌은 발산을 감추기에 충분히 짧다. **5시즌**이 기준이다 — 멀티시즌이 게임의
축이고, 리그가 가라앉는 것이 3~4시즌째에 보인다.

| #   | 불변식                                             | 지금                                                                   |
| --- | -------------------------------------------------- | ---------------------------------------------------------------------- |
| 1   | 리그별 **중간 잔고 ≥ 0**                           | ✓ — `finance-leagues`(시즌 1)·`finance-multi-season`(4시즌)이 판정한다 |
| 2   | 리그별 중간 잔고 ≤ 그 리그 중간 구단의 **연 매출** | ✗ 4시즌에 세 리그 (EPL 1.37 · 챔피언십·세군다 1.02) — EPL은 3시즌부터  |
| 3   | 유저 3시즌 누적 손익이 **±£105M 안**               | ✗ +£448.9M (시즌 1~3)                                                  |
| 4   | 부채가 연 매출을 넘는 구단이 리그의 1/4 이하       | ✓ 4시즌 전 리그 0/N (160개 구단 중 0개)                                |

아래 표는 시즌별 추세를 보려고 잰 스냅샷이다 (시드 42 · 아스날 · 4시즌, 각 시즌 전환
직후). 1번의 판정은 하네스가 하고, 이 표는 그 사이의 모양을 보여줄 뿐이다:

| 시즌 | 유저 잔고 | EPL 중간 (÷매출) | 리그 1 중간 | 세리에B 중간 | 최저 리그 중간 |
| ---- | --------- | ---------------- | ----------- | ------------ | -------------- |
| 1    | £309.5M   | £129.7M (0.53)   | £9.9M       | £2.2M        | £2.2M          |
| 2    | £562.5M   | £204.4M (0.83)   | £17.4M      | £6.0M        | £6.0M          |
| 3    | £872.9M   | £259.1M (1.06)   | £16.3M      | £11.3M       | £11.3M         |
| 4    | £1,138.0M | £335.3M (1.37)   | £32.3M      | £13.8M       | £13.8M         |

최저는 네 시즌 내내 세리에B다 — 그 리그가 곧 마지막 열이다.

⚠️ **한 시드의 값이라 단위 사이의 차를 그대로 읽으면 안 된다.** 이적 시장이 세계를
흔들어 같은 코드로도 리그 중간 잔고가 수십 %씩 움직인다. **불변식의 통과·위반은 읽되
배수의 소수점은 읽지 않는다.**

**1번과 4번은 지켜진다.** 다만 1번의 여유는 **시즌 1에서만** 얇다 — 가드가 읽는 최저가
£2.2M(시드 42 · 세리에B)·£3.4M(시드 7)이고, 2시즌부터는 £6.0M →
£11.3M → £13.8M으로 벌어진다. 마지막 달 주급(§7.1)이 전 구단에서 시즌마다 네 주치씩
나가는 자리이기도 하다. **시즌마다 나가는 돈이 조금이라도 더 늘면 먼저 음수가 되는 것은
시즌 1이고**, 그때 볼 손잡이는 하위 리그의 초기 여유다 (`core/state.ts`의 `TIER_FINANCE` ·
`data/league-economy.ts`의 리그 경제 수준).

**2번은 시즌이 갈수록 넓어진다.** EPL이 3시즌부터 넘고(1.06 → 1.37) 4시즌에
챔피언십·세군다(둘 다 1.02)가 따라 넘는다. 상방 발산은 한 리그의 문제가 아니라 시간의
문제다.

**3번은 계속 벌어진다.** 이건 회계 결함이 아니다 — §12가 적은 대로 **사지 않는 구단의
장부가 좋아지는 것**이고, mock 진행의 유저는 영입을 거의 하지 않는다. 그래서 이 항목은
**mock 진행으로 재는 불변식이 아니다.** 지금 지켜지는 형태는 "PSR 한도가 손에 닿는
거리에서 출발한다"이고 — 첫 시즌 누적이 §10.2의 시즌 1 장부 손익과 **같은 값이다**
(마지막 달 마감이 두 자리에 같은 숫자를 세운다는 뜻이다) — 그 뒤의 누적은 감독이
사고파는 정도가 정한다.

테스트가 고정하는 것: 구조적 불변식(어느 구단도 인건비가 매출을 넘지 않고,
고정비가 매출의 4할을 넘지 않는다 — 시뮬 없이 t=0에서) · **3시즌 중간 잔고 ≥ 0** ·
이월 상한과 성과 보너스의 자 · 부채의 이자·동결·해제 경로 · 실측 시드가 같은 리그의
급여 자릿수를 벗어나지 않는 것.

재정 모델이 아니라 **그 시즌의 컵 운**을 재게 된다.

`recordFinance`는 옵션 객체 하나를 받는다 —
`{kind, category, label, amount, ref?, accounting?, time?, source?}`. 카테고리 없는
기록을 만들 수 없게 하는 자리다.

### 세이브 호환성

`category`를 optional로 두고 미기재를 `"other"`로 읽으므로 **`SAVE_VERSION`
(현재 6)이 그대로이고 진행 중 세이브가 그대로 열린다.** 로드 시
`financeReports`를 빈 배열로 채우고(persistence 원칙 4), 보고서는 없는 달을 소급
생성하지 않고 다음 달 1일부터 쌓는다.

## 12. 미해결

- ⚠️ **사지 않는 구단의 장부가 좋아진다** — §10.3의 3번이 남은 자리다. 회계는 맞다
  (§6.1의 잔존가가 원래 기간에 걸쳐 마르는 것) — 문제는 그 자리를 채울 **영입이
  일어나지 않는** 것이다. 유저는 mock 진행에서 거의 사지 않고, AI는 사지만 보고서가
  없어 손익이 보이지 않는다(§4.5). 감독이 실제로 사고팔면 저절로 닫히는 축이라
  "고칠 것"인지부터가 판단이다.
- ⚠️ **리그 안의 티켓 폭** — `club/finance.ts`의 `TICKET_TIER_FACTOR`(1.3~0.8)가 EPL의
  폭에 맞춰져 있어, 실제 폭이 더 넓은 세리에 A·리그 1의 최저가 구단은 여전히 실제보다
  높다. 리그별 폭을 주려면 새 축이 필요하다.
- **이적료 분할 납부** — `domain/records.ts`의 `Transfer`가 `fee` 한 값이라 이적료가
  하루에 다 나간다. 현금흐름 압박이 실감 나지만 협상 UI·검증이 커진다
- **구장 투자** — 수용 인원이 `data/club-profile.ts`의 고정값이라 감독이 바꿀 길이 없다.
  자금 조달은 §9.4의 부채를 쓰면 되지만, 상각 대상이 선수에서 자산으로 넓어진다
- **스태프 시스템** — `staff_wages`가 `STAFF_WAGE_RATE`로 선수 급여에서 파생될 뿐
  스태프라는 실체가 없다. 고용이 들어오면 이 값이 실제 합계가 된다
- **티켓 가격 결정권** — 가격은 `avgTicketPrice × TICKET_TIER_FACTOR`로 파생된다.
  감독이 정하면 관중과 수입이 트레이드오프가 된다 (팬 여론 시스템과 함께 검토)
