# 실시간 공간 경기

경기 화면은 서버가 계산한 선수와 공의 실제 위치를 그린다. 슈팅은 선수의
위치·압박·행동 선택에서 발생하고, 골은 그 슈팅의 결과다. 장면을 만들기 위해
이미 정해진 득점에 선수를 배치하지 않는다.

## 시계와 개입

- 킥오프 이후 경기 시계는 서버의 고정 간격 시뮬레이션이 민다.
- 감독이 입력을 시작하거나 우리 팀 편집 화면을 열면 서버에 정지를 요청한다.
  정지 응답은 진행 중인 계산의 저장이 끝났다는 장벽이다.
- 입력·전술 편집·명령 저장·LLM 해석은 각각 정지 사유다. 모든 사유가 해제되어야
  재개한다. 해석 실패나 저장 실패는 정지를 유지한다.
- 입력을 지우면 입력 정지가 풀리고, 전술 편집을 마치면 변경을 먼저 저장한다.
  지시를 보낸 경우 적용과 응답이 완료된 뒤 재개한다.
- 경기의 중단(골·파울·스로인)은 코어가 재개한다. 하프타임·연장 시작은 감독이
  재개한다. 연결이 끊기면 다음 저장 경계에서 정지하고, 재접속은 저장 상태를 읽는다.
- 배속은 벽시계와 경기 시계의 비율이다. 계산 간격·난수·판정 규칙을 바꾸지 않는다.

## 상태와 판정

`pendingMatch.spatial`은 선수 위치·속도·행동, 공, 틱, 재시작과 휴식 상태를 보존한다.
기본 배치와 실제 위치는 별개다. 지시 변경·교체가 기본 배치를 바꾸어도 뛰고 있는
선수를 순간이동시키지 않는다. 국면 재시작에는 규칙에 맞는 재배치가 허용된다.

패스·드리블·압박·차단·슈팅은 공간에서 계산한다. 패스와 슈팅의 질에는 능력치와
패킷의 제한된 전술 효과가 반영된다. 실제 위치에서 결정되는 공간 효과와 같은
포인트의 `edge` 효과를 중복 적용하지 않는다. 경기 장부의 사건·통계·피로를 함께
갱신하며, 종료 정산은 기존 경기 장부 경로를 지난다.

## 자연어와 상대 벤치

판독기는 전술 포인트에 선택적 구조화 행동을 붙인다. 행동은 선수·표적·국면·지역을
지정하며, 코어가 실재와 실행 가능성을 검증한다. 선수의 기본 포지션을 맞바꾸는
지시는 두 선수의 `set_player_tactic` 명령으로 적용한다. 기본 배치와 패킷은 즉시
바뀌고, 실제 선수는 재개 후 새 위치로 이동한다. 자유 문장을 코드가 다시 파싱하지
않는다. 공간으로 표현하지 않는 판독은 기존 시트의 제한된 효과로 반영한다.
LLM 호출 중 경기 시계는 정지한다. 같은 저장 스냅샷 위에서 해석하고 적용하므로
늦은 응답이 이미 지난 경기를 되돌리지 않는다.

상대 벤치는 점수·시간·체력·수적 변화에 따라 코어가 판단하며, 전술과 교체는
동일한 검증 경로를 사용한다. 판단 간격은 경기 시간으로 센다.

## 전송과 저장

경기 실행은 서버 세션이 소유한다. 짧은 실행 구간 동안 게임 잠금을 잡고,
구간 끝에서 저장한 후 놓는다. 정지·턴·전술 변경은 이 경계 뒤에 적용된다.
프레임은 선수 위치와 공만 보내고, 장부 뷰는 저장 경계에서 갱신한다.
클라이언트는 위치를 보간하며 결과를 판정하지 않는다.

세이브에 틱과 공간 상태가 들어가므로 새로고침과 정지·재개가 같은 경기를 잇는다.
기존 진행 중 세이브는 웹 경기 화면에 접속할 때 현재 시각과 장부를 유지한 채 공간
상태를 만든다. 화면을 열지 않는 CLI와 다른 구장 경기는 기존 xG 경로를 사용한다.
프레임 표시와 LLM의 실패는 확정된 경기 결과를 취소하지 않는다.

## 화면과 중계

실시간 판에는 양 팀과 공, 스코어, 초 단위 시각, 진행·정지 상태를 표시한다.
전술 편집은 별도 기본 배치를 다루며 경기판의 실제 선수 위치를 수정하지 않는다.
데스크톱은 경기장 왼쪽·터치라인 오른쪽, 모바일은 경기장 위·터치라인 아래로 배치한다.
경기 탭은 아이콘만 표시한다. 데스크톱에서 대화·전술·교체·대회는 터치라인 영역을
교대로 사용하고 경기장은 같은 자리에 유지한다. 모바일에서 전술·교체·대회 탭을 열면
경기장을 접고 패널이 무대 전체 높이를 사용하며, 대화 탭으로 돌아오면 경기장을 펼친다.
대화의 입력 초안과 스크롤은 탭을 바꿔도 보존한다.
모바일 입력에 집중하는 동안 경기장을 접고 경기 진행도 정지한다.
주요 사건은 즉시 기록으로 표시한다. 대화와 경기 후 서사는 확정된 사건을 읽으며
경기 시간을 진행시키지 않는다.

## 실행 범위와 검증

현재 실행기는 상주하는 단일 Node 프로세스의 Next 서버에 있다. SSE로 100ms마다
프레임을 보내며 경기 속도는 6배, 계산 간격은 경기 시간 50ms다. 약 1초마다
게임 잠금 안에서 체크포인트를 저장한다. 여러 브라우저 창의 정지 사유는 합쳐진다.
서버가 강제 종료되면 마지막 저장 이후 프레임은 복구되지 않을 수 있다.
다중 서버·서버리스 배포를 위한 외부 실행기와 세션 소유권 분배는 지원하지 않는다.

스키마로 검증한 전술 포인트의 행동은 압박·마크·커버·지원·침투·자리 유지다.
개인 행동은 선수당 첫 유효 포인트 하나를 사용한다. 그 밖의 표현은 기존 제한된
시트 효과를 사용하므로 자유로운 문장 전부를 새로운 물리 행동으로 생성하지는 않는다.
전술판의 교체 요청은 다음 경기 중단에 실행된다. 휴식 때 요청한 교체는 즉시 실행된다.

현재 공간 모델은 패스·차단·운반·슈팅·골키퍼 선방, 파울·경고·퇴장·부상,
오프사이드, 코너·프리킥·페널티와 재시작을 처리한다. 공중볼은 비행 높이와 도달
범위로 단순화한다. 세트피스 세부 루틴과 충돌 동작, 추가시간은 정밀하게 모델링하지
않는다. xG와 결정력 반영 기대치는 설명용 추정치이고, 득점 판정은 공의 경로에서
나오므로 기존 xG 모델과 같은 보정 수준을 보장하지 않는다.

즉시 중계는 사건 종류·시각·선수를 표시한다. 자동 LLM 생중계는 없으며 감독이
말을 걸 때 경기 상황을 해설한다. 종료 시 정산 대화로 넘어가고 승부차기는 기존
한 발씩 진행하는 경로를 사용한다.

`pnpm balance spatial-match`는 동일 전력 네 경기의 득점·슛·패스와 좌표 범위를
측정한다. 참조 밴드는 초기 조정용이며 리그 전체의 현실성을 검증하는 표본은 아니다.
시드 재현·체크포인트 복구·분할 계산·휴식·정지 장벽은 회귀 테스트로 검증한다.
