# story-fm — 전체 구조

**게임 전체가 하나의 채팅이다.** 유저는 감독 한 사람을 연기하고, 모델(GM)이
나머지 세계 전부를 연기한다. 상태를 바꾸는 유일한 통로는 스킬(도구 호출)이고,
장부(상태·규칙·수치)는 코어가 결정적으로 지킨다.

이 문서는 **무엇이 무엇과 어떻게 이어지는가**를 다룬다. 각 부분의 상세는 링크한
문서가 원본이다.

> 슬라이더와 스프레드시트 대신 **대화**로 팀을 이끈다 —
> 매 시즌이 한 편의 드라마가 되는 AI 풋볼 매니저.

| | Football Manager | story-fm |
| --- | --- | --- |
| 인터페이스 | 메뉴·슬라이더·표 | 자연어 채팅 (+ 보조 뷰) |
| 경기 | 2D/3D 엔진 관전 | 텍스트 중계 — 하이라이트 서사 |
| 선수 | 능력치 덩어리 | 능력치 + 페르소나(성격·기억·관계) |
| 재미의 중심 | 최적화·성취 | 서사·관계·납득되는 드라마 |
| 결과 설명 | 스탯으로 추정 | 원인 태그로 게임이 직접 설명 |

## 1. 세 층 — 데이터 · 시뮬레이션 · LLM

문서 폴더가 곧 이 층이다.

```
           감독 (자연어)                      화면 (읽기 전용 장부)
                │                                      ▲
                ▼                                      │
   ┌────────────────────────┐                          │
   │  LLM  docs/llm/        │  의도를 스킬로, 결과를 서사로
   │  모델 · 에이전트 · 프롬프트 │  ── 상태를 직접 바꾸지 못한다
   └───────────┬────────────┘
               │ 스킬 호출 (Zod 검증)
               ▼
   ┌────────────────────────┐         ┌────────────────────────┐
   │ 시뮬레이션 docs/simulation/│ ◀────▶ │   데이터  docs/data/     │
   │ 경기 · 시즌 · 이적 ·      │  읽고   │ 선수 · 팀 · 대회 · 인물   │
   │ 재정 · 커리어            │  쓴다   │ 게임 상태(세이브)         │
   └────────────────────────┘         └────────────────────────┘
             결정적 순수 함수                  카탈로그 + 세이브
```

- **데이터**는 *무엇이 존재하는가* — 선수·팀·대회·인물, 그리고 그것들이 세이브에
  어떻게 담기는가.
- **시뮬레이션**은 *무엇이 일어나는가* — 경기가 굴러가고 시즌이 흐르고 돈이 오간다.
  전부 결정적 순수 함수라 LLM 없이 테스트된다.
- **LLM**은 *그것을 어떻게 말하는가* — 감독의 말을 스킬로 옮기고 코어의 결과를
  서사로 되돌린다. **자유 텍스트는 게임 상태를 1비트도 바꾸지 못한다.**

### 세 가지 철칙

1. **LLM의 자유 텍스트는 상태를 바꾸지 못한다.** 모든 변경은
   `스킬 호출 → Zod 검증 → 결정적 상태 전이` 경로만 탄다.
2. **경기 결과도 코어가 정한다.** xg 구간 시뮬레이터가 사건을 굴려 확정하고 LLM은
   중계·연출로 옮긴다. 감독의 지시는 전력 패킷을 통해서만 결과에 닿는다.
3. **시간도 상태다.** 날짜는 `advance_time`, 경기 시계는 `advance_match`로만
   흐른다. 대화는 얼마든지 길어져도 세계는 멈춰 있다.

## 2. 한 턴이 지나가는 길

감독이 한마디 하면 이렇게 흐른다 — 이 경로가 이 게임의 전부다.

```
감독 발화
  → GM이 의도를 읽고 스킬을 고른다            docs/llm/agents.md
  → Zod 검증 → 코어가 상태를 바꾼다            docs/data/game-state.md
  → 바뀐 상태로 시뮬레이션이 굴러간다           docs/simulation/
  → 코어가 결과를 사실로 넘긴다 (앵커·사실 카드)
  → GM이 그것을 장면으로 쓴다                  docs/llm/prompts.md
  → 화면은 장부에서 파생된 것만 보여준다
```

**판정이 필요한 자리에서는 코어와 LLM이 일을 나눈다.** 코어가 앵커(가능한 범위)를
박고, LLM이 그 안에서 맥락을 읽어 판단하고, 코어가 한도로 자른다. 실패하면 앵커가
남는다 — 그래서 LLM이 죽어도 게임은 굴러간다. 팀토크·면담·이적 판정·훈련 결산·경기
평점·심경이 전부 이 구조다.

## 3. 채팅 문법

| 요소 | 형식 | 예 |
| --- | --- | --- |
| 행동·연출 | `*…*` | `*고개를 숙인다*` |
| 화자 발화 | `@화자명:` (이름, 직책 아님) | `@스티브 홀랜드: 죄송합니다...` |
| 내레이션 | `@:` — 화자 없는 연출 | `@: *라커룸이 얼어붙는다*` |
| 스킬 호출 | 구조화된 도구 호출 (칩·카드로 노출) | `team_talk({...})` |
| 조작 | `@: [시간 진행 — 하루]` — 손잡이, 감독 발화 아님 | |

- **권한 경계** — 유저는 감독 자신만 움직인다. 유저가 세계를 서술하면 GM은 사실이
  아니라 감독의 시도로 해석해 판정한다.
- 극단 행동도 수용하되 **세계는 반드시 그에 맞게 반응한다.**
- 직책·아이콘은 화면이 붙인다 → [data/people.md](data/people.md)

## 4. 게임 루프

게임은 **7월 1일(여름 이적창 개장)**에 시작한다. 선수단 소집은 7월 둘째 월요일,
개막은 8월 중순 — 프리시즌 동안 영입·훈련·시즌 계획이 선수단보다 먼저 움직인다.

```
온보딩 (팀 선택 + 감독 캐릭터 생성)          → simulation/career.md
 → 일상: 채팅 지시 ↔ 시간 진행(tick)         → simulation/season.md
 → 경기일: 패킷 → 구간 진행 → 검증 → 반영     → simulation/match.md
 → 시즌 종료: 보드 평가 · 전환 · 승강          → simulation/season.md
 → 다음 시즌 (멀티시즌)
```

**tick(하루)이 세계를 굴린다** — 훈련·회복·성장·부상, AI 팀의 경기·이적·재계약·
감독 경질, 협상 응답 도착, 기자회견 개최. 감독의 결정이 필요한 일 앞에서만 멈춘다.
방치의 비용은 규칙이 아니라 시간의 결과다 — 면담을 미룬 불만 선수는 매일 갉힌다.

## 5. 화면

화면은 두 줄이다 — 얇은 상단 띠(시계·팀)와 **무대**. 무대의 기본은 채팅이고,
경기가 시작되면 왼쪽 판세 · 오른쪽 중계·지시로 갈린다. 장부 뷰는 오른쪽 위 아이콘
줄에서 연다.

| 뷰 | 내용 |
| --- | --- |
| 스쿼드 | 전술판(드래그 배치·역할·자동 저장) + 명단(체력·폼·평점·심경) |
| 달력 | 경기·훈련·이적창·추첨 — 칸은 경기만 칩·나머지는 색점, 칸을 열면 상세가 종류별 행(아이콘·대회 칩·승패 색)으로 가른다 |
| 재정 | 월간 보고서·원장·PSR |
| 대회 | 대회별 순위표(진출권·강등 구역)·라운드 일정·브래킷 |
| 커리어 | 감독 오각형·평판·트로피·시즌 기록 |

- 폭 1200px 이상이면 채팅과 장부가 나란히 선다.
- 결과 표시는 두 길뿐이다 — **칩 + 레일 말풍선**(갈 장부가 있는 스킬)과
  **채팅 카드**(결정에 필요한 원본 숫자). 어느 쪽도 아닌 스킬은 노출하지 않는다.
- **화면은 장부에서 파생된 것만 보여준다** — 화면이 따로 계산하면 같은 값이 두
  숫자로 보인다.
- UI에 조작법 안내 문구를 넣지 않는다 — 조작은 보이는 것으로 알린다.

## 6. 세계의 규모

- **5대 리그 96팀**이 리그전을 돌고, 컵용 2부 64팀 + 이적시장 전용 리그(사우디·
  MLS)가 있다. EPL은 실선수 777명 시드.
- 시즌 2,100여 경기 중 감독의 50여 경기만 구간 시뮬, 나머지는 간이 시뮬 —
  **LLM은 한 경기도 결정하지 않는다.**
- 국내 컵 6종 + 유럽 대항전 3종이 실제 규정대로 돈다 →
  [data/competition.md](data/competition.md)
- 세계는 감독 없이도 움직인다 — AI 팀끼리의 이적·재계약·감독 경질, 리그 전체의
  피로·회복·징계.

## 7. 현재 범위와 미구현

플레이 가능한 프로토타입. 온보딩 → 일상 지시 → 경기 → 시즌 전환 → 멀티시즌이
엔드투엔드로 돈다. 주요 미구현(상세는 각 문서의 "미해결"):

- 보드/구단주 요청·목표 시스템 (경질 경고는 있음)
- 세계가 먼저 말 걸기 — 기자회견 외 (설계는 [data/people.md](data/people.md))
- 서사 아크·장기 기억 축적
- 승부차기 연출 — 코어가 조용히 굴린다
- 감독 이직 — 경질이 곧 세이브의 끝이다
- 유스 아카데미 — 콜업은 있으나 육성 구조가 없다
