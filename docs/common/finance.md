# 구단 재정 (Club Finance)

> 실제 구단의 매출·비용 구조를 옮긴 재정 모델 — 실시간 원장 + 월간 보고서.

---

## 1. 재정의 두 층 — 원장과 보고서

**돈이 움직인 자리에서 원장에 한 줄이 적히고, 매월 1일 마감이 그달을 보고서 한
장으로 접는다.** 원장은 카테고리를 함께 지고(§4.1·§4.2) 최근 3개월만 남으며,
보고서는 영구다 — 보고서가 기초 잔고를 들고 있어 원장을 잘라도 잔고가
재구성된다 (§4.4).

**원장과 보고서는 유저 팀만 쌓는다.** AI 구단은 잔고만 갱신한다 — AI 재정은 잔고만
읽히므로 충분하고, 엔트리 비용은 구단 수에 비례한다 (§4.5).

**재정을 움직이는 축은 셋이다.**

| 축        | 움직이는 것                                                              |
| --------- | ------------------------------------------------------------------------ |
| 성적      | 전 시즌 순위 수당 · 생중계 편성 · 관중 · 리그 상금과 대회 상금 (§5)      |
| 리그      | 중계 풀·티켓 단가가 수입을(§5.1), 리그 경제 수준이 지출과 초기치를(§6.2) |
| 구단 체급 | 브랜드 등급이 상업 수입을(§5.3), 구장 수용인원이 매치데이를(§5.2)        |

그 결과가 다시 게임에 물리는 자리는 급여 비중·부채·보드 요청이다 (§9).

## 2. 실제 구단 구조 (설계 기준)

EPL 클럽 회계(2023–25 어림)를 참고한다. 게임에 옮길 가치가 있는 것은 **금액**이
아니라 **무엇이 금액을 움직이는가**다.

### 매출 3대 축

| 축           | 실제 비중 | 움직이는 요인                                                                       |
| ------------ | --------- | ----------------------------------------------------------------------------------- |
| **중계권**   | 40\~50%   | ① 균등 배분 ② **순위별 성적 수당**(1위와 20위 차 £45M+) ③ **생중계 편성 횟수 수당** |
| **상업**     | 30\~45%   | 브랜드 규모(≠ 성적) + 셔츠·키트 계약의 **UCL 진출·우승 보너스 조항**                |
| **매치데이** | 10\~20%   | 수용인원 × 점유율 × 티켓 단가 + 호스피탈리티                                        |

참고 수치: 2023-24 EPL 배분은 우승팀 약 £176M, 최하위 약 £110M. 매치데이는
아스날 약 £130M부터 중소 클럽 £15\~30M까지 벌어진다.

### 비용 3대 축

| 축           | 실제 비중                       | 비고                                                       |
| ------------ | ------------------------------- | ---------------------------------------------------------- |
| **급여**     | 매출의 60\~75% (EPL 평균 \~70%) | 선수 급여 + 비선수(코칭·사무) 급여 12\~18% + **승리 수당** |
| **운영비**   | 15\~25%                         | 경기 운영, 시설·아카데미, 원정·의료                        |
| **부대비용** | —                               | 이자·세금                                                  |

## 3. 설계의 축

| #   | 질문        | 결정                                                                                      |
| --- | ----------- | ----------------------------------------------------------------------------------------- |
| A   | 밸런스 기준 | **현실 정합** — 매출 대비 인건비·순익의 **비율**을 실제 구단에 맞춘다 (§10)               |
| B   | 관중 데이터 | **96팀 구장 수용인원 실측 근사**를 카탈로그에 넣는다 (라이선스 부채는 data-sourcing §7)   |
| C   | 티켓 가격   | **감독이 정한다** — 기준가 대비 비율(0.70\~1.50)로 저장하고 관중이 탄력으로 갚는다 (§5.2) |
| D   | 자본 지출   | **현금 즉시 + 손익 10년 상각** — 구장 증설이 현금과 손익 두 축을 탄다 (§6.1)              |

## 4. 데이터 모델

### 4.1 원장 엔트리 — 실시간 재정 이벤트의 원본

```ts
LedgerEntry = {
  // "led-<날짜>-<category>-<그날 순번>" — 결정적. 원장은 유저 팀만 쌓으므로 teamId가 없다
  id: string,
  date: DateString,
  time?: string,                  // 같은 날 순서 안정 (경기 후 항목)
  kind: "income" | "expense",
  category: FinanceCategory,      // 집계 축 — 안정 키 (§4.2)
  label: string,                  // 사람이 읽는 상세 (서사 재료)
  amount: number,                 // 항상 양수. 방향은 kind가 정한다
  ref?: { type: "match" | "player" | "competition", id: string },
  accounting: "cash" | "noncash", // 상각·선수 처분 손익은 noncash — 현금흐름/손익을 가른다
}
```

- **집계는 언제나 `category`로.** `label`은 표시·서사 전용이며 집계 키가 아니다.
- `ref`는 드릴다운("이 £4.2M은 어느 경기인가")과 서사 연결용.
- **멱등 키는 label이 아니다.** 대항전(`euro-prize.ts`)과 국내 컵
  (`domestic-cup.ts`)의 "같은 상금 두 번 금지" 검사는 `category + ref + 무엇 +
season`으로 만든 안정 키(`prize:competition:{cupId}:{무엇}:S{season}`)를 쓴다 —
  항목명을 고쳐도 같은 상금이 다시 나가지 않는다. `무엇`은 리그 페이즈 ·
  단계(`MatchStage`) · 우승 · 준우승을 가르는 축이라, 한 대회 한 시즌 안에서 키가
  겹치지 않는다.

### 4.1.1 사건의 수입·지출

GM은 대화에서 확정된 거래·지출의 금액과 근거를 `apply_finance_event`로 기록한다.
금액은 양의 안전한 정수이며, 지급 원인은 원장 라벨에 남긴다. 수입·지출은 잔고,
월간 보고서와 급여 비중에 반영된다.

- 수입: `commercial`, `merchandising`, `matchday`
- 지출: `facility`, `travel_medical`, `bonus`, `matchday_opex`

중계권·주급·상각·대회 상금은 해당 계약·경기·대회 명령이 계산하고 집행한다.
코어는 항목과 금액을 검증한다.

### 4.2 카테고리

```
수입: broadcast_equal      중계권 균등 배분
      broadcast_merit      중계권 성적 수당 (전 시즌 순위)
      broadcast_facility   생중계 편성 수당 (경기별)
      matchday             입장·호스피탈리티 수입 (경기별)
      commercial           스폰서십 (셔츠·키트·파트너)
      merchandising        머천다이징
      prize                대회 상금 (리그 순위 + 대항전)
      transfer_income      이적 대금 수령 (현금 · 손익 밖)
      transfer_gain        선수 처분 이익 (noncash)

지출: player_wages         선수 주급
      staff_wages          코칭·사무 스태프 급여
      bonus                성적 보너스 (승리 수당·우승 보너스)
      matchday_opex        경기 운영비
      facility             시설·아카데미 운영
      travel_medical       원정·의료
      capex                구장·시설 투자 (현금 · 손익 밖)
      depreciation         자산 상각 (noncash)
      transfer_fee         이적 대금 지급 (현금 · 손익 밖)
      signing_bonus        선수 계약 보너스 지급 (현금 · 손익 밖)
      transfer_amortization 선수 계약 취득원가 상각 (noncash)
      transfer_loss        선수 처분·계약 종료 손실 (noncash)
```

`capex`와 `depreciation`은 **같은 자산의 두 얼굴**이다(§6.1) — 구장 증설비가 한
번에 나간 현금이고, `자산 상각`이 그 값을 내용연수에 나눠 매달 장부에 적는 몫이다.

선수 계약의 이적료와 계약 보너스도 현금과 손익을 분리한다. 서명 시 날짜별 지급 의무를
기록하고 지급일에 한 번씩 현금을 정산한다. 계약 발효 시 총 취득원가를 자산으로 기록해
계약 기간의 경과 일수에 따라 상각한다. 분할금 지급일은 상각 일정에 영향을 주지 않는다.
매각 구단의 손익은 총 이적 대금에서 잔여 장부가를 뺀 금액이다. 재계약은 남은 장부가를
새 계약으로 넘기며 계약 종료는 잔여 장부가를 정리한다. 재정 화면은 미지급·미수령 의무를
현금 잔고와 따로 표시한다. 협상 절차는 [협상](../negotiation/README.md)에 있다.
1년 안에 만료되는 우리 선수의 계약 조회는 공통 재정 조회가 제공하며, 목록은 에이전트 센터에 표시한다.

원장 라벨은 `<항목명> — <대상>`으로 쓰고 **항목명에 카테고리 이름을 넣지 않는다** —
피드가 카테고리를 따로 찍으므로 같은 말이 한 행에 두 번 선다. 항목이 카테고리와
같으면(선수별 주급) 라벨은 대상만 남긴다.

**정기 비용은 대상별로 적는다** — `player_wages`는 매주 선수 한 명당 한 줄이다.
합계만 적으면 "누구에게 얼마"가 원장에서 사라지고, 감독이 드릴다운할 곳이 없다.
화면이 길어지는 문제는 피드가 접어서 푼다(§8.1).
**AI 팀은 예외로 합계 한 줄**이다 — AI 팀은 애초에 원장을 남기지 않으므로(§4.5)
명세를 만들면 잔고를 스물몇 번 나눠 더하는 값만 치른다.

### 4.3 월간 재정 보고서

```ts
FinanceReport = {
  id: string, teamId: string,
  month: "2026-08", season: number,
  openingBalance: number, closingBalance: number,
  income:  Array<{ category, amount, top: Array<{label, amount}> }>,  // top 3
  expense: Array<{ category, amount, top: Array<{label, amount}> }>,
  incomeTotal: number, expenseTotal: number,
  cashNet: number,      // accounting:"cash"만 — 통장의 변화
  pnlNet: number,       // 자본 투자 제외 + 자산 상각 포함 — 장부의 변화
  wageRatio: number,    // (player_wages + staff_wages) / 매출
  seasonToDate: { income, expense, cashNet, pnlNet },
  noteCards: FinanceNote[],  // 코어가 결정적으로 붙이는 **사실 카드** — 조언은 없다 (§7.1)
  highlights: Array<{   // 그달의 큰 비정기 항목 — 날짜와 금액을 남긴다 (§8.2)
    date, kind, category, label, amount
  }>,
}
```

`state.financeReports` — **유저 팀만** 생성한다.

노트는 문장이 아니라 카드다 — `{ code, value?, limit? }` 셋이면 월간 보고가 말할 수
있는 것이 전부 담긴다 (→ [overview.md](../overview.md) §1 철칙 4).

| `code`                   | `value`     | `limit`   |
| ------------------------ | ----------- | --------- |
| `wage-ratio-danger`      | 급여 비중   | 위험 문턱 |
| `wage-ratio-caution`     | 급여 비중   | 주의 문턱 |
| `cash-deficit-operating` | 현금 감소액 | —         |
| `debt-over-limit`        | 부채        | 부채 한도 |
| `debt-under-limit`       | 부채        | 부채 한도 |

문장은 화면과 GM이 만든다. 읽을 때는 `teamId === userTeamId`로 거른다 (`userReports`).

### 4.4 보존 정책

| 데이터      | 보존                                         |
| ----------- | -------------------------------------------- |
| 상세 원장   | **최근 3개월 롤링** — 실시간 피드·드릴다운용 |
| 월간 보고서 | **영구** — 집계·추이용                       |

보고서가 `openingBalance`를 갖기 때문에 원장을 잘라도 잔고 재구성이 가능하다.
불변식(테스트로 고정): `가장 오래된 보고서의 openingBalance + 이후 모든 흐름 = balance`.

카테고리 합계만 남기면 **"그 £37.5M이 언제 들어왔나"**에 답할 수 없다 — 두 건이
합쳐진 한 숫자만 남는다. 그래서 마감할 때 **그달의 큰 비정기 항목만 날짜째로
`highlights`에 옮겨 적는다**(§8.2). 절단 전에 옮기므로 원장이 잘려도 남고, 문턱을
넘는 일회성 항목만이라 달마다 한두 줄이다.

### 4.5 AI 팀은 잔고만

AI 팀은 **엔트리를 남기지 않고 잔고만 갱신**한다. AI 재정은 잔고만 읽히므로
충분하고, 재정이 도는 160개 구단 × 월 10여 건의 엔트리는 세이브만 부풀린다. `recordFinance`가 이 분기의 유일한
지점이다.

**재정이 도는 구단은 `isClubTeam && !isOutsideOurEconomy`다** — 무소속
(`freeagents`)은 클럽이 아니라 클럽이 없는 상태라 낼 주급도 받을 수입도 없고,
경기를 하지 않는 명단 전용 리그(사우디·MLS)는 재정을 굴리지 않는다. 카탈로그의
169개 자리에서 그 아홉을 빼면 160개 구단이다.

그래서 상금 중복 지급은 원장 조회가 아니라 **`FINANCE.prizesPaid` 키가 막는다.**
원장은 3개월만 남고 AI 팀은 아예 없으므로 "원장이 곧 사실"이 성립하지 않는다.

AI 팀도 간이 시뮬 경기마다 홈 수입·생중계 수당·원정 비용을 받는다
(`applyAiMatchFinance` — 순위표·폼을 쓰지 않는 가벼운 공식). 이게 없으면 AI 팀은
매치데이 수입 없이 주급만 내는 구조적 적자에 빠진다.

### 4.6 카탈로그가 든 재정 축

```ts
// packages/engine/src/common/data/club-profile.ts — 1부 96팀 + tier 폴백 4개
ClubProfile = {
  stadium: string,
  capacity: number, // 실측 근사 (결정 B)
  commercialTier: 1 | 2 | 3 | 4, // 브랜드 규모 — 전력 tier와 별개
};
LeagueCatalogEntry += {
  broadcastPool: number, // EPL 1.00 기준 배율
  avgTicketPrice: number, // 리그 평균 티켓 단가
};
```

구장·브랜드는 `TeamCatalogEntry`에 얹지 않고 **별도 파일**에 둔다 — 정체성
(이름·리그·전력 등급)과 살림(구장·브랜드)은 바뀌는 이유가 다르고, 재정 밸런싱은
표 하나만 만지는 편이 낫다. 등재되지 않은 팀은 tier 폴백을 쓴다.

`commercialTier`를 `tier`와 분리하는 이유: 뉴캐슬·에버튼·발렌시아는 성적보다
브랜드가 크고, 본머스·브렌트포드는 반대다. 실제 상업 수입 격차의 원인이다.

리그 중계권 풀 배율(초기값): EPL 1.00 · 라리가 0.45 · 분데스리가 0.35 ·
세리에 A 0.32 · 리그 1 0.16.

## 5. 수입 공식

모두 **결정적**이다 — 난수는 시드 해시만 쓴다 (같은 세이브·같은 날 = 같은 금액).

### 5.1 중계권

| 항목        | 시점      | 공식 (EPL 기준값)                                                            |
| ----------- | --------- | ---------------------------------------------------------------------------- |
| 균등 배분   | 매월 1일  | 시즌 £110M ÷ **12개월** = 월 £9.2M                                           |
| 성적 수당   | 매월 1일  | `£2.4M × (리그팀수+1 − 전 시즌 순위)` ÷ 12개월 → 1위 월 £4.0M, 20위 월 £0.2M |
| 생중계 수당 | 경기 직후 | 국내 리그 TV 슬롯 경기당 £1.1M                                               |

- **12개월 분납**이다. 실제 배분은 시즌 중 분기 지급이지만, 경기 없는 달(6·7월)에
  방송 수입을 0으로 두면 그 달의 급여 비중이 300%로 튀어 지표가 무의미해진다 —
  실제 구단도 현금은 연중 들어온다. 총액을 유지하고 고르게 나눈다.

- **세 항목 모두 리그별 `broadcastPool` 배율을 곱한다** — 균등 배분도 포함이다
  (`equalShareFactor`). 실제로 각국 중계권 규모는 리그마다 크게 다르다
  (리그1은 EPL의 0.16). 균등분만 배율을 끄면 약체 리그 구단이 EPL 수준 주급을 내면서
  6분의 1 수입을 받아 파산한다 — 수입과 지출이 같은 축을 타야 성립하고, **주급 곡선도
  리그를 안다**(`wages.ts` · §6.2).
- **TV 슬롯 판정은 캘린더에서 파생한다** — 주말 라운드를 금·토·일·월 실제 중계
  슬롯으로 흩는 편성이 이미 있으므로(AGENTS 현재 상태), **토요일 15:00만 비중계**로
  본다(실제 블랙아웃 규약). 시즌 38경기 중 약 32경기가 편성된다.
- **대항전은 생중계 수당 없음** — 유럽 방송 수입은 이미 UEFA 배분(참가비·승무
  수당)에 들어 있어 이중 계상이 된다.
- **첫 시즌은 전 시즌 순위가 없다** → 구단 `tier`로 대체한다 —
  `ASSUMED_RANK_BY_TIER`(1등급 3위 · 2등급 7위 · 3등급 12위 · 4등급 17위)가 그 자다.
  리그 팀 수를 세지 못하면 `DEFAULT_LEAGUE_SIZE`(20)를 쓰고, 리그 카탈로그에
  배율이 없으면 `DEFAULT_BROADCAST_POOL`(0.3)을 쓴다.
  (`euroEntrants`의 첫 시즌 처리와 같은 패턴). AI 팀은 지난 시즌 순위표를 저장하지
  않으므로(시즌 전환에서 파생 후 버린다) 항상 tier 어림을 쓴다 — AI 재정은 잔고만
  읽히므로 충분하다.
- 합계 어림 (12개월 만근 · 세 항목의 합 × `broadcastPool`):

  | 리그       | pool | 팀 수 | 우승팀 | 최하위 |
  | ---------- | ---- | ----- | ------ | ------ |
  | EPL        | 1.00 | 20    | £193M  | £148M  |
  | 라리가     | 0.45 | 20    | £87M   | £66M   |
  | 분데스리가 | 0.35 | 18    | £65M   | £51M   |
  | 세리에 A   | 0.32 | 20    | £62M   | £47M   |
  | 리그 1     | 0.16 | 18    | £30M   | £23M   |

  EPL 값은 실제 배분(£176M / £110M)과 근접하다. 리그별 수입 차에 맞춰 주급·초기
  재정에도 리그 배율을 적용한다 (§6.2).

**리그전을 굴리지 않는 리그**(컵 전용 2부)는 홈 경기가 없어 매치데이 수입이 없다 —
주급·스태프·시설·이자는 매달 내면서. 그 몫을 같은 공식으로 월할해 채운다
(`unplayedLeagueMatchdayMonthly`). 새 상수를 만들지 않고 수용인원 × 기본 점유율 ×
티켓가 × 호스피탈리티에서 파생한다 — 임의 금액을 넣으면 밸런스의 근거가 사라진다.

**무소속(`freeagents`)은 구단이 아니다** — `isClubTeam`으로 걸러 재정을 굴리지
않는다 — 굴리면 선수 명부 하나가 매달 시설비와 이자를 내며 적자를 쌓는다.

### 5.1.1 리그 순위 상금 — 시즌 리뷰에서

`(리그 팀수 + 1 − 순위) × £700k × broadcastPool`. 1부 다섯 리그 합계 연 £321M
(EPL £147M · 라리가 £66M · 세리에 A £47M · 분데스리가 £42M · 리그 1 £19M).

- **리그는 언제나 세이브 기준**(`leagueOfTeamIn`)이다. 승강은 `state.leagueOf`로만
  표현되므로 카탈로그 리그로 순위표를 부르면 강등팀도 승격팀도 자기가 없는 표를 받아
  순위가 0이 되고 **상금이 통째로 사라진다.**
- **리그전을 하지 않는 2부는 받지 않는다.** 0경기 0승점 순위표는 정렬이 안정적이라
  카탈로그 등재 순서가 그대로 순위가 되고, 매 시즌 같은 팀이 같은 돈(다섯 리그 합
  연 £17.0M)을 받아 2부의 재정 서열이 영구히 굳는다. 그 리그의 수입은 매치데이
  대체분이 메운다.
- **대항전 상금도 받지 않는다** — 2부 리그에는 유럽 티켓이 없다
  ([competition.md](../match/competition.md) §4). 그래서 2부의 수입은 매치데이
  대체분뿐이고, 그 수지는 `finance-second-tier` 하네스가 지킨다.

### 5.2 매치데이 (홈경기 직후)

```
attendance = round(capacity × occupancy)
수요       = max(base + Σ보정, OCCUPANCY_FLOOR 0.45)
occupancy  = min(수요 × 가격 탄력, 1.00)
단가       = 리그 avgTicketPrice × tier 보정(리그 폭) × 감독 배율 × 대회 보정
수입       = attendance × 단가 × (1 + 호스피탈리티율)
```

| 요인        | 값                                                                                                                      |
| ----------- | ----------------------------------------------------------------------------------------------------------------------- |
| base        | `OCCUPANCY_BASE` — tier1 0.97 · tier2 0.90 · tier3 0.85 · tier4 0.80                                                    |
| 순위        | `(OCCUPANCY_RANK_PIVOT(11) − 현재순위) / OCCUPANCY_RANK_SPAN(10) × OCCUPANCY_RANK_SWING(0.04)`                          |
| 최근 폼     | `OCCUPANCY_FORM_MATCHES`(5)경기 — `(승률 − OCCUPANCY_PAR_WIN_RATE(0.40)) × OCCUPANCY_FORM_SWING(0.05)` → −0.02 \~ +0.03 |
| 상대 매력도 | `OCCUPANCY_BY_OPPONENT_TIER` — tier1 +0.04 · tier2 +0.02 · tier3 0 · tier4 −0.02                                        |
| 더비        | `OCCUPANCY_DERBY_BONUS`(0.03) × `heat`(1\~3) — +0.03 \~ +0.09 ([team.md §3.2](team.md))                                 |
| 대회        | `OCCUPANCY_CUP_BONUS` — 컵 경기(국내 컵·대항전) +0.02                                                                   |
| 킥오프 슬롯 | `OCCUPANCY_WEEKNIGHT_PENALTY` — 월\~목요일 −0.03                                                                        |
| 시드 해시   | `OCCUPANCY_JITTER`(0.04) — ±0.02 (결정적 미세 변동)                                                                     |
| 하한        | `OCCUPANCY_FLOOR`(0.45) — **성적이 만드는 몫에만 걸린다** (아래)                                                        |

유럽전은 단가에 `EURO_TICKET_FACTOR`(1.15)가 붙고, 카탈로그에 평균가가 없으면
`DEFAULT_TICKET_PRICE`(£30)를 쓴다.

**더비 항은 상대 매력도와 따로 선다.** 관중을 부르는 것이 상대의 체급이기만 하면
리버풀-에버턴이 리버풀-본머스와 같은 자다 — 실제로 매진되는 것은 앞의 경기다.
tier1 구단(base 0.97)은 어느 heat에서도 만석에 붙으므로 이 항이 실제로 보이는 것은
중·하위 구단의 더비다.
호스피탈리티율 = tier1 0.35 · 2 0.28 · 3 0.20 · 4 0.15.

**하한은 성적이 만드는 몫에만 걸린다.** 순위·폼·상대가 아무리 나빠도 0.45는 오지만,
그 뒤에 곱하는 **가격 탄력과 친선 배율은 하한 밖**이다 — 표를 두 배 값에 팔면 관중은
0.45 아래로 내려가야 하고, 친선을 만석 판정에 넣지 않으려면 배율이 clamp 뒤여야 한다.
그래서 상한(1.00)만 곱한 뒤에 다시 잡는다: **표가 모자라던 구단은 값을 올려도 한동안
자리가 찬다** — 가격 결정권이 구단마다 다른 답을 갖는 것이 이 순서에서 나온다.

#### 리그 안의 티켓 폭은 리그마다 다르다 (`LEAGUE_TICKET_SPREAD`)

```
tier 보정 = 1 + (TICKET_TIER_FACTOR[tier] − 1) × 리그 폭
TICKET_TIER_FACTOR = tier1 1.30 · 2 1.10 · 3 0.95 · 4 0.80   (EPL의 폭)
```

`TICKET_TIER_FACTOR`는 EPL에서 잰 값이라 그대로 전 리그에 쓰면 **폭이 넓은 리그의
최저가 구단이 실제보다 비싸다.** 리그 폭은 그 표를 1을 축으로 늘이고 줄이는 한 개의
수다 — 리그 평균은 거의 그대로 두고 안쪽의 격차만 움직인다.

| 리그       | 폭   | 실효 tier 보정 (1 / 4) | 왜                                              |
| ---------- | ---- | ---------------------- | ----------------------------------------------- |
| EPL        | 1.00 | 1.30 / 0.80            | 표를 잰 자리 — 축이다                           |
| 세리에 A   | 1.35 | 1.41 / 0.73            | 유벤투스·인테르와 레체의 값 차가 EPL보다 크다   |
| 리그 1     | 1.35 | 1.41 / 0.73            | PSG 한 구단이 리그 위쪽을 통째로 끌어올린다     |
| 라리가     | 1.30 | 1.39 / 0.74            | 레알·바르사와 중소 구단 사이가 벌어져 있다      |
| MLS        | 0.90 | 1.27 / 0.82            | 프랜차이즈 구조라 값이 고르다                   |
| 분데스리가 | 0.75 | 1.23 / 0.85            | 입석·시즌권 보조가 리그 전체의 값을 눌러 붙인다 |
| 사우디     | 0.70 | 1.21 / 0.86            | 값 자체가 낮아 안쪽에서 벌어질 여지가 적다      |

**2부는 그 나라 1부의 폭을 쓴다** — 가격 문화는 리그가 아니라 나라의 것이다. 표에 없는
리그는 1.00이라 아무 일도 일어나지 않는다.

#### 감독이 정하는 티켓 가격 (`set_ticket_price`)

```
기준가     = 리그 avgTicketPrice × tier 보정(리그 폭)      ← 감독의 배율을 타지 않는다
배율       = clamp(부른 값 ÷ 기준가, TICKET_RATIO_MIN 0.70, TICKET_RATIO_MAX 1.50)
가격 탄력  = max(0, 1 − (배율 − 1) × TICKET_ELASTICITY 0.90)
```

감독이 부르는 것은 **금액(£)**이고 코어가 배율로 접어 `finance.ticketPrice`에 든다 —
승격·강등으로 기준가가 바뀌어도 감독의 선택이 그 자리에 남는다. 폭 밖의 값은 반려하지
않고 폭에서 잘라 받은 뒤, 실제로 선 값을 사실 카드가 적는다. 설정한 값은 이후 경기 수입 계산에 적용된다. **감독의 구단에만 걸린다**; AI 구단은 언제나 기준가다.

**탄력을 0.90으로 둔 이유**: 수입은 `배율 × 가격 탄력`에 비례하고, 그 곱이 최대가 되는
지점은 `(1 + 탄력) ÷ (2 × 탄력)` = **배율 1.06**이다. 즉 `avgTicketPrice`가 이미 시장이
찾아 놓은 값이고, **그 위에서 더 벌 수 있는 것은 표가 모자란 구단뿐이다** — 수요가 1을
넘어 잘리고 있던 구단은 잘리던 몫만큼(최대 +10% 안팎) 값을 올려도 관중을 잃지 않는다.
값을 폭 끝(1.50)까지 올리면 관중이 0.55배로 줄어 수입이 오히려 준다.

내리는 쪽은 **언제나 수입이 준다** — 관중은 늘고 돈은 줄어드는 것이 그 선택의 내용이다.
관중을 사는 데 값을 치르는 것이지 다른 이득이 붙지 않는다(§12).

**리그 평균 단가는 EPL 대비 비율로 잡는다** — 실제로도 다섯 리그의 티켓 가격 차는
중계권 차보다 크다(EPL만 유독 비싸고 분데스리가는 입석·시즌권 보조로 가장 싸다).

| 리그       | 단가 | EPL 대비 | 실효 객단가 (tier1 / tier4) |
| ---------- | ---- | -------- | --------------------------- |
| EPL        | £30  | 1.00     | £52.7 / £27.6               |
| 라리가     | £17  | 0.57     | £31.9 / £14.5               |
| 세리에 A   | £15  | 0.50     | £28.5 / £12.6               |
| 분데스리가 | £13  | 0.43     | £21.5 / £12.7               |
| 리그 1     | £12  | 0.40     | £22.8 / £10.1               |

실효 객단가는 호스피탈리티까지 얹은 값이고, **tier 보정에 리그 폭이 걸려 있다**(위) —
같은 £15 리그라도 세리에 A의 위아래 차가 분데스리가보다 넓다.

**절대값은 실제의 0.67배다** — 매출의 다른 축과 같은 눈금이다(§10.1). 축마다 배율이
다르면 **구단을 가르는 축이 브랜드가 아니라 구장 크기**가 된다. 세 축이 같은 배율에
서야 아스날의 수입 구성이 실제와 겹친다(§10.2).

**중립 경기(결승)는 홈 수입이 없고 양 팀 다 원정 비용을 낸다.** 게이트는 개최지의
몫이라 우리 장부에 오르지 않고, 두 팀 모두 남의 구장으로 이동한다. 편성표의 홈·원정
표기는 중립 경기에선 자리 이름일 뿐이라, 그것으로 원정비를 가르면 같은 결승에서 한
팀만 £120k(유럽 £400k)를 낸다.

**프리시즌 친선은 리그의 60%다** — 관중과 단가 **양쪽**에 0.6을 곱하므로 게이트
수입은 리그 홈경기의 약 36%다(실제 프리시즌도 관중이 덜 들고 표가 싸다). 관중
보정은 리그와 같은 공식을 쓰되 순위 보정이 사실상 0이고(프리시즌엔 순위표가
비어 있다) 대회 보정도 없다. **최근 5경기 폼 보정도 대회 경기만 센다** — 친선의
승패가 표를 팔면 프리시즌 성적이 살림에 남는다(season.md §2). 배율은 하한(0.45)을
적용한 **뒤에** 곱한다 — 친선을 만석 판정에 넣지 않기 위해서다. 홈 운영비(opex)는
매치데이 수입에 같은 비율로 붙고, 친선 원정 비용은 없다.

**중계권 수당은 없다**(`isTelevised`가 거짓) — 대회 상금도 승리 수당도 없다.
친선은 장부에 홈 매치데이로만 남는다.

**친선 원정에는 비용을 매기지 않는다** — 주최 측이 부담하는 자리다. 실제 프리시즌은
초청이라 판을 벌인 쪽이 게이트를 갖고 방문 클럽에는 출전료가 간다. 우리 모델엔
출전료가 없으므로 방문 쪽에만 정규 원정비(경기당 £120k)를 물리면 **한쪽만 있는
장부**가 된다. 그 차액이 특히 아픈 곳이 **리그전을 굴리지 않는 2부**다(§5.1) —
메울 리그 수입이 없어 프리시즌마다 구조적으로 깎이고, 실측에서 그 리그의 중간
잔고가 흑자에서 적자로 뒤집힌다. 새 상수를 만들어 깎는 대신 매기지 않는다.

**상대 구단의 몫도 같은 자리에서 넣는다.** 간이 시뮬은 두 팀을 다 챙기는데
(`applyAiMatchFinance`) 유저 경기는 유저 쪽만 기록해, 유저가 원정 가는 시즌 열아홉
경기의 **홈 팀이 입장 수입을 받지 못한다**(대신 운영비·원정비도 내지 않는다).
`applyMatchFinance`가 그 함수를 함께 부르고, 그 함수는 유저 팀을 건너뛰므로 겹치지
않는다.

### 5.3 상업·머천다이징 (매월 1일)

```
commercial   = base(commercialTier) × (1 + 조항)
조항         = UCL 진출 +0.15 · UEL 진출 +0.06 · UECL 진출 +0.03 · 지난 시즌 트로피 +0.20
               (`COMMERCIAL_UCL/UEL/UECL_CLAUSE` · `COMMERCIAL_TROPHY_CLAUSE`)
merchandising = base(commercialTier) × (1 + 최근 승률 보정)
보정          = clamp((승률 − MERCH_PAR_WIN_RATE 0.40) × MERCH_FORM_SLOPE 0.25, ±MERCH_FORM_SWING 0.10)
               창은 MERCH_FORM_MATCHES(6)경기, 친선 제외
승률          = Σ(경기 무게 × 승리) ÷ Σ(경기 무게)
               무게는 1, 더비는 1 + MERCH_DERBY_WEIGHT(0.5) × heat
```

| 브랜드 | 연 상업+굿즈 | 실제 어림 | 누가                      |
| ------ | ------------ | --------- | ------------------------- |
| 1      | £145M        | £220M     | 맨유·레알·바이에른·아스날 |
| 2      | £55M         | £82M      | 뉴캐슬·에버턴·발렌시아    |
| 3      | £24M         | £36M      | 중소 1부                  |
| 4      | £10M         | £15M      | 승격팀·2부                |

**등급 폭이 15배다** — 실제 격차(맨유 £300M 대 승격팀 £20M)가 그만큼이다. 값은
**실측 × 0.67** — 중계권이 이미 그 눈금에 있고(§5.1) 매치데이도 같은 배율에 선다(§5.2).

상업:굿즈는 대략 3:1로 가른다 (실제 회계의 스폰서십 대 리테일 비).

**굿즈 창에서 더비는 한 경기보다 무겁다** — heat 3이면 2.5경기다. 실제로 유니폼이
팔리는 것은 라이벌을 이긴 주간이고, 진 주간에는 반대다. 창은 그대로 6경기라
더비 하나가 다른 결과를 밀어내지는 않는다 — 무게만 바뀐다. 승률의 상한이 1이라
보정은 여전히 ±0.10에서 멈춘다.

조항은 **지난 시즌 성적에서 파생**한다 — 저장하지 않는다. 실제 스폰서 계약의
성과 보너스 조항을 옮긴 것이고, "유럽 진출이 다음 시즌 살림을 바꾼다"는 루프가
여기서 생긴다. 진출 조항은 대회마다 쌓이고, **트로피는 종류를 가르지 않는다** —
리그·국내 컵·대항전 어느 것이든 지난 시즌 우승이 하나라도 있으면 +0.20이고 두 개여도
같은 값이다. **트로피는 전 구단의 것으로 쌓이므로 AI 구단도 같은 조항을 받는다**
(`state.trophies` — [career.md](../story/career.md) §6).

**우승·진출 보너스의 순위 문턱은 고정된 계단이다** — 리그 팀 수에서 파생하지 않고,

선수단에 무엇을 약속했는가의 자이지 진출 자체의 판정이 아니다. 유저 팀에만 붙는다.

### 6.1 자산 상각 — 구장도 같은 두 축을 탄다

```
12,000석 증설 · £96M
  현금흐름  2026-08  −£96.0M   (즉시, capex)
  손익      매월      −£0.8M × 120개월 (depreciation)
```

구장 증설비는 **자산**이다: 현금은 착공일에 한 번 나가고, 손익은 내용연수에 나눠
문다. 전액을 착공 달의 비용으로 잡으면 구장을 키운 시즌 하나가 손익을 통째로 먹고
그다음 아홉 시즌은 공짜로 쓰는데, 실제 회계도 게임의 결도 그렇지 않다
— **좌석은 열 시즌에 걸쳐 값을 내므로 값도 열 시즌에 걸쳐 문다.**

- **내용연수는 `STADIUM_ASSET_MONTHS`(120개월 · 10년)이다.** 실제 구장의 감가상각은
  25\~50년이지만 우리 세계는 그 눈금에서 살지 않는다. 10년을 고른 근거는 §9.3이 이미
  적어 둔 **회수 기간**이다 — 12,000석이 시즌당 £9M 남짓을 벌고 £96M이 들었으니, 상각
  기간을 회수 기간에 맞추면 증설은 **갚는 동안 손익이 대략 0이고 다 갚은 뒤부터 이익**이
  된다. 감독이 원장에서 읽을 수 있는 이야기가 그 자리에서 나온다.
- **자산은 `TeamFinance.assets`에 든다** — `{ id, label, cost, since, months }`. 취득원가와
  기간이 자산의 정체다.
- **월초 정산이 자산을 훑어 `depreciation` 한 줄씩 적는다.** `since`로부터 지난 개월이
  `months`에 닿으면 멈춘다 — 상각 총합은 취득원가를 넘지 않는다.
- **`capex`는 손익에서 빠지고 `depreciation`은 현금에서 빠진다.** 보고서의 두 축이 이렇게 선다:

  ```
  현금 순증 = 수입 − (지출 − depreciation)
  장부 손익 = 수입 − (지출 − capex)
  ```

  그래서 장부 손익에서 **구장은 착공한 시즌이 아니라 열 시즌에 나눠 물린다.**

- 감독의 구단만 자산을 갖는다 — 보드 요청은 감독의 길이고(§9.3) AI 구단은 구장을 키우지 않는다.

### 6.2 리그 경제 수준 — 지출과 초기치도 리그를 안다

수입은 리그를 아는데(§5.1의 `broadcastPool`) 지출·초기치가 tier만 보면 비대칭이
생긴다. 세리에B 구단이 EPL tier와 같은 시설비를 내면서 리그 배율이 걸린 수입만
받아 가라앉고, PSG가 아스날과 똑같은 £120M으로 시작해 6분의 1 중계 수입으로 같은
살림을 산다. **두 자리가 같은 축을 쓴다** (`clubEconomyLevel` —
`common/data/league-economy.ts`):

| 무엇                      | 공식                                  |
| ------------------------- | ------------------------------------- |
| 시설·아카데미 · 이자·세금 | tier 정액 × 경제 수준                 |
| 초기 잔고                 | tier 정액(`TIER_FINANCE`) × 경제 수준 |

이 표는 재정 상수와 함께 놓이지 않고 **카탈로그 층**에 산다.

**축은 `broadcastPool`이 아니다.** 중계권 격차(EPL 대비 리그 1은 0.16)를 비용에
그대로 곱하면 인건비가 실제보다 훨씬 아래로 내려간다. 임금 모델이 이미 갖고 있던
**리그 임금 수준**(EPL 1 · 라리가 0.62 · 세리에 A 0.58 · 분데스리가 0.58 ·
리그 1 0.42)이 그 완만한 곡선이고, 실제로도 비용 격차는 수입 격차보다 작다 —
중계 수입이 적은 리그도 구단이 다른 수입으로 살림을 대기 때문이다.

- 여기에 **브랜드 보정**이 얹힌다 — 세계적 브랜드는 자국 리그 사정을 덜 탄다
  (레알·바이에른·PSG). 임금이 쓰는 보정을 그대로 쓴다.
- **2부는 그 나라 1부에서 파생한다** — 상수 하나로 묶으면 챔피언십과 리그 2가 같은
  살림을 산다. 실측 연 인건비: 챔피언십 £18.3M · 세리에B £14.3M · 리그 2 £12.7M.
- EPL은 배율 1이므로 **§10.2의 측정이 그대로 유지된다** — 이 작업은 EPL을 기준으로
  두고 나머지 리그를 그 눈금에 맞춘 것이다.
- ⚠️ **고정비는 세이브를 읽는다** — 시설·이자 고정비는
  `clubEconomyLevelIn(state, teamId)`으로 **지금** 리그·체급을 본다. 카탈로그
  소속으로 읽으면 강등한 구단이 2부 수입을 받으면서 1부 고정비를 낸다. 초기 잔고는
  세이브가 서기 전에 도는 값이라 카탈로그판
  (`clubEconomyLevel`)이 맞다 ([game-state.md](game-state.md) §1).

### 6.3 명명 스태프 — 파생 비율에서 덜어 낸다

수석코치·코치·의료진은 **이름과 계약을 가진 사람들**이고(→ [people.md](../story/people.md)
§2-2), 그들의 연봉은 매월 `staff_wages`에 **대상별 한 줄**로 선다 — 「이재현 (피지컬
코치)」. 감독이 자기 구단의 인건비를 사람 단위로 읽는 자리다.

```
명명 합계 = Σ (그 구단의 employment.contract.salary) ÷ 12
파생 몫   = max(0, 월 주급 총액 × STAFF_WAGE_RATE[tier] − 명명 합계)
staff_wages 총액 = 명명 합계 + 파생 몫 = max(파생 기준액, 명명 합계)
```

- **총액은 지금 실측과 같다** (§10.2). 명명된 사람은 스태프 급여를 **늘리는 것이
  아니라 그 안에서 이름을 얻는 것**이다 — 구단은 이미 코치와 의료진에게 급여를 주고
  있었고, 달라진 것은 그 몫에 얼굴이 붙었다는 사실뿐이다. 밸런스 실측을 지키는 방식이
  이것이다: 비율을 손대지 않고, 파생 줄에서 명명된 만큼을 뺀다.
- **명명 합계가 파생 기준액을 넘으면 파생 줄은 0이 된다.** 시작 인원 넷은 기준액 한참
  아래라 새 게임의 장부는 파생 비율 그대로다. 스태프 계약은 시즌 전환에서 같은 조건으로
  갱신된다.
- **AI 구단은 명명 스태프가 없다** — 파생 줄 하나뿐이다. 감독 구단만
  사람이 서고, 그 이유는 인물 카드를 96구단에 세울 이유가 없는 것과 같다.

### 7.1 시즌의 마지막 달은 전환이 닫는다

월초 훅만으로는 **시즌의 마지막 달이 시즌 안에서 마감되지 않는다.** 시즌은 6월 초에
끝나고 전환이 곧바로 7월 1일로 건너뛰므로 다음 월초 훅은 8월 1일이고, 그때 6월
보고서가 나온다. 그런데 6월은 리그 상금과 시즌 보너스(§5.1.1·§6)가 앉는 달이라, 그대로 두면 그 시즌의
장부가 가장 큰 달을 빠뜨린 채 다음 시즌으로 넘어간다.

그래서 `endSeason`이 **시즌 리뷰와 전환 사이에서** 마지막 달까지 마감한다
(`closeSeasonBooks`). 순서는 이것 하나뿐이다:

```
시즌 리뷰 (상금·보너스가 6월 원장에 앉는다)
  → 남은 주급 지급 → 6월 마감 (보고서 발행)
  → 시즌 전환
```

- **마감은 `state.season`·`state.calendar`가 아직 끝난 시즌일 때** 돌아야 한다.
  보고서의 시즌 번호는 그 둘로 역산하기 때문이다(`seasonOfMonth`).
- 8월 1일의 월초 훅은 6월 보고서가 이미 있는 것을 보고 건너뛴다 (멱등).
- **마감이 남은 주급을 함께 문다.** 주급은 월요일에만 나가는데(§6) 전환이 6월의
  남은 월요일을 건너뛴다. 정액 수입·고정비는 1일에 한 달치가 다 앉으므로, 그대로
  두면 마지막 달만 수입은 만근이고 주급은 한 주치다 — 그 후한 값이 시즌
  장부에 그대로 남는다. 그래서 마감 **전에** `closeSeasonBooks`가
  **다음 시즌 시작(7월 1일) 전날까지 남은 월요일 수**만큼 주급을 문다
  (`payWeeklyWages(state, weeks)`). 선수는 6월 30일까지 계약돼 있으므로 회계로도
  나가야 하는 돈이다. 원장에는 시즌 종료일 하루에 `(N주)`로 한 줄 선다 — 지나가지
  않은 날짜에 돈을 앉힐 수는 없다.

## 8. 실시간 노출

원장은 이미 실시간이므로 보이게만 한다.

1. **재정 활동 피드** — 오피스 재정 뷰 상단, 최근 **30줄** (날짜 · 카테고리 ·
   상세 · ±금액). → §8.1
2. **달력 일지 연동** — 큰 비정기 항목은 일자별 events에 `money`로 함께 (§8.2)
3. **tick 다이제스트** — 홈경기 수입·상금은 발생 즉시 한 줄

### 8.1 피드는 접는다 — 30줄은 사건 30개다

**접는 것은 뷰의 일이다.** 원장은 대상별로 정확히 남고,
화면에 내려보내는 피드에서만 묶는다.

정기 비용은 한 사건인데 원장에는 여러 줄로 앉는다 — 주급은 매주
**선수 한 명당 한 줄**이라 계약이 마흔다섯이면 그 하루가 피드를 통째로 덮는다. 접지
않으면 30칸이 사건 30개가 아니라 **한 날 한 카테고리**가 된다.

**묶는 단위** — `날짜 · 수입/지출 · 카테고리 · 현금/장부 · 항목명`이 모두 같은 원장
엔트리. 항목명은 라벨의 `—` 앞부분이고, 없으면 카테고리 자체다.

**대상이 있는 줄만 묶인다.** 항목명이 붙었거나 `ref`가 무언가를 가리키는 줄이다.
`이자·세금`과 `시설·아카데미 운영`은 카테고리가 같아도 서로 다른 사건이라 각자 선다 —
묶으면 라벨이 사라지고 두 항목이 한 금액이 된다. 항목명이 카테고리 이름을 되풀이하는
줄은 항목명이 없는 것으로 읽는다.

**한 줄이 싣는 것** — 합계와 대상별 명세(이름 · 금액, **큰 금액부터**). 한 건짜리
묶음은 접지 않고 원래 라벨 그대로 선다.

**항목명 자리는 비워 두지 않는다.** 카테고리로만 묶인 줄은 항목명이 없지만, 건수만
남기면 그 자리가 아무것도 알려주지 않는다 — 가장 큰 명세의 이름과 나머지 수로 읽는다
(`브루누 페르난데스 외 44명`). **세는 단위는 뷰가 낱말로 낸다** — 묶인 엔트리의
`ref.type`이 하나로 모이면 그것이 정한다(`player` → 명, 아니면 건). 무엇이 묶였는지는
코어만 알고, 문장(`외 N명`)은 목록과 그 낱말로 화면이 잇는다 (overview §5). 펼침은
갈매기 표식이 알린다 — 달력 `기록` 블록과 전술판이 이미 쓰는 규칙이라 새 상호작용이
아니다.

**30줄은 접은 뒤에 센다.** 원장을 30건 자른 다음 접으면 접기 전과 같은 화면이 된다.

**금액 눈금** — 접힌 줄의 합계와 명세 한 줄은 자릿수가 세 자리씩 다르다(합계 £1.2M,
명세는 월 £40k짜리). 그래서 **금액이 눈금을 고른다** — 백만 이상은 `£1.2M`, 그 아래는
`£40k`. 눈금을 백만으로 고정하면 명세가 전부 `£0.0M`이 되어 서른 줄이 아무 말도 하지
않는다. 이 자만 쓰는 것은 피드가 아니라 게임 전체다 (overview §5).

### 8.2 달력 일지에 서는 돈

달력은 **되돌아보는 화면**이다 — 부상도 성장도 카드도 날짜로 남는데 돈만 남지
않으면, 시즌을 넘긴 뒤 그해 가장 큰 상금의 날짜가 세이브 어디에도 없다.

**서는 것은 두 가지 조건을 다 넘긴 항목뿐이다.**

**① 비정기 항목만** — 카테고리로 가른다. 라벨은 보는 글자지 집계 축이 아니다(§4.1).

|             | 카테고리                               |
| ----------- | -------------------------------------- |
| 선다        | `prize` · `source: "narrative"`인 항목 |
| 서지 않는다 | 나머지 전부                            |

매달·매경기 같은 자리에 서는 항목(중계권·스폰서십·머천다이징·주급·스태프·시설·
매치데이·운영비·자산 상각·수당·원정의료)은 문턱을 넘어도 서지 않는다. 아스날의 월
중계권은 £9M이라 언제나 문턱 위인데, 그 줄이 매달 서면 일지가 글자 벽이 되고 그날
실제로 벌어진 일(부상·경고)을 덮는다.

**② 문턱을 넘을 것** — `min(£1M, 잔고의 1%)`, 하한 £100k.

둘 중 낮은 쪽이라 규모가 작은 구단은 자기 눈금으로 본다(잔고 £20M이면 £200k부터).
하한이 있는 이유는 빚진 구단이다 — 잔고가 0 이하면 1%도 0 이하가 되어 모든 항목이
통과한다. 문턱을 재는 잔고는 **마감된 달은 그달 기말 잔고, 진행 중인 달은 오늘
잔고**다.

**절단 뒤에도 남는다.** 일지는 저장하지 않고 기록 테이블에서 파생하는데(→
[game-state](game-state.md) §5) 원장은 3개월 뒤 잘린다. 그래서 파생 원본이
둘이다:

| 달           | 어디서 파생하나                                       |
| ------------ | ----------------------------------------------------- |
| 진행 중인 달 | 원장 (`finance.ledger`)                               |
| 마감된 달    | 보고서의 `highlights` — 절단 전에 옮겨 적은 것 (§4.3) |

마감은 절단보다 먼저 돌므로(§7) 옮겨 적을 원장이 언제나 있다. 두 원본이 겹치지
않는 이유는 마감이 **지난달까지만** 하기 때문이다 — 진행 중인 달은 보고서가 없다.

## 9. 재정이 게임에 물리는 지점

### 9.1 급여 비중

경고선은 게임 기준으로 65%(주의) / 75%(위험)이고 보고서 `notes`에 실린다.
오피스 카드의 헤드라인은 **시즌 누계**(`seasonWageRatio`)를 쓴다 — 한 달만 보면
프리시즌(매치데이 수입 0)에 100%를 넘어 지표가 무의미해진다. 보드 요청의 살림
계수(§9.3)가 같은 값을 읽는다.
분모인 운영 매출에는 선수 매각 대금과 선수 처분 이익을 포함하지 않는다.

### 9.2 부채 — 음수 잔고의 값

잔고가 음수로 내려가면 그만큼 **빌린 것**이다. 별도 테이블도 상환 일정도 두지
않는다 — 통장의 부호가 곧 부채이고, 흑자가 나면 저절로 갚아진다.

```
이자      매월 1일   부채 × 8% ÷ 12   (`facility` · 라벨 "부채 이자")
부채 한도 부채 > 주급 총액 × 20
```

- **이자는 그 달을 시작한 잔고**에 붙는다 — 이번 달 수입이 들어오기 전에 먼저 뗀다.
  새 카테고리를 만들지 않고 이자·세금과 같은 자리에 라벨로만 갈린다. 이자는 비용이라
  손익에 잡힌다.
- **원금은 자본 이동이라 손익에 없다** — 빌린 값은 이자가 문다.
- 연 8%는 실제 구단의 차입 금리대(6\~8%)의 상단이다. 여기서 빌리는 구단은 이미
  곤란한 구단이고, **무이자면 음수 잔고가 공짜**여서 재정이 게임에 물리지 않는다.
  금액이 아니라 비율이라 구단 규모를 저절로 탄다.
- **부채 한도는 보고서의 사실이다** — 월간 노트가 `debt-over-limit` ·
  `debt-under-limit`로 한도와 견준 값을 싣는다. §10.3 불변식 3번(부채 > 연 매출)보다
  훨씬 이른 선이다(아스날 기준 매출의 0.22배). 구단주와의 대화는 이 사실을 읽으며,
  부채가 자동으로 과제를 생성하지는 않는다.
- **AI 팀도 같은 이자**를 문다. 잔고만 갱신하므로(§4.5) 부채도 부호로 읽는다.
- 감독이 읽는 자리: 월간 보고서 `notes`(부채·연 이자)와 `get_finance`의
  둘째 줄. 화면은 이 사실을 받아 그리기만 한다.

### 9.3 보드 요청 — 구장 증설 (`request_board`)

`state.boardRequests`는 구장 증설의 요청과 명시적 보드 결정을 저장한다. 요청량은 좌석 수다.
GM은 실제 구단주의 `authorizedBy`, 승인·거절·조건부 결정, 승인량, 응답일과 준공일을 기록한다.
결정이 없는 요청은 날짜가 지나도 대기한다. 맥락 조건은 GM의 후속 결정으로만 해소된다.

승인량은 양의 정수이며 요청량 이하이고, 준공일은 착공일 이후여야 한다. 같은 구단의 공사가
진행 중이면 새 공사를 착공할 수 없다. 실행 시 해당 구단의 잔고를 다시 검사한다.
공사비는 좌석당 £8,000이며 착공 때 한 번 자산으로 지급하고, `STADIUM_ASSET_MONTHS`에 걸쳐 상각한다.
준공일에 승인한 좌석 수를 한 번 더한다. 감독이 이직하거나 무직이 되어도 소유 구단의 공사는 이어진다.

### 9.4 감독 연봉과 구단 재정

감독의 개인 지갑은 없다. 개인 생활과 지출의 서사는 GM이 맡으며 별도 잔액이나 사재
출연·개인 보너스 명령을 만들지 않는다. 구단 장부에는 감독 연봉만 남는다 — 매월
`staff_wages` 지출 한 줄이다(§6). 경질·계약 만료는 커리어를 끝내고
([career.md](../story/career.md)), 그날 장부에 따로 서는 정산은 없다.

## 9-1. 강등 — 절벽과 낙하산

강등은 이 게임에서 재정이 가장 크게 흔들리는 사건이다. 아래 표는 실측
(2024/25 EPL·EFL)을 그대로 옮긴 것이다.

| 축       | 실제                                                                                             | 게임                                                                                                                                      |
| -------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 중계권   | EPL £109\~175M → 챔피언십 **£11M** (−90%)                                                        | `broadcastPool` 1.0 → **0.10**                                                                                                            |
| 파라슈트 | 순수 중계 몫의 55/45/20%, **3년** (승격 1시즌 만의 재강등이면 2년)                               | `PARACHUTE_RATE` **[0.45, 0.36, 0.16]** — 우리 균등 배분이 중앙 상업까지 흡수한 값이라 비율을 낮춰 같은 금액을 만든다. **언제나 3년이다** |
| 매치데이 | **거의 안 떨어진다** — 레스터 £18.4M→£18.4M · 리즈 £29.9M→£30.6M (시즌권이 남고 점유율이 오른다) | 단가만 리그를 따라간다(£45→£24). 점유율 상한이 낙폭을 흡수한다                                                                            |
| 상업     | 계약 만료 시점에 **늦게** 온다 — 리즈 −10% · 레스터 −26%                                         | `RELEGATED_COMMERCIAL` [−10%, −25%, −35%]                                                                                                 |
| 총매출   | −33 \~ −41%                                                                                      | 같은 자리                                                                                                                                 |

- **파라슈트는 새 시스템이 아니라 균등 배분의 파생이다** — `떠나온 리그의 배율 ×
연차 비율`. `TeamFinance.parachute`(없으면 낙하산이 없다)가 출처와 연차를
  갖고, 월 정산이 균등 배분과 같은 항목에 **다른 라벨**로 적는다(감독이 "이 돈이
  언제 끊기나"를 원장에서 읽어야 한다).
- **승격하면 그 자리에서 끝난다** — 1부 배분과 겹쳐 받을 수 없다. 낙하산 기록도 함께
  지워지므로 **재강등 2년 규칙은 우리 세계에 없다** — "아직 받는 중"인 상태가 남지
  않는다. 실제 EPL의 2년 조항은 위 표의 실제 열에만 있다.
- ⚠️ **상업 감소와 파라슈트 종료가 3년차에 겹친다** — 실제로 노리치·왓포드가 맞은
  "이중 절벽"이다. 의도된 것이고, 그래서 강등 3년차가 재정의 최대 고비다.
- ⚠️ **4년차부터는 상업이 브랜드 정액으로 돌아온다.** 감소는 세 해짜리 지연 효과이지
  2부의 상업 수준이 아니다 — 상업 정액은 `commercialTier`(브랜드 등급)에서 나오고 그
  등급은 리그를 모른다(§5.3). 감소를 이어 가려면 상업 정액 자체가 리그를 알아야 하고,
  그건 새 축이라 이 표의 값이 아니다.
- ⚠️ **성적 수당은 리그가 바뀌면 지난 순위를 쓸 수 없다** — 챔피언십 1위와
  프리미어리그 1위는 같은 수당이 아니다(`SeasonRecord.leagueId`로 가른다).
- ⚠️ **이미 쓴 계약은 강등을 모른다** — 코어에 강등 조항이 없어 주급은 그대로 남는다.
  강등의 재정 사실은 구단주와의 대화에서 읽으며, 감축 목표는 자동으로 생성하지 않는다
  ([board.md](../story/board.md)).

## 10. 밸런스 기준 — 현실 정합

**기준은 총량이 아니라 구조다.** 실제 구단이 무엇을 얼마나 벌고 쓰는지의 **비율**에
맞춘다 — 우리 매출 규모가 실제의 몇 할이든, 매출 대비 인건비·순익의 자리가 같아야
재정이 게임에 물린다.

### 10.1 기준 축은 장부 손익이다

**판정은 장부 손익(`pnlNet`)이 한다** — 구장 투자(`capex`)가 현금을 한 번에 흔들어도
손익은 자산 상각으로 고르게 선다. 현금(`cashNet`)은 같은 하네스가 함께 찍되 판정하지
않는다: 두 축을 한 이름으로 부르면 "순익 밴드 안"이 어느 쪽을 말하는지 알 수 없다.

**구간의 숫자는 `finance-tier1` 하네스의 서술자가 쥔다**
(→ [balance-harness](balance-harness.md) · `pnpm balance --list`). 여기 적는 것은
그 구간이 왜 그 자리인가다.

| 지표                                   | 왜 그 구간인가                                                   |
| -------------------------------------- | ---------------------------------------------------------------- |
| tier1 유저 **연 장부 손익**(`pnlNet`)  | 대부분의 시즌은 본전 근처이고, 나쁜 해에 적자가 난다             |
| tier1 유저 연 **현금 순증**(`cashNet`) | 자릿수만 본다 — 판정은 손익이 한다                               |
| 경기 달 급여 비중                      | 실제 EPL 평균 \~70%. 프리시즌 달은 매치데이가 없어 대상에서 뺀다 |
| tier1 유저 연 수입                     | 실제 상위 구단 £400–700M — 우리는 그 6–7할                       |

⚠️ **두 상단은 12개월 합을 잰다.** 마지막 달이 시즌 안에서 마감되므로(§7.1) 이 합은
11개월이 아니라 12개월이고, 그 12번째 달이 순위·컵 상금을 통째로 진다 — 살림이 후한
것이 아니라 **세는 창이 그만큼**이다.

### 10.2 관측 방법

현재 밴드와 측정 항목은 `packages/engine/harness/catalog.ts`가 소유한다.
`pnpm balance --list`로 선택하고 해당 재정 하네스로 관측한다.

### 10.3 다년 불변식 — 세 시즌이 가드다

한 시즌은 발산을 감추기에 충분히 짧다. **가드가 재는 창은 세 시즌**이다
(`finance-multi-season`) — 리그가 가라앉는 것도 돈만 쌓이는 것도 그 안에 보이고,
그보다 길게 굴리면 한 번 재는 값이 십수 분을 넘는다.

| #   | 불변식                                             | 누가 재나                                                                    |
| --- | -------------------------------------------------- | ---------------------------------------------------------------------------- |
| 1   | 리그별 **중간 잔고 ≥ 0**                           | `finance-leagues`(시즌 1)·`finance-multi-season`(세 시즌)이 판정한다         |
| 2   | 리그별 중간 잔고 ≤ 그 리그 중간 구단의 **연 매출** | 1부는 `finance-multi-season`이 판정한다 · 하위 리그는 `reference`로만 찍는다 |
| 3   | 부채가 연 매출을 넘는 구단이 리그의 1/4 이하       | 가드 없음 — 스냅샷이 잰다 (§4.5)                                             |

**1번이 먼저 깨지는 자리는 초반 세 시즌이다.** 시즌마다 나가는 돈이 조금이라도 더
늘면 하위 리그의 중간 잔고가 먼저 음수가 되고, 그때 볼 손잡이는 하위 리그의 초기
여유다 (`app/create-game.ts`의 `TIER_FINANCE` · `common/data/league-economy.ts`의 리그
경제 수준).

**2번의 가드는 1부에만 선다.** 1부의 중간값은 스무 구단이 £100M대를 들고 있어 시드
사이의 폭이 한 자릿수 %다 — 불변식 그대로 1.0에서 판정할 수 있다. 하위 리그의
중간값은 £10M대라 시드에 수십 %씩 흔들려, 그 값을 가드로 세우면 하네스가 재정 모델이
아니라 그해 운을 잰다. 전 리그로 넓힌 값은 같은 1.0에 `reference`로 나란히 찍어 **넘는
리그를 보이게만** 한다 ([balance-harness](balance-harness.md) §2).

테스트가 고정하는 것: 구조적 불변식(어느 구단도 인건비가 매출을 넘지 않고,
고정비가 매출의 4할을 넘지 않는다 — 시뮬 없이 t=0에서) · **3시즌 중간 잔고 ≥ 0** ·
부채의 이자 경로 · 실측 시드가 같은 리그의 급여 자릿수를 벗어나지 않는 것.

⚠️ **밴드의 기준 축은 장부 손익이다**(§10.1) — `finance-tier1`에서 `연 장부 손익`이 그
자리에 서고, `연 현금 순증`은 시즌이 제대로 돌았는지 보는 난간이다. 다년 쪽은
`finance-multi-season`이 세 시즌을 재고 바닥과 천장을 둘 다 판정한다.

⚠️ **상단이 넓은 이유는 컵 상금이다.** 한 시즌의 대회 성적이 상금에서 £22M을
움직이고(실측: 같은 시드에서 7위·상금 £35M ↔ 6위·상금 £57M) 홈 경기 수까지 따라
바뀐다. 순위 상금의 계단(£2\~3M)보다 폭이 훨씬 커서, 상단을 좁게 잡으면 밴드가
재정 모델이 아니라 **그 시즌의 컵 운**을 재게 된다.

`recordFinance`는 옵션 객체 하나를 받는다 —
`{kind, category, label, amount, ref?, accounting?, time?, source?}`. 카테고리 없는
기록을 만들 수 없게 하는 자리다.

## 12. 미해결

- ⚠️ **번 돈이 나갈 축이 살림뿐이다.** 구단 사이에 돈이 오가는 길이 없어, 잉여 현금은
  주급·스태프·시설·이자 밖으로 쓰일 자리가 없고 잔고에 쌓인다. 쓰임새는 선수 이동을
  다시 설계할 때 함께 정한다 ([overview.md](../overview.md) §7).
- **스태프의 숫자 효과가 없다** — 코치·의료진은 이름과 계약을 갖고 서지만
  (§6.3 · [people.md](../story/people.md) §2-2) 훈련 흡수율·회복 속도 중 어느 것도
  움직이지 않는다. 그 축은 전부 `squad/`의 것이라 재정이 정할 값이 아니고, 값이
  붙기 전까지 명명 스태프는 **비용과 목소리**다. 값이 붙는 날 `STAFF_WAGE_RATE`의
  파생 몫이 얼마나 남아 있어야 하는지도 함께 판단해야 한다
- **티켓 가격에 팬 여론이 없다** (§5.2). 감독의 선택은 **관중 수와 수입의 트레이드오프**
  하나뿐이라, 싸게 파는 쪽은 언제나 수입이 준다 — 실제로 구단이 값을 눌러 두는 이유
  (시즌권 갱신·원정 팬·여론)가 우리 세계엔 값으로 서 있지 않다. 팬 여론 축이 생기면
  그 자리에 붙는다
