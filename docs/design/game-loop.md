## 1. 새 게임 (온보딩)

1. **팀 선택** — EPL 20팀 전부 선택 가능 (결정 #1). 난이도는 별도 옵션이
   아니라 **보드 기대치가 만든다**: 빅클럽은 우승권 요구, 승격팀은 잔류 목표.
2. **감독 캐릭터 생성 — 직접 입력** (결정 #11). 이름·배경을 유저가 자유
   텍스트로 입력하면, GM이 배경 서술을 해석해 능력치 4축(리더십·전술·협상·
   미디어)을 초기 배분한다 — **어느 무대의 커리어였나가 기준선을, 부임 구단의
   격이 그 하한을, 전문 분야가 축별 가산을** 정하고 합계는 고정이 아니다
   (→ attribute-model §9). 팀 선택이 여기서 한 번 더 쓰인다: 빅클럽은
   무경력자를 데려오지 않으므로 같은 배경도 맨시티(평균 50)와 승격팀(34)에서
   출발점이 갈린다. 예:
   "축구를 좋아하는 회사원" → 전 축 34 · "K리그에서 뛰다 은퇴한 수비수" →
   평균 45 · "프리미어리그 주장 출신" → 평균 53 · "챔피언스리그를 우승한
   감독" → 평균 60. 평판은 중립, 커리어 기록은 0에서 시작.
3. **월드 시드 발급** — `worldSeed`. 이후 모든 결정적 난수의 뿌리.
4. **첫 모델 턴** — 실모드는 GM이 감독 프로필·구단·스쿼드·일정을 컨텍스트로
   받아 부임 첫 장면을 매번 새로 쓴다. 장면과 어조는 달라져도 `@:` 내레이션 →
   `@수석코치` 첫 미팅 → 당장 선택할 일을 묻는 흐름은 지킨다. **튜토리얼을
   겸한다** — 별도 안내 화면 없이 수석코치가 대화로 스쿼드·일정·이적시장을
   브리핑한다. mock 모드 또는 LLM 실패 시에는 월드 시드로 선택한 여러
   규칙 기반 장면 중 하나를 사용해 새 게임 생성 자체는 막히지 않는다.

## 2. 캘린더 생성

| 항목           | 소스/규칙                                                                        |
| -------------- | -------------------------------------------------------------------------------- |
| 리그 일정 38R  | OpenFootball (CC0) — [data-sourcing §4](./data-sourcing.md)                      |
| 이적시장       | 여름·겨울 모두 조작 가능 (결정 #15 멀티시즌 — 여름 시장이 시즌 전환의 핵심 구간) |
| 계약 만료일    | 선수 계약 데이터에서 파생 → 만료 D-30에 attention 이벤트                         |
| 주간 훈련 리듬 | 경기일 기준 자동 배치 — D+1 회복, 주중 본훈련, D-1 가볍게                        |

- 프리시즌은 MVP에서 생략 — 1R 직전 주에서 시작 (친선경기 ❌).
- 캘린더는 코어 상태다. GM은 캘린더를 읽을 뿐 만들지 않는다.

## 3. `advance_time` 스펙

입력: `{ until: date | "next_match" | "next_event" }`

```
for day in (today .. until):
  dailyTick(day)                 # §4 — 결정적 갱신
  resolveScheduled(day)          # 캘린더 이벤트 해소
  events += sampleDynamic(day)   # 시드 확률 이벤트 (§4-8)
  if needsManager(events): break # 감독 결정 필요 → 그 날짜에서 정지
return digestLog                  # GM이 큐레이션해 보고
```

**시계를 세우는 것 — 오늘이 지나면 기회가 없어지는 일뿐**

| 멈춘다 | 멈추지 않는다 (다이제스트로만) |
| --- | --- |
| 경기일 도달 | 훈련 완료·성장·부상 발생 |
| 시즌 종료 | 들어온 이적 오퍼 · 우리 오퍼에 온 답 |
| **오늘이 기한인 협상** (`pendingVerdicts` ∩ `expiresOn === 오늘`) | 메디컬 결과(통과·소견) |
| | 벤치 불만 · 계약 만료 예고 |
| | 타 팀 경기 결과 · 정기 재정 흐름 · 스카우트 진행 |

⚠️ **예전엔 오퍼 한 통·훈련 부상 하나·벤치 불만 하나가 전부 시계를 세웠다.**
일주일을 넘기라는 지시가 이튿날 멈추면 감독에게는 시간을 흘릴 방법이 없다 —
손잡이를 몇 번이고 다시 눌러야 하고, 그때마다 GM이 같은 브리핑을 반복한다.
그 일들은 **하루 뒤에 처리해도 결과가 같으므로** 브리핑으로 쌓인다. 협상 기한만
예외인 이유는 넘기면 되돌릴 수 없어서다 — 한 협상당 많아야 하루 멈춘다.

- 다이제스트는 전부 나열이 아니라 서사 가치·시급성 기준 큐레이션
  (→ [narrative.md §4](./narrative.md)).

**페이싱은 모델이, 브레이크는 코어가.** 시계는 그 장면이 실제로 걸린 만큼
흐른다 — 이어지는 대화는 몇 분, 자리를 옮기면 한두 시간, 하루가 저물었으면 다음 날
아침이다. **날짜를 넘기는 것도 막지 않는다**: 지나치면 안 되는 것 앞에서는 이미
`advanceTime`이 멈춰 세우고(경기일·시즌 종료·기한 당일 협상) `short`로 알리므로,
프롬프트가 같은 일을 또 지시하면 페이싱만 굳는다.

⚠️ 실제로 그렇게 굳었다. 날짜 점프를 막으려고 "감독이 진행을 요청하지 않았으면 같은
날 **같은 시각**에 머물러라"를 걸었더니 시각까지 얼어, 대화가 몇 턴을 이어져도
시계가 `AM 9:00`에 못박혀 있었다. 헤더에 시간대만 적으면 (`[2026-07-13 오후]`)
코어가 눈금(14:00)으로 스냅하는데 그게 이미 지난 시각이면 되감기 방지에 걸려
**조용히 무시된다** — 그래서 프롬프트가 시:분을 요구하고, 시계가 제자리인 턴은
파싱 실패와 같이 서버 로그에 남는다.

**시간 이동 손잡이는 모델보다 먼저 흐른다.** 시간은 보통 모델이 첫 줄 헤더에
시점을 선언하고 코어가 따라가지만(`applyScenePoint`), 그 구조에서는 일주일을
넘긴 턴에 모델이 **그 일주일에 무슨 일이 있었는지 모른 채** 장면을 쓴다(결과는
다음 턴 입력에 실린다). 감독이 얼마를 넘길지 이미 정해서 누른 손잡이에는 물어볼
것이 없으므로, 코어가 먼저 굴리고 그 사이의 일을 상태 스냅샷에 실어 보낸다 —
모델은 도착한 자리에서 **보고**를 한다 (`parseTimeSkip` → `advanceForSkip`).

## 4. Daily tick — 결정적 갱신 목록

| #   | 갱신             | 규칙                                                                             |
| --- | ---------------- | -------------------------------------------------------------------------------- |
| 1   | 피로 회복        | 회복 곡선, recovery조 가속 (→ attribute-model §2·§4)                             |
| 2   | 부상 경과        | 남은 일수 감소, 복귀 판정                                                        |
| 3   | 훈련 진행        | 주간 계획 → 훈련일에 XP 적립 (→ attribute-model §3)                              |
| 4   | 폼 흐름          | 경기 없는 기간 중앙 회귀                                                         |
| 5   | 사기 흐름        | 중앙 회귀 + **방치 페널티** (미해결 불만·무시된 면담 요청은 하락 지속)           |
| 6   | 시장 진행        | 보낸 오퍼에 상대 응답 도착(거래형 판정은 응답 생성 시점에), 스카우트 리포트 완성 |
| 7   | 재정             | 주급 지급(주 1회), 수입 반영                                                     |
| 8   | 동적 이벤트 샘플 | 훈련 부상, 언론 이슈, 선수 요청 — `PRNG(worldSeed, day, channel)`                |
| 9   | 타 팀 경기       | 라운드 날짜에 간이 시뮬 (→ match-sim §7) — 결과·리그 테이블 갱신                 |

> 모든 난수는 `(worldSeed, day, channel)` 파생 — 같은 시드는 같은 세계.
> LLM 없이 tick 전체가 단위 테스트 가능 (AGENTS.md 5장).

## 6. 경기일 루프

`advance_time`이 경기일에 멈추면:

경기 전 브리핑 (`@수석코치` 상대 분석) → `set_lineup`/`set_tactics` 확정 →
`advance_match` 첫 호출 = 킥오프 (overview §4·§5) → 경기 → 경기 후 정리
(팀토크·미디어 축소판·부상 보고) → 일상 복귀.

## 7. 시즌 종료와 시즌 전환 (결정 #15 — 멀티시즌 코어)

### 시즌 리뷰

1. 최종 라운드 종료 → 보드 평가(기대치 대비 — 해임은 없지만 평가는 냉정하게,
   결정 #4), 리그·팀 내 어워드, 서사 에필로그 (→ narrative.md §6).
2. **커리어 적재**: 시즌 전적·최종 순위·수상 → 감독 커리어. **트로피
   보관함**(리그 우승 등)과 **업적**(무패 시즌, 유망주를 팀 MVP로 육성,
   3시즌 연속 상위권 등 — 정의 목록은 별도 관리)이 잠금 해제되어 커리어
   뷰에 영구 전시된다 (overview §2.4).

### 시즌 전환 (오프시즌 — `advance_time`이 처리하는 스케줄 이벤트)

| #   | 처리                                   | 규칙                                                                                                                     |
| --- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 1   | 나이 +1, 성장/쇠퇴 롤                  | attribute-model §3                                                                                                       |
| 2   | 은퇴                                   | 고령·능력치 기준 은퇴 판정 (공식) — 은퇴식은 서사로                                                                      |
| 3   | 신인 유입                              | **합성 유망주 생성** (personas §4와 같은 1회 생성 파이프라인) — 시즌이 갈수록 세계는 실명 데이터에서 자연스럽게 갈라진다 |
| 4   | 계약 만료                              | 만료 선수는 자유이적 시장으로                                                                                            |
| 5   | 타 팀 정비                             | 간이 이적 시뮬 (전력 공백 메우기 수준 — 규모는 남은 질문 #17)                                                            |
| 6   | 승강                                   | 남은 질문 #16 — 간이 승강(EPL↔챔피언십 3팀 교체) 추천                                                                    |
| 7   | 여름 이적시장 개장 → 새 시즌 일정 생성 | 일정 템플릿 재사용                                                                                                       |

### 멀티시즌 서사

- 미해소 아크는 다음 시즌으로 이월된다 (→ narrative §2) — "작년 그
  설욕전"이 진짜 작년이 된다.
- 오프시즌 진행은 다이제스트 중심으로 빠르게 — 원하는 유저만 협상·재계약에
  머문다.
