# 이적·계약 협상 (Transfers & Contracts)

> 상태: **설계 확정 — 구현 중.** LLM 판정 구조로 간다(사용자 확인). 시장가 계수만
> 미정이라 상수 하나로 분리해 뒀다 (`MARKET_VALUE_MULTIPLE`).

감독이 말로 협상하고, **코어가 딜 성공 확률을 결정적으로 계산**하고, 그 숫자를
근거로 **LLM이 상대편이 되어 판정**한다. 장부(이적료·계약·재정)는 코어가 지킨다.

---

## 1. 경계 — 누가 무엇을 정하는가

| | 코어 (결정적) | LLM (창발적) |
|---|---|---|
| 시장가·요구액·주급 기대치 | ✅ 공식 | ❌ |
| **딜 성공 확률 + 근거 분해** | ✅ `dealOdds()` | ❌ |
| 감독 발화 해석 (누구를·얼마에) | ❌ | ✅ |
| 오퍼 수락/역제안/결렬 **판정** | ❌ (검증만) | ✅ 확률을 근거로 |
| 감독의 설득 발화 → 주장(claim) 변환 | ❌ | ✅ |
| **설득 논거의 사실 대조** | ✅ `evaluatePitch()` | ❌ |
| 이적료·계약·재정 반영 | ✅ 스킬 | ❌ |
| 서사 (에이전트의 말, 단장의 태도) | ❌ | ✅ |

LLM이 판정하는 이유: 상대 구단·에이전트는 각자 동기를 가진 에이전트다(비전 1장).
"4200만을 기대하지만 감독이 UCL 진출권과 출전 보장을 얹었다"는 판단은 공식으로
환원하면 재미가 빠진다. 대신 **확률이 판단의 앵커**이고, 확률에서 크게 벗어난
판정은 분포 모니터링에서 드러난다 (§6).

### 1.5 설득 — 숫자로 못 넘는 벽을 넘는 수단

감독이 협상에서 쥔 손잡이가 **이적료와 주급 둘뿐**이면, 돈으로 안 되는 이적은
영원히 안 된다. 사우디에서 주 £3.4M을 받는 레전드는 어떤 예산으로도 안 오고,
주전이 보장된 선수는 더 큰 팀에도 안 간다. 그런데 현실에서는 그런 이적이
일어난다 — **말이 통했기 때문이다.**

그렇다고 "말만 잘하면 된다"로 두면 게임이 깨진다. 경계선은 하나다.

> **논거는 주장(claim)으로 구조화되고, 코어가 사실 대조한다.
> 인정된 주장만 확률을 움직인다. 거짓 주장은 오히려 깎는다.**

판정과 같은 구조다 — 코어가 근거를 계산하고, LLM은 감독의 발화를 주장으로
옮기며, 코어는 확인할 수 있는 것만 인정한다.

| 주장 | 코어가 확인하는 사실 |
| --- | --- |
| `homecoming` 네가 자란 곳이다 | `homegrownCountry` == 우리 리그 국가 |
| `reunion` 전에 함께했다 | TRANSFER 원장에서 우리 선수와 겹치는 소속 |
| `project_lead` 팀의 중심으로 | 우리 스쿼드 상위 3 안의 전력 |
| `last_chance` 지금이 마지막이다 | 33세 이상 또는 계약 1년 이하 |
| `starting_role` 주전으로 쓰겠다 | 그 자리에 더 나은 선수가 없다 |
| `trophy_push` 우승을 다툰다 | 리그 4위 이내 또는 대항전 진출 |
| `european_football` 대항전 무대 | `euroEntrants`에 우리가 있다 |
| `manager_reputation` 내 이름을 걸고 | 감독 명성 평균 60 이상 |
| `compatriot` 라커룸에 동포가 있다 | 같은 `homegrownCountry` 선수 보유 |
| `other` 그 밖의 이야기 | (확인 불가 — 서사로만) |

**표에 무게가 없다.** 이게 이 설계의 핵심이다. "이 선수에게 고향 복귀가 얼마나
큰가"는 표로 답할 수 있는 질문이 아니다 — 서른아홉에 마지막 우승을 노리는 선수와
스물셋의 유망주에게 같은 말이 같은 무게일 리 없다. 그래서 코어는 **사실 여부만**
가리고, 무게는 선수·에이전트를 연기하는 LLM이 판정한다.

코어가 쥐는 것은 둘뿐이다.

1. **거짓의 대가 (−1.4)** — 남용 방지라 결정적이어야 한다. 대항전에 안 나가면서
   나간다고 하면 선수가 알아챈다. 인정됐을 때 얻었을 것보다 큰 대가라, 논거를
   갖다 붙이는 것이 손해가 된다.
2. **판정 여유 (latitude)** — 확인된 논거 하나당 +12%p. 확률을 **올리지 않는다**.
   대신 `respondOffer`의 수락 하한을 연다: 확인된 논거가 하나라도 있으면
   **코어는 더 이상 수락을 막지 않는다.** 확률 3%짜리 딜도 선수가 고향으로
   돌아오기로 했다면 성사된다.

```
확인된 논거 없음   →  확률 5% 미만이면 코어가 accept를 반려한다
확인된 논거 있음   →  코어는 막지 않는다. 판단은 전적으로 선수의 몫이다
거짓 논거뿐        →  아무 문도 열리지 않고 확률만 깎인다
```

- **반복은 설득이 아니다.** 인정된 논거는 `NEGOTIATION.pitched`에 누적되고,
  같은 이야기를 다시 꺼내면 여유가 더 열리지 않는다.
- **감독의 실제 말이 판정자에게 전달된다.** `NegotiationRound.pitch`에 논거와
  감독이 한 말(`note`)이 남고, `describeNegotiation`이 그대로 보여 준다.
- **복귀 저항 같은 계수는 그대로 남는다** — 없앤 게 아니라 넘어서는 것이고,
  근거에 둘 다 보인다.

#### LLM에게 주는 지침 (GM 철칙 6·7)

- 확률이 낮다고 "불가능합니다"로 끝내지 않는다. 감독이 금액만 말하면 **무엇을 더
  걸 수 있는지 먼저 묻는다.**
- 판정할 때 확률은 참고일 뿐이다. 그 선수의 나이·처지·이력을 보고 판단하고,
  **어떤 이야기가 그를 움직였는지** note에 남긴다.
- 감독이 하지 않은 말을 지어내지 않는다 — 코어가 거짓으로 판정하면 손해다.
- 근거 없이 흔들리는 선수는 세계를 싸구려로 만든다.

### 확률을 재굴릴 수 없게 하는 장치
LLM이 판정하면 감독이 같은 조건으로 계속 물어보는 우회가 생긴다. **횟수 상한** 같은
딱딱한 규칙 대신, 상대의 **인내심이 닳는다**로 푼다 — 같은 조건을 반복하면 코어가
내놓는 확률 자체가 떨어진다.

```
patience 감쇠 = 0.72 ^ (같은 조건 반복 횟수)
```
"같은 조건"의 기준: 직전 오퍼와 이적료·주급이 각각 3% 이내. 조건을 유의미하게
올리면 감쇠가 초기화된다 — **흥정은 되고 난사는 안 되는** 선이 공식 하나로 잡힌다.
이 감쇠는 `factors`에 한 줄로 드러나므로("세 번째 같은 제안 −34") 감독도 안다.

- **응답은 시간을 쓴다** — 즉답 없음. 지연 일수는 상황에서 나온다 (아래)
- **결렬은 잠금** — `rejected`면 그 창에서 같은 선수에게 다시 오퍼할 수 없다
- 하드 상한은 폭주 방지선으로만 둔다 (협상당 8회)

이것이 "마감일 드라마"(game-loop.md 미해결 항목)를 만든다 — 창이 닫히기 3일 전엔
한 번의 오퍼가 마지막 기회다.

### 응답 지연 — 상황에서 나온다

고정 2~4일이 아니다. 상대의 반응 속도가 곧 정보다.

| 상황 | 지연 | 뜻 |
|---|---|---|
| 확률 15% 미만 (헐값) | **1일** | 볼 것도 없이 차인다 |
| 확률 15~70% | 2~5일 | 이사회가 논의한다 |
| 확률 70% 이상 | 1~3일 | 팔 마음이 있다 |
| 창 마감 3일 이내 | 위 값의 절반 (최소 1일) | 시간이 없다 |
| 같은 조건 반복 | +1일 | 상대가 지쳐 미룬다 |

범위 안의 실제 일수는 시드 해시로 뽑는다 — 결정적이지만 자연스럽게 흩어진다.

## 2. 데이터 모델

`TRANSFER`는 **원장(사실)** 그대로 둔다. 진행 중 협상은 별도 테이블이다 —
"완료된 이동"과 "합의 안 된 흥정"을 한 테이블에 섞으면 원장이 더러워진다.

```
NEGOTIATION (협상)
  id
  gamePlayerId
  kind          "buy" | "sell" | "renew"        ← 1차 범위. 임대는 다음
  counterpartTeamId | null                       ← renew는 null (상대가 선수 본인)
  windowId | null                                ← renew는 창 밖에서도 가능
  openedOn, expiresOn                            ← 창 마감 또는 개설 +14일
  status        "open" | "agreed" | "rejected" | "expired" | "completed"
  rounds        NegotiationRound[]
```
```
NegotiationRound (오퍼 한 번 = 한 row, 서사의 원천)
  date, by: "us" | "them"
  fee, weeklyWage, contractYears
  respondsOn                    ← 상대 응답 예정일 (us 오퍼만)
  probability                   ← 오퍼 시점에 코어가 계산한 확률 (사후 검증용)
  verdict | null                ← "accept" | "counter" | "reject" (them 응답)
  note                          ← LLM이 쓴 한 줄 (에이전트의 말)
```

`status="agreed"` → **수락 스킬**이 `TRANSFER` + `CONTRACT` + 재정 원장을 쓴다.
그때 `status="completed"`. 합의와 완료를 분리하는 이유: 구단 합의 후 개인 조건
합의가 남고(실제 이적도 두 단계다), 그 사이에 감독이 물러설 수 있다.

세이브에 저장한다 — 협상은 며칠에 걸쳐 진행되고 파생으로 되돌릴 수 없다.

## 3. 코어가 뱉는 것 — `dealOdds()`

```ts
dealOdds(state, { playerId, kind, fee, weeklyWage, years }): DealOdds
```
```ts
interface DealOdds {
  probability: number;        // 0~100 — 이 조건이 받아들여질 확률
  marketValue: number;        // 코어가 본 시장가
  askingPrice: number;        // 상대가 기대하는 값
  wageExpectation: number;    // 선수가 원하는 주급
  factors: Factor[];          // 확률 기여 분해 — { label, delta, why }
  blockers: string[];         // 확률과 무관하게 막는 것
}
```

**`factors`가 핵심이다.** 확률만 주면 LLM이 "왜"를 지어낸다. 분해해서 주면 판정도
서사도 근거를 갖는다 (디자인 원칙 2 — 납득 가능한 결과).

```
확률 34%
  +  기본            50   요구액의 71%를 제시
  − 요구액 미달     -28   상대는 £42M을 기대한다
  +  주급 충족       +9   선수 기대(£180k)를 넘겼다
  +  대항전 출전권   +6   UCL에 나가는 팀이다
  − 출전 경쟁       -11   같은 포지션에 82 OVR 주전이 있다
  +  감독 협상력     +8   협상 71
차단: (없음)
```

### 3.1 시장가 — 결정적 공식

```
marketValue = base(overall)
            × ageCurve(age, potential)
            × formBonus(form, 최근 출전·득점)
            × contractFactor(계약 잔여)
            × leagueFactor(리그 계수)
```

| 요소 | 규칙 |
|---|---|
| `base` | 주급 곡선과 같은 계열: `(ovr/40)^4.2 × 6,000 × 450` — 85 OVR ≈ £66M |
| `ageCurve` | 24~27 ×1.0 · 21 이하는 잠재력 반영 최대 ×1.35 · 30 ×0.6 · 33 ×0.3 |
| `formBonus` | 폼 ±3 → ×0.9~1.12 |
| `contractFactor` | 3년+ ×1.0 · 2년 ×0.85 · 1년 ×0.45 · 만료 **자유계약(이적료 0)** |
| `leagueFactor` | 리그 계수 1~5 → ×1.1 ~ ×0.85 |

`askingPrice = marketValue × sellerStance`, `sellerStance`는 상대 사정:
주전 여부(+), 같은 포지션 과잉(−), 재정난(−), 계약 1년 남음(−), 우리와 라이벌(+).

### 3.2 확률 — 두 관문의 곱

```
p_club   = σ( (fee / askingPrice − 1) × 6  + sellerPressure )
p_player = σ( (wage / wageExpectation − 1) × 5 + playerPull )
probability = p_club × p_player × urgency(창 마감까지 남은 일수)
```
- `sellerPressure` — 파는 쪽이 팔아야 할 이유 (재정·잉여·계약 만료 임박)
- `playerPull` — 선수가 오고 싶은 이유 (우리 평판·대항전·출전 기회·리그 격차·감독 평판)
- 감독의 `negotiation` 능력치가 두 항에 계수로 들어간다 (결정 #13)

### 3.3 정보 비대칭 — 확률에도 안개가 낀다

우리가 보는 숫자는 **지식 수준**(scouting.ts)에 따라 흐려진다. 스카우팅이 협상에서
값을 갖는 지점이다.

| 지식 | 시장가·확률 |
|---|---|
| `own` / `scouted` | 정확한 숫자 |
| `seen` (직접 상대해 봄) | ±10%p 밴드 — "반반쯤 보인다" |
| `rumoured` (평판뿐) | ±20%p 밴드 — 숫자 없이 라벨만 |

오차는 시드 해시로 결정적이다 (같은 질문에 같은 답 — 기존 안개 규칙과 동일).

## 4. 스킬 (상태 변경) · 조회 도구 (읽기 전용)

| 도구 | 종류 | 하는 일 |
|---|---|---|
| `deal_odds` | 조회 | 위 `DealOdds`. **상태를 바꾸지 않는다** |
| `list_negotiations` | 조회 | 진행 중 협상 요약 |
| `send_offer` | 스킬 | 협상 개설(없으면) + 오퍼 라운드 기록 + `respondsOn` 설정 |
| `respond_offer` | 스킬 | **상대 판정** — accept/counter/reject + 한 줄 근거. GM이 상대편이 되어 호출 |
| `accept_deal` | 스킬 | `agreed` 협상을 실행 — TRANSFER·CONTRACT·재정 반영 |
| `withdraw_offer` | 스킬 | 협상 철회 (status → rejected) |

### `respond_offer`의 코어 검증
LLM이 판정하지만 코어가 **가능한 판정만** 받는다.

- `probability`가 5% 미만이면 `accept` 거부 — "그 값에 팔 구단은 없다"
- `counter`의 역제안액은 `[fee, askingPrice × 1.15]` 안이어야 한다 (터무니없는 부르기 차단)
- 창·결렬 잠금·하드 상한 위반은 거부
- 판정은 `respondsOn` 이후에만 (미리 답할 수 없다)

### `accept_deal` — **계약이 아니라 메디컬을 잡는다**

이 도구는 관문이지 실행이 아니다. 부르면 검진 일정이 잡히고(`NEGOTIATION.medical`),
장부가 움직이는 것은 **결과가 나온 날**이다.

예전엔 이 도구 하나가 합의를 그 자리에서 이적으로 바꿨다. 그래서 오퍼가 도착한
날 도장을 찍고 기자회견까지 여는 장면이 한 턴에 담겼고, 이적이 서류 한 장으로
읽혔다. 실제 이적에서 합의와 계약 사이에는 언제나 하루가 있다.

**검진일** — 합의 다음 날부터 이틀 안(협상 시드로 결정적). 이적창 마감일에 잡힌
딜은 **그날 바로** 검진한다 — 창이 닫힌 뒤로 미루면 감독이 아무것도 못 하는 채로
딜이 사라진다. 협상 유효기간은 검진일까지 자동으로 늘어난다(같은 이유).

**소견은 불합격이 아니다** (`flagged`). 데려가는 쪽이 알고도 갈지 정한다.

| 결과 | 무슨 일이 | 감독의 선택지 |
|---|---|---|
| `passed` | 그날 코어가 계약까지 옮긴다 | 없음 — 이미 결정한 일의 확인이다 |
| `flagged` (영입·임대 영입) | 계약이 멈추고 주의 줄에 선다 | 강행(`accept_deal` 재호출) · 철회(`withdraw_offer`) · 값 재협상 |
| `flagged` (매각·임대 내보내기) | 사는 구단이 15% 깎아 다시 부르고 협상이 `open`으로 | 감독이 `respond_offer`로 답한다 |

**통과는 감독을 부르지 않는다.** 주의 줄(`pendingVerdicts`)에 세워 두면 GM이 매
턴 `accept_deal`을 다시 부르고 "결과를 기다리는 중"만 돌려받으며 같은 장면을
반복한다. 감독이 할 일이 없는 상태다.

**강행에는 대가가 있다** — 그 선수의 `injuryProneness`가 중간 부상 한 번만큼
오른다(검진이 본 것이 사실이었다는 뜻). 공짜면 소견은 읽고 넘기는 문장이 된다.

**소견을 보고 물러선 것은 결렬이 아니다** — `expired`로 적어 그 창이 닫히지
않는다. `rejected`로 적으면 `rejectedThisWindow`가 "조건을 다시 짜서 부르기"까지
막는데, 실제 이적에서 가장 흔한 결말이 그것이다.

**소견 확률** — `0.05 + 성향 × 0.06 + 나이 가산(30세 +0.05 · 33세 +0.12) +
부상 중이면 +0.8`, 상한 0.75. 유리몸 데이터(`injuryProneness`)가 이적시장에서
값을 하는 자리다. 판정은 협상 시드에 묶여 결정적이라 다시 굴려 뒤집을 수 없다.

### 검진 통과 뒤의 코어 검증
- 창 열림 (`buy`/`sell`), 협상 `status="agreed"`
- **이적 예산** ≥ 이적료 (game-loop.md §검증 범위: 예산·주급만)
- 파는 쪽 스쿼드 최소 인원 유지 (포지션군 하한 — 기존 `GROUP_TARGET` 재사용)
- 선수 소속이 협상 상대와 일치 (그 사이 다른 팀이 데려갔으면 무효)

실행:
```
TRANSFER row (fee, windowId, type="transfer"|"free")
기존 CONTRACT status="ended" → 새 CONTRACT (weeklyWage, years)
재정: 우리 지출 + 상대 수입, transferBudget 차감
GAME_PLAYER.teamId 변경 → 새 팀 배치는 예비 스쿼드 (감독이 라인업에 넣는다)
NARRATIVE_NOTE (salience 4)
```

## 4.5 이적 시장 전용 리그 — 사우디 · MLS

> **경기를 하지 않는 리그가 세계에 있다.** 일정도 순위표도 컵도 없고, 하는 일은
> 하나다 — 돈으로 선수를 흡수하고 레전드를 보관하는 것.
> (`league-catalog.ts` `kind: "market-only"`)

2부 64클럽이 "리그전 없이 컵에만 존재"하는 것과 같은 구조의 확장이다. 클럽을
카탈로그에 넣으면 `search_players`(풀이 `state.players` 전체)와 협상("우리 선수가
아닐 것"만 본다)은 **자동으로 열린다** — 새로 만든 건 아래 네 가지뿐이다.

### ① 세계에서의 자리

| | 리그전 | 국내 컵 | 순위표 | 재정 원장 | 이적 시장 |
| --- | --- | --- | --- | --- | --- |
| `playable` (5대 리그) | ✅ | ✅ | ✅ | ✅ | ✅ |
| `cup-only` (2부 64) | ❌ | ✅ | ❌ | ✅ | ✅ |
| `market-only` (사우디·MLS) | ❌ | ❌ | ❌ | **❌** | ✅ |

재정에서 뺀 이유는 분명하다 — 경기를 안 해 중계권도 매치데이 수입도 없는데
레전드 주급(주 £3.4M)은 나간다. 그대로 두면 한 시즌 안에 파산한다. 원장을 흉내
내는 대신 **상시 이적 예산**을 상수로 준다(`MARKET_LEAGUE_BUDGET` — 사우디
£250M · MLS £60M). 감독이 들여다볼 화면도 없는 곳의 장부를 정교하게 굴릴 이유가 없다.

전력 기준선에 2부 감점(`SECOND_DIVISION_PENALTY`)을 **얹지 않는다.** 약한 리그가
아니라 경기를 안 하는 리그다 — 감점을 주면 레전드가 헐값이 된다.

### ② 선수 풀 — 시드 + 동적 유출

개막 시점의 현실을 반영해 클럽마다 레전드 1~4명을 실명 시드로 두고
(`data/market-leagues.ts`), 나머지는 절차 생성으로 18명까지 채운다. 시간이 지나면
AI 팀의 노장이 이 리그로 계속 흘러 들어간다(아래 ③의 노장 선호).

⚠️ 이 시드는 5대 리그만큼 교차 검증되지 않았고 실명 부채도 함께 진다 —
data-sourcing.md §7.

### ③ 이적창이 다르다 — 이 리그들의 존재 이유 절반

`TransferWindow.leagueId`가 없으면 **5대 리그 공통 창**, 있으면 그 리그 전용이다.

| 리그 | 여름 | 겨울 |
| --- | --- | --- |
| 우리 (5대 리그) | 7/1 ~ **9/1** | 1/1 ~ 2/1 |
| 사우디 | 7/1 ~ **10/6** | 1/8 ~ 2/6 |
| MLS | 7/24 ~ 8/21 | **2/12 ~ 4/23** (북미 프리시즌) |

**등록은 사는 쪽 협회 규정을 따른다.** 그래서 우리 창이 닫힌 9월에도 사우디는
우리 주전에게 오퍼를 던질 수 있고, 팔면 **대체 영입은 못 한다** — 이 리그들이
만드는 가장 큰 드라마가 여기서 나온다.

- 매각 판정은 `dealOdds({ kind: "sell", counterpartTeamId })`가 **사는 쪽 창**을 본다.
- 영입 판정은 언제나 **우리 창**을 본다 (우리가 등록해야 하므로).
- `windowOpenOn(windows, date, leagueId?)`는 리그를 안 주면 공통 창만 찾는다 —
  섞어 찾으면 "사우디 창이 열렸으니 우리도 영입할 수 있다"는 엉뚱한 결론이 난다.
- 사우디·MLS 창은 **달력에 올리지 않는다.** 감독의 달력은 우리 리그의 것이다.

### ④ 돈 성향과 복귀 저항

`marketBiasOf(teamId)` — 오퍼 금액·주급·노장 선호를 리그별로 굽힌다.

| | 이적료 | 주급 | 노장(30+) 선호 |
| --- | --- | --- | --- |
| 사우디 | ×1.45 | ×3.5 | ×2.2 |
| MLS | ×0.75 | ×1.3 | ×1.6 |

역수입 밸런스는 **나이 곡선 + 복귀 저항** 둘로 잡는다.

- 그쪽에서도 계속 늙는다(기존 축별 노화 곡선). 34세 레전드는 34세의 능력치다.
- `wageExpectationOf`가 **현 주급의 115%**를 요구하는데 사우디 주급은 우리 상한을
  훌쩍 넘는다 — 자연 억제가 여기서 이미 걸린다.
- 그 위에 `RETURN_RESISTANCE`가 선수 관문 점수를 깎는다. **근거를 문장으로 남긴다**
  ("사우디 프로 리그의 주급을 포기해야 한다") — 블랙박스로 깎지 않는다(원칙 2).

돈을 포기하고 돌아오는 결정이 그래서 이야기가 된다.

### 매각 — 방향이 뒤집힌다 (구현됨)

매각의 시작은 **세 갈래**다.

| 갈래 | 스킬 | 무엇인가 |
|---|---|---|
| ① 이적 리스트 등재 | `set_transfer_list` | 값을 부르며 시장에 알린다 — 등재 선수에게 하루 34%로 오퍼가 붙고, **호가/시장가**만큼 확률이 깎인다(비싸게 부르면 더디 붙는다). 사는 쪽은 호가에서 최대 22% 깎고 들어온다 |
| ② 특정 구단에 직접 오퍼 | `offer_player` | `send_offer`의 거울상 — 우리가 값을 부르고 **사는 구단이 판정**한다(`respond_offer`) |
| ③ AI가 먼저 노린다 | (tick) | 하루 8% · 동시 3건. **자리가 막힌 선수·사기가 낮은 선수·값이 나가는 선수**에게 오고, 사는 구단은 그 자리가 우리보다 약하고 예산이 되는 곳에서 고른다 |

⚠️ **예전엔 ③뿐이었다.** 감독이 "이 선수를 팔자"고 해도 GM이 부를 도구가 없어서,
실제 세이브에서 GM이 `set_squad_level`(2군 강등)과 `adjust_transfer_budget`(예산
임의 증액)으로 매각을 **연기했다** — 선수는 그대로 남고 이적료는 장부에 없는 돈이
되어 이야기와 상태가 갈라졌다. 그래서 ①②를 열었고, 같은 이유로
`adjust_transfer_budget`의 한도를 **하루 누적**으로 고쳤다(주석은 "하루 상한"이라고
적혀 있었는데 코드는 건당이라 나눠 부르면 얼마든지 넘을 수 있었다).

오퍼가 도착하면 **attention 정지**로 감독을 멈춘다 — 14일 기한이 있는 결정을
놓치게 둘 수 없다.

확률의 관문도 뒤집힌다 (`kind: "sell"`).

| | 영입 | 매각 |
|---|---|---|
| 관문 ① | 파는 구단이 응할까 (제시 이적료) | **사는 쪽이 그 값을 낼까** (상한 = 시장가 ×1.15) |
| 관문 ② | 선수가 올까 (주급·출전 기회) | **선수가 떠날까** (주전이면 버틴다) |
| 안개 | 지식 수준에 따라 흐림 | 없음 (우리 선수다) |

관문 ②가 "핵심을 팔아 돈을 만드는" 선택을 공짜가 아니게 만든다 — 주전은 −%p로
버티고, 자리가 막힌 선수는 +%p로 떠나려 한다.

감독은 `answer_incoming_offer`로 수락·거절·역제안한다. 역제안하면 **사는 쪽이
판정할 차례**가 되고(`respond_offer`), 우리가 부른 값이 상대 상한을 넘으면 확률이
떨어진다.

**역제안의 방향도 뒤집힌다.** 우리가 부른 값에 사는 쪽이 답하는 것이므로 그쪽의
역제안은 **깎아 부르는 것**이다 — 시장가의 55%(`SELL_COUNTER_FLOOR`) 이상, 우리
호가 미만. 영입 기준(우리 제시액 이상)을 그대로 쓰면 사는 구단이 스스로 값을
올리는 판정만 남는다. 수락 → `accept_deal`이 반대 방향으로 실행되고 **판매 대금이 잔고와
이적 예산에 함께** 들어간다 (ADR 0002).

### 나가는 다른 문 — 방출·임대 (`departures.ts`)

매각만 있으면 감독이 할 수 있는 게 "누가 사 주면"으로 끝난다. 실제 구단은 안
팔리는 계약을 위약금을 물고 끊고, 못 쓰는 유망주를 내보내 뛰게 한다. 둘 다
**대가가 분명한 선택**이라 밸런스가 흔들리지 않는다 — 방출은 돈을 잃고, 임대는
전력을 잃는다.

| | 스킬 | 대가 | 상태 |
|---|---|---|---|
| 방출 | `release_player` | 잔여 주급의 **절반**(`SEVERANCE_RATE`, 최대 104주)을 즉시 지출 — 원장에 남아 PSR까지 간다 | 계약 종료 + 다른 구단으로 자유 이적 |
| 임대 | `loan_player` / `recall_loan` | 그 선수를 못 쓴다 | `GamePlayer.loan{fromTeamId, until, wageShare}` — 계약은 우리 것 |

- **무소속을 만들지 않는다.** `GamePlayer.teamId`가 필수라 "어디에도 없는 선수"를
  표현할 수 없다. 억지로 빈 팀을 만드는 대신 `nextClubFor`가 그 자리가 얇은
  구단으로 보낸다 — 실제로도 방출·만료 선수는 곧 다른 클럽을 찾는다.
- **임대는 주급을 나눈다.** 총액이 계약 합계에서 파생되므로(`weeklyWagesOf`)
  분담도 파생으로 반영된다 — 우리 쪽에서 `wageShare`만큼 빠지고 임대 팀에 얹힌다.
- 복귀는 `until`에서 파생한다 — tick이 매일 `returnDueLoans`로 되돌리고, 돌아온
  선수는 **2군으로** 들어온다(자리는 감독이 정한다).
- ⚠️ **임대 영입(loan-in)은 아직 없다.** 상대 구단과의 협상 흐름이 따로 필요하다.

### 임대 — 양쪽 다 흥정이다 (`kind: "loan"` / `"loan_out"`)

**빌려 오든 빌려주든 상대가 받아 줘야 성립한다.** 그래서 둘 다 `send_offer`로
들어가 같은 협상 테이블을 탄다 — 우리 일방 결정으로 처리하던 때는 도구가 하나
더 있었고 "보내면 그냥 되는" 이상한 규칙이었다. 흥정이 아닌 것은 **부르기**뿐이라
`recall_loan`만 따로 남는다.

임대 영입(`loan`)의 관문은 이적과 다르다.

| | 영입 | 임대 영입 |
|---|---|---|
| 구단 관문 | 이적료를 낼까 | **내보내도 되나** — 그 팀 주전이면 −2.4, 자리가 막혀 있으면 +, 21세 이하면 +1.1 |
| 선수 관문 | 올까 (주급·출전) | **가서 뛸까** — 우리 쪽 그 자리가 비어 있으면 +0.9 |
| 돈 | 이적료 | **임대료**(시장가 ×`LOAN_FEE_RATE` 0.08) + **주급 분담** |

내보내기(`loan_out`)는 매각과 관문이 같다(상대가 받을까 · 선수가 갈까) — 다른 건
값의 크기뿐이라 `askingPrice`가 흡수한다. 확정되면 계약은 원소속에 남고 `GamePlayer.loan{fromTeamId, until, wageShare}`만
붙는다 — 내보내는 임대와 **같은 필드**라 복귀·주급 분담이 같은 코드를 탄다.

### 무소속 — 리그가 아니라 리그 밖 (`league-catalog`의 `free`)

`GamePlayer.teamId`가 필수라 "어디에도 없는 선수"를 표현할 수 없다. 그래서 클럽
하나(`freeagents`)를 두되 **클럽이 아닌 것으로** 다룬다(`isClubTeam` — 초기 스쿼드
없음 · 일정·순위표·컵 없음 · 스쿼드를 논하는 모든 순회에서 제외).

- 방출·계약 만료는 **전부 여기로** 온다(`toFreeAgency`) — 예전처럼 코어가 목적지
  클럽을 골라 주지 않는다. 어디로 갈지는 시장이 정한다.
- **이적창이 열린 날** tick이 `signFreeAgents`를 돌린다: 선수마다 하루
  `FREE_AGENT_SIGN_CHANCE`(6%)에 이름값(OVR/70)과 나이(34세 이상 ×0.35)를 곱한
  확률로 팀을 찾고, 후보는 **그 포지션군이 얇고**(인원이 적을수록 가중치가 커진다)
  **수준이 비슷한**(상위 15명 평균과 OVR 차 8 이내) 구단이다. 하루 2건까지.
- **우리 팀은 이 경로로 선수를 받지 않는다.** 감독이 직접 데려와야 한다 —
  아니면 아무것도 안 해도 스쿼드가 채워진다.

### 판정을 기다리는 협상은 묻히면 안 된다

답이 도착한 **그 턴에 GM은 그 사실을 모른다** — 시간은 장면 헤더로 흐르고 결과는
다음 턴 입력에 실린다. 그 한 턴의 틈에서 감독이 다른 이야기를 꺼내면 협상이
잊히고 기한이 지나 사라진다. 그래서 세 겹으로 세운다.

1. `pendingVerdicts(state)` — 지금 도구 호출을 기다리는 협상의 **단일 소스**
   (답 도착 · 상대 오퍼 도착 · 합의됨). 협상 요약 블록의 한 줄로는 묻힌다.
2. 상태 스냅샷의 **주의 줄 맨 앞**에 `❗`로 선다.
3. 기한 **하루 전** 다이제스트가 한 번 더 세운다 — 결정하지 못한 채 사라지지 않게.

⚠️ 프롬프트 철칙 8이 통합 전 도구 이름(`answer_incoming_offer`)을 지목하고 있었다.
없는 도구를 부르면 실패하고 협상은 그대로 남는다 — **도구를 합치면 프롬프트의
지목도 함께 옮겨야 한다.**

### 다른 구단의 재계약 — 기다림에는 대가가 있다

예전엔 AI 팀의 만료 계약이 시즌 전환 때 통째로 자동 갱신돼서, 노리던 선수의 계약
상황이 시즌 내내 고정이었다. 이제 tick이 매일 `runAiRenewals`를 돌린다 — 만료
`AI_RENEWAL_WINDOW_DAYS`(240일) 안의 AI 계약을 검토해, **그 팀 주전일수록(×2.2)
어릴수록(×1.4)** 서둘러 잡는다. 재계약이 성사되면 **우리가 진행 중이던 협상은 그
자리에서 결렬**되고 다이제스트가 알린다. 스카우팅해 둔 선수의 재계약 소식도 전한다.

### 계약 만료 — 우리 팀도 자동 갱신되지 않는다

예전엔 시즌 전환이 **모든 팀**의 만료 계약을 자동 갱신해서, 재계약을 한 번도 안
해도 아무도 떠나지 않았다. 그러면 `open_renewal`이 서사용 버튼이 되고 설득 논거
`last_chance`("계약이 1년 남았다")도 실제 위협이 아니다. 이제 우리 선수는 계약이
끝나면 **무소속이 되어 떠나고**, tick이 **180·90·30일** 문턱에서 한 번씩 경고한다
(90일 이하는 attention 정지).

## 6. 검증 — 분포 모니터링

LLM이 판정하므로 시드 재현으로는 못 잡는다. AGENTS 6장 4의 원칙대로 **분포**를 본다.

- `NegotiationRound.probability`와 실제 `verdict`를 함께 저장한다
- 확률대별 수락률을 집계하는 스크립트: 20~40% 구간에서 수락률이 70%면 LLM이
  후한 것이고, 프롬프트를 고친다
- **mock 모드는 결정적** — `probability ≥ 50`이면 수락, `≥ 25`면 역제안, 아니면 결렬.
  테스트는 전부 mock으로 돈다 (LLM 없이 협상 전체 흐름을 검증)
- 코어 공식 단위 테스트: 시장가 곡선(나이·계약 잔여·리그), 확률 단조성
  (제시액이 오르면 확률이 내려가지 않는다), 안개 밴드의 결정성

## 6.5 재계약 — 관문이 하나다 (구현됨)

상대가 구단이 아니라 **선수 본인**이므로 이적창과 무관하게 언제든 열린다.
이적료가 없어 흥정은 주급과 연수로만 한다.

- **기대 주급이 이적 때보다 높다** — 남아 달라는 쪽이 우리이므로 협상력이 선수에게
  있다. 만료가 가까울수록 더 부른다 (1년 미만 ×1.25 · 2년 미만 ×1.15)
- 확률은 시그모이드 **하나**다 (곱하지 않는다). 붙는 것: 출전 기회, 사기, 계약 연수와
  나이의 궁합(31세에 3년은 반갑고, 23세에 2년은 짧다), 대항전 출전권, 감독 평판·협상력
- 선수의 역제안은 **주급**을 부른다 (기대치의 1.4배 이하). 그 값으로 다시 제안하면 합의된다
- 확정은 **CONTRACT만** 새로 쓴다 — 팀이 바뀌지 않으므로 TRANSFER를 남기지 않는다
  (원장은 이동의 기록이다)
- `expiringContracts(state, days)`가 만료 임박 선수를 뽑고, GM 상태 스냅샷의 주의
  항목에 올라간다 — 놓치면 자유계약으로 떠난다

## 6.6 실모드 검증 기록 (2026-07-28)

Opus로 4턴을 돌려 확인했다. **잘 된 것**: `deal_odds`를 실제로 호출해 시장가·요구액·
성사 확률·주급 기대치를 정확히 인용했고("£22.7M은 시티가 콧방귀 뀔 금액입니다.
시장가 £28.2M, 요구액 £32.4M, 성사 확률 32%"), 스카우팅으로 안개를 걷은 선수의
숫자를 지어내지 않았다. `open_renewal`도 나이(30세)를 고려해 3년·소폭 인상으로
제안했다. 조회 도구는 호출을 기록하지 않으므로 `toolCalls`에는 남지 않는다.

**찾은 문제 두 개** — 프롬프트를 고쳤다(철칙 6·7 추가):

1. **판정을 서사로만 쓰고 도구를 부르지 않았다.** 재계약 답이 도착했을 때 에이전트가
   "£170k면 서명하죠"라고 말하는 장면을 훌륭하게 썼지만 `respond_offer`를 호출하지
   않아 `verdict`가 null로 남았다 — 협상이 장부에서 멈춰 있었다. 철칙 6으로
   "답이 도착한 협상은 반드시 도구로 판정을 기록하라. 에이전트가 금액을 더 부르는
   장면을 썼다면 그것은 counter 판정이다"를 명시했다.
2. **직전 턴의 대상을 잃었다.** "그래도 일단 £22.7M으로 오퍼 넣어봐"에 대해 "어느
   선수에게 넣을까요?"로 되물었다. 되묻기는 철칙 2에 맞지만 목적어 없는 지시는
   방금 논의한 선수를 뜻한다. 철칙 7로 대화 흐름에서 대상을 먼저 찾게 했다.

⚠️ **두 수정은 아직 실모드로 재검증하지 못했다** — API 크레딧이 소진됐다.
재검증 시나리오는 `낮은 주급으로 재계약 제안 → 답 도착 → respond_offer로 counter가
기록되는지`이고, 확률 대비 판정 분포(설계 §6)도 함께 봐야 한다.

## AI끼리의 이적 시장 (`ai-market.ts`)

감독이 관여하지 않는 거래 — **세계가 스스로 도는 자리**다. 한 시즌을 다 돌려도
AI↔AI 이적이 0건이던 시절엔, 창이 열리고 닫히는 동안 리그의 스쿼드가 한 명도
움직이지 않았다.

**협상 과정은 없다.** 오퍼·역제안·설득은 감독의 것이고 AI끼리는 결과만 남긴다 —
하루 수백 번의 판정을 볼 사람이 없다. 남는 것은 거래 자체이고, 장부(TRANSFER ·
CONTRACT · 재정 · 전술 배치)는 감독의 딜과 같은 모양으로 쓰인다.

| 값 | 크기 | 근거 |
| --- | --- | --- |
| 1부 클럽당 시즌 이적 | 3.4건 | 실제 5~7건 − 우리가 모델링하지 않은 리그와의 거래 |
| 1부 클럽당 시즌 임대 | 1.9건 | 실제 3~5건(대부분 하부리그행) |
| 여름 : 겨울 | 7 : 3 | 실제 시장의 분포 |
| 마감 직전 일주일 | 시도 ×2.2 | 데드라인 데이의 리듬 |
| 이적료 | 중앙값 £14M · 최고 £93M | 시장가 × 구단 성향 × ±15% |

**맞추는 기준은 수준과 자리다** — 사는 쪽 상위 15명 평균과 선수 OVR의 차가 7
안쪽이고, 그 자리의 1군 인원이 얇아야 한다. 임대는 어린 자원(23세 이하)이 한 단계
아래 구단에서 뛰는 모양이고, 주급 분담은 받는 쪽 형편이 정한다(1부 50% · 2부 20%).

**리그를 살리는 문턱 넷** — ① 인원은 1군으로 센다(전체 스쿼드는 2군·유스까지 40~49명)
② 2부는 돈을 쓰지 않는다(리그전이 없어 수입이 없다 — 사는 것만 막고 파는 것과
임대로 받는 것은 그대로) ③ 현금 바닥(1부 −£10M · 그 밖 0) ④ **주급 여력**
(`clubWageBudget`의 1.1배). 주급을 안 보면 이적료는 못 내도 주급은 낼 수 있는 것처럼
보이는데, 파산의 실제 경로는 매주 나가는 그쪽이다.

### 계획은 주 1회, 실행은 날짜별로

매일 굴리면 하루 tick이 무겁고(시도 62회 × 스쿼드 색인), 한 날에 몰아 실행하면
"8월 3일에 리그가 통째로 이적한 날"이 된다. 그래서 **결정과 실행을 갈랐다**:

1. 창이 열린 동안 큐(`state.aiDeals`)가 비면 그 주의 거래를 한 번에 정한다.
2. 각 거래에 그 주 안의 날짜를 배분한다 — **마감 주에는 뒤로 쏠린다**(제곱 분포).
3. 그 날짜의 tick이 장부를 쓴다. 이때 **다시 검사한다** — 그사이 다쳤거나 이미
   옮겼거나 돈이 없어졌으면 조용히 무산된다(실제 시장의 결렬이다).

계획 중에는 작은 가계부를 들고 다닌다(`Ledger`) — 같은 선수를 두 번 팔지 않고,
한 구단의 예산을 두 번 쓰지 않고, 인원 상한도 그 주의 예정 변동까지 세어 본다.

결과: 시즌 이적일이 90일에 흩어지고 하루 중앙 4건, **마감일에 54건**이 몰린다.
하루 tick은 시장을 붙이기 전(37ms)으로 돌아왔다.

## 감독 시장 (`manager-market.ts`)

벤치의 사람도 바뀐다. 판단은 **등급별 자리**다 — tier 1은 10위, 2는 14위, 3은 18위,
4는 20위 아래로 처지면 자리가 흔들리고, 문턱에 걸린 구단이 하루 9% 확률로 결단한다
(부임 75일 유예 · 하루 2건 상한). 시즌 96구단 중 24건 안팎이 바뀐다.

⚠️ **기대 순위와의 차이로만 재면 안 된다.** 잔류가 기대인 구단(목표 17위)은 꼴찌를
해도 차이가 3이라, 그 규칙에선 **강등권 감독이 절대 안 잘렸다** — 실제로는 가장 자주
잘리는 자리인데 정반대가 됐다.

후임은 이름(`inventPersonName` — 수석코치·기자와 같은 풀)과 부임일, 새 전술 역량치를
갖는다. **새 감독 효과**도 남긴다: 선수단 체력 +6 · 폼 +0.1. 실제로 관측되는 짧은
반등이고, 그래서 감독을 바꾼 라이벌이 다음 몇 경기에서 달라진다.

### 감독도 잘린다 — 다만 경고가 먼저다

AI 구단은 조용히 자르지만 감독에게는 **경고가 먼저** 온다(한 달에 한 번까지 · 3회).
경질은 세 조건이 모두 맞을 때다: 경고 3회 · **리그 최하위권(19·20위)** · 보드 신뢰 25 미만.
AI보다 훨씬 관대한데, **아직 새 구단에 부임하는 길이 없어 경질이 곧 세이브의 끝**이기
때문이다(그 길이 생기면 문턱은 AI와 같아져야 한다).

순위를 기대 위로 올리면 경고가 하나 지워진다 — 되돌릴 수 있어야 압박이 이야기가 된다.
경질되면 `state.dismissal`이 남고 시계가 멈춘다.
