# 경기 시뮬레이션 (Match Sim)

> 🚧 **초안 v0.2** · 2026-07-21 · [game-overview §4](./game-overview.md)의 심화
> — 전력 분석 패킷 · LLM 진행 루프 · 검증 · 분포 모니터링
>
> v0.1(결정적 1분 틱 엔진)에서 방향 전환 (결정 #14): **경기는 매치 티어
> LLM이 진행·중계·연출을 한 몸으로 시뮬레이션한다.** 코어는 근거(패킷)와
> 장부(검증·기록)를 맡는다.

**한 줄 요약: 코어가 "누가 유리한가"를 계산해 건네면, LLM이 "무슨 일이
일어나는가"를 이야기하며 결정하고, 코어가 그 사건을 검증해 장부에 적는다.**

---

## 0. 요구사항

1. **영향성** — 선수 능력치·전술·상태·감독 능력치가 결과에 통계적으로
   반영되어야 한다 (§5 분포 모니터링으로 측정).
2. **일관성** — 경기 장부(스코어·시계·인원·스탯)에 모순이 없어야 한다 (§4).
3. **설명 가능성** — 주요 사건은 전력 분석 패킷을 근거로 설명된다 (원인 태그).
4. 결정성은 **요구하지 않는다** — 같은 입력에서도 다른 경기가 나올 수 있다
   (결정 #14). 재현 가능해야 하는 것은 패킷 계산과 검증 규칙뿐.

## 1. 전력 분석 패킷 (코어, 결정적)

경기 시작 시와 전술 변경 시마다 코어가 재계산해 LLM에 주입하는 **유일한
판단 근거**.

```ts
StrengthPacket {
  zones: { attack, midfield, defense } × 양팀,  // 유효 능력치 가중합 (폼·사기·피로 반영)
  matchups: [{ zone, edge: 'home'|'away'|'even',
               size: 'slight'|'clear'|'big', why }],   // 존별 우열 + 근거 한 줄
  tacticalFit: { home, away },  // 전술 상성 해석 × 감독 전술 소화율 (attribute-model §7)
  keyPoints: [...],             // 위협/약점 — "태호(pace 88) vs 상대 좌백(pace 61)"
  guide: { expectedGoals, upsetChance },  // 참고 힌트 — 강제 아님
}
```

- **숫자 + 한 줄 해석**을 함께 담는다 — LLM이 중계에서 그대로 인용할 수
  있는 형태가 곧 원인 태그의 근거가 된다.
- `TacticsSpec`은 v0.1과 동일 (formation · mentality · 라인 · 압박 · 템포 ·
  폭 · 패스스타일 · 선수별 지시). 자연어 → 스펙 변환·반문은 ai-manager.md.
- 상대 AI 전술: 상대 감독 성향 프로필 → 규칙 기반 선택 + 스코어 상황 대응
  (v0.1 유지 — 여긴 LLM 불필요).

## 2. 진행 루프 (`advance_match`)

```
advance_match 호출
 → 매치 티어 LLM: StrengthPacket + 경기 장부(스코어·시계·카드·교체·최근 흐름)
     를 컨텍스트로, 다음 정지점까지 중계 서사 + log_match_events(tool call)
 → 코어: 이벤트 검증(§4) → 장부 갱신 — 실패 시 해당 이벤트 반려·재생성
 → 정지점 (연출 판단 or until 도달) — 유저 개입 가능
```

- **개입(전술·교체)은 패킷 재계산 → 다음 진행부터 반영.** 재시뮬은 없다 —
  경기는 대화처럼 앞으로만 흐른다.
- 하프타임은 강제 정지 (팀토크 기회).
- 중계 텍스트와 사건 결정이 한 호출에서 나온다 — "이야기했는데 장부에 없는
  골"이 생기지 않도록, 서사에 등장한 주요 사건은 반드시 `log_match_events`에
  포함되어야 한다 (출력 후검증 — ai-manager §6).

### 경기 장면의 대화와 연출 — 누구와, 어떻게

경기 장면도 [overview §2.1](./game-overview.md)의 롤플레이 문법 그대로다
(`@중계` · `@수석코치` · `@:` 연출 + 스킬 호출). 매치 티어가 중계·연출·대화
전부를 한 턴에서 오케스트레이션한다.

**시점별 대화 상대 (리얼리즘 규칙)**

| 시점 | 대화 가능 | 비고 |
| --- | --- | --- |
| 킥오프 전 (라커룸·터널) | 선수 전체 · 수석코치 | `team_talk` 기회 |
| 진행 중 정지점 | 수석코치 · 벤치 선수 | **그라운드 위 선수와 대화는 불가** — 외침만 |
| 하프타임 (라커룸) | 선수 전체 · 수석코치 | 강제 정지 — `team_talk` · `talk_to_player` |
| 종료 후 | 전체 (+ 믹스트존 기자) | 경기 후 정리 |

- **외침 (터치라인 지시)** — "태호! 더 올라가!" → 짧은 개인 지시로 해석
  (`set_player_instructions` 경로). 소음·선수 반응 같은 전달 연출은 매치
  티어 재량, 효과는 여느 지시처럼 패킷에 반영.
- **수석코치 = 경기의 상시 대화 상대.** 전력 패킷과 장부를 '사람 말'로
  읽어주는 존재 — 조언의 톤은 페르소나를 따르되 **사실(패킷·장부)은
  왜곡하지 않는다**. "물어보면 근거 있는 답이 나온다"가 경기 UX의 기둥.
- **벤치 선수 대화** — `talk_to_player` 판정형 그대로 (사기·관계). "몸 풀어
  둬"는 교체 복선 연출로 이어진다.
- **대화의 영향 경계 (철칙 유지)** — 대화 자체는 상태 무영향. 판정형 스킬로
  이어질 때만 상태가 변하고, 판정은 GM 티어 고정 (→ economy §2).

**매치 티어 컨텍스트 (경기 프리픽스 — economy §4)**

경기용 시스템(중계 스타일 · 문법 · 화자 규칙) + `StrengthPacket` + 경기 장부
+ **등장 페르소나**(수석코치 + 출전·벤치 명단의 핵심 페르소나 speechStyle)
+ **서사 메모리 발췌**(이 경기와 관련된 것 — 라이벌 악연, 유망주 데뷔전)
+ 일상 맥락 요약. → 중계가 "이어지는 이야기"가 되고, 벤치의 대화 상대가
어제의 면담을 기억한다.

**목업 — 진행 중 정지점의 벤치 대화**

```
[모델] @중계: *38′ — 민준의 중거리 슛이 크로스바를 강타합니다!* 아, 아깝습니다!
      @: *벤치가 일제히 일어섰다 앉는다*

[감독] *벤치 끝의 현우를 본다* 현우야, 몸 풀어. 후반에 저 왼쪽은 네가 찢는다.

[모델] ⚙ talk_to_player({ player: "이현우", judged: { outcome: "motivated", intensity: 2 } })
      @이현우: *벌떡 일어나 재킷을 벗는다* 준비됐습니다, 감독님.
      @수석코치: *귓속말로* 좋은 카드예요. 상대 우측 풀백, 발이 느립니다 —
      현우가 정확히 잡아먹는 유형이에요.
```

## 3. MatchEvent와 원인 태그

```ts
MatchEvent { minute, type, team, actors[], causes: CauseTag[], detail }
```

- 스키마는 v0.1 유지. `causes`는 **LLM이 패킷 항목을 인용해 부여**한다 —
  패킷에 없는 우열을 근거로 쓰면 후검증에서 경고. "블랙박스 서사 금지"의
  새 형태다.
- 태그는 경기 후 분석·"왜 졌어?" 답변·서사 메모리 태깅의 근거로 그대로 쓰인다.

## 4. 검증 — 경기 장부의 무결성 (코어, hard rules)

| 규칙 | 내용 |
| --- | --- |
| 시간 순증 | 이벤트 분(分)은 단조 증가, 0~90(+추가시간) 범위 |
| 인원 | 퇴장·교체아웃 선수 재등장 금지 · 교체 5인/3회 · 미등록 선수 금지 |
| 스코어 일관성 | goal 이벤트 수 = 스코어. 서사 속 골 = 장부 속 골 |
| 빈도 상한 | 분당 주요 이벤트 한도, 경기당 득점 상한(soft 가이드 + hard 반려) — 12골 경기 방지 |
| 파생 스탯 | 슛·점유율 등 요약 스탯은 이벤트에서 코어가 재계산 — LLM의 숫자를 믿지 않는다 |

- 반려 시 해당 tool call만 오류 반환 → LLM이 수정 재기록 (Zod 재시도와
  동일한 패턴, AGENTS.md 6-2).

## 5. 능력치 영향 보장 — 분포 모니터링 하네스

결정적 시드 재현 대신 **통계로 검증**한다 (오프라인 밸런스 도구, LLM 포함
실행):

- 고정 매치업 세트(대등 / 한쪽 우위 / 압도)를 각 N회 반복 → **전력차 대비
  승률·득점 분포 곡선**을 측정.
- 기준: 실제 EPL 분포와 비교 — 홈 승률 · 무승부율 · 평균 득점 · 업셋 빈도
  (Football-Data.co.uk, [data-sourcing §2](./data-sourcing.md)).
- **전술 민감도**: 같은 스쿼드에서 전술만 바꿔 효과의 방향·크기 확인 —
  감독 전술 소화율 계수 포함.
- 기준 이탈 시 튜닝 대상: 패킷의 표현(해석 문장), 프롬프트 규약, `guide`
  힌트 강도 (→ `balance.md`).

## 6. 경기 후 반영 (코어, 결정적)

스탯 적재(이벤트 재계산) → 평점 산출 → 폼 Δ → 사기 Δ(결과+개인 활약) →
피로 정산 → 부상 확정 → 재정(입장 수익 간이) → 리그 테이블 → 서사 훅
태깅(salience → narrative.md). v0.1과 동일 — **사건은 창발, 반영은 공식.**

## 7. 타 팀 간이 시뮬 (결정 #5)

유지 — 전력 스칼라 + 홈 어드밴티지 → 확률 샘플로 결과·득점자만. 유저
경기만 LLM이 시뮬레이션한다 (품질을 쓸 곳에 쓴다).

## 8. 테스트

- **검증 규칙 단위 테스트** — LLM 없이, 조작된 이벤트 스트림을 입력해
  반려·통과 확인.
- **패킷 계산 단위 테스트** — 결정적이므로 일반 단위 테스트.
- **분포 하네스 (§5)** — LLM 포함이라 CI가 아닌 주기 실행. 밸런스 회귀의
  기준선.

## 9. 미해결

- 득점 상한 등 극단값의 hard 수치
- 추가시간 처리 (LLM 재량 vs 코어 규칙)
- 패킷 갱신 주기 — 경기 중 피로 누적을 얼마나 자주 재반영할지
- `guide` 힌트(expectedGoals)가 LLM을 과도하게 앵커링하는지 검증
- 서사-장부 정합 후검증의 구현 방식 (서사 텍스트 파싱 vs 프롬프트 규약 신뢰)
