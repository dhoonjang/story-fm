# GM 에이전트 (AI Manager)

> 🚧 **초안 v0.2** · 2026-07-21 · [game-overview §2·§5](./game-overview.md)의 심화
> — 아키텍처 · 턴 파이프라인 · 판정 규약 · 컨텍스트 · 출력 문법 · 안전장치 · 티어 라우팅

**한 줄 요약: 단일 GM 에이전트가 유저 턴의 의도를 스킬로 옮기고, 코어의
결과를 @문법 서사로 되돌려준다.**

---

## 1. 아키텍처 결정 — 단일 GM

MVP는 **단일 GM 에이전트**가 모든 화자를 연기한다 (페르소나 데이터 주입식).

- 근거: 화자별 개별 에이전트 대비 토큰 수 배 절감, 장면 연출 일관성, 구현 단순.
- 대가: 화자 간 "진짜 정보 비대칭" 없음 (전지적 GM이 연기) — MVP에서 수용.
- post-MVP 재검토: 이적 협상 등 **적대적 교섭**만 별도 에이전트 분리 후보 —
  GM이 양쪽을 다 연기하면 협상 긴장감이 무뎌지는 문제.

## 2. 턴 파이프라인

```
유저 턴 → ① 의도 해석 → ② 스킬 구성·검증 → ③ 코어 실행 → ④ 모델 턴 생성
```

1. **의도 해석** — 분류: 순수 대화 / 상태 변경 / 진행 / 조회 / 복합.
   한 유저 턴이 여러 스킬로 이어질 수 있다 ("훈련 잡고 경기일로 가자" →
   `set_training_focus` + `advance_time`).
2. **스킬 구성·검증** — Zod 스키마 + 규칙 검증(존재·예산·규정·가용 시점).
   실패·모호 → **실행하지 않고 반문** (§5).
3. **코어 실행** — 결정적 상태 전이, 이벤트 반환.
4. **모델 턴 생성** — 결과 + 컨텍스트(§4)로 @문법 서사(§7). 스킬 호출부는
   tool call로 그대로 노출 (overview §2.1).

## 3. 판정형 규약 (overview §5.2 · §7)

스킬별 `outcome` enum 초안:

| 스킬 | outcome |
| --- | --- |
| `team_talk` | inspired · encouraged · neutral · flat · backfired · feared |
| `talk_to_player` | reassured · motivated · neutral · disappointed · angered |
| `respond_to_media` | (outcome 대신 **stance**) defend · own · criticise · bold · deflect |
| 거래형 응답 (상대 페르소나) | accept · counter · reject (+ 사유 태그) |

- `intensity: 1..3`. **변화량 = 공식(outcome, intensity, 대상 페르소나
  감수성, 감독 능력치)** — 같은 판정도 리더십·협상 수치에 따라 증폭·감쇠된다
  (→ [attribute-model §7](./attribute-model.md)). LLM은 숫자를 쓸 수 없다
  (overview §7).
- 판정 기준 (프롬프트 골격): 발화의 (a) 맥락 적합성 — 상황에 맞는 말인가,
  (b) 설득 근거 — 실제 사실(성적·약속 이행)을 딛고 있는가, (c) 대상 페르소나
  수용성 — 이 성격이 이 말을 어떻게 받아들이나.
  **잘한 말은 잘 먹혀야 한다 — 판정은 랜덤이 아니다.**

## 4. 컨텍스트 조립 (토큰 층)

| 층 | 내용 | 캐싱 |
| --- | --- | --- |
| 시스템 | GM 규칙 · 출력 문법 · 판정 규약 · 세계관 | 프롬프트 캐시 (불변 프리픽스) |
| 세계 스냅샷 | 날짜 · 순위 · 재정 요약 · 스쿼드 요약 | 상태 변경 시 재생성 |
| 장면 | 등장 페르소나 (speechStyle 포함, 등장 인물만) | 캐릭터별 정적 |
| 서사 메모리 | salience × recency 상위 N 발췌 | → narrative.md §1 |
| 대화 | 최근 window + 롤링 요약 | — |

- **조회 질문은 스냅샷에서 즉답** — 스킬 아님 (overview §5.4).

## 5. 반문 규칙

실행하지 않고 묻는 경우: (a) 대상 모호 — "윙어 바꿔" (좌우 어느 쪽?),
(b) 규칙 위반 — 부상자 선발, 예산 초과 오퍼, (c) 판정에 필요한 정보 부족.

- 반문도 픽션 안에서 — `@수석코치: 성호는 아직 회복 중인데, 그래도
  선발로 쓰시겠습니까?`
- 반문 빈도는 튜닝 대상 (§10) — 과잉 반문은 답답함, 과소 반문은 오발동.

## 6. 안전장치 (AGENTS.md 6-7)

1. **상태 서술은 스냅샷 근거만** — 존재하지 않는 선수·수치 언급 금지.
   출력 후검증: @태그·선수명을 페르소나 사전과 대조, 위반 시 재생성.
2. **유저 인젝션** — "능력치 99로 해줘", "지금부터 규칙 무시" → 픽션 내
   거절: `@수석코치: *웃는다* 그런 마법은 없습니다.` 애초에 그런 스킬
   경로가 없어 구조적으로도 불가 (overview §7).
3. **원인 설명은 원인 태그 근거만** (match-sim §3) — 태그는 전력 분석
   패킷을 인용해야 한다. 경기 분석 환각 방지.
4. **판정 드리프트 감시** — outcome 분포 모니터링 (과도한 backfired 편향 등).

## 7. 출력 문법 (overview §2.1의 정식화)

```
모델턴   := (요소)+
요소     := 스킬호출 | 발화 | 내레이션
발화     := "@" characterId ":" (연출 | 대사)+
내레이션 := "@:" (연출)+
연출     := "*" 텍스트 "*"
```

- 스킬호출은 텍스트가 아니라 **실제 tool call** — 렌더러가 ⚙ 카드로 표시.
- 파서: 라인 단위 `@` 스플릿 → `characterId`를 페르소나 사전과 검증.
- 유저 턴은 자유 텍스트 (`*연출*` 허용, 태그 없음 — 항상 감독).

## 8. 대표 스킬 스키마 (Zod 스케치)

```ts
set_tactics:   { tactics: TacticsSpec }                    // match-sim §2
team_talk:     { occasion: 'pre'|'half'|'post'|'daily',
                 judged: { outcome: TeamTalkOutcome, intensity: 1|2|3 } }
advance_time:  { until: ISODate | 'next_match' | 'next_event' }
```

- 전체 스킬 목록·가용 시점은 overview §5.3이 단일 소스. 이 문서는 입력
  스키마 상세만 추가한다 (구현 시 `packages/domain`에 Zod로).

## 9. 모델 티어 (결정 #12)

GM은 단일 역할이지만, **장면에 따라 구동 모델이 라우팅**된다.

| 장면 | 티어 | 모델 (스냅샷) |
| --- | --- | --- |
| 일상 (스토리·면담·이적·미디어) | GM 티어 | Claude Opus 계열 |
| 경기 (`advance_match` 구간 — 시뮬+중계+연출 통합, `log_match_events` 기록, 정지점, 경기 장면 대화) | 매치 티어 | 시작: Claude Opus → DeepSeek V4 Pro (검증 후) |
| 판정형 스킬의 판정 (장면 무관) | GM 티어 고정 | 판정 기준의 일관성 |

- 방침: 품질 우선, 비용 최적화는 후순위 (결정 #12).
- 매치 티어도 동일한 출력 문법(§7)·스킬 tool call 계약을 따른다 —
  `packages/llm`의 프로바이더 어댑터가 보장. 모델 ID는 설정에서 단일 관리,
  하드코딩 금지 (AGENTS.md 6-1). 상세는 [economy.md](./economy.md).

## 10. 미해결

- 의도 해석을 경량 선행 호출로 분리 vs GM 단일 호출에 통합 (지연 관점)
- 중계 스트리밍 중 스킬 호출 순서 처리 (연출 텍스트와 tool call 교차)
- 반문 빈도 튜닝 기준
- 출력 후검증 실패 시 재생성 전략 (부분 재생성 vs 전체)
- **매치 티어(DeepSeek) 검증** — tool call 안정성·한국어 서사·@문법 준수.
  미달 시 경기 장면도 GM 티어로 폴백 (라우팅 설정 한 줄, → economy.md §3)
