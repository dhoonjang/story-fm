# 게임 개요

**게임 전체가 하나의 채팅이다.** 유저는 감독 한 사람을 연기하고, 모델(GM)은
나머지 세계 전부를 연기한다. 스토리·훈련·이적·경기가 모두 채팅에서 벌어지고,
상태를 바꾸는 유일한 통로는 스킬(도구 호출)이며, 장부(상태·규칙·수치)는 코어가
결정적으로 지킨다. 채팅 밖에는 명단·달력·재정·대회·커리어를 읽는 오피스 뷰가 있다.

> 슬라이더와 스프레드시트 대신 **대화**로 팀을 이끈다 —
> 매 시즌이 한 편의 드라마가 되는 AI 풋볼 매니저.

| | Football Manager | story-fm |
| --- | --- | --- |
| 인터페이스 | 메뉴·슬라이더·표 | 자연어 채팅 (+ 보조 뷰) |
| 경기 | 2D/3D 엔진 관전 | 텍스트 중계 — 하이라이트 서사 |
| 선수 | 능력치 덩어리 | 능력치 + 페르소나(성격·기억·관계) |
| 재미의 중심 | 최적화·성취 | 서사·관계·납득되는 드라마 |
| 결과 설명 | 스탯으로 추정 | 원인 태그로 게임이 직접 설명 |

## 1. 핵심 구조

```
              플레이어 (자연어 입력)
                     │
        ┌────────────▼────────────┐      ┌───────────────────────┐
        │        메인 채팅          │      │   오피스 (읽기 전용)      │
        │  스토리 전개 · 경기 연출    │      │  스쿼드 · 달력 · 재정     │
        │  화자: 코치·기자·구단주·선수 │      │  대회 · 커리어           │
        └────┬──────────▲─────────┘      └───────────▲───────────┘
             │ 스킬 호출  │ 결과·서사                   │ 프로젝션
        ┌────▼──────────┴────────────────────────────┴───────────┐
        │              게임 코어 (결정적 장부)                       │
        │  상태(선수·팀·재정·일정) · 시뮬 · 전력 분석 · 규칙 검증        │
        └─────────────────────────────────────────────────────────┘
```

세 가지 철칙:

1. **LLM의 자유 텍스트는 게임 상태를 1비트도 바꾸지 못한다.** 모든 변경은
   `스킬 호출 → Zod 검증 → 결정적 상태 전이` 경로만 탄다.
2. **경기 결과도 코어가 정한다.** xg 구간 시뮬레이터가 사건을 굴려 확정하고
   LLM은 중계·연출·대화로 옮긴다. 감독의 지시는 전력 패킷을 통해서만 결과에
   닿는다 ([match-sim.md](./match-sim.md)).
3. **시간도 상태다.** 날짜는 `advance_time`, 경기 시계는 `advance_match`로만
   흐른다. 대화는 얼마든지 길어져도 세계는 멈춰 있다.

### 채팅 문법 (롤플레이)

| 요소 | 형식 | 예 |
| --- | --- | --- |
| 행동·연출 | `*…*` | `*고개를 숙인다*` |
| 화자 발화 | `@화자명:` (이름, 직책 아님) | `@스티브 홀랜드: 죄송합니다...` |
| 내레이션 | `@:` — 화자 없는 연출 | `@: *라커룸이 얼어붙는다*` |
| 스킬 호출 | 구조화된 도구 호출 (채팅에 칩으로 노출) | `team_talk({...})` |
| 조작 | `@: [시간 진행 — 하루]` — 화면 손잡이, 감독 발화 아님 | |

- **권한 경계** — 유저는 감독 자신만 움직인다. 유저가 세계를 서술하면 GM은
  사실이 아니라 감독의 시도로 해석해 판정한다.
- **감독의 행동도 흔적을 남긴다** — 책상을 엎으면 판정형 스킬을 거쳐 사기·관계에
  반영된다. 극단 행동도 수용하되 세계는 반드시 그에 맞게 반응한다.
- 직책·아이콘은 화면이 붙인다(`speakerRoles`) — [people.md](./people.md).

### 스킬 유형

| 유형 | 결정 방식 | 예 |
| --- | --- | --- |
| 진행형 | 시계를 움직이고 그 사이를 코어가 해소 | `advance_time` |
| 설정형 | 감독의 결정을 검증 후 기록 — 판정 없음 | `set_lineup` |
| 판정형 | 수행의 결과를 LLM이 판정(`outcome, intensity`) → 변화량은 코어 공식 | `team_talk` |
| 거래형 | 상대(선수·구단) 판정은 LLM, 확률 앵커·한도는 코어 | `send_offer` |

도구 표면은 33개 — **한 판단은 한 도구**로 묶는다(라인업+1·2군 이동이 한 요청,
오퍼는 방향을 인자로). 전체 카탈로그는 [llm.md](./llm.md)와
`packages/engine/src/skills/`.

### 변경 가드레일

**LLM은 "무엇이 일어났는가"를 정하고, "얼마나 변하는가"는 코어 공식이 정한다.**
면담 판정이 `{outcome: "encouraged", intensity: 2}`면 사기 +Δ는 공식이 계산한다.
극적 능력치 이벤트("각성")는 없다 — 능력치는 훈련·경기·나이 경로로만 변한다.
판정형·결산형(훈련·평점·심경)은 모두 **코어 앵커 ± 한도** 구조다.

## 2. 게임 루프

게임은 **7월 1일(여름 이적창 개장)**에 시작한다. 선수단 소집은 7월 둘째 월요일,
개막은 8월 중순 — 프리시즌 동안 영입·훈련·시즌 계획이 먼저 움직인다.

```
온보딩 (팀 선택 + 감독 캐릭터 생성)
 → 일상 루프: 채팅 지시(훈련·전술·라인업·면담·이적) ↔ 시간 진행(tick)
 → 경기일: 전력 패킷 → 구간 진행(정지점 개입) → 장부 검증 → 반영
 → 시즌 종료: 보드 평가 · 시즌 전환(은퇴·유스·커리어 적재)
 → 다음 시즌 (멀티시즌)
```

- **tick(하루)** 이 세계를 굴린다 — 훈련·회복·성장·부상, AI 팀의 경기·이적·
  재계약·감독 경질, 협상 응답 도착, 기자회견 개최. 감독의 결정이 필요한 일
  앞에서 멈춘다. [season.md](./season.md)
- **시간 이동은 화면 손잡이**(하루·일주일·다음 경기)가 기본이다 — 코어가 먼저
  굴리고 그 사이의 일을 상태 스냅샷으로 GM에게 넘겨 보고시킨다.
- 방치의 비용은 자연스럽게 생긴다 — 면담을 미룬 불만 선수는 tick마다 사기가
  내려간다. 별도 페널티 규칙이 아니라 시간의 결과다.

## 3. 화면 구조

화면은 두 줄이다 — 얇은 상단 띠(시계·팀)와 **무대(stage)**. 무대의 기본은
채팅이고, 경기가 시작되면 왼쪽 판세(`MatchView`) · 오른쪽 중계·지시로 갈린다.
장부 뷰는 오른쪽 위 아이콘 줄에서 연다.

| 뷰 | 내용 |
| --- | --- |
| 스쿼드 | 전술판(드래그 배치·역할·자동 저장) + 명단(체력·폼·평점·심경) |
| 달력 | 경기·훈련·이적창·추첨 — 경기만 칩, 나머지는 색점 |
| 재정 | 월간 보고서·원장·PSR ([club-finance.md](./club-finance.md)) |
| 대회 | 대회별 순위표(진출권 구역)·라운드 일정·브래킷 |
| 커리어 | 감독 오각형·평판·트로피·시즌 기록 |

- 폭 1200px 이상이면 채팅과 장부가 반반으로 나란히 선다. 결과 표시는 채널 셋 —
  채팅 카드(결정에 필요한 원본 숫자) · 접히는 칩(지시 확인) · 레일 말풍선(장부
  변경 알림).
- 경기가 끝나면 그 구간의 중계는 결과 한 줄 카드로 접힌다.
- UI에 조작법 안내 문구를 넣지 않는다 — 조작은 보이는 것으로 알린다.

## 4. 데이터 모델 (요약)

**카탈로그(불변 초기치)와 게임 세이브(가변 상태)의 2-레이어.** 새 게임은
카탈로그를 읽어 `GAME_PLAYER`/`GAME_TEAM`으로 인스턴스화한다.

- 선수: 능력치 15축 + 폼·체력·심경 + 포지션/역할 적합도. [attribute-model.md](./attribute-model.md)
- 전술이 라인업의 원본: `TACTICS → TACTIC_ASSIGNMENT`. 팀에 선발 배열은 없다.
- 일정 축 단일화: 경기·훈련·이적창·추첨이 전부 `SCHEDULE_ENTRY`.
- 이적·계약: `TRANSFER`(원장) · `CONTRACT` · `NEGOTIATION`(진행 중 흥정 분리).
  [transfers.md](./transfers.md)
- 재정: 원장 + 월간 보고서, 이적료는 현금 즉시·장부 상각. [club-finance.md](./club-finance.md)
- 세이브 호환: 새 테이블은 로드 시 빈 배열, 새 필드는 optional — 버전을 올리지
  않는 것이 원칙. ERD와 상세는 [implementation-notes.md](./implementation-notes.md)

## 5. 세계의 규모

- **5대 리그 96팀**이 리그전을 돌고, 컵용 2부 64팀 + 이적시장 전용 리그(사우디·
  MLS)가 있다. EPL은 실선수 777명 시드, 유럽 4대 리그도 실선수, 2부는 절차 생성.
- 시즌 2,100여 경기 중 감독의 50여 경기만 구간 시뮬, 나머지는 간이 시뮬 —
  **LLM은 한 경기도 결정하지 않는다.**
- 국내 컵 6종 + 유럽 대항전 3종(UCL/UEL/UECL)이 실제 규정(진입 라운드·추첨
  방식·홈 배정·날짜)대로 돈다. [season.md](./season.md)
- 세계는 감독 없이도 움직인다 — AI 팀끼리의 이적·재계약·감독 경질, 리그 전체의
  피로·회복·징계.

## 6. 현재 범위와 미구현

플레이 가능한 프로토타입(데이터 모델 v6). 온보딩 → 일상 지시 → 경기 → 시즌
전환 → 멀티시즌이 엔드투엔드로 돈다.

주요 미구현(상세는 각 문서의 "미해결"):

- 보드/구단주 요청·목표 시스템 (경질 경고는 있음)
- 세계가 먼저 말 걸기 — 기자회견 외 (설계: [people.md](./people.md))
- 서사 아크·장기 기억 축적
- 승강 처리 (강등 구역 표시도 그래서 없다)
- AI 팀의 폼·적응도 성장 (밸런스 편향의 뿌리 — match-sim.md §7)
- 토큰 예산 상한
