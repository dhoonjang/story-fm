# LLM 통합 — 티어 · 어댑터 · 입출력

**단일 GM 에이전트가 유저 턴의 의도를 스킬로 옮기고, 코어의 결과를 @문법
서사로 되돌려준다.** 방침은 품질 우선 — 비용 최적화는 후순위이되, 캐시·컨텍스트
위생 같은 구조적 효율은 설계에 넣는다(지연과 품질을 위한 것이기도 하다).

## 1. 티어와 라우팅 (`packages/llm/src/config.ts`)

**프로바이더는 티어가 고른다 — 세트로 묶지 않는다.** 한 회사가 모든 자리에서
가장 좋거나 가장 싸지는 않다.

| 티어 | 담당 | 모델 (스냅샷 — 코드가 원본) |
| --- | --- | --- |
| GM | 서사·의도 해석·판정(장면 무관 고정) | Claude Opus |
| 매치 | 경기 중계·연출·경기 장면 대화 | Gemini Flash Lite |
| 잡무(chore) | 훈련 결산·경기 평점·심경 — 자주 돌지만 서사를 쓰지 않는 판정 | GPT Luna |

- 중계를 가볍게 두는 이유: **사건은 코어가 정한다** — 모델은 옮길 뿐인데 90분에
  스무 번 도니 지연이 곧 게임 속도다. 잡무를 싼 티어로 보내는 이유는 값보다
  **빈도**다. 잡무의 출력은 코어 앵커 ± 한도 안에서만 움직이므로 모델이 조금
  무뎌도 게임이 무너지지 않는다.
- **판정은 GM 티어 고정** — 팀토크·면담 판정 기준이 장면에 따라 흔들리면 안
  된다(심판은 한 명).
- ⚠️ `LLM_PROVIDER`는 전 티어를 갈아엎는 스위치가 아니라 **선호 순위**다 —
  티어가 고른 곳에 키가 없을 때 어디로 보낼지를 정한다.
- ⚠️ **키가 없는 제공자로는 보내지 않는다** — 보내면 그 티어만 조용히 mock이
  되어 "GM은 멀쩡한데 중계만 무뎌진" 이유를 알 수 없다.
- **`MODELS`의 빈 칸은 "그쪽으로 안 보낸다"는 뜻** — OpenAI는 잡무 모델만 두어
  키 하나가 없어져도 서사가 그쪽으로 새지 않는다.
- 라우팅은 순수 함수(`tierConfig(name, env)`)라 키 조합을 인자로 갈아 끼워
  테스트한다. 모델 ID 하드코딩 금지 — 설정 단일 관리.
- `LLM_MODE=mock|real` — mock이면 키 없이 개발·테스트가 돈다. mock과 실모드는
  같은 시뮬레이터를 쓰고 서술 주체만 다르다.

## 2. 어댑터 계약 (`packages/llm`)

```
GameLLM (제공자 중립 계약)
 ├─ AnthropicAdapter — cache_control 프리픽스 캐싱
 ├─ GeminiAdapter    — implicit caching · thought signature/function id 보존
 └─ OpenAIAdapter    — 잡무 전용
```

- 출력 계약은 티어와 무관하게 동일: @문법, 스킬은 tool call, 구조화 출력은
  Zod 검증 + 재시도.
- 이력은 **제공자 원형으로 태깅**해 저장한다 — Gemini의 thought signature와
  function call id를 평탄화하면 다음 호출이 실패할 수 있다. 설정이 바뀌면
  장부·패킷은 유지하고 원형 대화 이력만 새로 시작한다.
- **사고는 최소**(Anthropic 끔 · Gemini `MINIMAL`), ⚠️ **출력 상한 64,000** —
  상한은 사고와 본문을 함께 덮으므로 장면 길이로 좁히면 본문이 잘린다.
- ⚠️ **Anthropic은 화면에 흘릴 곳이 없어도 스트리밍으로 부른다.** SDK가
  `max_tokens > 21,333`인 비스트리밍 요청을 **보내기 전에** 거부한다
  (`calculateNonstreamingTimeout` — 예상 소요가 10분을 넘는다는 판정). 상한이
  64,000이므로 `onText` 없는 호출은 전부 그 자리에서 터졌고, 온보딩이 매번
  실패해 첫 장면이 늘 규칙 기반 폴백으로 열렸다. `onText`는 델타를 받을지만
  가른다 — 최종 메시지는 어느 쪽이든 같다.
- ⚠️ **GPT-5.6은 Chat Completions에서 함수 도구와 추론을 함께 못 쓴다** —
  `reasoning_effort: "none"`이라야 한다. 서사를 이쪽으로 옮기려면 Responses
  API로 갈아타야 한다.
- **스트리밍은 세 어댑터가 같은 `onText` 계약을 쓴다.** OpenAI는 Chat
  Completions 위에 붙였다 — 막고 있던 것은 추론 + 함수 도구의 조합이지
  스트리밍이 아니다. 갈아타면 저장 이력의 모양이 통째로 바뀌어(`messages[]` →
  input item[]) 이미 `openai` 태그가 붙은 세이브가 버려지므로, 추론이 실제로
  필요해지는 날 옮긴다. 도구 호출은 **`index`가 자리를 정하고**(id·이름은 첫
  조각에만, 인자는 문자 단위로 쪼개져 온다) 사용량은 `include_usage`가 붙여
  주는 마지막 chunk에만 실린다 — 그 옵션이 없으면 계측이 이 티어를 못 본다.

## 3. 입력 구조 — 변경 빈도 순 3층 + 이번 턴

앞 두 층은 프롬프트 캐시(0.1×), 마지막 층만 매 턴 정가로 읽힌다. 캐싱은
프리픽스 매치 — 앞이 1바이트라도 바뀌면 뒤가 전부 무효이므로, ⚠️ 고정층에
날짜·ID 인터폴레이션 금지.

| 층 | 내용 | 변경 빈도 |
| --- | --- | --- |
| 고정 | 도구 정의 + 시스템 프롬프트 | 불변 |
| 레퍼런스 | 감독 프로필 + 인물 카드 + 선수 명부 / 경기 땐 전력 패킷 | 드묾 |
| 이력 | 지난 턴들 — 시작점을 6턴 단위로만 이동(프리픽스 안정) | 매 턴 |
| 이번 턴 | 감독 발화 + 상태 스냅샷(`role:"system"` 오퍼레이터 채널) | 매 턴 |

- ⚠️ **명부는 조회 표가 아니라 사람들이다** — "이 이름들이 모두 화자다".
  조회 안내를 헤더에 얹으면 카드 없는 서른 명이 조회 대상으로 굳는다.
- **평시와 경기 이력은 갈린다**(`relevantTurns`) — 한 이력에 섞으면 중계가
  이적 협상을 읽고 GM이 중계 수십 턴을 읽는다(토큰 + 맥락 오염). 대신 두
  다리로 잇는다: 경기로 들어갈 땐 `buildMatchBrief`(직전 평시 감독 발화 3개를
  **그대로** — 요약하면 말투와 의도가 먼저 사라진다), 경기가 끝나면
  `matchDigest`(결과·득점·최고 평점 — **장부에서 코어가 뽑는다**).
- 상태 스냅샷: 날짜·다음 일정·주의(협상 ❗·회견)·선수 근황(cues)·화면 조작
  누적(`pendingEdits`) — "이미 반영됨, 도구로 다시 하지 마라"와 함께.
- `state.phase`는 라우팅 전용 — 모델 입력에 넣지 않는다.

### 조회 도구 — 창이 아니라 검색

능력치·배치·타 팀·순위·일정·과거는 컨텍스트에 넣지 않고 읽기 전용 도구 7종으로
온디맨드 제공: `search_players` · `get_player` · `get_squad` · `get_team` ·
`get_league` · `get_schedule` · `get_career`. 상대·대회·라운드·날짜 범위·방향으로
좁혀 "다음 맨유전"에 정확히 답하고, **무엇을 뒤졌는지** 헤더에 밝힌다. 답할
도구가 없으면 모델은 지어낸다 — 컨텍스트 밖 사실에는 각각 읽을 자리를 준다.

## 4. 스킬 표면 — 한 판단은 한 도구

도구는 33개. 같은 순간에 함께 정해지는 것들이 갈려 있으면 GM이 하나를
빠뜨린다 — 라인업은 1·2군 이동까지 한 요청(`set_lineup`의 `squadLevels`),
한 선수의 자리·역할·개인 지시는 `set_player_tactic` 하나, 오퍼는 방향을
인자로(`send_offer` kind=buy/sell/loan/loan_out).

| 유형 | 계약 |
| --- | --- |
| 진행형 | 시계를 움직인다 — `advance_time`·`advance_match`만 |
| 설정형 | 검증 후 그대로 기록 |
| 판정형 | LLM이 `{outcome, intensity}`를 판정, **변화량은 코어 공식** |
| 거래형 | 상대 판정은 LLM, 확률 앵커·한도는 코어 |

- 판정 기준: 맥락 적합성 · 설득 근거(실제 사실을 딛고 있는가) · 대상 페르소나
  수용성. **잘한 말은 잘 먹혀야 한다 — 판정은 랜덤이 아니다.**
- 반문 규칙: 대상 모호·규칙 위반·정보 부족이면 실행하지 않고 픽션 안에서
  묻는다(`@수석코치: 성호는 아직 회복 중인데, 그래도 쓰시겠습니까?`).
- 유저 인젝션("능력치 99로")은 픽션 내 거절 — 애초에 그런 스킬 경로가 없어
  구조적으로도 불가능하다.

## 5. 결산 계약 — 앵커 ± 한도

자주 도는 판정(잡무 티어)은 전부 같은 구조다: **코어가 앵커를 박고, LLM이
맥락으로 다시 매기고, 코어가 한도로 자른다. 실패하면 앵커가 남는다** —
결산 하나 때문에 게임 진행이 막히지 않는다 (한 번은 다시 부른다 — §9).

| 결산 | 시점 | 폭 |
| --- | --- | --- |
| 훈련(`training-rater`) | `advance_time` 구간을 한 묶음으로 | 전술 적응도 ±3 · 능력치 팀 3점 |
| 경기 평점(`match-rater`) | 경기 종료 후 | 앵커 ±1.2 + 근거 한 줄 |
| 심경(`mood-rater`) | 시간 진행·경기 뒤, 평점 다음 | 문장 재작성 — 사실 검사로 버림 |

## 6. 출력 문법

```
모델턴   := (요소)+
발화     := "@" 화자이름 ":" (연출 | 대사)+     — 이름, 직책 아님
내레이션 := "@:" (연출)+
연출     := "*" 텍스트 "*"
스킬호출 := 실제 tool call (렌더러가 칩 또는 카드로 표시 — overview §3)
조작     := "@: [시간 진행 — 하루]"             — 손잡이, 감독 발화 아님
```

- 중계의 원인 설명은 패킷의 원인 태그 근거만 — 경기 분석 환각 방지.
- 시각 페이싱은 모델이, 브레이크는 코어가 — 날짜를 넘기면 안 되는 것 앞에서는
  `advanceTime`이 멈춰 세우므로 프롬프트가 같은 일을 또 지시하지 않는다.

## 7. 프롬프트 관리 원칙

- 프롬프트는 코드처럼 — 별도 파일/상수로 버전·diff 추적
  (`packages/agents/src/gm-prompt.ts` 등). 매직 스트링 금지.
- ⚠️ **수정은 지우는 방향이 기본이다.** 문제가 보이면 지시를 덧붙이지 말고
  그 행동을 시키는 기존 문구를 먼저 지운다 — 새 지시로 증상을 덮으면 원인은
  남고 프롬프트만 길어진다. 규칙만 남기고 이유·비유·중복 예시는 넣지 않는다.
- 런타임 오버라이드는 두지 않는다 — 프롬프트는 코드로만 관리한다. 상수가 유일한
  원본이라 지금 도는 문장이 곧 저장소의 문장이고, 변경은 diff로 남는다.
- 프롬프트 변경은 별도 커밋으로 분리한다.

## 8. 토큰 예산과 계측 (`packages/llm/src/usage-meter.ts`)

계측은 **팩토리 한 곳에 붙는다** — 모든 실호출이 `createGameLLM`을 지나므로
어댑터 셋에 같은 코드를 복제하지 않고도 세션 누적과 상한이 빠짐없이 걸린다.
누적 자체는 순수 함수라 장부를 손으로 굴려 검증한다.

- **사용량 계약은 티어와 무관하게 같다** — 입력·출력·캐시 읽기/쓰기.
  ⚠️ `inputTokens`는 **캐시분을 포함한 입력 전부**다. Gemini·OpenAI는 프롬프트
  합계에 이미 포함하지만 Anthropic은 빼고 보고하므로 어댑터가 되돌려 놓는다 —
  안 그러면 캐시가 잘 먹을수록 분모가 줄어 히트율이 1을 넘는다.
- **히트율 = 캐시 읽기 ÷ 입력.** 0은 프리픽스가 조용히 무효화됐다는 신호다 —
  고정층에 날짜·id가 섞이면 매 턴 앞이 바뀌어 뒤가 전부 정가로 읽히는데, 화면엔
  아무 증상이 없고 요금만 오른다. 캐시가 걸릴 만한 크기(1,024 토큰)를 세 번 넘게
  보냈는데 히트율이 0인 티어만 경고한다 — 잡무의 짧은 결산 프롬프트는 애초에
  캐시가 안 걸려 신호가 아니다.
- **상한은 `LLM_TOKEN_BUDGET`**(세션 누적 입력+출력). 없거나 0 이하면 무제한이다
  — 오타 하나로 결산이 통째로 멎는 것보다 상한이 안 걸린 채 로그에 남는 편이 낫다.
- ⚠️ **상한은 게임을 멈추지 않는다.** 넘겨도 **GM·중계는 계속 돌고** 경고 한 번만
  남는다 — 그 자리에는 대신 세울 값이 없다. 끊기는 것은 **잡무뿐**이고, 결산은
  원래 실패하면 앵커가 남는 계약이라(§5) 건너뛴 자리에 이미 코어의 값이 서 있다.
  건너뛴 횟수도 장부에 적는다 — 안 적으면 결산이 왜 비었는지 알 수 없다.
- 세션 = 프로세스. 게임 단위로 보려면 새 게임에서 `resetLlmUsage()`를 부른다.

## 9. 실패 — 한 번 더 부르고, 그다음은 자리마다 다르다

모든 호출은 실패하면 **한 번만** 다시 부른다 (`packages/agents/src/retry.ts`).
갈리는 것은 그다음이다.

| 자리 | 두 번째도 실패하면 |
| --- | --- |
| GM 턴 · 중계 | 오류 — 아무것도 저장하지 않고 화면이 안내한다 |
| 첫 장면 (`runOnboardingTurn`) | 오류 — **게임을 만들지 않는다** |
| 평점 · 심경 · 훈련 결산 | 삼키고 **코어 앵커가 남는다** (로그는 남긴다) |

- **장면을 대신 써 주지 않는다.** 규칙 기반 장면으로 덮으면 유저는 그것이
  게임인 줄 알고, 개발자는 실모드가 도는 줄 안다 — SDK가 비스트리밍 요청을
  거부하는 동안 모든 첫 장면이 규칙 장면이었는데 아무도 몰랐다(§2).
  첫 장면이 실패했는데 세이브가 남으면 유저는 그것을 이 게임의 시작으로
  받아들이므로, 게임 자체를 만들지 않는다.
- **결산은 다르다.** 값이 없으면 코어 앵커가 이미 그 자리에 서 있다 — 평점
  하나 때문에 경기 결과가 되감기거나 시간 진행이 막히는 편이 더 나쁘다.
- ⚠️ **재시도의 조건: 아직 자국이 없을 때만.** 도구가 이미 돌았으면 상태가
  바뀌었고(이중 반영), 델타가 나갔으면 장면이 두 번 그려진다. 대부분의
  실패(인증·혼잡·한도·연결)는 첫 글자보다 먼저 온다.
- 턴 실패는 **아무것도 저장하지 않는 것이 곧 롤백**이다 (`turn-runner`), 실패는
  채팅에 남기지 않는다 — 픽션 밖의 사건이라 세계의 화자가 알 수 없다.
- mock 모드(`LLM_MODE=mock`)는 폴백이 아니라 **모드**다. `mock-gm.ts`의 규칙
  장면은 거기서만 쓰인다.

## 10. 미해결

- 계측을 화면에 세울지 — 지금은 `llmUsage()`·`describeUsage()`로 코드에서만 읽는다
- 적대적 교섭(이적 협상)의 별도 에이전트 분리 검토 — 단일 GM이 양쪽을 다
  연기하면 협상 긴장감이 무뎌진다
- 출력 후검증 실패 시 재생성 전략(부분 vs 전체)
