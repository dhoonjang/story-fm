# 능력치 모델

**선수의 역량은 15축 하나로 서술된다.** 자리에서의 의미는 포지션 가중치와 역할이,
오늘의 값은 상태(폼·체력)가, 감독이 아는 정도는 안개(관측 가능성)가 정한다.
값이 변하는 경로는 훈련·경기·나이뿐이고 반영 폭은 언제나 코어 공식이 쥔다 —
LLM 판정은 "무엇이 남았나"까지만 말한다.

선수의 "할 수 있음"은 서로 독립인 세 층이다.

| 층            | 저장                            | 스케일      | 뜻                      | 변하는 경로                     |
| ------------- | ------------------------------- | ----------- | ----------------------- | ------------------------------- |
| 능력치        | `GAME_PLAYER.attributes`        | 15축 0~99   | 가진 역량               | 결산 판정 · 월간 성장 (§6)      |
| 포지션 적응도 | `PLAYER_POSITION.proficiency`   | 자리별 0~99 | 그 자리를 아는가        | 그 자리 출전 · 전향 훈련 (§8)   |
| 전술 적응도   | `TACTIC_ASSIGNMENT.familiarity` | 0~100       | 이 전술이 몸에 붙었는가 | 훈련·경기 결산 · 전술 변경 (§7) |

경기에서 셋은 곱으로 만난다 — `effective = roleFit × 상태 × 포지션 적응도 ×
전술 적응도` ([../simulation/match.md](../simulation/match.md) §1.1).

## 1. 15축 — 신체 4 · 기술 5 · 정신 5 · GK 1

**전 선수가 15축 전부를 갖는다** — 포지션별 예외 분기 없음(`goalkeeping`도 필드
플레이어가 낮은 값으로 보유). 관측 열은 §9 안개의 두 계층이다.

| 계열 | 축            | 표시     | 주 용도                                  | 관측                           |
| ---- | ------------- | -------- | ---------------------------------------- | ------------------------------ |
| 신체 | `pace`        | 스피드   | 뒷공간·역습, 라인 높이의 대가            | 관측형                         |
|      | `stamina`     | 지구력   | 체력 소모·회복 속도, 연전 로테이션       | 관측형                         |
|      | `strength`    | 몸싸움   | 경합 승률, 부상 저항                     | 관측형                         |
|      | `aerial`      | 공중볼   | 세트피스·크로스 공수                     | 관측형                         |
| 기술 | `finishing`   | 결정력   | 슛 → 골 전환                             | **분석형**                     |
|      | `dribbling`   | 드리블   | 압박 탈출, 1대1 돌파                     | 관측형                         |
|      | `passing`     | 패스     | 점유·빌드업, 패스 배분                   | 관측형                         |
|      | `kicking`     | 킥력     | 롱패스·배급·세트피스 킥                  | 관측형                         |
|      | `tackling`    | 태클     | 볼 탈취, 수비 존 전력                    | 관측형                         |
| 정신 | `vision`      | 시야     | 찬스 창출, 전진 패스 성향, 전술 습득(§7) | **분석형**                     |
|      | `positioning` | 위치선정 | 오프더볼 + 수비 커버, 전술 습득          | **분석형**                     |
|      | `composure`   | 침착성   | 실책·페널티, 폼 기복(§5), 전술 습득      | **분석형**                     |
|      | `aggression`  | 적극성   | 압박 소화 강도, 파울·카드                | 관측형                         |
|      | `leadership`  | 리더십   | 주장 적합도, 팀토크 전파, 라커룸         | **분석형**                     |
| GK   | `goalkeeping` | 골키핑   | GK 존 전력                               | 관측형 (매 경기 표본이 쌓인다) |

- GK의 개성은 이 한 축이 아니라 공유 축과의 조합이다 — `aerial`(장악) ·
  `kicking`(배급) · `passing`(발밑) · `composure` · `positioning`(커맨드).
- `stamina`의 한글 라벨은 **지구력** — 상태 수치 "체력"(§5)과 이름이 겹치지 않게.
- 부속: `overall`은 파생 캐시(§4) · `potential`은 구간으로만 노출(§9.1) ·
  나이는 저장하지 않고 `birthdate`에서 계산(`ageOf`).
- **히든 능력치는 없다.** FM의 숨은 축(Consistency 등)이 만드는 재미는 §9 관측
  가능성이 대신한다 — 축은 전부 존재하되 밖에서 알아내기 어려운 축이 있을 뿐이다.
  단일 값이라 장부·서사·조회 도구가 모두 같은 값을 본다.
- **키·체중은 능력치가 아니라 묘사다** — 공중볼·몸싸움이 이미 축에 있어 전력에
  다시 넣지 않는다. 시드 실측이 우선, 없으면 자리 기준치 + 공중볼(키) ·
  몸싸움−스피드(체중)로 파생한다.
- **등번호는 현재 소속팀에서의 식별자다.** `GAME_PLAYER.squadNumber`에 1~99를
  optional로 저장한다(구 세이브 호환을 위한 optional이며, 클럽 소속 선수는 런타임에
  항상 번호를 갖는다). 실존 선수는 공식 번호 시드를 우선하고, 미확인·생성 선수는
  포지션 관례와 팀의 빈 번호로 결정적 배정한다. 이적·임대·복귀 때는 새 팀에서 다시
  배정하며 같은 팀의 번호는 겹치지 않는다.

## 2. 포지션 가중치 (`POSITION_WEIGHTS`)

능력치는 **가중치 테이블 하나를 통해서만** 전력이 된다 — `overall`, `roleFit`,
시뮬 존 점수가 전부 같은 소스의 파생이다. 실 값은 코드가 단일 소스다
(`packages/domain/src/player.ts` — 문서에 표를 복제하지 않는다).

```
roleFit(선수, 자리, 역할) = Σ(축값 × w) / Σ(w)   그리고 자리·역할 기준점으로 정규화
```

**값은 단계가 아니라 소수 — 0.05~3.0, 0.05 해상도.**

| 값      | 뜻                                                 |
| ------- | -------------------------------------------------- |
| 3.0     | 그 자리를 정의하는 축 — **자리마다 정확히 하나**   |
| 2.0~2.9 | 핵심. 없으면 그 자리를 못 본다                     |
| 1.2~1.9 | 중요. 수준을 가른다                                |
| 0.6~1.1 | 보조                                               |
| 0.2~0.5 | 미미                                               |
| 0.05    | 바닥 (`FLOOR_WEIGHT`) — 거의 무관하지만 0은 아니다 |

**무게는 "이 자리에 중요한가"만으로 정하지 않는다 — 그 축이 자리를 실제로
가르는가를 함께 본다.** 카탈로그에서 자리 간 평균의 표준편차(σ)가 낮은 축
(`positioning` σ 2.5 — 파생 축이라 구조적으로 평평하다)에 최고 무게를 주면 그
자리 점수가 "이 선수가 대체로 얼마나 좋은가"로 수렴해 자리 간 폭이 죽는다.
현재 같은 선수의 자리 간 폭은 중앙값 10 · p90 18이고, EA 대조도 함께 좋아졌다
(σ 3.05 · |오차|≤2 72%) — EA의 OVR도 자리 핵심 축에 집중돼 있다.

- ⚠️ **합은 의미가 없다.** `roleFit`이 가중 평균이라 자리 안의 상대 비율만 결과에
  닿고, 자리·역할 간 수준 차는 기준점(`RAW_PIVOT` + `ROLE_PIVOT`)이 흡수한다.
  한 자리의 축을 손보면 그 자리 **모든 역할의** 기준점을 다시 재야 한다.
- ⚠️ **하한은 0이 아니라 0.05.** 0이면 그 축이 그 자리에 존재하지 않게 되어 태클
  30인 9번과 60인 9번이 같은 선수가 된다. 0.5는 바닥이 아니라 "보조의 절반"이다 —
  GK 가중치 합의 17%가 무관한 축이 되어 자리의 색이 흐려진다. 지금은 1% 남짓.
- ⚠️ **눈금이 다른 축은 바닥으로만, 아홉 자리에 균일하게.** `leadership`은 평균
  42로 다른 축(66)과 눈금이 다르다 — 일부 자리에만 보조로 얹으면 그 자리만 −1.7
  낮아진다. 균일하면 자리별 기준점이 흡수한다. 리더십의 주 통로는 주장 지명·
  팀토크·라커룸이지 전력이 아니다.
- ⚠️ **골키퍼는 골키핑이 지분 65%.** 39%였을 때 골키핑 79인 선수의 종합이 82로
  나왔다. 지금은 |종합−골키핑|≤2가 85%, EA 일치 95%. 배급·커맨드는 값을 움직이되
  뒤집지는 못한다.
- ⚠️ `pace`가 센터백 기본값에서 0.65까지 내려간 것은 "느린 센터백이 공짜"라서가
  아니다 — 그 대가는 라인을 올릴 때 **역할**(커버·리베로)이 받는다 (§3).
- **전력 가중치 ≠ 기능적 영향.** `aggression`·`leadership`은 가중치가 낮아도
  파울·퇴장·주장·팀토크·라커룸이라는 별도 경로로 게임에 크게 작용한다.

## 3. 세부 역할 — FM 역할 체계 50종

같은 자리도 시키는 일에 따라 요구 역량이 갈린다. 이름은 새로 짓지 않고 **풋볼
매니저의 역할명을 그대로 쓴다** — 감독이 이미 아는 말이라 설명 없이 전달된다.
FM의 **듀티**(수비/지원/공격)는 두지 않는다: 역할과 곱하면 백 가지가 넘고, 그
축은 전술 6축이 이미 갖고 있다. 다만 듀티가 담던 것 중 **요구 역량이 실제로
갈리는 짝은 역할로 되살린다** — 센터백의 커버/스토퍼.

| 자리 | 역할 (첫 항목이 기본값)                                                                               |
| ---- | ----------------------------------------------------------------------------------------------------- |
| GK   | 골키퍼 · 스위퍼 키퍼                                                                                  |
| CB   | 센터백 · 커버 센터백 · 스토퍼 · 볼 플레잉 디펜더 · 노넌센스 센터백 · 리베로 · 와이드 센터백           |
| FB   | 풀백 · 노넌센스 풀백 · 윙백 · 컴플리트 윙백 · 인버티드 풀백 · 인버티드 윙백                           |
| DM   | 수비형 MF · 앵커 · 하프백 · 딥라잉 플레이메이커 · 볼 위닝 MF · 레지스타 · 세군도 볼란테               |
| CM   | 중앙 MF · 박스투박스 · 어드밴스드 플레이메이커 · 메짤라 · 카릴레로 · 로밍 플레이메이커 · 볼 위닝 MF   |
| AM   | 공격형 MF · 어드밴스드 플레이메이커 · 섀도 스트라이커 · 트레콰르티스타 · 엔간체                       |
| W    | 윙어 · 인버티드 윙어 · 인사이드 포워드 · 와이드 MF · 디펜시브 윙어 · 와이드 플레이메이커 · 라움도이터 |
| CF   | 딥라잉 포워드 · 폴스 나인 · 컴플리트 포워드 · 트레콰르티스타                                          |
| ST   | 어드밴스드 포워드 · 포처 · 타깃 포워드 · 프레싱 포워드 · 컴플리트 포워드                              |

- **역할은 전체 표가 아니라 기본값에서의 차이(`delta`)로 정의한다** — 결과는
  `[FLOOR_WEIGHT, 3.0]`으로 잘린다. "인버티드 풀백도 여전히 풀백"이 구조로
  지켜진다.
- ⚠️ **역할마다 기준점(`ROLE_PIVOT`)을 따로 둔다.** 없으면 역할 선택이 곧 공짜
  능력치다 — 높은 축만 얹는 컴플리트 포워드는 누구를 넣어도 오르고, 평균이 낮은
  축을 키우는 프레싱 포워드는 누구를 넣어도 내려간다. 기준점이 있으면 평균적인
  선수는 어느 역할에서도 69이고, 갈리는 건 "이 선수가 그 역할에 맞느냐"뿐이다.
- 커버/스토퍼의 스피드 가중치: **커버 2.5 > 스토퍼 1.1 > 기본 0.65.** 스토퍼도
  기본값보다 높다 — 나갔다가 등 뒤로 털리는 게 그 역할의 고유한 실패 방식이라
  나가는 첫 발이 필요하다.

## 4. 종합(overall) · 좌우 분화 · 주발

**표시용 종합은 역할을 타지 않는다.** `overall`은 그 선수가 **가장 잘 맞는
자리에서 기본 역할로** 낸 값(`bestOverall`)이다 — 카드의 숫자 하나가 역할 목록
만큼 여러 등급을 가지면 안 된다. 주 포지션 하나만 쓰지 않는 이유: 시드의 주
포지션 표기는 출처마다 갈린다(EA는 윙어를 LM/RM으로 적는다). **실제로 맡은
자리·역할의 전력은 `roleFit(axes, position, role)`이 따로 내고** 그게 경기와
라인업에 쓰인다. 화면의 OVR·선발 평균도 배치된 자리 기준이다(`slotOverall`).

**CF는 ST와 접지 않는다** — ST는 최종 수비선을 무는 9번(공중볼·몸싸움·위치선정),
CF는 내려와 연결하는 전방(드리블·시야). SS는 CF와 같은 가중치를 쓴다.

### 좌우 분화

자유 배치라 중앙 라인 안에서도 좌우가 갈린다: LCB/RCB · LDM/RDM · LCM/RCM ·
LAM/RAM · LF/RF · LST/RST.

- **요구 역량은 같다** — `weightSlotOf`가 좌·중·우를 한 슬롯으로 접어 `roleFit`이
  동일하다.
- **적응도도 같다** (`MIRROR_VARIANTS` — 묶음 감점 없음). 선호 여부도 좌우를 함께
  본다(`isNaturalAt`). 반대로 RB↔RWB(라인 높이)·ST↔CF(역할)는 같은 묶음이어도
  감점이 남는다.
- **갈리는 건 주발뿐** — `GAME_PLAYER.foot`은 좌·우 별점(1~5)이고, 보정은
  `round((그쪽 발 − 반대쪽 발) × 0.75)` (`footAdjust` — 5/4면 ±1). 약발이
  좋을수록 차이가 준다. 카탈로그 생성과 폴백 계산이 같은 함수를 쓴다.
  ⚠️ 폭이 자리를 바꿀 만큼 크면 "왼발이면 왼쪽만"이 되어 라인업 판단이 죽는다.

### 주발·약발 데이터

5대 리그 시드 2,977명 중 **2,334명(78%)이 실측**(EA FC 27 `Preferred Foot` ·
`Weak Foot`). 실측 분포: 1성 0.3% · 2성 16% · **3성 60%** · 4성 21% · 5성 2%.

- ⚠️ **조사가 닿지 않은 실존 선수는 5/4로 두고 지어내지 않는다** — 해시로 흩으면
  실제로는 멀쩡한 선수가 우연히 나빠진다.
- ⚠️ **절차 생성 선수는 반대로 실측 분포를 표집한다** (`syntheticFoot`) — 전원
  4로 두면 합성 선수만 통째로 양발잡이가 된다.
- ⚠️ **3성(최빈값)을 4로 접지 않는다** — 접었더니 카탈로그의 90%가 4가 되어 좌우
  배치 판단이 밋밋해졌다.

## 5. 상태 — 폼과 체력

```
유효 능력치 = base × (1 + form × 0.09 + (condition − 75) × 0.0025)
```

| 상태             | 정의역               | 효과                                                              |
| ---------------- | -------------------- | ----------------------------------------------------------------- |
| 폼 `form`        | −1.0 ~ +1.0 실수     | 양 끝에서 ±9%                                                     |
| 체력 `condition` | 0~100 (기준 75)      | +6% ~ −19%. **22 미만은 구멍**(자리를 못 지킨다) · 부상 확률 가중 |
| 부상             | none / minor / major | 출전 불가                                                         |

### 5.1 폼 — 시간 축을 가진 컨디션 (`engine/squad/form.ts`)

**1이 곧 절정, −1이 곧 바닥.** 값 자체가 비율로 읽히고 화살표 각도·표시 계수가
전부 이 축의 파생이다.

| 성분       | 규칙                                                                                                                    | 값                   |
| ---------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------- |
| 개인 성과  | 경기 평점이 움직인다. 중립점은 평점 공식 기준선(6.0)이 아니라 **분포의 중앙 6.3** — 6.0을 중립으로 두면 하강이 사라진다 | (평점 − 6.3) × 0.233 |
| 팀 결과    | 승패는 약하게 — 폼의 주인은 개인 활약                                                                                   | ±0.05                |
| 기복       | `composure`가 폭을 정한다 — 히든 축 없이 개성을 만든다                                                                  | ×0.7~1.3             |
| 평균 회귀  | **매일** 0으로 끌린다 — 연승이 멈추면 식는다                                                                            | −0.0167/일           |
| 양 끝 감쇠 | 절정에 가까울수록 더 오르기 어렵다. 식는 방향은 온전히                                                                  | 상한에서 이득 ×0.25  |

- 골 보너스는 없다 — 골은 이미 평점에 크게 실려 있어 이중 계산이 된다.
- 시즌 전환 때 0으로 리셋.
- **폼은 말로 부른다** (`formLabel`): 절정(≥0.73) · 상승세(≥0.33) · 평소 ·
  침체(≤−0.33) · 바닥(≤−0.73). 채팅·조회 도구·심경·명단이 같은 라벨을 쓴다.
- 화살표는 도형 하나를 각도로 돌린다(`formAngle` = 90 − 폼×90도, 절정에서만 12시).
  각도·경계는 엔진이 정하고 뷰는 실어 나른다.
- ⚠️ **폼을 읽는 다른 코드(심경 문장 등)의 문턱은 `formLabel` 눈금(±0.33·±0.73)과
  같아야 한다** — 옛 −3~~3 정수 눈금(±1·±2.2)이 남으면 그 가지가 통째로 죽는다
  (정의역이 −1~~+1이라 영영 오지 않는 조건이 된다).

### 5.2 체력 — 저장도 한 축 (`PlayerState.condition`)

체력은 몸의 준비 상태만 저장한다. 경기가 깎고 휴식·훈련 강도가 채운다.
팀토크·면담·기자회견의 사기 효과는 폼을 움직이며, 불만은 별도 이슈와 심경으로
남는다. 소모·회복·구멍·로테이션 수치는
[../simulation/match.md](../simulation/match.md) §3.

- ⚠️ **체력에서 감정을 읽지 않는다.** 경기 한 판이 30~50을 가져가 경기 다음 날은
  누구나 바닥이다 — `condition < N`을 "마음이 떴다"로 읽으면 이긴 다음 날 선수단
  전원이 침울해지고 이적 판정·재계약·오퍼까지 오염된다. 마음의 근거는
  `hasIssue`(라커룸 불만)·폼·정착·출전 기회이고, 체력은 감정어 없이 사실로만
  쓴다. 심경 한 줄의 계약은 [people.md](people.md).
- 왜 낮은지는 심경 한 줄(`describeMood` 앵커 + mood-rater 재작성)이 말한다.

## 6. 성장·쇠퇴

**누가 무엇으로 자라는지는 소속이 정한다** (`developsByCore`).

| 대상                     | 무엇이 움직이나              | 언제               |
| ------------------------ | ---------------------------- | ------------------ |
| 감독 팀 1군              | 훈련·경기 **결산 판정**(LLM) | 훈련 구간·경기마다 |
| 감독 팀 2군 · 모든 타 팀 | 코어 **월간 성장**           | 매월 1일           |

4,000명분을 매달 모델에 태울 수 없어서 결산을 받지 못하는 선수에게는 코어가
같은 질문(이 나이의 이 선수는 이 축에서 자라는가)에 답한다.

### 6.1 결산 판정 — 훈련과 경기가 같은 템플릿

판정 형식: `playerId · 전술 적응도 변화 · 능력치 축 · 방향(±1) · 근거`.
능력치 규칙은 함수 하나를 공유한다(`applyAttributeStep`) — 한 번에 한 축 ±1,
인원 상한, 잠재력 상한. ⚠️ 규칙을 두 곳에 복제하면 한쪽만 조여진다.

|           | 전술 적응도 | 능력치 인원 | 허용 축                   |
| --------- | ----------- | ----------- | ------------------------- |
| 훈련 결산 | −1 ~ 3      | 0~5명       | 그 기간에 **훈련한 축만** |
| 경기 결산 | −2 ~ 8      | 0~11명      | 제한 없음                 |

판정이 없으면(mock·모델 실패·검증 탈락) 그 구간은 아무것도 남기지 않는다 —
게임은 계속 굴러간다. 잦은 이벤트라 싼 모델을 쓴다 ([llm/agents.md](../llm/agents.md)).

### 6.2 판정 한 칸이 그대로 오르지 않는다 (`attributeGainScale`)

열여덟의 한 칸과 서른의 한 칸은 같은 사건이 아니다. 셋을 곱한다:

```
실제 상승 = 판정(±1) × 잠재력 여유(천장에 닿으면 0)
                    × 나이(≤18 ×1.15 … 25~27 ×0.6 … 34+ ×0.15, 축마다 시계가 다르다)
                    × 현재 수준(85→86은 60→61보다 무겁다 — 잠재력 여유와 다른 항이다)

N(x, s) = ln(1 + s×clamp(x, 0, 1)) / ln(1 + s)
잠재력 여유 = N((potential−value)/10, 2)
현재 수준   = N((100−value)/40, 1)
```

18세 60(잠재 85)은 판정 한 번에 한 칸, 30세 85(88)는 열두 번을 받아야 한 칸이다.

- ⚠️ **못 채운 몫은 `growthCarry`에 쌓인다.** 이 그릇이 없으면 곡선이 늘 1보다
  작은 노장은 아무리 훈련해도 영영 그대로다. **한 번에 한 칸까지만** 반영해 밀린
  캐리가 장부를 두 칸 뛰게 하지 않는다. (구 세이브엔 없어 optional)
- **내려가는 건 깎지 않는다** (`attributeDeclineScale`) — 이미 꺾이는 축은 오히려
  더 크게 받고(1 + |노화|×0.25), 젊고 안 꺾이는 축만 조금 눌러 둔다(≤24세 ×0.7).
  서른셋의 스피드가 나빠졌다는 판정은 그대로가 맞다.
- 잠재력 상한은 **오를 때만** 막는다 — 이미 넘은 선수도 늙는다. 아래 바닥은 1.

### 6.3 월간 성장 (코어 — `engine/squad/development.ts`)

매월 1일, 선수당 **최대 2축 ±1**: 축별 노화 곡선(`agingDelta`) × 잠재력 여유 ×
시드 난수(결정적).

| 곡선                    | 축                                                                |
| ----------------------- | ----------------------------------------------------------------- |
| 이르게 정점, 28+ 급락   | pace · stamina · dribbling                                        |
| 30~32 유지 후 완만 하락 | strength · aerial · finishing · tackling · goalkeeping            |
| 34+까지 성장 (24~33 +1) | passing · kicking · vision · positioning · composure · leadership |
| 거의 불변 (성향)        | aggression                                                        |

"다리는 죽고 머리로 뛰는 베테랑"이 데이터에서 나온다. ⚠️ **노화를 시즌 경계에
몰지 않는다** — 매달 조금씩 움직여야 "요즘 발이 예전 같지 않다"가 시즌 중에
관찰 가능한 사건이 된다. 시즌 전환은 은퇴 판정과 명단 정리만 한다.

### 6.4 자리도 결산이 판정한다

개인 훈련(`set_player_training`)의 축(`axis`)·자리(`position`) 모두 훈련 결산의
몫이다. 자리는 `positionGain`(0~2, `POSITION_TRAIN_MAX`)으로 오르고, 새 자리가
본업을 넘어서면 코어가 주 포지션을 옮긴다(장부 정리).
⚠️ 코어가 날짜를 세어 올리는 경로는 없다 — 같은 축을 두 주체가 나눠 쥐면 안 된다.

- 서사 이벤트는 능력치 접근 불가 — "각성" 없음. 능력치는 이 장의 경로가 전부다.

## 7. 전술 적응도 (`familiarity`)

"이 전술을 몸이 익혔나". 대상은 포메이션 + 슬라이더 6축 **한 덩어리**
(`tacticsSignature`). 값은 선수 개인의 것이고 팀 적응도는 그 평균(파생)이다.

**상승은 전부 LLM 판정, 하락은 전부 코어(결정적).** 판정은 자료(대화·지시·사건·
출전 시간)를 읽고 훈련 −1~~3 · 경기 −2~~8 안에서 결론을 내고, 하락은 감독이 "이
슬라이더를 한 칸 옮기면 얼마 손해인지" 예측할 수 있어야 하므로 공식이다.

### 7.1 상승 곡선 (`applyFamiliarityGain`)

판정이 낸 값이 **현재 위치만큼 깎여 들어간다** — 아래 구간(훈련 ≤65 · 경기 ≤62)은
판정 그대로라 한 달이면 80에 닿고, 위로 갈수록 무뎌진다. **훈련만으로 95까지,
100은 경기의 몫**이다(시즌 실측: 벤치 95 · 로테이션 99 · 주전 100).

위쪽 감쇠는 정규화 로그의 좌우를 뒤집은 `R(x,s)=1−N(1−x,s)`다. `x`는 남은
여유의 비율이고 훈련은 `s=2.5`, 경기는 `s=3.5`를 쓴다. 시작과 천장은 정확히
0·1에 붙고, 위로 갈수록 완만하게 느려진다.

- **적응도의 천장 100은 닿을 수 있어야 한다** — 능력치 99가 "세계 최고"라는
  상대적 자리인 것과 달리 100은 "완전히 붙었다"는 상태다.
- **선수마다 속도가 다르다** — 흡수율은 `tacticalUptake`(시야·위치선정·침착성
  평균)가 정한다(40 → 0.68 · 85+ → 1.0). 잘 읽는 선수가 같은 훈련에서 1.5배를
  가져가 80까지 훨씬 빨리 붙는다.
- ⚠️ **흡수율은 1을 넘지 않는다** — 넘으면 판정 상한(3·8)이 뚫려 "한 번에 게임을
  크게 흔들 수 없다"는 계약이 흐려진다.
- ⚠️ **흡수율과 하락 배수(`shiftFactor`)는 같은 함수다** — 빨리 익히는 선수가 잘
  잊으면 앞뒤가 안 맞는다. 계수의 방향은 반대다: 이해가 높을수록 흔들림은 작고
  배움은 크다.
- ⚠️ **`familiarity`는 소수다** (`FamiliaritySchema` 0~100 — 옛 세이브의 정수도
  그대로 통과). 정수로 자르면 85 위에서 판정 +3이 0이 되어 값이 멎는다. 화면은
  반올림, 성장 로그는 눈금이 실제로 넘어갔을 때만.
- ⚠️ **판정 프롬프트에 이 곡선을 적지 않는다** — 모델이 "높으니 조금만"이라고 또
  깎으면 이중으로 줄어든다. 모델은 얼마나 스몄는지만, 얼마가 남는지는 코어가.

### 7.2 하락 — 거리 × 개인 (`tacticsDistance`)

포메이션 교체 25, 슬라이더는 축별 비용 × 칸 수:

| 축               | 한 칸 | 근거                               |
| ---------------- | ----- | ---------------------------------- |
| 수비 라인 · 압박 | 4     | 여럿이 동시에 다시 맞춰야 성립한다 |
| 멘탈리티 · 폭    | 3     | 무게중심과 간격                    |
| 템포             | 2     | 개인이 맞추기 쉽다                 |
| 패스 길이        | 1.5   | 공 가진 선수의 선택에 가깝다       |

**방향이 맞으면 오히려 오른다** (`AXIS_AFFINITY`) — 축마다 양 끝이 요구하는
능력을 정의하고 변화가 그 선수 쪽으로 갔는지 잰다. 짝은 시뮬이 그 축의 이득을
재는 능력과 같은 계열이다(롱볼 쪽 킥력·공중볼, 짧은 쪽 패스·침착성 등).

- ⚠️ 부호가 뒤집히므로 **왕복은 정확히 제자리** — 오가며 적응도를 불릴 수 없다.
- ⚠️ 배수·방향 항은 **선발 평균 기준으로 정규화** — 팀이 내는 값은 그대로고 누가
  대가를 치르는지만 갈린다. 팀 전체의 성향 이득은 적응도가 아니라 시뮬의 존
  이득(`tacticalDeltas`)으로 돌아온다.
- ⚠️ **역할 변경의 대가는 결정 하나에 한 번** (`roleMemo`) — 기준은 그날 아침의
  역할이고 차액만 가감하므로 알약을 눌러 보며 골라도 누적되지 않는다.

### 7.3 기억 (`TacticAssignment.drilled`)

**적응도의 기억은 선수마다 따로다.**

| 무엇      | 어떻게                                                                              |
| --------- | ----------------------------------------------------------------------------------- |
| 도착 수준 | 각자 자기 기억에서 — 해 본 전술이면 그때 값, 처음이면 가장 비슷한 기억에서 거리만큼 |
| 왕복      | 기억이 닫는다 — 재분배·대칭 조건 불필요                                             |
| 개인차    | 전이 거리를 자기 자로 잰다 (`personalDistance` = 습득력 × 적합도)                   |
| 팀 적응도 | 개인값의 평균 (파생)                                                                |

- ⚠️ **보정은 결과에 더하지 않고 거리에 넣는다** — 더하면 도착 수준이 기억과
  어긋나 왕복이 샌다.
- ⚠️ **해 본 전술이면 그 기억만 쓴다** — 전이 후보와 max로 섞으면 유추값이 실제
  도달값을 넘어 왕복이 샌다.
- **새 영입은 기억을 갖고 온다** (`memoriesOf` — 직전 팀의 전술과 그 팀의 숙련
  수준). 정착이 끝나면 더는 얹지 않는다. 그래서 세 전술을 돌려막으면 셋 다 익고,
  바닥은 매번 새 설정으로 옮겨 다닐 때 온다.
- **망각**: 안 쓴 기억은 `MEMORY_FADE_DAYS`(14일)마다 1씩, 붙잡는 힘
  (`memoryRetention` ×0.7~1.5)이 주기를 늘리고 줄인다. ⚠️ 습득과 **같은 축**
  (`tacticalUptake`)을 쓴다 — 반대로 걸면 개인차가 상쇄된다. 기억은
  `DRILLED_LIMIT`(8)개까지, 넘치면 오래 안 쓴 것부터 밀린다.
- ⚠️ **하한도 시간 경로도 없다.** 유지만으로 오르는 +1은 없고(달력 넘기기가 훈련과
  같아진다), 0까지 떨어질 수 있다 — 시뮬은 적응도를 곱셈 팩터(0.79~1.00)로 쓰므로
  0을 곱하는 일은 없다.

## 8. 포지션 적응도 (`proficiency`)

단일 규칙 `positionProficiency` — 엔진(`proficiencyAt`)과 웹 전술판이 **같은
함수**를 쓴다. ⚠️ 복제하면 서버가 계산한 값과 화면이 보여 준 값이 조용히 갈린다.

| 관계                                                                           | 값                                        |
| ------------------------------------------------------------------------------ | ----------------------------------------- |
| 주 포지션                                                                      | 88~96                                     |
| 좌우 미러 (`MIRROR_VARIANTS`)                                                  | 감점 없음 — 주발만 가른다 (§4)            |
| 사실상 같은 자리 (`POSITION_CLUSTERS` — 풀백↔윙백 · 측면 미드↔윙어 · ST·CF·SS) | −2                                        |
| 인접 확장 (생성 시 1~2곳)                                                      | 70~82                                     |
| 목록에 없는 자리 (폴백)                                                        | 보유값 − 전술판 거리 × 0.4 − 라인 교차 10 |
| 필드 ↔ 골문                                                                    | 바닥 25                                   |

- 폴백이 **전술판 거리**(`positionDistance`)를 쓰는 이유: 라인 경계만 보면
  ST→CAM이 RB→LB보다 생소하게 나오는 역전이 생기고, 자유 배치에서 자리는 코드가
  아니라 좌표라 거리가 유일하게 일관된 척도다.
- ⚠️ **감점 폭이 전술 적응도보다 크다** — `PROFICIENCY_SPREAD` 90%p >
  `FAMILIARITY_SPREAD` 15%p. 전술은 몇 주면 익히지만 자리는 커리어가 만든다.
  12%p였을 때는 배치 최적화가 10번을 6번에 세우고도 합이 높다고 계산했다.
- ⚠️ 이 팩터는 sim이 단일 소스로 갖고(`strength-packet.ts`) 엔진의 배치 채점
  (`slotStrength`)도 같은 함수를 부른다 — 복제하면 "배치가 고른 자리"와 "경기가
  계산하는 자리"가 갈린다.
- 명단 게이지는 자리×전술을 합친 표시용 `adaptationOf`다. 포지션은 경기와 같은
  로그 곡선으로 0~99를 정규화하고, 최대 감점 폭 `90 : 15×자리 민감도`로 섞는다
  (AM 약 86:14 · CM 약 81:19 · ST 약 91:9). 경기 계산은 이 합산값을 쓰지 않고
  `profFactor × famFactor`를 각각 적용한다. 전술판 칩에는 적응 게이지를 두지 않는다.

## 9. 안개 — 관측 가능성 (히든 능력치의 대체물)

지식 수준(선수 단위 5단계)에 **축의 계층**(§1 관측 열)을 곱한다. 오차값:

| 계층             | own | adapting | scouted | seen | rumoured |
| ---------------- | --- | -------- | ------- | ---- | -------- |
| 관측형 (몸과 발) | 0   | ±1→0     | ±1      | ±3   | ±6       |
| 분석형 (판단)    | 0   | ±3→0     | ±3      | ±6   | ±10      |

- 경계선은 *실행 vs 판단*이다 — 패스 성공률은 한 경기에도 드러나지만 결정력은
  표본이 모자라고 위치선정·시야는 화면 밖에서 일어난다. **스카우팅을 마쳐도
  분석형은 ±3이 남아** "데려와 봐야 아는 선수"가 생긴다 — 히든 축 없이 같은 서사.
- 지식 수준은 저장하지 않고 출전 명단·스카우트 리포트에서 파생한다.
- ⚠️ **오차는 결정적** — `(seed, playerId, 축)` 해시. 같은 질문에 같은 답, 참값은
  항상 구간 안.
- ⚠️ **표현 계층 전용** — 코어(장부·판정·전력 패킷)는 언제나 참값으로 계산한다.
- `overall`은 판단 계열을 포함하는 합성값이라 **분석형** 오차를 쓴다. 오차가 큰
  축은 숫자 대신 밴드 라벨로만 노출한다(§10).
- ⚠️ **안개는 축에만 씌우고 합성값은 파생시킨다** — 관측된 축의 `roleFit` + 관측
  오프셋 하나(`observedFit`). 값마다 따로 굴리면 화면이 같은 규칙을 재현할 수
  없고 같은 선수의 OVR이 두 숫자로 갈린다. 오프셋이 자리마다 같아 자리끼리의
  비교도 흔들리지 않는다. 표시용 종합만은 저장값 + 오프셋 — 관측 축에서
  `bestOverall`을 다시 굴리면 리그 전체 눈금이 부수효과로 움직인다
  (`apps/web/lib/slot-overall.ts`가 화면 쪽 단일 소스).
- 협상 확률·몸값은 흐리지 않는다 — 계약 조건은 계약서에 적혀 있다.

### 9.1 잠재력 — 숫자가 아니라 구간

| 수준     | 출발 폭 | 좁히는 방법                              | 한계 |
| -------- | ------- | ---------------------------------------- | ---- |
| own      | ±6      | 출전 10경기당 −1                         | ±2   |
| adapting | ±9      | 같음                                     | ±2   |
| scouted  | ±12     | 재파견 1회당 −3 (`SCOUT_REPEAT_LIMIT` 3) | ±6   |
| seen     | ±16     | 없음                                     | ±16  |
| rumoured | 미지    | 스카우트를 보내야 한다                   | —    |

- **끝까지 ±2는 남는다**(`POTENTIAL_FLOOR`) — 성장은 예언이 아니다. 스카우트는
  훈련장을 못 보므로 ±6이 한계(`POTENTIAL_SCOUT_FLOOR`).
- 중심을 참값에서 결정적으로 흔들고 폭을 펼치되 **참값은 언제나 구간 안**,
  하한은 현재 실력 아래로 안 내려간다. 코어의 성장 계산은 참값을 쓴다.

### 9.2 경기 중 체력 — 별도 채널 (`readCondition`)

경기 화면의 남은 체력은 지식 5단계를 **쓰지 않는다** — 리포트는 오늘 저 다리에
얼마가 남았는지 말해 주지 않고, 처음 보는 선수라도 걸어 다니면 보인다.
폭 = 출발점(우리 2 · 상대 12) + 소모분 × (우리 0.15 · 상대 0.28), 감독의
분석 능력이 곱으로 좁힌다(99면 ×`ANALYSIS_FLOOR` 0.35). 90분 기준 우리 ±7~±2 ·
상대 ±22~±8 — **킥오프엔 거의 정확하고 정작 교체를 정할 후반 막판이 가장 흐리다.**

- ⚠️ 편향은 **경기마다 한 번** 뽑혀 90분 내내 고정 — 정지점마다 튀면 상대가
  지치는 중인지 내 눈이 흔들리는지 구분할 수 없다.
- ⚠️ **누구도 값 하나로 서지 않는다**(최소 ±1) — 0을 허용하면 화면이 그걸 "잰
  값"으로 읽는다.
- ⚠️ **다리가 멈춘 건 안개가 못 가린다** — 추정 구간은 구멍 문턱(`GAP_CONDITION`
  22)을 넘지 않고, 구멍 키포인트에 소진 수치를 적지 않는다(흐린 값이 문장으로
  샌다). 화면 표현은 [../simulation/match.md](../simulation/match.md) §8.
- 경기 밖(스쿼드·조회 도구)의 우리 선수 체력은 정확하다.

### 9.3 정착 (`adapting` · `engine/squad/settling.ts`)

막 영입한 선수는 우리 선수여도 흐리다 — 오차는 스카우트 수준에서 출발해 정착
진행도만큼 걷힌다(`observationMargin` × (1 − progress)). **언제 걷히는지는
달력이 아니라 감독이 정한다** — 크레딧이 목표에 닿으면 끝난다.

| 쌓이는 것                    | 크레딧                        |
| ---------------------------- | ----------------------------- |
| 경기 출전 1회                | 8                             |
| 팀 훈련 1일 (휴식·부상 제외) | 1.5                           |
| 그냥 함께 보낸 하루          | 0.5                           |
| 면담 `talk_to_player`        | 앵커 5 ± 4 (나쁜 결과면 음수) |
| 팀토크 `team_talk`           | 앵커 1.5 ± 1.5                |
| 주장 지명 `set_captain`      | 15 (소속 기간에 한 번)        |

목표 = 100 × 배수: 나라를 건넜으면 ×1.3 · 라커룸에 같은 협회 출신 ×0.85 ·
21세 이하 ×1.2 · 30세 이상 ×0.9 (배수는 한 줄씩 근거로 남는다).
**주전으로 쓰면 한 달, 아무 데도 안 쓰면 반년.**

- **대화의 무게는 GM이 정하고 경계는 코어가 쥔다** — 스킬이 `settling` 인자를
  받고 코어는 앵커 ±`EVENT_BAND`로 자른다 (경기 평점과 같은 구조).
- ⚠️ **대화 크레딧은 하루에 한 번** — 반복이 이득이면 면담 연타가 최적 전략이 된다.
- 거의 다 파생이다(TRANSFER 원장·출전 명단·훈련 일정). **대화만 원장이 필요하다**
  (`SETTLING_EVENT` — 어디에도 기록이 안 남아 파생할 원본이 없다. 옛 세이브는 빈
  배열, 버전 유지).
- 유스 콜업은 정착이 없다 — 이미 이 클럽 사람이다.
- 진행률은 명단 `?`의 툴팁, **남은 일수는 어디에도 쓰지 않는다** — 얼마나 걸릴지는
  감독이 앞으로 무엇을 하느냐에 달렸다.
- 전술·포지션 적응도(`adaptationOf`)와 다른 축이다 — 그건 "자리와 전술을
  아는가", 이건 "이 클럽 사람이 됐는가".

## 10. 노출 규약

- **오피스 뷰**: 우리 선수는 숫자 그대로(15축·폼 화살표·체력·심경), 타 팀은 §9
  오차를 반영한 관측값 + OVR 옆 `±N`(오차 0이면 안 그린다).
- **채팅(GM)**: 숫자를 읊지 않고 밴드로 — 90+ 월드클래스 · 85~~89 리그 최상위권 ·
  80~~84 정상급 · 75~~79 준수한 주전감 · 70~~74 스쿼드 자원 · ≤69 유망주/백업.
- 조회 도구(`get_player`)는 15축을 쏟지 않고 가중치 상위 축 + 특징 축만 요약한다
  ([llm/agents.md](../llm/agents.md)).

## 11. 감독 능력치

감독도 0~99 다섯 축(리더십·전술·훈련·협상·분석)을 갖는다. 선수 축과 달리 **효과의
계수**로만 쓰인다 — 무엇에 곱해지고 어떻게 자라는지는
[../simulation/career.md](../simulation/career.md)가 원본이다.

## 12. 미해결

- `positioning`이 수비 위치선정과 오프더볼 침투를 구분하지 못한다 — 축이 모자란
  문제(파생 축의 구조적 평평함도 여기서 온다).
- **DERIVED_AXES 8축의 실측 교체** — 현재는 시드 7축(6축+GK)에서 결정적으로
  파생한다(`deriveAxes`). `leadership`은 공개 소스가 가장 얇아 마지막까지 파생으로
  남을 수 있다.
  ⚠️ 파생 계수는 EA 세부 스탯과 **축별로** 대조한다 — 가중치 0인 축은 OVR에
  흔적을 안 남겨 합만 봐서는 못 잡고, 계수보다 **어느 시드에서 파생하는지**가
  먼저다(GK의 공중볼·힘은 `physical`이 아니라 `goalkeeping`에서). 파생 축이
  원천의 복사본이면 축을 늘린 의미가 없다(`aggression` r≈0.6 유지). 회귀는
  `attributes.test.ts`의 눈금 가드·연동 가드가 막는다. 현재 |오차|≤2 65%.
- 스카우트 리포트의 깊이 — 분석형 오차(±3)를 더 좁히는 수단이 없다.
- 자체 능력치 산정 모델 — 라이선스 부채 청산 장치 ([sources.md](sources.md) §7).
- 가중치 지문·오차 폭·상태 계수 튜닝 — 분포 모니터링 하네스 미자동화.
