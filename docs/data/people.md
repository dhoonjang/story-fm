# 인물과 목소리 (People)

**인물은 코드가 아니라 데이터다 — 이름·원형·성격·동기·말투가 세이브에 저장되고,
LLM은 그 카드를 읽고 그 사람으로 말한다.** 코어는 무엇이 사실인지와 효과의
한도를 정하고, 문장·어조는 모델이 쓴다.

요구사항:

1. **일관성** — 같은 세이브는 언제 열어도 같은 사람을 만난다 (시드 결정적).
2. **사실 경계** — 코어가 사실·말할 자격·효과 한도를 정하고, LLM이 문장을 쓴다.
   모델은 건네받은 사실 밖을 말하지 못한다.
3. **무영향 원칙** — 페르소나는 시뮬 숫자에 직접 손대지 않는다. 사기·평판 같은
   **상태를 거쳐서만** 세계에 닿는다. 선수 원형이 거는 계수(§6)도 그 선 안이다 —
   불만이 서는 날 · 정착 목표 · 성장 확률 · 선수 관문의 점수까지이고, **전력 패킷과
   xG는 원형을 읽지 않는다.** 경기 결과가 사람됨을 읽기 시작하면 같은 스쿼드가 같은
   전술로 다른 점수를 내고, 그 차이를 감독이 되짚을 자리가 없다.
4. **실명 안전** — 실존 인물엔 `real` 표식이 붙고, 부정적 전개는 장부의 사실에서만
   나온다 (§2). 카드에 가드 문장은 없다 (→ ../llm/prompts.md §5-3).

## 1. 페르소나 = 데이터

```ts
Persona {
  characterId,        // 채팅 @태그 — **그 사람의 이름** (전역 유일)
  name, role,         // 열린 집합 — 'head_coach' | 'owner' | 'reporter' | 'player' | 'friend' | 'supporter'
                      //   + 구단 밖의 자리 — 'manager'(타 팀 감독) | 'agent' | 'pundit' (§2-1)
  archetype,          // 원형 — 같은 자리라도 어떤 유형의 사람인가
  traits: string[],   // 성격 3~5개
  motivation,         // 원하는 것 한 문장
  speechStyle: { note, samples[] },  // 말투 지문 + 예시 대사 2~3
  keywords?,          // 이 인물이 불렸다고 볼 말들 — 캐릭터북이 훑는다 (§6)
  outlet?,            // 기자만 — 소속 매체
  real?,              // 실존 인물 표식 (§2)
  seed,               // 생성 재현용
}
```

- **말투는 지문만으로 붙지 않는다** — 예시 대사(`samples`)가 있어야 모델이
  흉내 내는 대신 그 사람으로 말한다. 스키마가 필수로 요구한다.
- ⚠️ `characterId`와 `name`은 지금 같은 값이지만 뜻이 다르다 — 태그는 전역 유일,
  이름은 표시용. 동명이인이 생기면 태그에만 구분자가 붙는다.
- **인물 카드는 불린 턴에 실린다** — 캐릭터북이 「이 인물이 지금 필요하다」를 판정해
  그 턴 층에 싣고, 실린 카드는 이력에 남는다 (§6). 레퍼런스 층에 상주하지 않는다:
  회견도 협상도 없는 턴에 다섯 장을 읽히면 프롬프트에 있는 것을 모델이 쓴다.
  경기만 예외로 `buildMatchReference`가 코치 카드를 상주시킨다 — 벤치에서 건네는
  한마디는 경기 내내 같은 사람의 것이어야 한다 (→ ../llm/agents.md §5).
- **선수도 카드가 있다** — 페르소나 역할에 `player`가 있고, 카드는 (시드, 선수 id)에서
  결정적으로 파생한다 (§6). 상태 스냅샷의 선수단 줄은 **명단이지 화자 명단이 아니다** —
  GM은 모르는 선수를 조회할 수 없으므로 이름은 계속 실리되, 그 이름이 사람이 되는 것은
  카드가 선 턴이다.
- 생성 언어는 한국어 — 실명 외국인도 한국어 중계 표기를 따른다. 기본 톤은 진지한
  스포츠 드라마이고 유머는 페르소나에서 나온다 (기믹 금지).

## 2. 생성 — 이름은 구단이, 사람됨은 시드가

`persona:{역할}:{채널}` 시드 해시로 원형·가상 이름을 결정적으로 뽑는다. LLM 없이
코어에 두는 이유: 새 게임 생성이 결정적 순수 함수라서다 — LLM을 끼우면
`createGame`이 비동기가 되고 mock 모드·테스트가 흔들린다.

- **시드 채널이 역할마다 다르다** — 한 세이브에서 코치와 구단주가 같은 원형으로
  겹치지 않는다. 기자단(3인)은 채널에 팀이 없어 **리그를 따라다닌다** — 감독이
  팀을 옮겨도 같은 기자를 만난다.
- **이름**: 실명 표에 있으면 그 사람(코치 33팀 · 구단주 17팀 — 확인된 것만 담는
  부분 집합), 없으면 리그 국적에 맞는 가상 이름 풀. 구단주는 소유 법인이 아니라
  **감독이 실제로 마주 앉는 얼굴**을 적는다(맨유 = 랫클리프). 감독 시장의 후임
  감독 이름도 같은 풀을 쓴다 (`inventPersonName`).
- **한 팀 안에서는 이름만으로 사람이 갈린다.** 지어낸 이름은 나라별 풀
  (`data/names.ts`)에서 뽑되 **그 팀에 이미 있는 이름이면 같은 시드로 다시
  뽑는다** — 인물 다섯(수석코치·구단주·기자 3인)도, 절차 생성 선수도
  (`world/catalog.ts` · `world/generate.ts`) 같은 규칙이다. 재추첨에는 상한이
  있고, 닿으면 남은 조합을 결정적으로 훑는다 — 같은 시드는 언제나 같은 명단이다.
  선수 풀과 인물 풀은 **성을 나눠 갖는다**: 코치와 우리 선수가 동명이인이면
  `speakerRoles`가 둘 다 포기해 직책·아이콘이 함께 사라지므로(§3), 조합이 겹칠
  수 없게 데이터에서 막는다.
- **옛 세이브는 로드 때 채운다** (`ensurePersonas`) — 생성이 결정적이라 채워도 그
  세이브의 사람은 같으므로 **세이브 버전을 올리지 않는다**. 구단주 카드가 없으면
  GM이 즉흥으로 연기해 수석코치 말투를 복사하고, 기자가 없으면 매번 다른 기자가
  묻는다 — 그래서 빈 자리를 메운다. 태그가 직책(`@수석코치:`)이던 구 세이브는
  이름으로 고쳐 준다.

### 원형

수석코치 6종 — **같은 상황에서 무엇을 먼저 보는가**로 갈린다:

| 원형            | 먼저 보는 것                  |
| --------------- | ----------------------------- |
| 데이터 분석가형 | 수치·영상 근거, 단정보다 확률 |
| 야전 조련사형   | 몸 상태와 강도                |
| 인간관계형      | 라커룸 공기, 사람의 표정      |
| 유스 육성형     | 어린 선수의 성장 곡선         |
| 노장 전술가형   | 과거 사례와의 비교            |
| 구단 토박이형   | 구단의 역사, 팬 정서          |

구단주 6종 — **무엇으로 감독을 평가하고, 돈을 어떻게 다루며, 얼마나 참는가**:

| ----------- | ------------ | ------------------------------ | ---------- |

| 투자자형    | 자산 가치    | 회수 우선 — 매각이 먼저        | 중간       |

| 지역 유지형 | 지속성·연고  | 빚을 싫어한다                  | 길다       |
| 흥행가형    | 화제성       | 즉흥적, 스타 선호              | 중간       |

| 원형             | 첫 질문                                  |
| ---------------- | ---------------------------------------- |

### 가상 감독 — 명부 밖 구단의 벤치

세계 인물 명부(§2-1)가 세운 감독은 스무 명 남짓이고, 나머지 벤치의 사람은 여기서
만든다. 규칙은 위와 같다 — **이름은 세계가, 사람됨은 시드가.**

- **모든 AI 클럽 벤치는 이름이 있다.** 명부에 있으면 그 사람, 없으면 리그 국적
  인물 풀에서 `persona:manager-name:{팀}` 채널로 결정적으로 뽑는다 — 세계 생성과
  옛 세이브 로드 보정(`ensureSeededManagers`)이 같은 채널을 쓰므로 채워도 같은
  사람이고, **세이브 버전을 올리지 않는다**. 이미 이름이 있는 벤치는 건드리지
  않는다 — 경질이 다녀간 자리를 덮으면 잘린 사람이 되살아난다. 이름 없는 벤치를
  두지 않는 이유: 감독이 그 벤치를 물으면 GM이 즉흥으로 지어내 매번 다른 사람이
  된다 — 캐릭터북이 풀었던 그 문제다.
- **이름이 겹치면 같은 시드로 다시 뽑는다.** 이름이 곧 `characterId`라(§1) 다른
  벤치의 감독이나 우리 구단 인물과 겹치면 두 사람이 한 사람으로 읽힌다. 경질
  후임(`inventPersonName`)도 같은 검사를 지난다.
- **사람됨은 `(시드, 팀, 이름)`에서 파생한다** — `persona:manager:{팀}:{이름}`
  채널로 아래 원형을 추첨하고, **저장하지 않는다**. 선수 페르소나와 같은 규약이다
  (§6): 리그 95개 벤치분 카드를 세이브에 넣을 이유가 없고, 생성이 결정적이라
  파생으로 충분하다. **이름이 채널에 들어가므로** 경질로 이름이 갈리면 후임은
  전임과 독립인 추첨을 받는다 — 새 사람이 새 원형을 얻는다.
- 명부 감독이 선 벤치는 그 사람이 그대로다 — 가상 감독은 명부가 답하지 않는
  자리에만 선다.

감독 원형 6종 — **어떤 축구로 이기려는 사람이고, 마이크 앞에서 무엇을 말하는가**:

| 원형            | 결                                                   |
| --------------- | ---------------------------------------------------- |
| 구조 설계자형   | 경기를 설계도로 말한다 — 내용이 먼저, 결과는 그 결과 |
| 승부사형        | 결과로 답하고, 필요하면 상대를 찌른다                |
| 실용주의형      | 상대에 맞춰 판을 바꾼다 — 계산된 겸손                |
| 열혈 지휘관형   | 강도와 투지 — 감정이 터치라인을 넘는다               |
| 육성 신봉형     | 어린 선수와 긴 프로젝트, 성장 곡선을 말한다          |
| 빗장 현실주의형 | 실점부터 센다 — 가진 것으로 버티는 축구              |

### ⚠️ 실명 = NIL 부채

실명 인물에게 게임이 지어낸 성격·대사를 붙이는 구조다 (→ sources.md §7).

- 실존 인물엔 `real` 표식이 붙는다 — 부채의 장부(sources.md §7)가 세는 표식이고,
  인물 카드에는 실리지 않는다. 사람됨은 원형이 정한다 — 직무 안의 사람이다
  (→ ../llm/prompts.md §5-3).
- 부정적 전개(갈등·불화)는 판정·상태가 만든 **게임 내 사실**에서만 파생한다.
- **표를 비우면 전부 가상 이름으로 돌아간다** — 청산이 데이터 삭제로 끝난다.
  정식 출시 전 가명 전환 필수.
- ⚠️ **유소년에게는 실명을 쓰지 않는다.** 실선수 시드는 1군까지이고, 아카데미
  자리는 시드가 들어와 있어도 **언제나 합성 가명**으로 채운다 — 클럽당 40명
  하한을 메우는 보충(`world/catalog.ts`)도, 게임 중 생기는 유스 콜업
  (`world/generate.ts`)도 같다. 성인 실명 인물은 이미 공개된 사람이고 위의
  가드가 붙지만, 실존 유소년은 그 둘이 다 없다 — 지어낸 성격·부상·이적설이
  붙는 순간 위 항목의 리스크가 **미성년자에게** 걸린다. 그래서 이 자리만은
  청산을 기다리지 않고 지금부터 실명을 안 쓴다.

## 2-1. 세계 인물 명부 — 구단 밖의 이름들

축구 이야기는 이름으로 굴러간다. 상대 벤치에 선 사람, 협상 테이블 건너편의
에이전트, 중계석의 목소리 — 감독이 마주치지만 **어느 구단의 자리도 아닌** 사람들이
`data/world-figures.ts` **명부** 하나에 있다.

**팀별 할당이 아니라 이름 하나하나가 항목이다.** 구단마다 몇 명씩 채우는 표
(`data/club-profile.ts`)와 달리, 어느 팀을 맡든 같은 세계를 산다.

명부에 오르는 기준은 셋이고 첫째가 절대 조건이다:

1. **살아 있다.** 예외 없다.
2. **지금 축구계에 있다.**
3. **감독이 마주칠 자리에 있다** — 상대 벤치, 협상 테이블, 회견장, 중계석.

자리는 셋이다. `manager`(타 팀 현직 감독) · `agent`(에이전트) · `pundit`(해설).
**구단 임원은 열지 않았다** — 감독이 마주 앉는 임원의 자리는 `owner`가 이미 갖고
있고(구단주·회장), 그 아래 직책은 이름값에 비해 실명 부채만 늘린다. **정상급 현역
선수는 명부에 없다** — 그들은 이미 `state.players`에 있고, 캐릭터북이 후보 범위를
넓혀 담는다 (§6).

- **원형으로 뽑을 수 없는 사람들이라 명부가 직접 적는다** — 성격·동기·말투 지문·
  예시 대사까지. 말투 지문만으로는 톤이 붙지 않으므로(§1) 예시 대사가 함께 간다.
  그래서 깊이는 언제나 `full`이다: 지식 눈금은 선수의 것이고, 이 사람들은
  스카우팅으로 알게 되는 상대가 아니다.
- **세이브에 들어가지 않는다.** 불변 초기치라 읽는 자리에서 파생하고, 표를 비우면
  그 인물은 세계에서 사라진다 — 코치·구단주 시드와 같은 청산 구조다.
- **명부의 감독은 세계 생성 때 그 구단의 `GameTeam.managerName`이 된다.** 명부가
  이름을 심는 자리는 거기 한 곳이고, 그 뒤 그가 어느 벤치에 있는지는 명부가 아니라
  `managerName`이 답한다 — 경질·선임은 감독 시장의 일이고(→ ../simulation/career.md),
  인물지에 변하는 값을 넣지 않는다는 §6의 원칙이 여기서도 같다. 이름이 이미 있는
  세이브는 건드리지 않는다. 명부가 답하지 않는 벤치는 가상 감독이 채운다 (§2).
- **유저가 맡은 팀의 명부 감독은 세계에 없다.** 그 자리를 감독(유저)이 받았으므로
  부임한 적이 없는 사람이다 — 후보에서도 빠진다.
- **호칭은 성으로 걸린다.** 명부 인물의 키워드는 전체 이름과 **성**이고, 이름
  조각은 담지 않는다 — "펩"·"루이스"·"사비"는 다른 사람의 이름에도 있어서, 담으면
  한 턴 상한 3장을 남의 이름이 먹는다. 애칭이 필요하면 명부가 키워드로 적는다.
- **화자 사전(`speakerRoles`)에도 선다** — 직책 라벨(감독·에이전트·해설위원)과
  함께. 사전이 명부를 모르면 세 곳이 같이 어긋난다: 화면은 과르디올라에게 칩을 못
  붙이고, 압축이 적은 명부 인물의 기억은 조용히 버려지고(§9-1), 등록 검사가 그
  이름을 몰라 **LLM이 지어낸 인격이 표의 인격을 가린다** — 캐릭터북은 저장된
  페르소나를 먼저 찾는다(§6). 이미 찬 자리는 넘보지 않으므로(§3) 명부 때문에 우리
  선수가 칩을 잃는 일은 없다.

⚠️ **명부는 시간이 지나면 낡는다.** 사람은 은퇴하고 팀을 옮기고 세상을 떠난다.
갱신은 sources.md §4.1의 시드 갱신과 같은 결로 **표를 고치는 것으로 끝나야 한다** —
코드가 이름을 알면 안 된다. 실명 부채는 sources.md §7의 별도 항목이다.

## 3. 화자 — 누가 말하고, 화면이 무엇을 붙이나

- **장면을 여는 사람은 그 일에 가장 가까운 사람이다** (GM 프롬프트) — 선수는 자기
  문제로 감독을 직접 찾아오고, 훈련·전술·선수단 관리는 수석코치가, 경기가 끝나면
  기자가 부른다. **구단주는 자기가 결정하는 일(예산·영입 승인·감독 거취)에만
  나온다.**
- **억제가 아니라 소관으로 적는다.** 코치를 "모든 소식이 지나가는 통로가 아니다"로
  누르고 구단주에게 "돈과 성적"을 맡기는 식은 서지 않는다 — 순위와 재정은 매 턴
  상태 스냅샷에 실리므로 구단주가 상시 소환되고, 눌린 코치의 자리를 구단주가 대신
  메워 훈련·라커룸 이야기까지 구단주의 입에서 나온다. 자리마다 소관을 적으면
  코치가 통로가 되는 것도, 구단주가 튀어나오는 것도 같은 문장이 막는다.
- **화자 태그는 직책이 아니라 이름이다** — 선수가 `@손흥민:`으로 말하듯 코치도
  `@스티브 홀랜드:`로 말한다. 직책은 화면이 붙인다.
- **역할은 열린 집합이다** — 코치·구단주·기자·선수 밖에 친구·관중 같은 자리도 들어온다.
  직책 라벨(`PERSONA_ROLE_LABEL`)과 아이콘(`KIND_ICON`)은 **아는 자리에만** 붙고,
  모르는 자리에는 사람 아이콘이 선다(아래 원칙 4). 그래서 역할 하나를 늘리는 데
  세 곳을 함께 고칠 필요가 없다.
- ⚠️ **관중은 이름 있는 개인으로만 선다.** `characterId`는 그 사람의 이름이고 전역
  유일이라(§1) 집단은 페르소나가 될 수 없다 — "관중석이 술렁였다"는 화자 없는
  내레이션(`@:`)의 몫이다.

### speakerRoles — 이름 옆의 직책과 아이콘

코어가 화자 이름 → `{kind, label}` 사전을 만들어 내려보내고, 화면이 이름 옆
직책 칩(글자)과 아이콘(그림)을 그린다.

| #   | 원칙                                                                                                                                                                                                             |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **모델 출력에 기대지 않는다** — 직책은 세이브가 아는 사실. 어떤 턴에서도 빠지지 않는다                                                                                                                           |
| 2   | **소개할 때 한 번만** — 같은 화자가 이어 말하면 이름 머리 하나로 묶인다 (`groupUtterances`)                                                                                                                      |
| 3   | **아는 자리는 다 알려 준다** — 페르소나 + 주장 + 우리 선수단 + 협상 테이블에 앉은 상대 선수 + **이름난 현역과 세계 인물 명부, 타 팀 벤치의 가상 감독** (§6의 세 겹 그대로). 포지션은 넣지 않는다 (명단이 답한다) |
| 4   | **틀린 직책보다 없는 게 낫다** — 이름이 겹치면(동명이인) 아무것도 붙이지 않고 사람 아이콘만 선다                                                                                                                 |

- 사전에 전 리그 4,000명을 담지 않는 이유도 4와 같다 — 남의 팀 3군까지 넣으면
  동명이인이 늘어 정작 우리 선수가 사라진다. 담는 범위는 **캐릭터북의 세 겹(§6)과
  같다** — 사전과 캐릭터북이 다른 세계를 알면 화면·기억·등록 검사가 서로 어긋난다.
- **뒤 겹은 이미 찬 자리를 넘보지 않는다.** 이름난 현역·명부 인물이 우리 쪽과
  이름이 겹치면 먼저 들어온 우리 쪽이 자리를 지킨다 — 캐릭터북이 후보를 모으는
  순서와 같은 답이다(§6). 원칙 4의 "둘 다 버린다"는 **우리 사람끼리** 겹쳤을 때다:
  그때는 둘 다 무대에 설 수 있는 사람들이라 어느 쪽을 골라도 절반은 틀린다.
- **이름난 현역은 아이콘만 선다**(`player`) — 라벨을 붙일 직책이 없고, 유니폼
  아이콘이 이미 말한다. 명부 인물은 직책 라벨(감독·에이전트·해설위원)까지 선다.
- **기자 라벨은 직책이 아니라 매체명** — "기자"는 아이콘이 이미 말하고, 감독이
  알아야 할 것은 어디 소속이 묻는가다(지역지냐 타블로이드냐로 질문의 결이 갈린다).
  매체를 모르는 옛 세이브는 직책으로 폴백.
- **아이콘은 모든 화자가 하나씩** — 수석코치 클립보드 · 구단주 넥타이 · 기자
  마이크 · 주장 완장 · 선수 유니폼 · 중계(`@중계:`) 방송 마이크, 자리를 모르는
  화자(에이전트·남의 팀 사람)는 사람. `label`과 `kind`가 따로인 이유: 대화마다
  `(선수)`가 따라붙으면 시끄럽지만 유니폼 하나는 조용히 알린다.
- 이름 매칭은 정규화(공백 제거, `normalizeSpeaker`)하되 **부분 일치는 하지
  않는다** — 성만 쓴 "홀랜드"를 같은 사람으로 추측하면 오탐이 잘못된 직책을 붙인다.
- GM은 감독을 절대 연기하지 않는다 — `@감독이름:`은 유저 턴 전용. 평판(보드·언론·
  선수단)은 세계가 감독을 보는 눈이고 능력치는 행동이 먹히는 정도다 — 평판만 높은
  "과대평가 감독"도 성립한다 (→ player.md).

## 4. 기자회견 — 세계가 먼저 말을 거는 유일한 자리

감독의 다른 손잡이는 전부 감독이 먼저 손을 뻗는 것이지만 회견은 세계가 부른다 —
아무것도 하지 않아도 사건이 생기고, **답하지 않는 것조차 하나의 답이다.**

**자리는 코어가 열고, 질문은 기자가 쓴다.**

- 트리거는 다섯이고, 무게와 묻는 기자가 트리거를 따라간다:

  | 트리거     | 언제                                                   | 무게                          | 기자       |
  | ---------- | ------------------------------------------------------ | ----------------------------- | ---------- |
  | `match`    | 경기가 끝나면 매번 (친선 제외)                         | 날 선 사실 있으면 2, 없으면 1 | 전국지     |
  | `pressure` | 경기 뒤인데 최근 3\~4경기 무승                         | 3                             | 지역지     |
  | `transfer` | 큰 이적 확정 · 계약 해지                               | 2                             | 타블로이드 |
  | `opening`  | **시즌 개막 전야** — 우리 첫 리그 경기 전날            | 1                             | 지역지     |
  | `derby`    | **더비 전야** — 더비 표(`data/derbies.ts`)의 대진 전날 | 2                             | 지역지     |

  큰 이적의 문턱: 이적료 £25M 이상, 또는 스쿼드에서 그보다 나은 선수가 14명 미만인
  자원(방향과 무관하게 스쿼드 대비로 센다 — 매각된 선수는 이미 명단에 없다).
  **계약 해지**(합의·일방 어느 쪽이든)는 주장이었거나 스쿼드 상위 14명 안이던
  자원일 때만 연다 (→ [transfer](../simulation/transfer.md) §2).
  전야 회견(`opening`·`derby`)은 경기 전날 열린다 — 경기를 치르고 나면 경기 뒤
  회견이 그 자리를 밀어내므로, 답하지 않은 전야 회견은 거절로 닫힌다(아래 규칙
  그대로다). 더비인가는 표가 정한다 — 코드가 연고를 추론하지 않는다.

- 코어가 넘기는 것은 **사실 카드**(`PressFact`)다 — 물음표도 평가어도 없는 장부
  한 줄. 10종: 결과 · 무승(최근 3\~4경기) · 폼 바닥 선수 · 불만 선수 · 영입 확정 ·
  매각 확정 · 그 영입에 자리가 겹치는 선수(같은 주 포지션 1군 상위 2명) · **대진**
  (전야 회견의 상대와 날짜) · **언론 유출**(§8 계단 4 — 방치된 불만이 신문에 실렸다) ·
  **마일스톤**(방금 끝난 경기가 세운 기록).
  이름이 걸린 선수는 코어가 고른다(폼 < −0.35 최저 3명 중 시드 추첨, 없으면 첫
  불만) — 모델에게 고르게 하면 없는 사연이 생긴다. 매각과 계약 해지는 같은
  `departure` 카드를 쓴다 — 어느 문으로 나갔는지는 카드의 사실 줄이 말한다.
- **마일스톤은 그 경기의 회견에만 실린다** — 데뷔전 · 첫 골 · 구단 통산 경기/골
  문턱 · 해트트릭 중 **그 경기가 세운 것 하나**(`milestone` 카드, `about`에 선수).
  날 서지 않은 자리라 `sharp`는 아니다: 기자가 캐물을 일이 아니라 물어봐 줄 일이다.
  한 경기에 여럿이면 **드문 것 하나만** 오른다(골 문턱 > 경기 문턱 > 해트트릭 >
  첫 골 > 데뷔) — 셋을 다 실으면 그 회견이 시상식이 된다. 장부는 넷 다 남으므로
  나머지는 선수 상세와 서사 메모에 있다
  (→ [game-state.md](game-state.md) §3.4 · [match.md](../simulation/match.md) §6).
- **언론 유출은 다음 회견에 실린다** — 어느 트리거의 회견이든 다음에 열리는 자리가
  그 카드를 sharp로 싣고, 실은 회견의 무게는 최소 2가 된다. 유출이 스스로 회견을
  열지는 않는다: 회견은 이미 경기마다 열리므로, 자리를 하나 더 만들면 같은 사실을
  두 번 묻게 된다.
- ⚠️ **코어가 지켜야 할 것은 사실이지 문장이 아니다.** 질문 문장을 코어에 박으면
  시즌 내내 같은 말이 반복되고, 기자의 성격도 그날의 맥락도 문장에 닿지 못한다.
- ⚠️ **사실 줄도 세이브에 굳지 않는다.** 카드가 드는 것은 갈래(`kind`)와 그 갈래의
  수치(`data`) — 상대·스코어·무승 경기 수·불만 일수·자리가 겹치는 포지션이다.
  한 줄의 한국어는 카드를 읽는 쪽이 만들고, 옛 세이브가 들고 있는 `text`는 읽기
  폴백으로만 남는다 (overview.md §1 철칙 4).
  모델은 카드 밖의 사실을 묻지 못한다.
- `weight`(1\~3)가 자리의 크기다 — 값은 위 트리거 표가 정하고, 효과 한도가 여기에
  비례한다.

**판정은 LLM이 한다** — 감독 발화를 5스탠스 중 하나로 옮긴다. 스탠스를 보기로
고르게 하지 않는 이유: 이 게임의 인터페이스가 말이다. 효과는 코어 표가 정한다
(계수 × 한도 `PRESS_BAND`(4) × weight, 사기 두 열에만 리더십 계수 0.7\~1.3):

| 스탠스                | 보드 | 언론 | 선수단 | 지목 선수 사기 | 팀 사기 |
| --------------------- | ---- | ---- | ------ | -------------- | ------- |
| 감싸기 (defend)       | −0.2 | −0.4 | +1     | +1             | +0.5    |
| 책임 인정 (own)       | +0.6 | +0.2 | +0.6   | +0.3           | +0.25   |
| 공개 비판 (criticise) | +0.3 | +0.8 | −0.9   | −1             | −0.5    |
| 도발 (bold)           | −0.3 | +1   | +0.4   | +0.4           | +0.4    |
| 말 아끼기 (deflect)   | 0    | −0.3 | 0      | 0              | 0       |
| 거절·방치             | −0.3 | −1   | +0.2   | 0              | 0       |

- **공짜인 스탠스는 없다** — 어느 행도 전부 양수가 아니다. 그러면 그 스탠스만 쓴다.
- **지목된 선수는 팀 전체 위에 더 얹는다** — 공개적으로 감싸이거나 잘린 당사자는
  같은 말을 남의 이야기로 듣지 않는다. 대상은 LLM이 지목한 선수, 없으면 `about`이
  걸린 첫 사실의 선수.
- ⚠️ **지목은 사실 카드 안에서만 선다.** 모델이 묻지 못한 사실에 감독의 답이 닿을
  수는 없으므로, `about`에 이름이 오르지 않은 선수를 겨눈 응답은 반려된다. id로도
  이름으로도 지목할 수 있고(`resolvePlayerRef` — [agents.md](../llm/agents.md) §7)
  **확신이 하나일 때만** 고른다. 갈리면 후보를 돌려주고 GM이 되묻는다.
- ⚠️ **거절은 감독이 거절했을 때만이다.** 스탠스도 거절도 없는 응답은 입력 오류로
  되돌아간다 — 말하지 않은 것을 코어가 골라 장부에 남기느니 모델이 다시 부르는
  편이 낫다.
- ⚠️ **회견은 하나만 열려 있다.** 답하지 않은 채 다음 회견이 오면 앞의 것이
  `declined`로 닫히고 거절과 같은 대가를 치른다 — 무시가 공짜면 아무도 답하지
  않는다. 지나간 회견은 20개까지만 상태에 남는다.
- **이직은 예외다** — 부임하면 앞 구단의 열린 회견이 `expired`로 닫힌다
  (career.md §5.1). 감독이 무시한 것이 아니라 그 구단을 떠난 것이라 대가가 없고,
  새 구단의 첫 회견이 그 자리를 거절로 닫지도 않는다.
- 옛 세이브엔 회견 테이블이 없다 — 로드 시 빈 배열 (세이브 버전 유지).

## 5. 심경 — 몸의 말과 마음의 말

선수 상태는 `체력`(condition) 하나와 **심경 한 줄**로 보인다. 심경은 **코어가
사실을 고르고, 화면이 문장으로 옮기며, 결산(LLM)이 맥락으로 다시 쓴다** — 경기
평점·훈련 결산과 같은 계약.

### 코어 사실 (`moodFactsOf`)

⚠️ **코어는 문장을 쓰지 않는다** (overview.md §1 철칙 4). 상태 테이블에서 가장 말이
되는 이유 하나 + 곁들임 한 조각을 골라 **사실 카드 최대 2장**(`MoodFact[]`)으로 낸다 —
원인 코드 + 수치 + 기간, 그뿐이다. 화면이 그 카드를 한 문장으로 옮기고
(`apps/web/lib/mood.ts`), `get_player`는 카드를 그대로 GM에게 넘긴다.

카드는 14종이다: `injury`(부위 · 복귀까지 일수) · `suspension`(남은 경기) ·
`grievance`(사유 코드 · 며칠째 · 연패 수 · **원형 코드** · **계약 지위와 최근 창의
선발 수** — §5-2) ·
`demotion`(2군 며칠째 · **원형 코드** · 그 사람의 문턱 일수) ·
`settling`(진행 % · 출전 수) ·
`afterglow`(며칠 전 · 승무패 · 평점 · 자기 경기 등급 · **그 경기가 세운 마일스톤**) ·
`no-minutes`(벤치/명단 밖) ·
`form`(등급) · `condition`(무거움/가벼움) · `departure`(떠난 선수 이름 · 며칠 전) ·
`contract-ending`(남은 일수) · `leader`(완장·서열 — §5-1) · `young`(나이) · `steady`.

카드를 고르는 우선순위는 "감독이 지금 조치해야 하는 순서"다:

1. **못 뛰는 사유** — 부상(복귀 D-일)·정지. 있으면 그게 전부다.
2. **마음** — 라커룸 불만 → **2군에 내려가 있음**(며칠째) → 정착 중(새 영입) →
   직전 경기의 여운(3일까지 — 팀 결과와 개인 평점을 갈라 말한다: 이긴 경기에서
   부진한 선수와 진 경기에서 제 몫을 한 선수는 마음이 다르다. 그 경기가 데뷔전이나
   100경기였다면 여운 카드가 그 **마일스톤 코드**를 함께 든다 — 새 카드를 세우지
   않는 이유는 그것이 별개의 마음이 아니라 **그 경기의 여운**이어서다). 2군 카드가 출전
   기회보다 앞에 서는 이유는 그것이 **못 뛰는 이유 자체**여서다 — 감독이 내린
   결정이 사실로 남지 않으면 강등은 아무 데도 닿지 않는다.
3. **출전 기회** — 시즌 개막 후 출전 0인 벤치·명단 밖 선수만. ⚠️ 개막 전에는
   말하지 않는다 — 프리시즌엔 아무도 뛴 적이 없어 벤치 전원에게 걸린다.
4. **폼** — 눈금은 `formLabel` 하나가 갖는다(절정 0.73 · 상승세 0.33 ·
   침체 −0.33 · 바닥 −0.73). ⚠️ 숫자로 옮겨 적으면 그 가지가 소리 없이 죽는다.
5. **몸** — 등급으로만: ≤35 `heavy`, ≥85(다른 말이 없을 때만) `light`.
6. 곁들임 — **최근 3일 안의 계약 해지**(떠난 선수 이름) · 계약 만료 180일 안 ·
   **라커룸에서 선 자리**(주장·부주장·리더 그룹 — §5-1) · 20세 이하.
   ⚠️ **계약 만료 곁들임은 `contract` 불만이 걸린 선수에게는 서지 않는다** — 같은
   사실을 불만 카드가 이미 말하고 있어, 두 장 한도 안에서 폼이나 몸을 밀어낼 뿐이다.
   해지는 팀 전체에 같은 카드로 걸린다 — 누가 그와 가까웠는지를 가를 관계 점수가
   아직 없다(§10 미해결).

⚠️ **몸은 몸의 말로, 마음은 마음의 말로.** 경기 한 판이 체력 30\~50을 가져가므로
경기 다음 날은 누구나 바닥이다 — 체력에서 감정을 읽으면 이긴 다음 날 선수단
전원이 침울해진다. 지친 것과 마음이 뜬 것은 다른 사실이다.

### 결산 (`mood-rater`) — 다시 쓰는 계약

규칙만으로는 늘 같은 문장이 나온다 — 같은 "불만"도 벤치의 고참과 이적 요청을
넣은 주전이 다르다. 그래서 훈련·평점 결산이 도는 **같은 자리**(시간 진행 뒤 ·
경기 종료 뒤 평점 다음)에서 같은 결산 에이전트로 돈다.

- 대상은 **그 구간에 사건이 있었던 선수 최대 8명**(`MOOD_BATCH`) — 3일 내 경기
  출전(가중 3)·불만(4)·**2군에 내려가 있음(3)**·정착 중(2)·폼 양 끝(2)으로 고른다.
  부상·정지 선수는 뺀다 — 사실이 이미 정확해 다시 쓸 여지가 없다.
  ⚠️ **2군은 경기를 뛰지 않는다** — 강등된 선수를 여기서 세지 않으면 내린 다음
  날부터 결산에서 조용히 사라진다.
- 브리프가 싣는 `anchor`도 **사실 줄**이다 — 카드를 `·`로 이은 한 줄일 뿐, 평가어도
  연출어도 없다. 모델이 읽는 것은 끝까지 사실이다.
- **사실은 코어가 잡고 결만 맡긴다** (`applyMoodNotes`) — 버리는 조건 셋:
  ① 대상이 아닌 선수 ② 한 문장이 아니거나 120자 초과 ③ 불만이 걸린 선수인데
  문장에 "불만"이 없음. 길이는 **저장할 문장으로 잰다** — 종결 부호가 없으면
  마침표를 붙인 뒤에 재므로 121자가 세이브로 나가지 않는다. `?`·`!`로 끝나는
  문장도 그대로 종결로 본다. 버려지면 앵커가 남는다 — 빈 줄이 생기지 않고 시간 진행도
  막히지 않는다 (실패·타임아웃도 삼킨다).
- 문장은 `GAME_PLAYER.state.moodNote`에 저장한다 — 대화·사건이 원본이라 파생할
  표가 없다 (optional — 세이브 버전 유지). **코어가 저장하는 유일한 심경 문장이고,
  그것을 쓴 것은 모델이다.**
- ⚠️ **열흘이 지나거나 부상·정지가 생기면 코어가 이긴다** (`moodOf`) — 지난주의
  결이 오늘의 심경인 척하면 화면이 거짓말을 한다. 그때는 `note`가 `null`로 돌아가고
  화면이 카드로 다시 쓴다.

### 불만의 사유 (`PlayerIssue.reason`)

라커룸 불만은 **사유 코드**로 남긴다 — 문장으로 적으면 그것을 읽는 자리마다
`"${note}에 불만이 쌓여 있다"` 같은 짜깁기가 생긴다.

| 코드              | 언제                                                                            | 딸린 수치                |
| ----------------- | ------------------------------------------------------------------------------- | ------------------------ |
| `minutes`         | 월요일, 계약 지위가 부르는 선발 비율에 최근 8경기가 못 미칠 때 (`tick.ts`)      | `count` = 모자란 선발 수 |
| `losing-run`      | 연패가 문턱을 넘을 때 (`slump.ts`)                                              | `count` = 연패           |
| `early-return`    | 휴가를 접고 소집을 앞당겼을 때                                                  | —                        |
| `demotion`        | 2군에 21일을 둔 핵심 자원 (`core/tick.ts`)                                      | —                        |
| `listed`          | 이적 리스트에 14일을 올려 둔 핵심 자원 (`core/tick.ts`)                         | —                        |
| `blocked-move`    | 값이 붙은 오퍼를 감독이 거절했을 때 (`negotiation.ts`)                          | —                        |
| `contract`        | 만료가 문턱 안인데 열린 재계약이 없다 (`core/tick.ts`)                          | —                        |
| `out-of-position` | 주 포지션 밖 선발이 4경기 이어졌을 때 (`match-flow.ts`)                         | `count` = 연속 경기      |
| `promise`         | 감독이 한 약속의 기한이 지났는데 장부가 이행을 못 찾을 때 (`squad/promises.ts`) | —                        |

아홉 사유가 **한 자에 선다** — 화면의 ⚠불만 줄도, 심경 카드도, 회견의 유출 카드도,
다가옴의 주제(§8)도 같은 코드를 읽는다. 사유를 하나 늘리면 그 넷이 함께 는다.

**연패 불만은 한 연속에 한 명이다** — 문턱(`SLUMP_ISSUE_LOSSES` 4)을 **넘는 그
경기에서만** 이름이 붙고, 이어지는 5·6연패는 새 이름을 올리지 않는다. 매 경기 한
명씩 올리면 한 번의 붕괴가 스쿼드의 주력을 통째로 불만으로 채우고, 압력 눈금(§8)의
선수 채널이 그 수만큼 한꺼번에 사다리를 오른다 — 붕괴의 대가가 라커룸 하나가 아니라
스쿼드 붕괴가 된다. 연속이 끊겼다가 다시 문턱을 넘으면 그때 다시 한 명이다.

**강등은 즉시 불만이 아니다** — 내린 날은 사실 카드(`demotion`)만 서고, **21일**
(`DEMOTION_PATIENCE_DAYS`)**에 그 선수의 `patience`를 곱한 날**을 그대로 두면 그때
불만이 걸린다(§6 — 저울질하는 스타 13일 · 팀 우선 베테랑 30일). 방치의 대가는 규칙이
아니라 시간의 결과여야 한다(overview.md §1 철칙 4). 대상은 **우리 스쿼드에서 그보다
나은 선수가 14명 미만**(`SQUAD_CORE_SIZE`)인 자원뿐이다 — 로테이션 자원을 2군에
내리는 것까지 반란이 되면 2군이 못 쓰는 손잡이가 된다. 추첨이 없어 감독이 날짜를
셀 수 있고, **1군 승격이 그 불만을 지운다**(면담이 잘 풀려도 지워진다 — 사유를
가리지 않는 기존 경로다). 내려간 날은 `PlayerState.demotedOn`이 들고 있다.

**출전 불만은 지위가 잰다 — 주사위가 없다.** 매주 월요일, 1군 선수의 **최근
`PROMISE_WINDOW_MATCHES`(8)경기 선발 비율**을 그의 **계약 지위**가 부르는 비율
(§5-2 `SQUAD_STATUS_STARTS`)과 대조해 못 미치면 그 자리에서 `minutes` 불만이 선다.
`count`는 **모자란 선발 수**다 — 여덟 경기 중 몇 번을 더 세웠어야 했는가.
백업·유망주의 기대 비율은 0이라 **백업으로 데려온 선수는 벤치에 앉아도 불만을 내지
않는다**: 그가 어떤 자리로 왔는지가 계약에 적혀 있기 때문이다(§5-2). 확률을 걷어 낸
이유는 강등·등재와 같다 — 방치의 대가는 규칙이 아니라 시간의 결과여야 하고
(overview.md §1 철칙 4), 감독이 예측할 수 없는 불만은 손잡이가 아니라 소음이다.

- **창은 팀의 경기이고, 세는 것은 그가 설 수 있었던 경기다.** 창 안의 경기 중 그가
  **부상 중이던 날**은 분모에서 빠진다 — 못 나온 것이 감독의 결정이 아닌 경기까지
  세면 복귀 첫 주에 불만이 선다. 남은 경기가 `PROMISE_MIN_MATCHES`(3) 미만이면
  판정하지 않는다.
- **창이 차기 전에는 서지 않는다** — 우리가 그 창의 경기 수를 아직 치르지 않았으면
  비율이 표본이 아니다. 그래서 첫 `minutes` 불만은 빨라도 개막 두 달 뒤다.
- **지금 부상·정지 중인 선수에게는 서지 않는다** — 뛸 수 없는 사람이 출전 기회를
  따지지 않는다.
- 대상은 1군이다. 2군에 내려간 선수의 불만은 `demotion`이 이미 말한다.

**어긴 약속은 다른 사유와 같은 사다리를 탄다** — 기한이 지난 약속을 장부가 이행으로
읽지 못하면 `promise` 불만이 서고(§5-2), 그 뒤는 다른 여덟과 똑같다: 심경 카드에
오르고, 압력을 쌓고, 방치하면 언론에 흘러 이적 요청까지 간다. 사유를 따로 둔 것은
그것이 **감독 자신이 세운 원인**이기 때문이다 — 출전이 모자란 것과 세우겠다고
말해 놓고 안 세운 것은 라커룸에서 다른 사실이다.

⚠️ **같은 날 둘이 겹치면 약속이 이긴다.** 한 선수에게 불만 줄은 하나이므로 판정
순서가 곧 승자다 — 약속 판정이 출전 불만보다 먼저 선다. 어긴 약속이 감독 자신이
세운 원인이라는 것이 그 이유이고, 다가옴의 눈금도 그렇게 말한다(§8 — 약속 9 ·
출전 7).

**등재는 공개된 결정이다** — 감독이 값을 부르며 시장에 내놓은 순간 선수도 안다.
그래서 문턱이 강등(21일)보다 짧다: 기준 `LISTED_PATIENCE_DAYS`(**14일**)에 그 사람의
`patience`를 곱한 날(§6 — 저울질하는 스타 8일 · 팀 우선 베테랑 20일)을 그대로 두면
불만이 걸린다. 대상은 강등과 같은 자다 — **우리 스쿼드에서 그보다 나은 선수가 14명
미만**(`SQUAD_CORE_SIZE`)인 자원뿐이라 백업 정리는 조용하다. **리스트에서 내리거나
팔리면 지워진다** — 원인이 사라진 것이 등재 그 자체이기 때문이다.

**막힌 이적은 값이 가른다** — 우리 선수에게 온 매각 오퍼를 감독이 거절할 때
(`answer_incoming_offer`), 그 이적료가 **시장가 언저리 이상**(`isSeriousOffer` —
시장가의 `MARKET_NEAR_LOW` 85%)이면 `blocked-move`가 선다. 헐값 오퍼를 물리는 것은
선수도 아는 옳은 결정이라 세지 않는다 — 값이 붙은 자리를 막았을 때만 감독의 결정이
된다. ⚠️ **시장가 자체는 문턱이 될 수 없다**: AI의 첫 호가는 흥정의 여지를 남기려고
시장가의 75~100%로 들어오므로([transfer.md](../simulation/transfer.md) §6), 그 자를
쓰면 값이 붙은 오퍼를 막은 일이 라커룸에 영영 닿지 않는다. 호가가 「시장가 언저리」에
섰는지를 재는 자와 같은 것이다(transfer.md §1). 임대 오퍼는 세지 않는다(나가는 것이 아니라 다녀오는
것이다). 이 사유만 문턱이 날짜가 아니라 **한 번의 결정**이다.

**계약은 두 문턱이다** — 활성 계약의 만료가 `CONTRACT_DEMAND_DAYS`(**180일**) 안이고,
**우리 스쿼드 상위 14명**이며, **열린 재계약 협상이 없으면** 불만이 선다. 다만 지금
주급이 그의 기량이 부르는 값(`wageByRating`) 이상이면 문턱이 절반
(`CONTRACT_DEMAND_PAID_DAYS` **90일**)으로 미뤄진다 — 서열대로 받고 있는 선수는 급할
것이 없고, 밀려 있는 선수는 반년 전부터 묻는다. **이 불만을 지우는 것은 재계약 성사
하나뿐이다**(`executeRenewal`) — 협상을 여는 것은 압력을 멈출 뿐이다(§8). 시상 뒤의
가중은 걸지 않는다: 시상 자체가 아직 장부에 없다
(→ [../simulation/season.md](../simulation/season.md) §9).

**자리 밖 기용은 선발로 센다** — 주 포지션(`naturalPositionOf`)의 **묶음 밖**에
선발로 서면 `PlayerState.outOfPositionRun`이 하나 오르고, **제자리에 선발로 서면**
0으로 돌아간다. `OUT_OF_POSITION_RUN`(**4경기**)이 이어지면 불만이 걸리고 `count`가
그 경기 수다. 날이 아니라 경기인 이유는 그것이 실제로 겪는 단위여서다 — 2주에 한
경기를 뛰는 선수와 사흘에 한 경기를 뛰는 선수에게 같은 날짜를 걸면 뒤쪽만 화를 낸다.

⚠️ **선발이 아닌 경기는 세지도 지우지도 않는다.** 이 눈금이 재는 것은 「그가 선발로
선 최근 경기가 연속 몇 번 자리 밖이었나」다 — 벤치에 앉힌 한 경기가 눈금을 지우면
감독이 그것을 껐다 켰다 할 수 있고, 그 선수가 실제로 겪는 것(선발로 설 때마다 딴
자리다)과도 다르다. **묶음으로 재는 것**(`positionGroupOf`)은 CB에서 FB로 옮긴 것과
CB에서 ST로 올린 것이 다른 일이기 때문이다.

**팀을 떠나면 불만도 끝난다** — 매각·방출·임대 송출·계약 만료 어느 문으로
나가든 공통 지점(`clearDepartedState`)이 그 선수의 불만을 지우고, 감독이
이직하면 옛 구단의 불만을 통째로 비운다(`acceptManagerOffer` —
`approachPressure`를 비우는 것과 같은 결).

옛 세이브는 사유 대신 문장(`note`)을 들고 있다 — 읽는 쪽이 `reason ?? note`로
받는다 (둘 다 optional, 세이브 버전 유지).

## 5-1. 라커룸 서열 — 완장과 리더 그룹 (`squad/hierarchy.ts`)

라커룸에는 완장 하나가 아니라 **서열**이 있다. 감독이 정하는 것은 완장 둘(주장·부주장)
뿐이고, 나머지는 **저장하지 않고 파생한다** — 등록 현황과 같은 원칙이다. 저장하면
영입·출전·시즌 롤오버마다 갱신해 줄 자리가 늘고, 그중 하나만 빠뜨려도 화면과 판정이
다른 서열을 읽는다.

### 서열 점수 (`standingScore` — `packages/domain/src/player.ts`) — 네 항의 가중 합, 0~99

| 항                | 지분 | 무엇을 읽나                            | 만점      |
| ----------------- | ---- | -------------------------------------- | --------- |
| `leadership`      | 0.55 | 16축의 리더십 그대로                   | 99        |
| 나이              | 0.15 | 21세에서 30세까지 선형                 | 30세 이상 |
| 그 셔츠의 출전 수 | 0.20 | 그 팀 1군 통산 출전 (`careerTotalsOf`) | 100경기   |
| 재적 시즌 수      | 0.10 | 그 팀 기록이 남은 시즌 수              | 4시즌     |

- **리더십이 절반을 넘게 가진다** — 나머지 셋은 "라커룸이 그를 얼마나 오래 봤는가"라
  같은 리더십이면 오래 있은 쪽이 앞선다. 리더십이 20인 유망주는 100경기를 뛰어도
  리더십 80인 신입을 넘지 못한다(11.0 + 19.8 vs 44.0).
- **개막 전에는 리더십과 나이만 선다.** 시드 스쿼드는 출전도 재적도 0이라 서열이
  리더십으로 정해지고, 시즌이 지날수록 오래 뛴 선수가 올라온다.
- 동점은 선수 id 순으로 가른다 — 같은 세이브는 언제나 같은 서열이다.

### 리더 그룹 — 1군 상위 다섯

후보는 **1군뿐이다**. 2군에 내려간 선수는 감독의 일상에도 라커룸의 아침에도 없다
(2군으로 내리면 완장도 함께 빠진다 → [team.md](./team.md) §5). **임대 보낸 선수도
빠진다** — 계약은 우리 것이어도 아침마다 도는 훈련장이 남의 것이다
(→ ../simulation/transfer.md §2).

- 서열 상위 `LEADER_GROUP_SIZE`(5)명이 리더 그룹이다.
- **완장은 서열을 이긴다** — 주장·부주장은 서열과 무관하게 그룹에 든다. 감독이
  세운 사람이 그룹 밖에 서면 완장이 뜻을 잃는다.

### 완장 — 감독의 결정 둘 (`set_captain`)

- **주장·부주장은 각각 한 명**이다. 부주장을 주장으로 올리면 부주장 자리는 빈다.
- 결과 항목에 **리더십과 재적**이 함께 선다 — 완장이 결정이 되려면 감독이 무엇을
  보고 골랐는지가 그 자리에 남아야 한다.
- **승계는 서열이 정한다** (`successorCaptainOf`): 주장이 비면 **부주장이 잇고**,
  부주장도 없으면 서열 최상위가 완장을 받는다. 은퇴·이적으로 주장이 사라진 시즌
  롤오버가 이 규칙을 쓴다. ⚠️ 골키퍼를 거르지 않는다 — 누가 라커룸을 이끄는가는
  포지션이 아니라 리더십이 답한다.
- **새 게임의 첫 주장도 서열 최상위다** (`createGame`). 개막 전에는 출전도 재적도
  0이라 리더십과 나이가 그 자리를 정한다. OVR로 세우던 자리였는데, 그러면 리더십
  20인 최고 선수가 완장을 차고 감독이 첫 팀토크부터 가장 나쁜 라커룸 계수를 받는다.
  부주장은 비워 둔다 — 감독이 처음 채우는 완장이 하나는 남아 있어야 한다.
- **그 경기의 완장** (`matchCaptainOf`)은 명단 안에서 다시 정해진다: 주장이 명단에
  없으면 부주장이, 둘 다 없으면 명단 안 서열 최상위가 완장을 찬다.

### 리더십이 닿는 자리 — 넷

| 자리                | 무엇이 곱해지나                                                            |
| ------------------- | -------------------------------------------------------------------------- |
| 팀토크의 전파 폭    | **라커룸 계수** — 완장과 리더 그룹의 리더십 (→ ../simulation/career.md §2) |
| 다가옴의 압력       | **리더 배수** — 리더의 불만은 더 빨리 임계에 닿는다 (§8)                   |
| 떠난 선수의 사기 폭 | **리더 배수** — 리더가 나가면 라커룸이 더 크게 흔들린다                    |
| 새 영입의 정착      | **리더 항** — 리더가 선 라커룸은 새 사람을 더 빨리 받아들인다              |

**리더 배수** (`LEADER_WEIGHT`) — 주장 2.0 · 부주장 1.6 · 리더 그룹 1.3 · 나머지 1.0.
같은 눈금이 압력과 이탈 사기 둘 다에 걸린다: 무게가 자리마다 다르면 "리더가 무겁다"가
어느 자리에서 얼마나 무거운지 감독이 알 수 없다.

**라커룸 계수** (`dressingRoomFactor`) — 완장의 리더십에 0.6, 리더 그룹 평균에 0.4를
주어 목소리 하나를 만들고, `0.8 + (목소리/99) × 0.4` = **0.80~1.20**을 팀토크의 사기
변화량에 곱한다. 감독의 리더십 계수(0.70~1.30)와 **곱해진다** — 말을 하는 사람과 그
말이 울리는 방이 따로 있기 때문이다.

- ⚠️ **좋은 말만 커지지 않는다.** 잘 통하는 라커룸에서는 어긋난 말도 그만큼 크게
  울린다. 한쪽에만 걸면 리더 그룹이 공짜 보너스가 되고, 그러면 감독이 라커룸을
  고를 이유가 없다.
- **경기 중에는 그 경기의 명단이 방이다** — 하프타임 팀토크의 목소리는 그날 뛰는
  사람들이 낸다. 주장이 결장한 경기의 하프타임은 부주장의 리더십이 방을 정한다.
- 완장도 리더 그룹도 없으면 계수는 1.0이다 — 코어가 없는 사람의 목소리를 지어내지
  않는다.

**정착의 리더 항** (`SettlingFactor` `leaders`) — `1 − 0.2 × (본인을 뺀 리더 그룹의
리더십 평균 / 99)` = **0.80~1.00**을 필요 크레딧에 곱한다
(→ [player.md](./player.md) §9.3).

## 5-2. 약속 — 감독의 말이 장부에 서는 자리 (`squad/promises.ts`)

이 게임의 인터페이스는 말이고, 잘한 말은 잘 먹혀야 한다
([../llm/prompts.md](../llm/prompts.md) §3). 그런데 말이 **공짜**면 가장 잘 먹히는
말이 가장 값싼 말이 된다 — 불만 선수를 면담 한 번의 "다음 경기 선발이다"로 잠재우고
잊는 것이 최적 전략이 되고, "방치의 대가는 시간의 결과"라는 규약(overview.md §1
철칙 4)이 약속 앞에서만 빈다. 그래서 감독이 한 약속은 **장부에 선다.**

⚠️ **코어가 드는 것은 코드와 날짜뿐이다.** 무슨 말로 약속했는지는 장면의 것이고,
장부는 갈래·기한·상태만 든다. 이행 판정도 전부 장부에서 나온다 — 어느 자리에서도
문장을 읽지 않는다.

약속은 두 자리에 산다: 시즌 단위의 **계약 지위**와 기한이 있는 **약속 장부**.

### 계약 지위 (`Contract.squadStatus`) — 계약에 적히는 약속

선수가 **어떤 자리로 왔는가**. 다섯이고, 이 순서가 곧 서열이다.

| 지위     | 코드       | 기대 선발 비율 (`SQUAD_STATUS_STARTS`) | 8경기 기준 |
| -------- | ---------- | -------------------------------------- | ---------- |
| 핵심     | `key`      | 0.70                                   | 6경기      |
| 주전     | `starter`  | 0.50                                   | 4경기      |
| 로테이션 | `rotation` | 0.25                                   | 2경기      |
| 백업     | `backup`   | 0                                      | —          |
| 유망주   | `prospect` | 0                                      | —          |

- **백업·유망주가 0인 것은 눈금이 아니라 규약이다** — 그 자리로 온 선수에게는 벤치가
  곧 약속의 이행이다. 뛰고 싶으면 지위를 다시 흥정하거나(재계약) 떠나야 한다. 이
  줄이 없으면 백업 영입이 곧 반란이 되어 스쿼드를 채우는 일 자체가 손해가 된다.
- `promiseKept(startShare, status)`는 `startShare >= SQUAD_STATUS_STARTS[status]`
  **하나다** — 약속 이행 판정과 출전 불만(§5)이 같은 자를 쓴다. 자를 둘 두면 "약속은
  지켰는데 불만이 서는" 상태가 생긴다.
- **지위 없는 계약은 지금 서열에서 파생한다** (`squadStatusOf` → `derivedSquadStatus`).
  두 문을 차례로 지난다.
  1. **스쿼드의 핵심 안인가** — 그보다 나은 선수가 `SQUAD_CORE_SIZE`(14)명 이상이면
     거기서 끝이다: 만 21세 이하면 `prospect`, 그 밖은 `backup`. 등재·계약 불만이
     쓰는 것과 **같은 자**다(§5). 자리 깊이만 보면 서른 명짜리 1군이 열두어 자리로
     나뉘어 자리마다 둘째까지 로테이션이 되고, 여덟 경기에 여든여덟 자리뿐인 판에
     감당할 수 없는 기대가 스물여섯 개 선다 — 백업 정리가 조용한 이유와 같은
     이유로 여기서 끊는다.
  2. **그 자리에서 몇째인가** — 주 포지션에 그보다 나은 선수가 없고 스쿼드 상위
     `KEY_SQUAD_RANK`(5)면 `key`, 나은 선수가 없으면 `starter`, 하나면 `rotation`,
     그 밖은 위와 같이 `prospect`·`backup`.

  ⚠️ **이 문은 파생에만 걸린다.** 서열 밖의 선수에게 감독이 주전을 약속했다면 그것은
  약속이지 파생이 아니라, 계약에 적힌 지위는 그대로 선다. 파생은 **지금 실제로 서는
  순서**라 옛 세이브가 로드되며 없던 불만을 만들어 내지 않는다.

- **지위는 협상에서 정해진다** — 오퍼(`send_offer`)·재계약 제안(`open_renewal`)이
  지위를 함께 싣고, 합의된 지위가 새 계약에 적힌다(§5-2는 계약의 칸이지 협상의
  칸이 아니다 — 협상 라운드가 나르는 값은
  [../simulation/transfer.md](../simulation/transfer.md) §1). 제시된 지위가 없으면
  파생값이 그대로 계약에 적힌다.
- **설득 논거 `starting_role`은 지위 약속으로 접힌다** — 코어가 사실로 확인한 "주전
  보장"은 성사되는 순간 `starter` 지위로 계약에 남는다. 확인되지 않은 논거는 남지
  않는다: 선수가 믿지 않은 말이 계약에 적힐 이유가 없다.

### 약속 장부 (`state.promises`) — 기한이 있는 약속

면담(`talk_to_player`)과 다가옴의 응대(`respond_to_approach`)에서 감독이 한 말 중
**갈래가 있는 것**만 장부에 선다.

| 갈래       | 감독이 한 말         | 기본 기한        | 이행 판정 (`tickPromises`)                     |
| ---------- | -------------------- | ---------------- | ---------------------------------------------- |
| `minutes`  | "너를 세우겠다"      | 56일             | 기한까지 선발 비율이 `starter` 기대(0.50) 이상 |
| `transfer` | "보내 주겠다"        | 다음 이적창 마감 | 이적 리스트에 올렸거나 실제로 내보냈다         |
| `renewal`  | "재계약을 열겠다"    | 30일             | 그 선수의 `renew` 협상을 열었다                |
| `captain`  | "네가 다음 주장이다" | 90일             | 기한 날 그가 주장이다 (부주장은 아니다)        |

- **같은 선수·같은 갈래의 약속은 하나다.** 열려 있는 동안 같은 약속을 다시 하면
  반려된다 — 기한이 매번 밀리면 약속이 다시 공짜가 된다.
- **대상에 맞지 않는 약속은 반려된다** — 이미 주장인 선수에게 `captain`, 이미 리스트에
  오른 선수에게 `transfer`, 재계약이 이미 열린(또는 활성 계약이 없는) 선수에게
  `renewal`. 지킬 것이 없는 약속은 장부에 서지 않는다.
- **기한은 감독이 좁힐 수 있다** — `days`를 실으면 `PROMISE_DAYS_MIN`(7)~
  `PROMISE_DAYS_MAX`(365) 안에서 그 값이 기한이 된다. "다음 달까지 세우겠다"와
  "이번 시즌 주전이다"는 다른 약속이다.
- **`minutes` 약속의 자는 `starter`다.** "너를 세우겠다"는 말에 지위 다섯 중 하나를
  고르게 하지 않는다 — 지위를 바꾸는 것은 계약이 하는 일이고, 면담에서 하는 약속은
  "주전으로 쓰겠다" 하나다. 기한 안에 그가 **설 수 있었던** 경기가
  `PROMISE_MIN_MATCHES`(3) 미만이면 **지킨 것으로 본다**: 세울 경기가 없었던 것은
  감독이 어긴 것이 아니다.
- **떠나면 약속도 끝난다** — `clearDepartedState`가 그 선수의 열린 약속을 지우고,
  감독이 이직하면 옛 구단의 약속이 통째로 사라진다(`acceptManagerOffer` — 불만·압력과
  같은 결).
- 판정은 **기한 날 하루**다. 판정이 끝난 약속은 `kept`·`broken`으로 남아 이력이 된다 —
  같은 선수에게 다시 약속할 수 있는 것은 그때부터다.

### 지킨 값과 어긴 값 (`PROMISE`)

| 판정            | 당사자 사기                    | 선수단 평판 | 그 밖                              |
| --------------- | ------------------------------ | ----------- | ---------------------------------- |
| 지킴 (`kept`)   | `PROMISE_KEPT_MORALE` **+6**   | **+2**      | —                                  |
| 어김 (`broken`) | `PROMISE_BROKEN_MORALE` **−8** | **−4**      | `PlayerIssue{ reason: "promise" }` |

어긴 쪽이 큰 것은 규약이다 — 지킨 약속은 감독이 **당연히 할 일**을 한 것이고, 어긴
약속은 감독이 하지 않은 일이다. 값이 같으면 남발하고 절반만 지키는 것이 아무것도
약속하지 않는 것보다 이득이 된다. 평판이 함께 움직이는 것은 **약속이 라커룸 전체가
보는 일**이기 때문이다: 한 사람에게 한 말이 지켜지는지를 나머지가 센다.

## 6. 캐릭터북 — 인물 정보를 필요한 순간에 싣는다

인물 카드는 두 상태밖에 없었다: **늘 있거나**(코치·구단주·기자단이 레퍼런스 층에
상주) **아예 없거나**(선수). 캐릭터북이 그 사이다 — 「이 인물이 지금 필요하다」를
판정해 그 턴에만 싣고, 실은 카드는 이력에 남는다.

⚠️ **레퍼런스에서 넣었다 뺐다 하는 것은 지금보다 나쁘다.** 레퍼런스는 캐시
프리픽스라 한 턴 카드를 끼우면 그 턴에 레퍼런스와 그 뒤 이력이 통째로 무효가 되고
다음 턴에 또 무효가 된다 (→ ../llm/agents.md §5). 그래서 카드는 **이번 턴 층**으로
들어가고, 다음 턴부터 이력의 일부가 되어 이력 캐시에 편입된다. 비용이 **등장한
인물 수**에 비례하지 턴 수에 비례하지 않는다.

### 캐릭터북에 있는 것

- **화자** — 페르소나가 있는 사람 전부. 선수도 포함된다.
- **키워드** — 이름, 이름 조각, 직책어, 소속 매체, 역할어("구단주" · "이적" ·
  "회견"). ⚠️ **명시적으로 나열한 것만 본다.** 성만 쓴 "홀란드"를 같은 사람으로 보는
  부분 일치는 오탐을 만든다는 §1의 원칙(`normalizeSpeaker`)이 여기도 그대로다 —
  별칭이 필요하면 키워드로 적는다. 두 글자 미만은 키워드가 되지 못한다.
- **인물지** — 성격·동기·말투·예시 대사·관계. 코어가 조립하는 것은 **구조**이고
  (`characterEntry`), 문장으로 옮기는 것은 프롬프트의 몫이다.
- **관계 초기값은 원형 조합에서 결정적으로 나온다** (`world/relations.ts`) — 세이브에
  저장하지 않는다. 원형마다 **먼저 보는 축** 하나가 있고(§2의 원형 표가 그 축이다 —
  코치 근거·몸·사람·성장·경험·구단, 구단주 효율·자산·경기·위상·연고·화제, 기자
  연고·경기·화제), 두 사람의 축이 통하는 짝이면 `aligned`, 부딪히는 짝이면 `tense`,
  나머지는 중립이라 카드에 서지 않는다. 짝의 표는 코드가 한 곳에 갖는다. 관계는
  세이브의 페르소나(코치·구단주·기자단) 사이에만 서고, `full` 깊이의 카드에만
  실린다 — 사이의 결은 매일 보는 사람이나 아는 것이다. **사건이 관계를 움직이는
  점수는 아직 없다** (§10) — 이 값은 첫인상이고, 그 뒤의 일은 인물별 기억이 갖는다.
- **인물별 기억** — 그 사람에게 있었던 일 몇 줄(§9-1). 카드가 서는 자리에 함께 실리되
  **그 턴 층에만** 선다. 인물지와 달리 기억은 **압축이 더하므로**(§9-1), 이력이 다시
  그리는 카드에 지금의 기억을 붙이면 압축 한 번에 지난 턴들의 바이트가 함께 달라진다
  (→ ../llm/agents.md §5). 이력의 카드는 **신원까지**이고, 늘어난 기억은 재주입이
  나른다 (아래 「언제 싣나」).

### 누가 후보인가 — 세 겹

리그 4,000명을 전부 훑지는 않는다. 남의 팀 3군까지 담으면 동명이인이 늘어 **정작
우리 선수가 사라진다** (§3 원칙 ③). 그렇다고 우리 선수단만 담으면 "메시 같은
자원이면"이라고 말하는 순간 GM이 근거 없이 지어낸다. 그 사이를 세 겹으로 긋는다:

| 겹                 | 누구                                                                                            | 깊이          | 상한 경합     |
| ------------------ | ----------------------------------------------------------------------------------------------- | ------------- | ------------- |
| **우리 사람**      | 수석코치 · 구단주 · 기자단 · 세이브의 페르소나 · **우리 선수단** · 협상 테이블에 앉은 상대 선수 | 지식 눈금     | **먼저 선다** |
| **이름난 현역**    | 종합 82 이상 · **시장 전용 리그 시드 명단의 이름**                                              | 지식 눈금     | 나중          |
| **세계 인물 명부** | 타 팀 감독 — 명부(§2-1)와 가상(§2) · 에이전트 · 해설                                            | 언제나 `full` | 나중          |

- **선을 능력치로 긋는 이유** — 세계에 명성 필드가 없고, 시장가는 나이를 먹은
  레전드를 0으로 만들어 **정확히 담아야 할 이름을 떨어뜨린다**. 잠재력은 유망주의
  것이라 더 나쁘다(85 이상이 대부분 스물 미만이다). 남는 값이 종합이고, 82는
  세계 5,300명 중 **58명**이 서는 선이다.
- **레전드는 능력치가 답하지 못한다.** 마흔한 살 호날두는 82지만 서른아홉 메시는
  80이고 수아레스는 75다. 그래서 두 번째 조건이 붙는다 — **시장 전용 리그
  (사우디·MLS)의 시드 명단에 있는 이름은 능력치와 무관하게 후보다.** 그 표는
  이미 "감독이 데려올 만한 이름"만 담기로 하고 만든 명단이라(`data/market-leagues.ts`),
  **표가 곧 명성의 선이다**. 지금 50명이고, 표에서 지우면 세계에서 사라진다.
- **깊이는 지식 눈금이 그대로 정한다** — 남의 팀 선수는 대개 `rumoured`라 원형과
  평판 한 줄까지만 선다. 스카우팅을 보내면 깊어지고, 데려오면 전부 선다.
- **가상 감독의 명단은 벤치다** — 명부에 없는 구단의 감독은 `GameTeam.managerName`이
  이름을 대고, 카드는 (시드, 팀, 이름)에서 파생한다(§2). 깊이는 명부 감독과 같이
  언제나 `full`이다 — 감독은 스카우팅으로 알게 되는 상대가 아니다. 유저 구단의
  벤치는 유저의 것이라 후보가 아니다.
- **상한 경합** — 한 턴 3장을 두고 겹이 다투면 **우리 사람이 먼저 선다.** 자리
  (`RANK_POINTED` → 발화 → 이력)가 먼저이고, **같은 자리 안에서** 우리 쪽이
  앞선다. 감독이 이번 턴에 "메시"라고 썼다면 메시는 직전 턴에 나온 우리 선수보다
  앞서고(자리가 다르다), 같은 문장에 우리 선수 셋과 메시가 함께 있으면 우리 셋이
  선다.
- **이름이 겹치면 우리 쪽이 이긴다.** `characterId`는 전역 유일이므로 명부의 이름이
  세이브의 현역과 같으면 한 사람만 남는다 — 후보를 모으는 순서가 그 답이다
  (우리 사람 → 이름난 현역 → 명부, 먼저 들어온 쪽이 자리를 지킨다).
- **깊이는 뽑힌 뒤에 묻는다.** `knowledgeOf`는 세이브의 경기 기록을 훑으므로 후보
  전원에게 물으면 그 비용이 후보 수에 비례한다. 카드가 되는 것은 최대 3장이다.

### 굳는 것과 변하는 것 — 자리가 셋이다

주입한 카드는 이력에 남는다. 그런데 선수 정보는 대부분 변한다 — 폼·컨디션·부상·
심경·계약·관측 능력치. 3주 전 카드에 "폼 좋음"이 적혀 있으면 그 문장이 이력에 서서
모델이 낡은 사실로 말한다. 세 자리가 각각 다른 일을 맡고 **서로 대체하지 못한다.**

| 자리                                  | 무엇을                                                                 | 왜 거기여야 하나                                                                     |
| ------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| **캐릭터북** (주입)                   | 인물지 — 성격 · 동기 · 말투 · 예시 대사 · 관계                         | 세이브당 불변이라 이력에 굳어도 안전하다. **변하는 값은 절대 여기 넣지 않는다.**     |
| **상태 스냅샷** (`speakerCues`)       | 사실 **한 조각**, 최대 3명                                             | GM은 모르는 선수를 조회할 수 없다 — 근거가 없으면 한 번 불린 이름만 계속 말한다 (§7) |
| **조회** (`search_players(playerId)`) | 지금의 사실 전부 — 폼 · 체력 · 심경 · 부상 · 징계 · 계약 · 관측 능력치 | 발화 직전에 부르면 그 순간의 값이 온다. 이력에 굳지 않는다 (→ ../llm/agents.md §7)   |

**캐릭터북은 "이 사람이 누구인가"만 싣고 "지금 어떤가"는 조회가 맡는다.** 조회하라는
규칙은 GM 시스템 프롬프트의 「입력」이 한 번 갖는다 — 카드 묶음에 포인터를 달지
않는다. 카드는 데이터이고, 거기 실린 지시문은 이력에 굳어 턴마다 쌓인다
(→ ../llm/prompts.md §5).

### 언제 싣나

- **직전 1턴의 이력과 이번 턴 감독 발화**에서 키워드를 훑는다. "홀란드 불러줘"는 그
  턴에 걸린다. 창이 짧아도 새는 것이 없다 — 매 턴 훑고, 걸린 카드는 이력에 남아
  창이 미끄러질 때까지 그대로 서 있다.
- **한 턴에 최대 3장.** 더 걸리면 세계가 지목한 인물 → 이번 턴 발화 → 직전 턴 순으로
  자른다.
- **세계가 먼저 여는 자리는 키워드를 기다리지 않는다** — 열린 회견은 그 기자를 직접
  지목하고(§4), **새 게임 첫 장면**은 수석코치를 지목한다. 감독이 부른 적 없어도 그
  자리에 서는 사람들이라 지목이 키워드를 대신한다. 회견은 코어가 세이브에서 읽어
  지목하고(`pendingPress`), 첫 장면은 이력도 발화도 없는 턴이라 **호출자가** 이름으로
  지목한다 — 둘 다 같은 `RANK_POINTED` 자리로 들어가 상한·중복 제거·정렬을 그대로
  탄다. 코어는 사실만 내고(overview.md §1 철칙 4), 키워드 매칭은 그 위의 일반 경로다.
- **이력 창 안에 이미 있으면 다시 싣지 않는다.** 창은 글자 상한 안에서 6턴 단위로만
  미끄러지므로(→ ../llm/agents.md §5) 밀려난 카드는 **저절로 재주입 대상**이 된다 —
  만료 규칙을 따로 두지 않는다. 압축으로 접힌 구간의 카드도 같다.
- **지식 눈금이 오르면 다시 싣는다** — 스카우팅이 끝난 선수는 더 자세한 판으로 한 번
  더 선다.
- **기억이 늘어도 다시 싣는다** — 압축이 그 인물 앞으로 기억을 적어도(§9-1) 창 안에 서
  있는 카드는 그 기억을 갖고 있지 않다. 주입 기록이 **그때 실린 기억 수**를 함께 남기므로
  (아래) 늘어난 것을 보고 한 번 더 세운다. 보관 상한(§9-1)에 닿은 인물은 수가 늘지 않아
  여기 걸리지 않고, 그 갱신은 카드가 창 밖으로 나가는 첫 조건이 받는다 — 그러자고 카드
  텍스트를 세이브에 남기지는 않는다. 재주입 조건은 그 셋뿐이다.

### 세이브에는 주입 기록만 남는다

`buildGmHistory`는 `state.chat`을 매 턴 **다시 렌더링**한다. 그러니 세이브에 남기는
것은 **주입 기록**(어느 턴에 누구를, 그때의 지식 눈금이 얼마였고 기억이 몇 줄이었는가)
뿐이고, 카드 텍스트는 그 턴을 렌더링할 때 다시 붙는다. 채팅 화면은 깨끗하고 이력은
결정적으로 재현된다. 기록이 없는 옛 세이브는 카드 없는 이력으로 읽히고, 기억 수가 없는
기록은 **재주입을 부르지 않는다** — 그 자리를 0으로 읽으면 옛 세이브의 카드가 한꺼번에
다시 선다. 세이브 버전은 올리지 않는다.

### 지식 눈금이 인물지의 깊이를 정한다 — 3단

새 눈금을 만들지 않는다. `squad/scouting.ts`의 `Knowledge` 다섯 단계를 그대로 쓰고,
`views/lookup.ts`의 `playerCard`가 이미 같은 눈금으로 사실을 가른 것처럼 인물지도
같은 눈금으로 갈린다 (→ player.md §9).

| 눈금               | 인물지                                                   |
| ------------------ | -------------------------------------------------------- |
| `own` · `adapting` | 원형 · 성격 · 동기 · 말투 지문 · 예시 대사 — 전부        |
| `scouted` · `seen` | 원형 · 성격 · 말투 지문 (동기와 예시 대사는 서지 않는다) |
| `rumoured`         | 원형과 평판 한 줄 — 말투는 없다                          |

라커룸에서 매일 보는 우리 선수는 다 서고, 평판으로만 아는 선수는 소문 수준까지만
선다. 눈금이 오르면 같은 인물이 더 자세한 판으로 다시 주입된다.

### 선수 페르소나는 저장하지 않는다

**(시드, 선수 id)에서 결정적으로 파생한다.** 리그 전체 4,000명분 카드를 세이브에
넣을 이유가 없고, 생성이 결정적이라 같은 세이브는 언제 열어도 같은 사람을 만난다
(§2와 같은 규약). 세이브의 `personas`에 남는 것은 자리가 하나뿐인 인물 — 코치·
구단주·기자단 — 이다.

원형 추첨에는 **나이와 포지션**이 걸린다. 스트라이커와 센터백이 같은 확률로 같은
사람이 되면 원형 표가 세계를 설명하지 못한다 — 골잡이는 자기중심·득점욕이, 노장은
멘토·라커룸 리더가, 어린 유망주는 조급함이 더 자주 나온다. **국적은 걸지 않는다** —
실명 선수에 국민성 고정관념이 실릴 위험이 있다 (sources.md §7).

### 선수 원형 10종 — 감독 앞에서 무엇을 먼저 말하는가

### 원형 → 상태 전이 계수 (`PLAYER_ARCHETYPE_TRAITS`)

원형이 프롬프트에만 살면 GM이 연기하는 사람과 장부가 그 선수에게 붙이는 사실이
어긋난다 — 대사는 "제 자리가 어디입니까"인데 불만은 팀 우선 베테랑과 같은 날 선다.
그래서 원형마다 **계수 넷**이 붙고, 그 넷이 닿는 자리는 아래 넷뿐이다.

계수는 **도메인 표 하나**(`packages/domain/src/persona.ts`)가 갖는다. 원형이
(시드, 선수 id)에서 결정적으로 파생하므로 계수도 파생이다 — 세이브에 아무것도
저장하지 않고, **옛 세이브는 로드만으로 같은 계수를 얻는다.** 히든 능력치가 아니다:
새 축을 선수에 심는 대신 이미 있는 원형을 읽는다 (player.md §1).

- **닿지 않는 것**: 전력 패킷 · xG · 부상 성향 · 노화 하락. 앞의 둘은 요구사항 3의
  선이고, 뒤의 둘은 사람됨이 아니라 몸의 일이다 — 성실한 선수가 천천히 늙으면
  직업의식이 노화를 되돌리는 축이 된다.
- **다가옴(§8)에는 따로 걸지 않는다.** 압력 눈금은 이미 원형이 정한 날짜에 선
  불만에서 자라고, 그 자리에 서는 화자의 인물 카드가 원형을 들고 간다 — 같은 사실을
  두 번 실으면 사다리가 원형을 두 번 읽는다.

## 7. 선수 근황 (cues) — 세계에 지금 무슨 이야기가 있는가

부상·정지·불만만으로는 상태 스냅샷이 내보내는 선수 이름이 몇 주씩 바뀌지 않는다 —
GM이 아는 "이야기가 있는 선수"가 늘 같은 두세 명이라 모델이 다른 선수를 세울
근거가 없다. 그래서 **1군 선수의 사실 한 조각을 최대 3명분** 싣는다.

- 사실 4종: 폼 절정(≥0.5)/바닥(≤−0.4) · 복귀 임박(14일 안 — 재활 초입은 주의
  줄의 부상 항목이 이미 말한다) · 새 영입 적응 중 · **직전 세 경기**(날짜순 —
  배열 순서가 아니다. 컵·대항전 대진은 `state.matches` 뒤에 붙는다) 연속 명단 제외.
- 회전은 두 축: **최근 6턴에 말한 사람은 뒤로 민다**(지우지 않는다 — 어제 말한
  선수라도 오늘 부상에서 돌아왔으면 그게 더 큰 사건이다), 나머지는 **날짜로
  굴린다**(근황은 며칠씩 그대로라 정렬만으로는 같은 이름이 몇 주 내내 맨 앞이다).
- 누가 말했는지는 `@이름:`으로 세되 **이름은 §1과 같은 정규화(`normalizeSpeaker`)로
  맞춘 뒤 견준다** — 모델이 "스티브홀랜드"로 적어도 같은 사람이다. 원문 그대로
  견주면 공백 하나 차이로 방금 말한 선수가 회전에서 빠져 계속 맨 앞에 선다.
- 결정적이다 — 같은 날 같은 세이브면 같은 목록.
- ⚠️ **코어가 내놓는 것은 사실뿐이다** — 누가 말할지도, 그 사람이 할 말도 정하지
  않는다 (회견의 사실 카드와 같은 결). 문장은 GM이 쓴다.

## 7-1. 수석코치의 눈 (coach cues) — 원형이 고르는 사실

근황(§7)이 "세계에 지금 무슨 이야기가 있는가"라면 이쪽은 **그중 이 코치가 무엇을
먼저 보는가**다. 6원형(§2)은 여기가 서기 전까지 말투와 관계 초기값에만 닿아 있었다 —
데이터 분석가형과 야전 조련사형이 같은 스냅샷을 읽고 같은 것을 말했다. 원형이 요구
3("시뮬 숫자에 손대지 않고 **상태를 거쳐서만** 세계에 닿는다")을 지키며 게임에 닿는
자리가 이것이다: 코어가 원형별로 **다른 갈래의 사실 조각**을 고른다.

- **턴당 최대 2장**, 상태 스냅샷의 `<coach>` 블록 ([../llm/agents.md](../llm/agents.md) §6).
- **재직 중에만 선다** — 맡은 팀이 없으면 벤치에 함께 앉는 사람도 없다.
- **새로 재는 값은 하나도 없다.** 여섯 갈래 전부 이미 장부에 있는 파생을 읽기만
  한다 — 코치의 눈이 만드는 것은 값이 아니라 **순서**다.
- **원형이 고르지 않는 한 장이 그 앞에 선다** — 지난 구간의 **훈련 결산**
  (`training-report`). 훈련장은 갈래를 가릴 것 없이 이 코치가 여는 자리라, 여섯 눈
  중 누구의 것도 아니고 자리도 따로 갖는다(2장 상한 밖). 카드가 **최근 3일 안**의
  구간일 때만 서고, 싣는 것은 구간·세션 수와 **건수·이름까지만**이다 — 근거 한
  줄과 낱낱의 수치는 달력 일지와 `get_player`가 갖는다
  (→ [../simulation/season.md](../simulation/season.md) §4).

| 원형 키             | 사실 코드                                           | 먼저 보는 것                                                                                   |
| ------------------- | --------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `drill_sergeant`    | `tired` · `injury-log`                              | 3일 안 경기의 선발 중 체력 60 이하 · 이번 시즌 부상 이력과 그동안 빠진 경기 수                 |
| `analyst`           | `opponent-table` · `opponent-form` · `matchup-axis` | 다음 상대의 구단 등급과 순위표 행 · 그 팀의 최근 5경기 · 여섯 축에서 가장 벌어진 두 축         |
| `youth_developer`   | `prospects` · `reserve-record`                      | 2군 잠재력 상위 2명의 나이·종합·잠재력과 최근 30일 성장 로그 · 그 둘의 2군 리그 출전·득점·평점 |
| `man_manager`       | `dressing-room` · `captain`                         | 열린 불만의 수와 이름 · 정착 미완 인원 · 주장의 폼과 시즌 기록                                 |
| `veteran_tactician` | `head-to-head` · `h2h-tally`                        | 다음 상대와의 최근 맞대결 3건 · 장부에 남은 통산 전적                                          |
| `club_loyalist`     | `derby` · `gate` · `expectation`                    | 다음 경기가 더비인가 · 다음 홈경기의 예상 관중과 점유율 · 기대선과 지금 순위의 계단 수         |

- **원형 키는 라벨에서 되찾는다.** 세이브에 남는 것은 `"데이터 분석가형"` 같은
  **라벨**이라(`generateHeadCoach`), 표는 `coachArchetypeKeyOf`가 라벨 → 키로 되짚어
  찾는다. 되찾지 못한 원형은 **빈 블록**이다 — 카드가 서지 않을 뿐, 다른 코치의 눈이
  대신 서지는 않는다.
- **없다는 것도 사실이면 선다.** 처음 만나는 상대의 "장부에 맞대결 기록 없음"은
  자리를 채우는 빈 줄이 아니라 **없는 과거를 지어내지 말라는 사실**이다. 반대로 볼
  것이 아예 없는 갈래는 아무 줄도 내지 않는다.
- **`<coach>`는 코치 이름을 태그의 속성으로 세운다** — 안쪽 줄에 `이름:`을 적으면
  모델의 발화 문법(`@이름:`)과 한 글자 차이라 코어가 낸 사실이 코치가 이미 한 말처럼
  읽힌다 (회견·다가옴이 id를 속성으로 세우는 것과 같은 이유다).
- **`expectation`이 싣는 것은 두 순위가 아니라 그 사이의 간격이다** — 기대 순위는
  `<manager>`가, 지금 순위는 `<now>`가 이미 싣는다. 계단 수는 뺄셈이지 평가가 아니다.
- **회전은 근황과 같은 두 축이다.** 이름이 걸린 사실은 **최근 6턴에 그 이름이
  말했으면 뒤로 밀고**(`recentSpeakers` — §7과 같은 한 함수다), 나머지는 **날짜로
  굴린다**. 갈래가 셋인 원형(분석가·토박이)은 자리가 둘이라 날마다 다른 짝이 선다.
- 결정적이다 — 같은 날 같은 세이브면 같은 두 장.
- 사실이 하나도 없는 날(다음 경기가 멀고 2군이 비어 있고 라커룸이 조용한)에는 블록이
  서지 않는다. 자리를 채우려고 없는 사실을 만들지 않는다.
- ⚠️ **코어가 내놓는 것은 사실뿐이다** — §7과 같은 규칙이다. "체력 58", "잠재력 84 ·
  이달 +2"는 서고 "쉬게 하시죠", "위험합니다"는 서지 않는다. 권고도 평가어도 코어의
  것이 아니다 (overview.md §1 철칙 4). 그 사실로 무슨 말을 할지는 GM이 이 코치의
  말투로 쓴다.

## 8. 다가옴 (Approaches) — 세계가 먼저 말을 건다

회견 밖에서 세계가 감독에게 말을 거는 통로. **사실이 압력으로 쌓여 임계를 넘으면
코어가 장면을 열고**(`club/approach.ts`), 감독은 `respond_to_approach`로 답한다.
회견과 같은 결이되 자리가 다르다 — 회견은 마이크 앞이고, 다가옴은 복도와 감독실이다.

| 단계 | 내용                                                        | 상태 |
| ---- | ----------------------------------------------------------- | ---- |
| 1    | 사실 카드 — 질문 문장을 걷어내고 사실만 넘긴다 (§4)         | ✅   |
| 2    | 압력 눈금 · 임계 · 하루 한 건의 문 · `respond_to_approach`  | ✅   |
| 3    | 사다리 — 방치가 계단을 올린다 (선수 5계단 · 주장·구단주 3)  | ✅   |
| 4    | 채널 — 선수 본인 · 주장 · 구단주(보드 요청) · 에이전트 대리 | ✅   |
| 5    | 사다리 위 계단 — 언론 유출(4) · 이적 요청(5)                | ✅   |

### 압력 눈금 — 원인이 서 있는 동안 쌓인다

압력은 **저장한다**(`state.approachPressure`). 감독이 무엇을 했는지의 누적이라
장부에서 파생할 수 없는 유일한 값이다 — 나머지(불만·순위·폼)는 전부 파생이다.

| 주제              | 채널     | 원인이 서 있다는 것                                                     | 하루 | 처음까지 |
| ----------------- | -------- | ----------------------------------------------------------------------- | ---- | -------- |
| `minutes`         | 선수     | 출전 기회 불만이 열려 있다                                              | 7    | 15일     |
| `losing-run`      | 선수     | 연패 속에 이름이 붙은 불만                                              | 9    | 12일     |
| `early-return`    | 선수     | 휴가 반납 소집 불만                                                     | 6    | 17일     |
| `demotion`        | 선수     | 2군 방치 불만                                                           | 5    | 20일     |
| `listed`          | 선수     | 이적 리스트 등재 불만                                                   | 6    | 17일     |
| `blocked-move`    | 선수     | 감독이 막은 이적 불만                                                   | 9    | 12일     |
| `out-of-position` | 선수     | 자리 밖 기용 불만                                                       | 6    | 17일     |
| `promise`         | 선수     | 감독이 어긴 약속 (§5-2)                                                 | 9    | 12일     |
| `contract`        | 에이전트 | 계약 만료 불만 + **열린 재계약 협상이 없다**                            | 5    | 20일     |
| `interest`        | 에이전트 | 최근 14일 안에 우리 상위 14명에게 온 **값이 붙은** 오퍼가 거절·만료됐다 | 8    | 13일     |
| `morale`          | 주장     | 1군 평균 폼이 −0.2 아래                                                 | 8    | 13일     |
| `results`         | 구단주   | 8경기를 치르고 리그 순위가 보드 기대 아래                               | 4    | 25일     |

- **주제는 사유 코드를 따라간다** — 아홉이 `PLAYER_ISSUE_REASONS`(§5) 그대로다.
  사유가 하나 늘면 채널도 눈금도 따라 늘어난다. 사유 밖의 주제는 셋이다
  (`interest` · `morale` · `results`).
- **`promise`가 `blocked-move`와 같은 눈금인 것은 원인이 같은 종류이기 때문이다** —
  둘 다 **감독의 한 번의 결정**이 세운 불만이라 날짜가 아니라 그 자리에서 선다.
  기다렸다가 잊히는 일이 아니므로 가장 빠른 축에 선다.
- **`contract`는 사유이면서 화자가 에이전트다.** 계약은 선수가 감독에게 직접 묻는
  일이 아니라 **협상 테이블 건너편**에서 오는 일이라, 계단 1부터 명부의
  에이전트(§2-1)가 대리한다. 그가 들고 오는 사실은 남은 일수와 **요구 주급**
  (`renewalExpectation`)이다. 위 두 계단(유출·요청)은 다른 사유와 **같은 사다리**를
  탄다 — 협박을 별도 채널로 열지 않는다.
- **`interest`는 사유가 아니다.** 불만이 걸리지 않고 원장의 사실(거절·만료된 오퍼)만
  서므로, 창(14일)이 지나면 그대로 식는다. 값의 자는 `blocked-move`와 같다 —
  `isSeriousOffer`를 지난 오퍼만 센다: 헐값이 흘러간 것은 에이전트가 감독을 찾아올
  일이 아니고, 그것까지 세면 이적창마다 감독실 문이 열린다. 답하는 것으로 지울 원인이
  없으니 사다리도 3에서 멈춘다. ⚠️ **`blocked-move`와 함께 설 수 있다** — 감독이 값이
  붙은 오퍼를 물리면 둘 다 참이다: 선수는 자기 이적이 막힌 것을, 에이전트는 구단들이
  물어본 것을 말한다. 다른 사실이고 다른 화자라, 겹치는 것은 자리가 아니라 사건 하나의
  두 얼굴이다. 그래도 소음이 되지 않는 이유는 문 다섯이 그대로여서다 — 열려 있는 자리는
  하나이고 하루에 한 건이므로 둘은 며칠 간격으로 갈라 선다.
- **`contract`의 압력은 재계약을 여는 순간 멈춘다** — 열린 `renew` 협상이 있으면
  원인이 서지 않아 하루 12씩 식는다. 다만 **불만 자체는 남는다**: 그것을 지우는 것은
  성사뿐이다(§5). 협상을 열고 방치하는 것이 답이 되면 손잡이가 공짜가 된다.
- 원인이 사라지면 **하루 12씩 식고** 0에서 멈춘다. 압력은 지워져도 **계단은 남는다** —
  한 번 말한 사람은 처음부터 다시 시작하지 않는다.
- **`minutes`만 행동으로 내려간다** — 최근 7일 안에 선발로 섰으면 그날은 7이 쌓이는
  대신 10이 빠진다. 감독의 말이 공짜가 아니어야 하기 때문이다: 벤치 불만은 선발로
  세워야 진짜로 내려가고 응답은 시간을 벌 뿐이다.
- **임계는 계단을 탄다** — `100 × (계단 + 1)`. 처음은 100이고, 한 번 말한 주제는
  200 · 300 · 400을 채워야 다시 온다. 같은 사람이 같은 말을 같은 간격으로 반복하지
  않게 하는 장치다.
- **구단주의 자리에는 열린 보드 요청이 함께 실린다** — 원형이 이적창마다 거는 조건이
  있으면 그 요청 줄이 사실 카드에 sharp로 선다
  (→ [../simulation/career.md](../simulation/career.md) §5.2).
- **리더의 불만은 더 빨리 쌓인다** — **불만이 여는 주제**의 하루치에 **리더 배수**가
  곱해진다(주장 2.0 · 부주장 1.6 · 리더 그룹 1.3 — §5-1). 주장의 출전 기회 불만은
  15일이 아니라 8일 만에 감독실 문을 두드린다. ⚠️ **식는 쪽에는 걸리지 않는다** —
  리더를 선발로 세우는 것이 다른 선수를 세우는 것보다 더 큰 해명일 이유는 없다.
  ⚠️ **불만이 아닌 주제(`interest`)에는 걸리지 않는다** — 남의 구단이 눈독을 들이는
  일은 그 선수의 마음이 아니라 시장의 사실이라, 라커룸에서 선 자리가 그 속도를
  정할 이유가 없다.
- **자리가 열리면 배경 카드에 그 사람의 완장이 함께 실린다** (`ApproachContext.leader`)
  — 같은 불만이라도 주장이 들고 온 것과 후보 선수가 들고 온 것은 다른 자리다.
- **주장이 오는 자리(`morale`)의 사실 카드는 두 개의 폼을 든다** — 1군 평균과
  **리더 그룹 평균**이다. 라커룸이 통째로 식은 것과 리더들만 처진 것은 감독이 손댈
  자리가 다르다.

### 사다리 — 무시할수록 오른다

계단은 **답할 때마다, 무시할 때마다** 하나씩 오른다. 꼭대기는 **주제**가 정한다 —
**불만 사유인 아홉은 5**, 그 밖(`interest`·`morale`·`results`)은 **3**이다(보드 경고가
3/3에 서는 것과 같은 규약). 채널이 아니라 주제인 이유는 위 두 계단이 **방치된 불만이
있어야 서는 사건**이기 때문이다 — 유출할 불만도, 대리로 넣을 요청도 없는 주제는
거기까지 오를 것이 없다.
계단이 그 자리의 **무게**이고, 효과의 폭이 `3 × min(계단, 3)`이다 — 위 계단이라고
사석의 말이 회견보다 멀리 가지는 않는다.

계단 1~3은 그 일에 가장 가까운 사람이 온다 — 선수 본인이거나, `contract`·`interest`
라면 그의 에이전트다. 불만 사유인 주제의 위쪽 두 계단은 **방치가 행동이 되는 자리**다 — 감독실 문을 두드리는 대신 세계가 움직인다:

- **계단 4 — 언론에 말한다.** 자리가 아니라 **사건**이다. 임계(400)를 넘으면 그
  불만이 언론에 흘러나오고(`state.pressLeaks`), **다음 회견의 사실 카드에 sharp로
  실린다**(§4 — 그 회견의 무게는 최소 2가 된다). 감독이 답할 자리가 따로 없으므로
  값은 그 회견에서 치른다. **유출은 압력을 풀지 않는다** — 말한 것은 신문이지
  감독이 아니라서, 직전 임계의 75%가 남아 다음 계단을 앞당긴다.
- **계단 5 — 이적 요청.** 명부의 에이전트(§2-1)가 **대리로** 찾아온다 — 선수가
  같은 말을 네 번 하러 오지 않는다. 자리가 **열리는 순간** 코어가 이적 요청을
  상태에 세우고(`PlayerState.transferRequestedOn`), AI 시장이 그 선수에게 오퍼를
  내기 쉬워진다 (→ ../simulation/transfer.md §1). 어느 에이전트인가는 (시드, 선수)
  에서 결정적으로 뽑는다.

**이적 요청이 서 있는 동안 그 선수의 압력은 더 쌓이지 않는다** — 그 일은 이제
시장의 것이다. 요청이 걷히는 길은 둘뿐이다: **불만이 전부 풀리면**(면담·승격·선발)
거둬들이고, 팀을 떠나면 다른 상태와 함께 지워진다(`clearDepartedState`). 감독의
스탠스는 요청을 지우지 못한다 — 답이 원인을 지우지 않는 규칙 그대로다.

**답하는 것과 무시하는 것의 차이는 남는 압력이다.**

| 감독이 한 것            | 압력                | 계단 | 값                            |
| ----------------------- | ------------------- | ---- | ----------------------------- |
| 답했다 (스탠스 5종)     | 0                   | +1   | 스탠스 표 × 폭 (§4와 같은 표) |
| 거절했다                | 직전 임계의 **75%** | +1   | 무시 행 × 폭                  |
| 사흘 동안 답하지 않았다 | 직전 임계의 **75%** | +1   | 무시 행 × 폭                  |

거절과 방치의 값이 같은 이유는 하나다 — **답하지 않은 것은 답하지 않은 것이다.**
남은 압력이 다음 계단을 앞당기므로, 무시하면 같은 사람이 더 빨리 더 크게 온다.

⚠️ **그 채널의 꼭대기 계단에서는 남는 것이 없다.** 더 오를 칸이 없으면 앞당길 것도
없다. 이 예외가 없으면 마지막 임계의 75%가 늘 깔려 있어 얼마 안 채우고 다시 오고,
만성 불만 다섯이 2주에 한 번씩 문을 두드린다 — 사다리의 끝이 가장 시끄러운 자리가
된다.

**⚠️ 찾아온 사람 앞에서는 시계가 선다.** 자리가 열린 날 `advanceTime`이 멈춘다 —
오늘이 기한인 협상과 같은 예외다(→ ../simulation/season.md §5). 사흘이면 자리가
사라지므로, 시간이 그 위를 지나가면 감독은 답할 기회 없이 대가만 치른다.

**⚠️ 답이 원인을 지우지는 않는다.** 응답은 압력만 되돌린다. 불만을 실제로 푸는 길은
면담(`talk_to_player`)·승격·선발이고, 순위를 되돌리는 길은 승점뿐이다.

### 효과는 그 자리에 있던 사람에게만 닿는다

스탠스 5종은 회견의 것을 그대로 쓴다(§4). 다만 **사석의 대화는 언론에 실리지
않으므로** 채널마다 움직이는 축이 다르다.

| 채널     | 움직이는 축                         | 왜                                     |
| -------- | ----------------------------------- | -------------------------------------- |
| 선수     | 선수단 평판 · 당사자 사기 · 팀 사기 | 라커룸에서 벌어진 일이다               |
| 주장     | 선수단 평판 · 팀 사기               | 주장은 라커룸을 대신해 왔다            |
| 구단주   | 보드 평판                           | 감독실 문을 닫고 한 이야기다           |
| 에이전트 | 선수단 평판 · 당사자 사기           | 협상 테이블의 사담도 라커룸에는 들린다 |

폭은 `APPROACH_BAND(3) × min(계단, 3)`이라 3~9다 — 회견(`PRESS_BAND` 4 × 무게)보다
좁다. 마이크 앞에서 한 말이 복도에서 한 말보다 멀리 간다.

### 소음을 막는 다섯 개의 문

1. **열려 있는 다가옴은 하나뿐** — 겹치면 **임계를 가장 많이 넘긴 것**이 서고 나머지는
   압력으로 남아 나중에 더 크게 온다. 절대값이 아니라 임계 대비인 이유는 계단마다
   임계가 다르기 때문이다 — 300을 채운 3계단은 100을 채운 1계단보다 급하지 않다.
2. **하루 한 건** — 답한 날에도 그날 안에 다음 자리가 열리지 않는다.
3. **감독이 지나친 날에는 다음 사람이 오지 않는다** — 사흘째에 자리가 닫힌 그날은
   비운다. 방치의 결과가 곧바로 소음으로 이어지면 대가가 아니라 벌점이 된다.
4. **같은 화자 7일 쿨다운** — 어제 감독실에 왔던 사람이 오늘 또 오지 않는다.
5. **갓 열린 회견이 있으면 열리지 않는다** — 한 번에 감독에게 답을 요구하는 자리는
   하나다. 다만 회견은 다음 회견이 오기 전까지 닫히지 않으므로(§4), **감독이 사흘째
   지나친 회견은 자리를 다투지 않는다** — 안 그러면 답하지 않은 회견 하나가 시즌 내내
   세계를 조용하게 만든다.

⚠️ **반대 방향은 막지 않는다.** 회견을 여는 것은 경기·이적이라 미룰 수 없다 — 다가옴이
열려 있는 동안 경기가 끝나면 두 자리가 함께 선다. 먼저 사라지는 쪽은 다가옴이다.

### 코어가 내놓는 것은 사실뿐이다

`Approach`는 `PressFact[]`를 그대로 든다 — **사실 카드는 한 모양이다**(overview.md §1).
화자(`speakerId`)와 그 사람이 아는 사실만 넘기고, 그가 무슨 말을 어떻게 꺼내는지는
GM이 쓴다. **한 줄 배경도 카드다** — `{ code, value?, limit? }`로,
`transfer-request`·`grievance`·`contract-demand`(남은 일수)·`interest`(오퍼 건수)·
`dressing-room-form`·`standing`(지금 순위와 보드가 건 순위) 여섯이다. 문장은 읽는 쪽이 만들고 옛 세이브의 `context` 문장은 폴백으로만 남는다. 열린 다가옴의 화자는 회견의 기자와 같은 자리로 캐릭터북에 실린다(§6) —
세계가 먼저 여는 자리는 감독이 이름을 부르기를 기다리지 않는다.

## 9. 서사 메모리

- `NARRATIVE_NOTE { date, text, salience 1~5, kind? }` — **세이브에 남는 유일한 GM
  기억.** 스킬 결과·tick 사건(회견·이적·경질 등)이 `pushNarrative`로 쌓고 최대
  200개를 유지하며, 상태 스냅샷에 **최근 4개**가 "최근 사건"으로 실린다.
- **시간이 넘어가며 벌어진 일은 다이제스트에만 두지 않는다** — 다이제스트 줄은
  그 턴의 모델 입력으로만 가고 화면에는 서지 않으므로(agents.md §4), GM이 장면에
  옮기지 않은 사건은 감독에게 없는 일이 된다. 감독이 나중에 되짚을 사건은
  **반드시 이 표를 지난다**: 오퍼 답 도착 · 협상 기한과 만료 · 보드 답신도
  포함해서. 일지의 원본이 이 표 하나이기 때문이다.
- **일지(diary)는 저장하지 않는다** — 오피스 달력의 일자별 일지는 기록 테이블
  (경기·이적·성장·부상)에서 파생한다. 장부에 원본이 있는 것을 두 번 적으면
  반드시 어긋난다.
- **서사 메모리도 그 기록 테이블 중 하나다** — 저장된 줄이 날짜별 **「소식」**
  (`kind: "news"`)으로 일지에 그대로 선다. 코어가 새 문장을 쓰는 것이 아니라 이미
  적힌 줄을 날짜에 세우는 것이다. 규칙 셋:
  - `match` 갈래는 빼놓는다 — 그날의 경기 줄은 일정 축이 이미 세운다. 갈래가 없는
    옛 세이브의 줄은 `other`로 본다(무엇인지 모르는 줄이지 경기 줄이 아니다).
  - 한 날에 여럿이면 **무게 내림차순**, 같으면 적힌 순서다.
  - **같은 날 같은 문장은 한 번만 선다** — 기록 테이블이 이미 세운 줄(이적창 개폐
    같은)을 서사 표가 다시 세우지 않는다.
  - 조회도 같은 표를 읽는다 — `get_league(view=calendar)`는 `from`이 오늘보다
    앞이면 그 범위의 일지를 일정 뒤에 함께 낸다.
- `CHARACTER_MEMORY { characterId, date, text, salience 1\~5 }` — **인물이 소유하는
  기억.** 서사 메모리와 같은 결이되 주인이 다르다: 세계의 사건은 시간순으로 쌓이고,
  이쪽은 한 사람의 것이라 **그 인물이 무대에 설 때 함께 실린다** (§9-1).
- **주입은 salience×recency 가중이다** — 상태 스냅샷의 「최근 사건」은 최신 4건이
  아니라 `salience × 0.5^(지난 일수 / 반감기 7일)`이 큰 4건이다(같으면 최신이
  이긴다 — 뽑힌 뒤에는 시간순으로 선다). 어제의 스카우트 한 줄(1)이 지난주의 경질
  임박(5)을 밀어내지 않는다.

### 서사 아크 — 기억을 이야기로 엮는 골격

`NARRATIVE_ARC { id, kind, subjectId, stage, openedOn, updatedOn, resolvedOn,
title? }` — 세이브에 남고(옛 세이브는 빈 배열), **개폐는 전부 코어 장부의
사실에서 결정적으로 판정한다**(`world/arcs.ts`, 매일 tick). 아크는 데이터일 뿐
강제 이벤트가 아니다 — 코어 상태를 바꾸지 않고, GM이 흐름을 읽는 재료로만 선다.

단계는 `open → rising → climax → resolved` **한 방향으로만** 움직인다 — 사실이
잠깐 물러났다고 이야기가 되감기면 GM이 지난 턴과 다른 흐름을 읽는다. 갈래와
개폐 규칙은 아홉이고, 주인(`subjectId`)은 선수 아크면 선수 id, 팀 아크면 팀 id다.
**표의 어느 칸에도 난수가 없다** — 전부 장부에서 읽는 수와 날짜다:

| kind                 | 주인 | 열림 (open)                                                        | rising                                          | climax                                                 | resolved                                      |
| -------------------- | ---- | ------------------------------------------------------------------ | ----------------------------------------------- | ------------------------------------------------------ | --------------------------------------------- |
| `board-standoff`     | 팀   | 보드 경고 **1회**                                                  | 경고 2회                                        | 경고 3회, 또는 마지막으로 판정된 구단주 요청이 불이행  | 경고가 지워졌다 · 경질 · 이직                 |
| `grievance`          | 선수 | 불만(`PlayerIssue`)이 **7일**을 넘겼다                             | 14일                                            | 28일, 또는 다가옴 계단 ≥ 2                             | 불만이 지워졌다 (면담·승격·이적)              |
| `captain-succession` | 팀   | 주장이 **32세 이상**이고 계약 만료 ≤ 365일, 또는 나이 무관 ≤ 180일 | 만료 ≤ 120일, 또는 주장이 **30일 이상** 결장 중 | 만료 ≤ 60일, 또는 30일 이상 결장인데 **부주장이 없다** | 완장이 넘어갔다 · 주장 재계약 · 주장이 떠났다 |
| `injury-comeback`    | 선수 | 우리 선수의 예상 결장 **30일 이상** 부상                           | 재활 반환점을 지났다                            | 복귀 14일 안 (근황의 눈금과 같다)                      | 복귀했다 (또는 팀을 떠났다)                   |
| `veteran-twilight`   | 선수 | **33세 이상**이고 계약 만료 ≤ 365일                                | 만료 ≤ 180일                                    | 만료 ≤ 90일, 또는 나이·종합이 이미 **은퇴 문턱**       | 재계약 · 은퇴 · 이적                          |
| `transfer-saga`      | 선수 | 협상 라운드 **2회 이상** (한 방 거절은 아니다)                     | 라운드 3회                                      | 합의(메디컬 대기 포함)                                 | 완료·결렬·만료                                |
| `prospect-rise`      | 선수 | **21세 이하** · 시즌 1군 출전 **5** · 시즌 평점 **6.3 이상**       | 출전 10                                         | 출전 15                                                | 스물둘 · 평점이 문턱 아래 · 시즌이 바뀌었다   |
| `losing-run`         | 팀   | 리그 3연패                                                         | 4연패                                           | 5연패부터                                              | 연속이 끊겼다                                 |
| `winning-run`        | 팀   | 리그 3연승                                                         | 4연승                                           | 5연승부터                                              | 연속이 끊겼다                                 |

세 갈래는 **사실 하나로 열리지 않는다** — 그것이 이 표에서 가장 중요한 줄이다.
`prospect-rise`는 나이·출전·평점 셋이 동시에 서야 열리고, `veteran-twilight`는
나이와 계약 시계를 겹쳐 읽으며, `captain-succession`은 완장·나이·계약·결장·부주장
공석을 함께 본다. 하나만 보면 스물한 살 전원이 유망주 아크를 갖고, 계약 마지막 해의
전원이 황혼을 갖는다.

- **동시 활성 6개.** 갈래가 아홉이 되면서 넷은 좁아졌다 — 새 갈래 넷은 전부 **시즌을
  가로지르는 느린 이야기**(유망주·황혼·승계·대치)라, 넷에 묶어 두면 그것들이 자리를
  붙들고 앉아 불만·부상 같은 **그 주의 이야기**가 열릴 자리가 없어진다. 여섯이면 느린
  것 하나둘과 빠른 것 서넛이 함께 서고, 스냅샷 블록은 여섯 줄로 여전히 짧다.
- 자리가 차면 새 아크는 열리지 않는다 — 이미 선 아크는 밀려나지 않고, 후보끼리는
  **감독이 조치해야 하는 순서**로 선다:
  보드 대치 > 불만 > 주장 승계 > 부상 복귀 > 베테랑 황혼 > 이적 사가 > 유망주 성장 >
  연패 > 연승. 같은 갈래면 subjectId 사전순이다. 앞쪽은 감독의 자리와 라커룸이 걸린
  것, 뒤쪽은 지켜보는 것이다 — `prospect-rise`가 연속 기록 위에 서는 것은 유망주에게는
  기용이라는 손잡이가 있고 연승·연패에는 없기 때문이다.
- **`prospect-rise`는 임대 보낸 선수도 주인으로 삼는다** — 계약은 우리 것이고 출전은
  남의 경기장 것이다(→ ../simulation/transfer.md §2). 임대는 출전을 사는 거래이므로,
  2부에서 스무 경기를 뛰는 열아홉 살이야말로 이 이야기의 원형이다. 시즌 기록은 그가
  **지금 뛰는 팀**의 줄에서 읽고, 사실 줄에 그 팀 이름이 함께 선다.
- **출전은 리그만 세지 않는다** — 장부의 시즌 1군 출전(`SeasonStat.apps`)은 리그·컵·
  유럽을 합친 하나의 수다. 컵에서 터진 유망주도 같은 이야기라 그대로 쓴다. 2군 리그
  기록(`reserveApps`)은 섞이지 않는다.
- 같은 (갈래, 주인)의 활성 아크는 하나다. 닫힌 아크는 20개까지 남고 오래된 것부터
  밀린다 — 서사 메모리 200개와 같은 규약.
- **미해소 아크는 다음 시즌으로 이월된다.** 시즌 롤오버는 아크를 지우지 않는다 —
  아크를 닫는 것은 언제나 **사실의 부재**다. 그래서 사실이 시즌을 넘는 아크(부상
  재활·열린 협상)는 이야기도 시즌을 넘고, 사실이 시즌과 함께 지워지는 아크는
  같이 닫힌다: 연속 기록은 시즌의 것이고(slump.ts) 불만·압력도 롤오버가 비운다
  (§8). 감독이 팀을 떠나면 옛 구단의 아크도 전부 닫힌다(불만을 비우는 것과 같은 결).
- **활성 아크는 상태 스냅샷에 선다** — 단계·코어가 뽑은 사실 줄과 함께, 닫힐 때까지
  GM이 매 턴 그 흐름을 읽는다. 시간을 손잡이로 넘긴 턴에는 단계가 움직인 사실이
  「그 사이 벌어진 일」에 실린다.

**이름은 압축 에이전트가 제안하고 코어가 검증한다** — `registerCharacters`와 같은
계약(§9-1). 이력이 접힐 때 이름 없는 활성 아크가 브리프에 실리고, 모델이 제안한
제목을 코어가 검사한다: 아크가 실제로 있고 · 아직 활성이며 · **이름이 없어야**
받는다(한 번 붙은 이름은 시즌 내내 같은 이야기를 가리켜야 한다). 길이는 30자
이내. 걸린 항목만 버리고, 이름이 없으면 코어의 사실 줄이 그 자리를 대신한다 —
이름 짓기가 실패해도 아크는 굴러간다.

## 9-1. 캐릭터북 갱신 — 무엇을 LLM에 맡길지가 경계다

이력이 접힐 때(→ ../llm/agents.md §5-1) 그 구간을 요약하는 김에 캐릭터북도 갱신한다.
같은 구간을 두 번 읽지 않으려는 것이 아니라, **접히는 순간이 그 구간에 누가 있었는지를
마지막으로 아는 순간**이기 때문이다.

⚠️ **인물지의 성격·동기·말투는 LLM이 고쳐 쓰지 않는다.** 페르소나는 시드로 결정적으로
생성되고(`world/persona.ts`), LLM이 그걸 덮어쓰면 "같은 세이브는 같은 사람을 만난다"는
§2의 규약이 깨진다 (AGENTS.md §6.4 — 창발한 출력은 검증 없이 게임 상태가 되지 않는다).

맡길 수 있는 것은 둘뿐이다.

| 맡기는 것        | 코어가 검사하는 것                                                                              |
| ---------------- | ----------------------------------------------------------------------------------------------- |
| **인물별 기억**  | 그 `characterId`가 실제로 이 세계의 화자인가 · 길이 · 인물당 보관 수                            |
| **새 인물 등록** | `characterId` 전역 유일 · 이름이 이미 선 화자와 겹치지 않는가 · 자리(`role`)가 열린 집합 안인가 |

**두 검사의 이름 범위는 캐릭터북이 이름을 찾는 해석과 같다** — 세이브의 페르소나 ·
화자 사전이 아는 자리 전부(§3, 명부와 이름난 현역 포함) · **리그의 선수 전부**(선수
페르소나는 이름에서 파생하므로, §6). 기억 필터가 화자 사전만 보면 명부 인물·파생
선수 앞으로 적힌 기억이 조용히 버려지고, 등록 검사가 그 이름을 모르면 압축이 "조제
무리뉴"를 `friend`로 새로 세운다 — 캐릭터북은 저장된 페르소나를 먼저 찾으므로 표가
적은 인격이 LLM이 지어낸 인격에 **가려진다.** 리그의 선수 이름까지 등록을 막는 것도
같은 저울이다: 지어낸 지인이 실존 선수의 이름을 우연히 받는 것보다, 그 등록 하나가
버려지는 쪽이 싸다(틀린 직책보다 없는 게 낫다는 §3 원칙 4와 같은 결).

- **인물별 기억 한 줄** — 그 인물에게 이번 구간에 벌어진 일. `NarrativeNote`와 같은
  결이되 **인물이 소유한다**. 인물당 보관 수에 상한이 있고 넘치면 오래된 것부터 밀린다 —
  §9의 서사 메모리가 200개를 유지하는 것과 같은 규약이다. **더해진 기억이 이력을 고치지는
  않는다** — 지난 턴의 카드는 그때 실린 그대로이고, 새 기억은 그 인물이 다시 주입될 때
  실린다 (§6).
- **새 인물 등록** — GM이 즉흥으로 세운 화자(상대 감독·에이전트·감독의 사람)를
  캐릭터북에 넣는다. 새 데이터라 Zod 검증과 **이름 충돌 검사**가 함께 간다:
  `characterId`는 전역 유일이고(§1), 이름이 이미 선 화자와 겹치면 **등록하지 않는다** —
  겹친 자리에 아무것도 붙이지 않는 `speakerRoles`의 원칙(§3 ③)을 등록 쪽에서도 든다.
- **기존 인물은 자리를 지킨다.** 이미 있는 `characterId`로 등록이 오면 그 페르소나는
  건드리지 않는다. 갱신은 기억을 더하는 것뿐이다.
- **실패해도 게임은 굴러간다** — 검사에 걸린 항목만 버리고 나머지는 반영한다. 압축
  자체가 실패하면 캐릭터북도 그대로다.

## 10. 미해결

- **압력의 눈금은 하네스가 재는 값이다** — 임계·증가량(§8)은 실제 플레이의 건수로만
  검증되므로 `approach-rate` 하네스가 시즌당 건수를 잡고 있다
  (→ ../simulation/balance-harness.md). 밴드 밖이면 눈금을 옮기는 것이 먼저다.
- **관계 점수** — 관계의 초기값은 원형 조합이 결정적으로 채우지만(§6), **사건이
  관계를 움직이는 점수**는 없다. 계약 해지의 심경 카드가 팀 전체에 같은 무게로
  걸리는 이유가 그것이다(§5) — 누가 그와 가까웠는지를 가를 값이 아직 없다.
- **라이벌 악연이 아크가 되지 않는다** — 갈래는 아홉이고 그중 셋은 여러 사실을 겹쳐
  읽어 열리지만(§9), 라이벌은 그중에 없다. 관계 점수가 먼저이기 때문이다: 여러 시즌에
  걸친 악연을 하나의 이야기로 여닫으려면 **사건이 관계를 움직이는 값**이 있어야 하고,
  그 값이 위 항목대로 아직 없다.
