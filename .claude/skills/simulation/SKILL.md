# 한 시즌 시뮬레이션 — 감독으로 플레이한다

이 스킬은 **정해진 시나리오의 게임을 열어 한 시즌(7월 1일 → 다음 7월 1일)을
감독으로 끝까지 진행**한다. 목적은 둘이다 — 실제 플레이어가 남길 만한 기록
(`apps/web/.log` · `apps/web/.data`)을 남기는 것, 그리고 그 과정에서 게임이
어긋나는 자리를 발견해 이슈로 올리는 것. 이기려고 무리하는 것이 아니라
**그럴듯한 감독이 하는 일을 빠짐없이** 하는 것이 기준이다.

⚠️ 세 문장이 이 스킬의 전부다. 나머지는 그 풀이다.

1. **한 번에 한 턴.** 요청 하나가 끝나기 전에 다음 요청을 보내지 않는다.
   병렬도, 백그라운드 루프도, 정해진 문장을 정해진 구간에 쏘는 스크립트도
   없다.
2. **읽고 나서 결정한다.** 매 턴의 서사 · 도구 결과 · 상태를 읽고, 감독이 그
   자리에서 할 결정을 한다.
3. **장부가 이야기를 이긴다.** 계약 · 영입 · 교체가 됐는가는 GM의 문장이 아니라
   상태(`views`)로 확인한다.

## 2. 준비

### 2-1. 서버

- 게임은 **`http://localhost:3000`의 dev 서버**를 통해 돌린다. 유저의 서버다 —
  절대 죽이지 않는다. `curl -s localhost:3000/api/games`가 답하면 그대로 쓴다.
- 아무것도 듣지 않으면 `pnpm dev`를 백그라운드로 띄우고(`run_in_background`)
  `GET /api/games`가 200을 줄 때까지 기다린다. 띄운 서버는 시뮬이 끝나도
  그대로 둔다 — 로그 · 세이브를 유저가 열어 볼 자리다.
- 실모드여야 한다: `config/llm.yml`의 provider 키(`GEMINI_API_KEY` 또는
  `GOOGLE_API_KEY`)가 서버의 환경에 있어야 한다. `LLM_MODE=mock`으로는
  시뮬레이션의 의미가 없다 — 첫 장면의 서사가 규칙 문장으로만 오면 멈추고
  유저에게 말한다.
- 기록은 기본 자리(`apps/web/.log` · `apps/web/.data`)에 남긴다.
  `STORY_FM_DATA_DIR` · `STORY_FM_LOG_DIR`를 옮기지 않는다. **`.log`는 절대
  비우지 않는다.**

### 2-2. 작업 폴더와 환경

```bash
export SIM_DIR=<scratchpad>/simulation      # 상태 · 저널 · 요청 원문
export SIM_HOST=http://localhost:3000
B=.claude/skills/simulation/bin              # 이 스킬의 스크립트 넷
```

| 스크립트                                   | 무엇                                                                                                                                                                    |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `new-game.sh`                              | 시나리오로 게임을 연다 → `$SIM_DIR/game.txt`                                                                                                                            |
| `turn.sh '<json>'`                         | 턴 하나. 끝날 때까지 기다리고 서사 · 도구 줄 · 상태를 찍는다                                                                                                            |
| `state.sh [--fetch] <갈래> [N]`            | 마지막 페이로드 요약 — `brief` `attention` `first` `reserve` `xi` `calendar` `contracts` `finance` `table` `match` `youth` `windows` `registration` `reputation` `chat` |
| `lineup.sh --dump` · `lineup.sh body.json` | 전술판 — 지금 선발을 body로 뽑고, 고쳐서 결정적으로 저장                                                                                                                |

턴 본문의 모양은 `turn.sh` 머리에 있다: `message`(1,000자 이내) · `operation`
(`skip_days` · `skip_to_next_match` · `advance_match`) · `orders`(교체 · 전술 ·
자리 · 역할 — 코어가 그대로 집행한다).

### 2-3. 시나리오

정해진 게임이다 — 같은 시드는 같은 세계를 세우므로 시즌마다 결과를 견줄 수
있다.

| 항목 | 기본                                                                                                                                   | 바꾸려면         |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| 팀   | `manutd`                                                                                                                               | `SIM_TEAM`       |
| 감독 | 마이클 캐릭                                                                                                                            | `SIM_MANAGER`    |
| 배경 | 맨체스터 유나이티드의 미드필더 출신 감독. 저번 시즌 위기의 맨체스터 유나이티드를 중도 부임하여 살리고 챔피언스 리그 진출을 성공시켰다. | `SIM_BACKGROUND` |
| 시드 | 908121501                                                                                                                              | `SIM_SEED`       |

`/simulation`은 새 게임을 연다. `/simulation resume <gameId>`면
`export SIM_GAME=<id>` 뒤 `state.sh --fetch brief`로 이어 간다 — 저널(§8)이
어디까지 왔는지 말해 준다.

```bash
$B/new-game.sh && export SIM_GAME=$(cat $SIM_DIR/game.txt)
```

첫 장면(부임 회견)이 온다. 여기서부터 §4의 루프다.

### 2-4. 시간 감각

시즌 하나는 경기 55–65개, 턴 600–800개다. 턴 하나가 3–20초라 **서너 시간
이상** 걸린다. 전경에서 한 턴씩 간다. 컨텍스트가 길어져 요약되면 저널과
`state.sh --fetch brief`가 기억이다 — 그래서 저널은 매 경기 뒤 갱신한다.

## 3. 단 하나의 진행 규칙 — 순서대로, 읽고, 결정하고

- **요청은 언제나 하나만 날아 있다.** `turn.sh`가 돌아오기 전에 다른 `turn.sh` ·
  `lineup.sh`를 보내지 않는다. 서버는 게임 하나에 잠금 하나라 두 번째 요청은
  3초 뒤 409로 물러난다 — 그 409가 보이면 내가 병렬로 보낸 것이다.
- **백그라운드 없음.** `run_in_background`로 턴을 보내지 않는다.
  서브에이전트에게 경기를 나눠 주지 않는다. `for … turn.sh` 루프로 여러 턴을
  한 번에 돌리지 않는다 — 「경기 끝까지 N번 advance」도 안 된다. 정지점마다
  읽을 것이 있다.
- **정해진 문장 없음.** "60분입니다. 지친 선수 셋 빼세요" 같은 문장을 매 경기
  같은 자리에 보내는 것은 플레이가 아니다. 말은 그 자리의 상황에서 나온다.
- 턴이 끝나면 세 가지를 읽는다: ① 서사(세계가 무엇을 말했나 — 코치 · 기자 ·
  선수의 질문에 답할 것이 있나) ② 도구 줄(`=== 이번 턴의 도구 ===` — 반려 ·
  미해결이 있나) ③ 상태(`=== 상태 ===` — 날짜 · phase · 안건 · 다음 경기 · 경기
  중이면 스코어와 교체 수).
- 감독의 말은 **감독의 말**이다(overview.md §3): `*행동*`은 별표, 대사는
  따옴표. 세계를 서술하지 않는다("PSG가 승인했다"가 아니라 "PSG에 오퍼를
  넣는다"). 한 메시지는 한 주제, 1,000자 이내.

## 4. 하루의 루프

`phase`가 `idle`인 동안 반복한다.

1. **안건부터** — `state.sh attention`. 비어 있을 때까지 시간을 흘리지 않는다.

   | kind       | 무엇                                                            | 답하는 법                                                                                                           |
   | ---------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
   | `press`    | 기자회견이 열려 있다                                            | §4-1. 다음 회견이 열리거나 시즌이 넘어가면 불참(거절)으로 닫힌다                                                    |
   | `approach` | 누가 감독을 찾아왔다(선수 · 에이전트 · 구단주) — `D-`가 남은 날 | 사흘 안에 답한다. 방치는 거절과 같은 값이다                                                                         |
   | `verdicts` | 감독의 답을 기다리는 협상 — 상대의 답이 굳어 차례가 왔거나 기한 | 기한 전에 답한다(기한 당일 시계가 멈춘다) — 수락이면 "서명한다"(accept_deal), 역제안이면 받거나 되부르거나 물러난다 |
   | `promises` | 기한이 다가온 약속                                              | 다음 선발에 반영한다(§5-1)                                                                                          |

2. **오늘의 일** — 달력(`state.sh calendar`)과 §6의 체크포인트를 본다. 이적창이면
   §6-3, 매달 1일이면 §6-2, 경기 사이마다 §6-1. 할 말이 있으면 한 턴에 한 주제로
   말한다.
3. **시간을 흘린다** — 다음 경기가 7일 안이면 `skip_to_next_match`(날짜는
   `views.calendar.entries[].isNext`), 아니면 `skip_days` 7(또는 1). 시계는
   경기일 · 기한 협상 · 다가옴 · 시즌 끝에서 멈춘다 — 멈춘 곳의 서사와 안건을
   읽고 1로 돌아간다.
4. `phase`가 `matchday`가 되면 §5.

### 4-1. 기자회견

회견은 세계가 먼저 말을 거는 자리다 — 경기마다(친선 제외), 무승 3–4경기,
개막 · 더비 전야, 큰 이적, 시즌 마지막 리그 경기 뒤. 스탠스별 대가(career.md
§4): 감싸기 −보드 −언론 +선수단 · 책임 인정 +보드 +언론 +선수단 · 공개 비판
+언론 −선수단 · 도발 +언론 −보드 · 말 아끼기 −언론 · 불참 −언론 크게.

- 이겼으면 대체로 **책임 인정이나 도발**(공은 선수에게, 말은 당당하게), 졌으면
  **책임 인정**, 선수가 표적이면 **감싸기**를 쓰되 한 달에 몇 번으로 제한한다.
  한 시즌 같은 스탠스로 가지 않는다 — 언론 평판이 45 아래로 내려가면 감싸기를
  끊는다.
- 답은 회견 안건이 선 **바로 그 턴이나 다음 턴**에 한다. 시간을 흘려 불참으로
  닫히게 두지 않는다.

## 5. 경기일

### 5-1. 킥오프 전 (phase `matchday`)

1. `state.sh first` · `state.sh xi` · `state.sh calendar 3` — 다음 경기의 대회와
   상대, 그 다음 경기까지의 간격을 안다.
2. **선발 원칙**
   - 부상 · 정지(`available` 아님)는 뺀다. 경고 누적으로 다음 경기 정지가 임박한
     선수는 큰 경기 앞이면 아낀다.
   - 체력 `condition.value` 70 미만이거나 `fatigueBand`가 `heavy` ·
     `overloaded`면, 대체자가 종합 −6 안에 있는 한 벤치로. 다음 경기까지 3일
     이하면 로테이션 3–5명, 컵 초반 · 약한 상대면 더.
   - **GK 자리에는 GK만.** 모든 슬롯은 `positions`에 그 자리(또는 같은
     포지션군)가 있는 선수. 슬롯 코드는 `GK` · `LB LCB CB RCB RB` ·
     `LWB LDM CDM RDM RWB` · `LM LCM CM RCM RM` · `LW LAM CAM RAM RW` ·
     `LF CF RF` · `LST ST RST`.
   - 벤치 9: GK 하나, 수비 · 중원 · 공격 각 둘 이상. 약속(`promises`)이 걸린
     선수는 기한 전 선발 비율을 맞춘다.
   - 유스에게 분을 줄 자리(컵 초반 · 승부가 기운 뒤)를 시즌 내내 만든다 — 구단
     비전의 「유스 출전」이 이것을 센다.
3. `lineup.sh --dump > $SIM_DIR/xi.json` → 고친다 → `lineup.sh $SIM_DIR/xi.json`.
   200이 오고 찍힌 선발이 내가 짠 것인지 확인한다. 전술 5축(멘탈 · 라인 · 압박 ·
   템포 · 폭)과 패스 스타일도 같은 body에 싣는다 — 상대와 상황이 정한다.
4. **팀토크** — 한 턴, 상황에서 나온 말. 약속으로 읽힐 말("다음 경기도 네가
   선발이다")은 뜻이 있을 때만.
5. `{"operation":{"kind":"advance_match"}}` — 킥오프.

### 5-2. 경기 중 (phase `match`)

`advance_match` 한 번이 정지점 하나까지(골 · 퇴장 · 부상 · 하프타임 · 종료, 최대
25분) 굴린다. 정지점마다:

1. 서사를 읽는다 — 코치가 무엇을 제안했나, 상대가 무엇을 바꿨나.
2. `state.sh match` — 분 · 스코어 · 교체 창 · 온필드 체력 · `gassed` · 경고 · 벤치.
3. 결정한다:

   | 상황                                | 한다                                               |
   | ----------------------------------- | -------------------------------------------------- |
   | `gassed`거나 60분 이후 체력 40 아래 | 같은 자리의 벤치와 교체                            |
   | 경고 1장 + 거친 경기                | 큰 경기면 교체 검토                                |
   | 60분 이후 지고 있다                 | 공격적 교체 + 멘탈 · 라인 한 칸 위                 |
   | 75분 이후 두 골 차 이상 앞선다      | 지친 주전 보호, 유스에게 분                        |
   | 퇴장 · 부상                         | 자리를 메운다(부상은 코어가 뺀다 — 빈 자리를 확인) |

   교체는 **`orders`로** 낸다 — 이름이 아니라 id, 한 정지점에 함께 낸 교체가
   창 하나다(`subs.limit` — 다섯 명 · 창 셋):

   ```bash
   $B/turn.sh '{"message":"마이누는 다리가 멈췄다. 산투스로 바꾸고 라인은 한 칸 내린다.","orders":[{"kind":"substitution","out":"kobbie-mainoo","in":"andrey-santos"},{"kind":"tactic","axis":"defensiveLine","value":3}]}'
   ```

   `state.sh match`의 온필드가 바뀌었는지 본다. 특정 분에 멈추고 싶으면 말로
   한다("62분에 멈춰 달라") — GM이 그 분까지 굴린다.

4. 바꿀 것이 없으면 `advance_match`.
5. 종료 휘슬이 오면 마감(결산)이 같은 턴에 이어진다. 결과 · 평점 · 부상 · 경고를
   읽고 §5-3.

### 5-3. 경기 뒤

- 회견 안건이 섰으면 §4-1.
- `state.sh first`로 부상 · 정지 · 체력을 읽고 다음 경기 계획을 저널에 한 줄
  적는다(§8).
- 경기 리포트가 필요하면 `GET /api/games/$SIM_GAME/match-report/<matchId>`
  (`views.calendar.entries[].match.matchId`).

## 6. 선수단 관리 달력

### 6-1. 경기 사이마다 (보통 3–7일)

- **포지션 감사**: `state.sh first`에서 1군 GK ≥ 2, 포지션군(GK · DF · DM/MID ·
  AM/FW)마다 가용 인원 ≥ 2. 모자라면 2군 승격(`lineup.sh` body의
  `squadLevels`) · 영입 · 임대. 1군은 20–30명.
- **훈련**: 이번 주 경기 수와 체력을 보고 한 턴에 말한다 — 주 2경기면 회복 위주,
  새 전술이면 전술, 프리시즌은 체력.
- **약속 · 불만**: `promises`가 걸린 선수, `hasIssue`인 선수는 면담이나 선발로
  답한다.

### 6-2. 매달 1일

- **계약**: `state.sh contracts`. `daysLeft` ≤ 365인 모든 선수에 결정 하나 —
  잡는다(재계약을 **지금** 연다), 판다(다음 창에 매각), 보낸다(대체자 계획).
  만료 180일 안에 재계약이 없으면 선수가 먼저 불만을 세우고, `(사전계약 가능)`이
  붙은 선수는 남의 구단이 반년 전에 데려갈 수 있다. **답이 오면 그날 서명한다** —
  서명 전엔 계약이 아니다.
- **재정**: `state.sh finance` — 잔고 · 주급 여력 · 보드 요청(`board`) · 예산
  동결. 보드 요청은 기한 전에 이행하거나 한 번 되묻는다(불이행 −6, 이행 +3).
- **평판**: `state.sh reputation`.

### 6-3. 이적창 (여름 7/1–9/1 · 겨울 1/1–2/1)

1. 창이 열린 날: 필요 자리 목록(§6-1의 감사 + 만료로 나갈 사람) · 예산 · 주급
   여력 · 팔 사람(잉여 · 불만 · 만료 임박).
2. 스카우트 임무는 **첫 주에** 건다(2주 걸린다) — 자리 · 나이 · 상한액을 말로.
3. 오퍼는 창 중반까지 넣고, 답이 막히면 **마감 7일 전에 플랜 B**를 실행한다.
   역제안은 받을지 그 턴에 정한다.
4. 들어온 오퍼(`verdicts`)는 매번 답한다 — 거절도 답이다. 같은 창에서 값이 붙은
   오퍼를 두 번 막으면 이적 요청이 선다.
5. 마감 전: `state.sh registration` — 등록 25(만 21세 초과) · 홈그로운 8. 명단이
   차면 영입은 2군으로 들어온다.
6. 창이 닫힌 뒤 `state.sh first`로 **모든 영입이 명단에 있는지** 확인한다(§7).

## 7. 장부가 이야기를 이긴다 — 검증

상태를 바꾸는 일은 **바뀐 것을 `views`에서 본 뒤에야** 끝난 것이다.

| 한 일              | 확인                                |
| ------------------ | ----------------------------------- |
| 선발 저장          | `lineup.sh` 200 + 찍힌 선발         |
| 교체               | `state.sh match`의 온필드           |
| 영입 · 임대        | `state.sh first`에 그 선수          |
| 재계약 서명        | `contractUntil`이 새 날짜           |
| 매각 · 방출        | 명단에서 사라짐 + `finance.balance` |
| 유스 계약          | `state.sh reserve`에 이름           |
| 훈련 · 주장 · 키커 | 도구 줄의 성공                      |

GM이 "확정됐다"고 써도 `views`에 없으면 **되지 않은 것**이다 — 그 턴 id를
발견(§8)에 적고, 장부의 상태(`verdicts` · "협상 목록 보여줘")를 읽어
맞는 길로 다시 낸다. 도구 줄에 반려가 서면 같은 뜻을 다른 길로 — 선발은
전술판, 교체 · 전술은 `orders`, 그 밖은 문장을 좁혀서.

## 8. 저널 · 발견 · 마무리

- `$SIM_DIR/journal.md` — 게임 날짜별 한 줄: 무엇을 결정했고 왜. 매 경기 뒤
  결과 한 줄(대회 · 상대 · 스코어 · 교체 · 부상). 이어 갈 때 첫 줄부터 읽는다.
- `$SIM_DIR/findings.md` — 이상한 자리마다: 게임 날짜 · 무엇이 어긋났나(서사
  vs 장부) · 턴 id(`pnpm log`에서 찾는다 — 실패한 턴도 남는다). 고치지 않는다 —
  플레이 중 발견은 이슈가 된다.
- **시즌이 끝나면**(7/1이 다시 오면) 유저에게 보고한다: 최종 순위 · 전적 · 컵 ·
  잔고 · 평판 · 주요 영입/매각 · 만료 처리 · 발견 목록. 그 뒤 발견마다 `issue`
  스킬로 — 우선순위는 유저가 정한다. `pnpm log --games`가 기록의 위치를 준다.

## 9. 막혔을 때

| 증상                          | 한다                                                                                                                       |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `=== 오류 === … "retry":true` | 10초 뒤 같은 본문을 한 번 다시 보낸다. 또 실패하면 `pnpm log`로 그 턴을 열고 발견에 적은 뒤 문장을 바꾼다                  |
| `retry:false`                 | 본문이 잘못됐다(1,000자 초과 · orders 형식). 고쳐 보낸다                                                                   |
| `done 페이로드 없음`          | 서버는 턴을 끝까지 돌렸을 수 있다 — `state.sh --fetch brief`로 지금 상태를 읽고 나서 판단(같은 지시를 두 번 보내지 않는다) |
| `lineup.sh` 409 `경기 중`     | 경기 중이다 — `orders`로                                                                                                   |
| `lineup.sh` 409 `retry`       | 턴이 도는 중 — 내가 병렬로 보낸 것. 끝나기를 기다려 다시                                                                   |
| `GET /api/games` 무응답       | 서버가 없다 — §2-1. 유저의 3000 · 3311은 절대 죽이지 않는다                                                                |
| 첫 장면이 규칙 문장뿐         | mock 모드 — 멈추고 유저에게                                                                                                |

## 10. 하지 않는다

- 턴을 병렬 · 백그라운드 · 루프로 보내지 않는다. 서브에이전트가 경기를 대신
  뛰지 않는다.
- `.log` · `.data`를 비우거나 옮기지 않는다. 유저의 dev 서버를 죽이지 않는다.
- GM의 문장을 근거로 다음 결정을 하지 않는다 — `views`가 근거다.
- 정해진 문장을 반복하지 않는다. 지난 턴의 말을 복사해 보내지 않는다.
- 플레이 중 코드를 고치지 않는다 — 발견은 이슈로.
- 세계를 서술하는 문장을 보내지 않는다(감독은 감독만 움직인다).
- 약속을 흘리지 않는다 — 출전 · 재계약 · 주장 · 등번호를 입에 올리면 장부에
  약속이 선다.
